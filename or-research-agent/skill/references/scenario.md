# 找场景：从文献机制到可研究的决策问题

## 工作方法
1. 将用户问题拆成系统对象、决策、约束、信息时序、目标。各做一次场景检索和方法检索，保留关键词、时间、库版本、结果数与选读理由。
2. 先定位最邻近的2–5篇论文，再读其问题定义、关键假设和局限。摘要不足时取本地 PDF 的对应页。找“已有方法在哪个现实条件下失效”，不要只组合热门词。
3. 可从信息不确定、资源瓶颈、服务规则、空间网络或多主体协调选一个主变化；解释它改变哪条约束/哪个目标，以及现有模型为什么不能直接解决。
4. 为候选给出机制、可证伪预测、对立解释、数据可获得性和最小验证。结合用户目的推荐，推荐理由是研究取舍，不是客观创新分数。

## 场景卡
| 字段 | 要回答的问题 |
|---|---|
| 决策者/服务对象 | 谁在什么时间点控制什么？ |
| 实际矛盾 | 哪种服务或资源权衡导致现有决策低效？ |
| 决策与边界 | 派单/路由/选址/定价哪项内生，哪些已给定？ |
| 最邻近工作 | paper_id、document_id、原文定位、已有方法、适用前提 |
| 主变化 | 精确改变哪个前提，有什么业务依据？ |
| 待检验假设 | 若该变化重要，应观察到何种差异？什么结果能否定它？ |
| 最小数据 | 订单、网络、时间、成本、容量等具体字段、单位与来源 |
| 基线与消融 | 原方法/简单规则/去掉新机制各比较什么？ |
| 风险与反对理由 | 文献已覆盖、数据拿不到、机制影响太小等 |

交付场景表和一个明确 RQ，如“当站点起降工位拥挤时，显式考虑工位占用的派单相比忽略占用，会怎样改变准时率与地面资源需求？”这只是问题，不预先写提升比例。

## 停止与转向
没有真实痛点证据时标为模型探索。最邻近工作已经覆盖关键机制时，缩小到可验证的结构或实验区别；不得称其首创。数据不足不妨碍推导原型，但限制经验结论。需要证明新颖性时扩展外部原始出版来源，并记录截止时间与检索范围。
