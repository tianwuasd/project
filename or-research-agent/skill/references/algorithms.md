# 求解算法：由结构选择方法

| 模型结构 | 候选方法 | 必须核对的条件 |
|---|---|---|
| 小中型紧凑 MILP | 通用 MILP、有效不等式、warm start | 变量规模、松弛强度、数值尺度；记录 incumbent/bound/gap |
| 巨量可行路径/排班列 | 列生成、branch-and-price | 定价的状态/资源/对偶信息；负 reduced cost；整数分支兼容性 |
| 新列带新同步行 | 列行生成 | 新行如何被识别与分离，漏行会使当前解不可行 |
| 可分两阶段、连续 recourse | Benders/L-shaped | 对偶可用、可行性割、最优性割；整数 recourse 另需适用方法 |
| 大规模复杂路径/同步 | ALNS、matheuristic | 可行性维护、删除/修复、权重更新、局部精修、超时回退 |
| 序贯在线决策 | 滚动优化、ADP/RL | 状态、动作、转移、奖励、历史信息、训练测试隔离、安全可行回退 |
| 学习辅助定价/构造 | 学习模型 + 精确校验 | 学习只提候选；找不到候选不是不存在改进列 |

## 输出算法卡
输入/输出、主问题与子问题、伪代码、每步保持的不变量、最坏复杂度或规模瓶颈、求解时间预算、终止条件、失败回退、参数与随机种子、理论保证的范围。基线至少一个简单策略与一个可核验优化基线；是否增加复杂方法由结构与实测瓶颈决定。

列生成的终止要有可靠定价证明；LP 下界与可行整数上界区分。ALNS、RL 或 learned pricing 单独不提供全局最优保证。精确分支定价需每个相关节点的定价/边界正确，不能把根节点列生成完成等同整体精确。

## 实验设计
小规模先用枚举或可求最优实例做正确性检查，大规模再比较同等时间预算下的质量。最小化问题相对 gap 写清分母，如 `(UB-LB)/max(abs(UB),1e-8)`，两者都有效且 LB≤UB；负/零目标另说明尺度。不可比较的界不合并。

覆盖规模、需求负载、资源容量、时间窗、随机扰动强度和系统边界。消融每次只去一个机制。报告可行率、目标、准时率/违约量、平均与尾部时间、求解器状态。随机方法采用预先固定多个种子，给分布/区间，禁止只挑最好一次。训练和测试跨时间/区域切分，避免未来信息泄漏。

每次运行记录输入文件哈希、代码/版本、求解器与版本、机器、预算、随机种子、状态、objective/bound/gap、可行性复算、耗时。声明未运行的步骤；规划表不可当实验结果。

## 自带微型求解例
`scripts/solve_demo.py` 用枚举给固定模式集全局最优，贪心演示局部决策损失，已有 SciPy 时用 MILP 交叉验证。其输入必须已经给定可行配送模式，并标记资源占用。没有路径生成、无人机个体位置连续、随机或实时调度；扩展这些机制时重新建模和验证。
