## 3. GPU 策略：空闲优先，有条件共享

1. 候选范围取用户显式 GPU 列表与继承的 CUDA_VISIBLE_DEVICES 的交集，使用 UUID 登记。启动子进程后核验其实际 UUID、可见序号和 DDP rank 的映射；rank 号不直接当作物理显卡编号。沿用旧 ImageCHD 对 PyTorch 2.15 NCCL 设备绑定的处理。
2. 显卡数量由用户选择 1–4 张，正式配置默认请求精确两卡。优先选择满足容量的空闲卡。空闲卡数量不足请求数量时进入有超时的等待。全局 batch 默认 4，可修改，手动指定显卡及各卡份额均需满足所选数量和合计。
3. 只有获准集合内全部显卡都有任务，且 `sharing: when_all_busy` 时才评估共享。共享候选需负载较低、有足够显存，并有匹配的真实容量记录。缺少容量证据时等待空闲卡执行有界容量测量，不在忙卡上猜测模型峰值。
4. 共享建议初值：观察 30 秒、每 2 秒采样，利用率 P90 不超过 50%；窗口内最小空闲显存至少为 `1.2 × 匹配配置的实测进程峰值 + max(4 GiB, 总显存的10%)`。这些数值继承原计划作为可调初值，不代表服务器最优值。
5. 实测峰值覆盖模型、阶段、patch/序列长度、每卡 batch、精度、验证、DDP/NCCL 和同时驻留的上游网络，记录 GPU 型号及环境。Torch 分配/保留显存与进程总显存分别记录，不能仅凭 allocator 已分配值准入。
6. 空闲模式保留 `max(4 GiB, 总显存10%)` 的建议余量；按实际余量计算本任务分配预算。项目内部登记和加锁协调自身任务，启动前立即复查外部占用。该机制不对其他用户进程形成硬预留，也不能保证外部任务不瞬时增长。
7. 共享准入后按实际剩余显存、主机内存及本任务吞吐监督，不因外部 PID 的存在直接终止已批准共享。余量不足时停止新增供数，在安全更新边界提交完整状态后释放本任务显卡并重新排队。进程失败时使用最近完整检查点，未提交工作明确重算；不删除或终止外部任务。
8. 查询使用轻量 GPU/PID 信息；只有选定 worker 初始化所需 CUDA 上下文，不使用常驻占卡进程。预测 GPU 工作结束即释放设备，CPU 融合和写出按预算完成。

“有任务”按可靠清单中仍存活的 GPU 计算进程判定，包含本项目登记任务和外部计算任务；显示服务不直接等同于训练任务。获准集合为空时立即报告；PID/可见映射证据缺失时不认定全部繁忙，也不批准共享。每阶段冻结授权范围，显式变更集合时重新核对整个集合和共享前提，实际成员变更遵守全组提交边界；不因候选不足而自行扩大范围。

## 4. 双卡、200 epoch 与数值语义

采用每卡一个进程的 PyTorch DDP/NCCL。一个训练任务的两张卡共同训练同一份模型；数据集、折数及模型之间的任务调度独立。默认一折占用两卡，其他折排队。

STU 预算拟显式配置 `epochs: 200`、`train_steps_per_epoch: 250`、`validation_steps_per_epoch: 50`，共 50000 次全局训练尝试及 10000 次全局验证步骤。这是随机 patch 训练预算；不表示每个 epoch 遍历全部病例。两张卡分担同一全局步骤，不将预算乘以卡数。AMP 跳过更新另计，不追加抽样补足成功次数。

| 配方 | 双卡 batch 建议 | patch 与精度 | 保持/改变的含义 |
|---|---|---|---|
| ImageCHD STU | 延续旧 global batch 4，两卡 `[2,2]` | 延续旧 128³ 及 FP16/scaler；FP32、BF16 作为显式配置 | 原旧配方为 1000 epoch，本次改为用户指定 200 epoch；其余学习率、poly 调度、增强及损失逐项核对 |
| CHD1282 STU | 用户指定 global batch 4，两卡 `[2,2]` | 按原配方核对 patch，保留原生 BF16/FP32 选择 | 原独立入口默认 batch 1；当前 batch 配置记录样本量变化 |

以上为本计划的建议配置，可手动修改。启动前冻结实际生效参数；显存不足时明确等待/停止，不自动缩小 patch、batch、训练预算或改精度。GPU 数量变化只在双方能够共同提交的边界进行；用户指定两卡固定组时不自动改变卡数。

损失迁移以原数学定义为准：CHD1282 保留逐病例可观测类别分组及背景/未知类边际化；ImageCHD 保留有效体素 CE 与受监督类别 Dice。DDP 按有效病例/体素数处理梯度缩放，batch Dice 聚合对应统计量，禁止直接平均两卡独立 Dice。深监督各输出遵守相同归约。没有监督的局部 batch、AMP 非有限梯度及停止请求全 rank 一致处理，避免通信分支不一致。

抽样与增强使用全局输入序号、所选种子和阶段身份生成独立随机状态，再将同一全局 batch 分给各 rank。worker 数量变化不改变已消费输入的身份；预取完成不等于已经消费。两套旧配方的取块和随机增强分别迁入并记录，避免更换调度时同时改变数据分布。

梯度累积由模型配方显式配置，并验证其损失定义；将多个 microbatch 的 Dice 简单相加不等同于整批 Dice。STU 变更卡数及不均分支持必须通过相应归约核查；Q 的 microbatch/累积和求解器预算保持其独立配方。

## 5. CPU、RAM、输入和加速

- 读取 affinity、容器/cgroup 限额、实时 CPU/RAM、I/O 压力；按整个任务组预算，包含 coordinator、rank、训练/验证 worker、病例构建、缓存、队列、pinned 输入和模型专属激活池。建议预算比例 80%，主机余量至少 4 GiB 且保留阶段准入可用量的20%；均可配置。
- worker 数量、病例构建并发、同时读盘数采用 auto 和手动上限。预算初始允许并发；持续输入等待且 CPU/RAM/I/O 有余量时增加，有稳定供数或吞吐收益消失时保持，资源压力时减少。内部数值库线程受控，避免 worker 与内部线程相乘。
- 每个驻留 worker 至少有真实派发槽，预取有界，设置观察窗口和冷却时间。记录 requested/applied、产出 PID、输入等待及全局吞吐，不能只记录理论核数。
- 沿用 MONAI 数据接口。确定性预处理按来源和计划身份缓存；相同计划可共享只读结果，不同折统计不同则分别缓存。跨 rank 缓存计入统一内存预算，原始读盘/解压及标签核验不在每卡、每轮重复执行。
- 默认 RAM 缓存，不自动生成全量重采样副本。文件缓存、概率缓存及 Q 激活转存均使用显式开关、容量与引用规则。每次扩容核对实时新增余量，避免把活动进程内存重复抵扣或过度承诺。
- 接入有界 pinned buffer、非阻塞传输和 CUDA 事件；仅预取已就绪的下一批，保护反向完成前仍被使用的存储。BF16/FP16 按模型选择，TF32、compile、activation checkpointing 和激活转存为独立可调设置，只有真实输出/梯度和吞吐验证通过才启用相应配置。
- 不使用一系列自动容量试验改变科学参数。一次真实规格有界容量检查后记录匹配身份；正常训练用实际完成步骤和轮次观察输入等待、通信及计算。状态查询不建立模型或申请 GPU。

## 6. 恢复、检查和产物

共用检查点保存模型、优化器、调度器、FP16 scaler、epoch/阶段/步数、尝试/成功/跳过计数、各 rank 的 CPU/CUDA/Python/采样随机状态、已消费游标、上游摘要和有效配置。累积过程中不提交不完整优化器状态；未消费预取允许重放。

rank0 原子写入并提交全组状态，其他 rank 只写有界运行反馈。普通保存、正常退出和资源重分配在完整边界进行；异常只使用已提交状态。已知资源等待/压力由监督器显式状态处理，可配置最多三次预算缩减和重新准入；未知数据、模型、通信或数值错误直接报告并停止，不无限重试。

每阶段默认一份 latest 完整状态；显式选模需要时另保留 best，完成引用按需复用。Q 沿用其 latest/best 完整状态要求，不能删掉下游仍引用的基座或定位器。final 指针引用已有有效权重，不额外复制整份同权重文件。

正式日志只保留阶段/轮次摘要、低频资源变化、错误及必要恢复证据；详细步骤追加并设容量上限。终端显示阶段、进度、速度、实际 GPU/worker、恢复及报告位置，不重复打印矩阵和整个预测记录。

必要检查集中在输入登记、启动准入、检查点提交/恢复和最终输出四处；运行中采用低频资源监督。短测专用的整模型参数克隆/变化比较移入验收入口，正式训练保持必要数值检查。兼容性区分计算定义、代码来源和执行参数，展示修改不能未经审计就迫使重训。

第8–10节的跨实现输出/梯度比较、连续与恢复轨迹比较和双卡分担核对属于开发验收；通过后不在每次正式训练中重复运行。实际任务保留数据及提示来源登记、启动容量身份、正常数值保护、提交/恢复核验和最终结果验证，不额外建立一套日常检查任务队列。

目录约定：过程与检查点在 course，最终掩膜与评价在 result，环境在 env，原件及共享预训练权重在 data。短测的临时结果在其独占 course 工作区完成验证后清理，仅保留小报告；已有完成结果按身份直接复用。

`folds.py` 维护已完成复用、未完成恢复、未开始排队。跨折核验外层患者隔离和一次验证覆盖；分清外层评价与内层选模，固定测试集不用于调参。单折验证仅证明所测折，三折评价汇总和可选预测集成单独验收。

### MedSAM2 的独立事项

官方实现含独立序列训练和提示传播，不能把现有 3D 卷积适配器改名后作为 MedSAM2。固定其输入灰度处理、切片顺序、提示策略、序列长度、可训练/冻结模块和权重来源。MONAI 仍负责项目的数据组织、空间记录与结果接口；模型专属输入处理保留单独配方。

源 NIfTI 按需解码为有界帧序列，先核对灰度转换和提示坐标，再适配官方输入接口；中间 RGB/重采样数组不默认写出整套副本。序列记忆和按目标传播的驻留量纳入 RAM/显存容量记录。

训练可从已知训练标注生成提示，未知类别不生成负提示。验证显式区分模拟提示与自动提示；无人工交互的正式预测使用仅依赖图像的已训练定位器，提示来自用户时单独标明。测试标签只进入评价，不能进入自动定位或提示生成。按结构输出二值概率/掩膜，转换 8/11 类图需要固定冲突规则。

优先选择 MedSAM2 官方 CT 配方及对应权重，不能把肿瘤预训练直接称为心脏专用模型。依赖提供独立锁定配置，按实际兼容性确定复用主环境或使用 env 下独立 MedSAM2 环境；共用工程接口。CUDA 扩展启用/禁用为显式选择，启用时构建失败即停止，不静默忽略。MedSAM2 的 epoch、每序列帧数、batch 和预算按其方法明确，STU 的200 epoch不自动传播到其他模型。

### Q 的独立事项

沿用 r2 的网络、监督、求解器及数值条件。现有外部 STU 权重仅在训练患者、A 组拟合计划、类别和上游身份都满足 Q 合同时复用；不能仅凭网络同名复用可能见过 B/C/D 的基座。Q-1 的中心线/半径头和方向特征不在本次路线一接入中启用。

CHD1282 保留11类与十三事件定义；ImageCHD按解剖名称建立适用事件、允许集合、定位通道及输出头，缺少的血管类别不补成真实标签。没有可评价关系参考时标记不可评价，不根据分割图生成临床真值。独立双卡能力按基座/定位器/局部三阶段分别接入并验收；旧单卡技术容量与激活池初值只作参考。

## 9. 文件组织和实施顺序

保持根 run.py、smoke.py、setup_env.py、update.py。新增职责如下，文件只在对应功能实施时创建：

| 位置 | 职责 |
|---|---|
| runtime/gpu.py、resources.py、supervisor.py | GPU 集合/共享准入、CPU/RAM 总预算、全组进程与压力状态 |
| data/supply.py、transfer.py、cache.py、augmentation.py | 实际供数池、消费序号、pinned/CUDA 事件、有界共享缓存及按配方增强 |

| datasets/discovery.py、splits.py | 两数据集清单生成、旧划分迁移及患者角色核查 |
| models/medsam2/、q_route1/、xu/ | 模型专属结构、提示/候选/求解/融合及配方 |
| configs/models/、datasets/、experiments/ | 可独立修改的模型、标签、划分、训练及资源参数 |

| 次序 | 交付 | 验收结束条件 |
|---|---|---|
| 1. GPU 与 STU 正式执行 | 单/双卡、epoch、AMP、固定全局 batch、GPU/主机预算、忙卡共享、恢复与简洁日志 | 获准的1–2例完成目标尺寸单/双卡少量真实更新；连续与恢复结果在预先定义容差内一致；共享条件和 UUID 映射正确 |
| 2. 两数据集正式输入与划分 | 自动清单、旧患者/三折名单迁移、按拟合组生成计划、训练入口 | 实际病例名单、每折人数和排除项可核查；正式配置身份固定；两卡 200 epoch 命令能够解析并通过有界实际运行 |
| 3. MedSAM2 | 独立模型及输入/提示/传播适配、训练、恢复、预测、评价 | 各数据集选定真实病例完成有限更新和提示式预测；标签与提示来源边界明确 |
| 4. Q r2 | 三阶段迁移、数据/事件参数化、冻结依赖、数值核对和双卡支持 | 基座→定位器→局部→一次融合有界贯通，逐阶段恢复及两数据集适用监督核实 |

第1与第2项共同构成 STU 正式启动条件。CPU/Linux/Gloo 检查、CUDA 容量、NCCL 双卡、实际吞吐分别记录，任何一项不能代替另一项；不预先承诺线性加速。每项开发结束交付源码、实际命令、短测报告和未覆盖条件。

## 10. 验收、版本与发布

开发验证复用最多两例真实数据；每项声明尺寸、输入数量、训练更新次数、产物及清理范围。双卡损失核查使用相同实际样本比较一组全局 batch 与两卡分担的输出/梯度/更新；分模型明确数值误差界。恢复核对状态载入及继续更新，资源变化只清理登记归属的本任务进程。

短测记录启动、拟合/预处理、冷/热供数、H2D、前后向、通信、验证、保存、预测/还原、内存/显存和清理。没有测量的指标标记未测量，不用设备数量或显存占用代替速度。真实服务器操作由用户执行命令并返回输出，本地检查不写成已在 zmic 验证。生成测试副产物前说明具体预算，执行时不额外要求服务器控制权限。

按模型阶段保留最少必要检查点，上游及 best 引用受保护；probability、逐ROI诊断或激活磁盘副本默认关闭，仅在明确诊断范围开启。报告和日志设容量上限，训练步骤不重复生成完成结果。

发布只同步 chd-segmentation。固定完整 Git 提交并核验源码；服务器实际 HEAD、origin/main、官方远端引用和运行入口在更新后重新核对。文档和显示改动与数值变更分别审计兼容性；旧训练记录与结果保留。若扩大训练合同造成不兼容，明确新旧范围，不通过删签名或改版本号绕过恢复检查。

## 11. 当前待冻结事项

实施时从旧项目核对真实患者/折名单、Q A/B/C/D 身份、正式病例尺寸和可评价标签；这些不由本计划虚构。双卡 batch/patch/精度按上面的数据集建议形成生效配置，容量测量后仍由显式配置决定。GPU UUID 使用用户的获准范围，不写入公开默认文件。MedSAM2 实施时固定上游版本及心脏任务提示/冻结配方，提供可核查的依赖和权重清单。

本计划完成不等于这些能力已经接入。正式两卡200 epoch任务在相应源码和目标服务器短测通过后启动；其余模型分别记录实施与验证状态。
