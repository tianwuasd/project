# 助手2继承main及模型资源接入

**Goal:** 在助手2独立工作目录继承助手1已发布main，并让MedSAM2和Q复用同一GPU准入及CPU资源预算，交付服务器所需文件清单。

**Architecture:** main固定为6ef3fd4c51eb53da26faa54a147fc35ae15ebc40，本地等价项目提交c28e191。沿用training/resources.py的设备选择、注册、共享容量和主机预算；模型执行分别维护官方MedSAM2训练和Q-r2累积梯度语义。

**Tech Stack:** 既有Python/PyTorch/MONAI依赖、官方MedSAM2、CPU/Gloo及目标CUDA/NCCL。

**Spec:** 用户要求继承助手1main、复用GPU加速策略、说明两模型需提交材料。

## 约定

- 修改和提交仅在助手2分支；助手1工作目录保持独立。
- 选卡与可见范围、空闲优先、共享显存实测、固定批量、CPU/RAM登记使用同一实现。
- MedSAM2保留官方损失、采样、优化器和75epoch日程；分布式使用官方Trainer。
- Q保留四次样本累积及三阶段算法，多进程按全局份额归约梯度。
- 验证使用既有批准的两例真实病例、每阶段每配置最多两次更新，报告与自动清理沿用已批准目录和容量。
- 本机32GiB RAM，MedSAM2单进程实测峰值约18GiB；本地MedSAM2只做单进程有界验证，CUDA/NCCL及多进程容量在目标环境实际验收。

## 验收记录

Q在ImageCHD一例真实病例上通过三进程[2,1,1]、三阶段各两次更新、参数一致性、完整恢复、变更份额拒绝及独立无标签预测；耗时478.274秒，清理35文件225920793字节。MedSAM2在同一病例上通过官方权重训练、完整恢复、一个实际数据worker及预取1批、原始网格提示式预测；耗时635.677秒，清理24文件624646226字节。Q训练角色资源投影准入和MedSAM2八帧序列预算通过实际病例检查。

运行使用CPU/Gloo；目标CUDA/NCCL、MedSAM2多卡容量、正式输入及持续提速未测量。源码已完成只读复核，批量及worker执行拓扑与预取预算均在实际检查中核对。具体病例身份、每阶段耗时、资源和清理记录保存在批准的独立报告目录。

## 重点核查

- 容量记录按模型、阶段、输入大小、精度和源码区分，禁止复用STU容量作为其他模型依据。
- 固定全局批量；MedSAM2官方DistributedSampler要求每卡相同batch，无法整分时在启动前拒绝。
- 恢复保存各rank随机状态与候选抽样状态，检查点同拓扑恢复。
- CPU预算落实到官方数据worker及Q数据缓存，完整训练边界检查内存压力。
- 代码、依赖及权重可迁移；Q患者分组和正式预测提示必须有实际来源。
