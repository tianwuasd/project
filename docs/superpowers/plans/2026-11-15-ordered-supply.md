# 按批次供数与主机就绪协调

目标：按全局消费顺序逐批准备数据，当前批消费后再派发下一批；保留 batch、采样种子、patch、间距、损失、轮数和完整恢复协议。

- [x] `data/supply.py` 将队列容量限定为一个当前批，提交、取出和消费分别记录；同一进程的 worker 数不超过本批实际样本数。
- [x] `training/build_gate.py` 按实际待构建病例的估算工作空间准入，统一限制同时构建数和总字节，缓存命中不重复申请整例构建空间。
- [x] `training/coordinator.py` 使用独立主机协调，所有 rank 的当前 CPU 数据及 CUDA 传输就绪后才进入训练通信；消费完成后释放当前批槽位。启动、模型加载和检查点写入同样隔离长 CPU/IO 等待。
- [x] `training/engine.py` 逐批派发，CPU 资源调整放在无未消费批次的边界；模型驻留、全局采样游标及检查点恢复保持原协议。
- [x] 验证最多两例真实病例、32³ 技术区域、两个 CPU/Gloo 进程及两次更新；检查首批顺序、队列容量、真实供数等待、恢复与释放。经授权检查单卡传输完成事件，无 GPU 训练。
- [x] 记录并清理本轮副产物，追加精确代码兼容关系。

发布本项目子目录、远端复核和强制更新及原任务继续命令，以独立发布回执记录确定提交和核验时间。

方案采用用户指定的逐批派发。单批内的多个 rank 和病例构建仍可并行，工作空间按实际病例估算加总。NCCL 超时继续负责训练通信，CPU 数据等待使用主机协调；不通过单纯放宽 NCCL 超时承接长预处理。
