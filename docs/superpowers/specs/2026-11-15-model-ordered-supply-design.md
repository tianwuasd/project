# Q 与 MedSAM2 按批次供数

按已授权要求修复多进程数据准备与通信的先后关系。Q 保持 r2 的采样、随机数调用顺序、损失与全局批量；MedSAM2 保持官方 DistributedSampler、BatchSampler、worker 随机种子、八帧 512 序列、完整编码器及优化步骤。

使用 multiprocessing 的共享 Condition 协调 CPU 就绪，不通过设备 collective 等待病例、验证或文件写入。就绪阶段及序号在各 rank 间逐项核对；进程失败由现有 spawn 父进程终止同组进程。保留通信超时设置。

病例构建按当前批次、当前样本位置公平授予名额。每个 rank 仅允许当前批次生成数据，下一批的构建须等待全部 rank 完成当前批次消费；DataLoader 可以提前分派索引，索引任务不能提前读取病例或创建图像缓冲。构建锁不跨越模型计算、通信或就绪等待。GPU 消费完成以当前设备同步为准。

Q 同步读取并保留 sample/loss 交替调用；候选索引每例准备前等待前例结束，训练每次更新读取份额保持原值。C 验证、随机状态收集和检查点保存均在进入设备通信前经过 CPU 就绪检查。

MedSAM2 包装官方 batch_sampler 的原始索引，标注批次及样本位置；包装数据集以覆盖读取、窗口转换和官方增强的整个构建过程。包装官方迭代器，在批次交付前检查全部 rank 数据就绪，消费结束后释放批次额度。官方 Trainer 通过现有子类在 DDP 初始化和传输完成后检查就绪，训练主体继续调用官方实现。

日志记录阶段、rank、批次、样本位置、等待请求数、构建名额、已完成样本数、准备批次深度及上限、构建耗时、消费耗时、CPU 同步等待，以及包含通信的设备计算时间。实际 NCCL 内部等待未测量时明确标记。

验证仅使用已批准的一至两例真实病例和 CPU/Gloo，每阶段最多两次更新。MedSAM2 完整训练仍受真实内存预算限制；独立验证官方 DataLoader 的供数协议不建立训练模型，记录零次训练更新。副产物在已批准目录自动清理，报告保留在对应 sync-reports。禁止登录服务器和自行使用 GPU。
