# 剩余病例并行与训练供数设计

用户要求：剩余病例少时把并行额度用于病例内部；减少反复回写和缓存丢弃；余量充足自动增大块；一并修正训练中的同类资源闲置。既有冻结间距、统计、标签插值、抽样、全局batch、patch、epoch及完整恢复协议保持。

实现采用现有NumPy/SciPy与线程执行器共享映射：重采样输出使用全局行优先坐标连续区间，区间互不重叠；完整插值轴线仍整体预滤波，每轴结束后才进入下一轴。所有样本和标签并列规则沿用现有函数。CPU额度在公共任务登记中分配到实际剩余病例，线程数只在有界工作波次之间调整；已完成的区间不会重复计算。

病例多时优先病例并发，病例少时按实际活动病例分享CPU。块从配置起始值增大到可手动设置的上限，依据真实余量与吞吐逐级调整；压力时缩小并发与工作块、回收本任务可释放页并等待稳定恢复。保持每秒内存监控及每次波次分配前实际准入。

正常计算保留可复用映射页，阶段结束再写回；压力回收、完成提交及独立读回校验继续生效。磁盘数组使用原格式、原配方和完整摘要；仅完整病例可复用，当前未完成病例在重启后重新构建。

训练继续使用固定slot的确定性请求。应用容量允许时保留当前批和一个顺序预取批，减少GPU等待供数；缓冲内存进入预算。CUDA pinned源保留至传输完成，收尾与异常必须安全释放；显卡占用抽样降低外部查询频率，资源调整后的重新准入仍读取实时状态。预算不足可退到单批，不改变科学设置。

验证只使用两例真实ImageCHD的最多64³区域，最多两次CPU/Gloo更新及恢复。比较常规/分轴插值的图像、标签、几何和采样位置，验证单病例线程并行、多病例额度、块调整及按顺序供数，记录实际耗时、峰值和清理。完整ct_1126与服务器CUDA/NCCL由用户操作。用户已允许本轮最多100个临时文件、1GiB磁盘峰值，结束自动清理，仅保留不超过2MiB日志报告；不使用GPU、不连接服务器、不安装依赖。
