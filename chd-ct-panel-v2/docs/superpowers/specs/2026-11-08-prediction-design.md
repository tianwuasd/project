# STU-Net-S 整幅预测设计

用户已批准在现有 CHD 项目实现预测，首批为原留出测试集。使用旧微调检查点，工程调度参考 server-engineering V2 0.7.2。新代码在独立分支开发，本机验收后交付，不合并 main。

## 输入与科学约束

- 原测试集只接受历史 test 角色，检查其不在来源模型 train_ids/val_ids 内；三折测试按对应折汇总。
- 新病例支持单折或三折。三折分别使用训练时的统计和空间计划，恢复至共同原网格后平均类别概率。
- 固定 SHA256 的 best/epoch/latest 检查点和来源代码；正式预测拒绝 smoke 模型，阶段性模型须显式允许。smoke 使用同一完整预测实现。
- 原模型的结构、训练 patch、类别 0..7、ignore=8、统计和预处理协议不改。旧预处理计划仅在预测副本补入概率重采样配置。
- 新病例仅用影像处理。已有缓存按来源/文件摘要校验后复用。GT 只在独立评价阶段读取。
- Gaussian 滑窗步长 0.5；TTA 默认开启并显式记录。禁用深监督输出，推理模式及混合精度；浮点累积使用 FP32。
- 结果恢复原体素网格，采用经过核验的物理几何。ImageCHD 原头信息需修正时输出匹配的参考 CT 副本，保留原件。

## 工程约束

- 默认最多 2 张获准空闲 GPU，各卡独立处理病例，模型驻留。GPU 预算为 free-max(4GiB,total*10%)，再受用户上限限制。
- 真实 patch 探测 1/2/4/8 等滑窗批量，按吞吐及显存选取；不修改 patch。整幅 FP32 输出累积明确列入 CPU/GPU 容量。
- CPU/RAM 复用 V2 80% 预算；每个 GPU 最多预取下一例，CPU 导出与 GPU 推理分开，队列按实际占用控制。
- GPU 外部占用后只释放本任务进程，未提交病例重新排队；没有获准 GPU 时等待。已知内存压力有界缩减并留证，未知错误停止。
- 逐病例原子提交，恢复核验结果完整性和任务身份。阶段心跳、窗口进度、峰值显存、读写/计算/导出耗时必须可查。
- 原训练、原数据只读；代码更新不热修改运行中的预测。提供冻结代码、后台启动和独立停止入口。

## 验收

真实旧检查点加载；测试角色隔离；真实 STU-Net 窗口拼接与批量对比；原图几何、缺预测指标；损坏结果拒绝；中断恢复；本机真实 CT 和 CUDA；冷启动与稳定计算分别计时。单卡本机通过不代表服务器双卡验收。
