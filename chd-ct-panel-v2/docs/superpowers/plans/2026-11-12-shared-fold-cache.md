# STU-Net 三折共享缓存实施计划

> 执行采用本会话原生实现，按任务验证，完成后独立复核。

目标是保留三折训练及各折独立数值参数，用一个活动折缓存目录限制磁盘占用。设计见 [共享缓存设计](../specs/2026-11-12-shared-fold-cache-design.md)。

## 约束与重点

- 数值处理顺序、插值、归一化、标签、训练划分及批量保持不变。
- 旧独立缓存继续可读，旧冻结任务保持原生产者。
- 活动折切换与读取互斥；building 不提供训练输入。
- 完成记录、数据实际位置和当前活动折必须一致。
- 同一活动折重建不将时间或进程编号混入科学身份。
- 真实验证限一个明确指定的病例、两组技术参数和零训练更新，产物范围须事前获准，结束只留必要日志。

## 实施记录

共享布局、活动折构建、训练与子进程占用登记、旧布局读取和精简路径已接入。活动缓存的 generation 只用于进程准入，不进入数值身份。文件管理、来源合同、冻结入口及路径规则由独立回归覆盖。

单病例入口为 `scripts/check_shared_cache.py --raw PATH --output PATH --case CASE_ID`，限定一个指定病例、两组技术参数、5 次生产叶函数转换和零训练更新。第二组参数显式扰动统计均值和 spacing，验证存储位置是否改变完整数组与属性。源文件摘要复核、实际文件数和逻辑字节、阶段耗时、总耗时、转换次数每秒、清理信息写入调用者指定目录的 acceptance.json。运行结束或失败后清理本次临时工作目录，留下必要日志。

独立源码复核覆盖共享目录、旧冻结代码、三折计划消费、临时编号分离及预测来源登记。网络、损失和检查点解释保持原源码，来源登记仍按完整训练生产者摘要核验。

发布范围为代码、通用使用说明和可执行验收入口。医学影像的病例编号、衍生尺寸、计时和验证结果只保存在本机验收记录中。全队列拟合、Linux/NFS、正式模型训练和 GPU 性能须分别验证。
