# 0.5.1：预处理优化与训练融合

本版将已验证的预处理执行优化和STU-Net-S V2训练放进同一main发布，并同步保留训练开发分支。既有预处理结果作为不可变输入，新训练独立创建结果目录；不需要重算预处理，不向旧数据写新签名。

## 使用旧结果

训练核验读取旧run的源合同、原分折、每折main-train拟合计划、完成标记及三个产物的SHA256，再核对数组格式、标注语义与前景坐标。它不会要求旧数据的预处理生产者等于当前预处理源代码。已知三列坐标仅对原先两份精确生产者允许只读补channel0；未知三列继续拒绝。四列v2结果无需该适配。

`run.py train --check-only`只做软件/输入合同检查，不代表GPU容量通过。启动核验显示每例进度，并每10秒反馈长阶段；不会把heartbeat当成完成百分比。正式训练使用main train+aux_train，验证只使用main val，外折test不进入供数。

服务器已完成目录是平台默认候选；优先级为显式`--prepared`、私有指定路径、最新成功prepare指针、平台已完成候选。未来新prepare会更新指针，候选不会强行盖过它。

## 两类加速分别验收

- 预处理：原插值核分区、跨折共用V2队列、chunk完整校验；过去的同输入实测见[预处理性能](preprocessing-performance.md)。它不会反过来改写已完成数据。
- 训练：固定全局batch在获准GPU间分担，全组CPU/RAM只预算一次，持久供数与有界预取、全组读闸门、同步AMP、完整epoch重组和压力恢复。详见[多GPU机制](multigpu.md)。

供数worker不是越多越快。比较同一B/patch/种子、实际消费次数和完整epoch墙钟；分别记录初始化、数据等待、计算、验证、检查点和溢出。没有在目标服务器测得吞吐前，不根据核数或预算宣称线性提速。未启用torch.compile和专用复制stream。

本地验证采用独立真实缓存夹具及受限训练规格，不覆盖原始数据和旧缓存。Linux/NCCL、多张真实CUDA、正式128³/B4容量、完整1000轮和分割效果继续独立验收。对已有训练的恢复仍使用匹配签名和冻结代码；本版不绕过旧训练科学签名。

恢复入口还拒绝不存在/空目录；已有检查点但latest指针丢失时拒绝隐式重置。不能把写错路径的`--resume`当作新训练启动。

## 本机验收

105项回归通过。实际CPU/Gloo覆盖1/2/3/4rank的B4分配、完整/混合/部分/全ignore监督、两种Dice归约，共32组数值配置；值、梯度、SGD更新、同步溢出及恢复通过。

真实旧缓存的单CUDA、64³/B1供数ABBA中，排除首轮暖机后的完整epoch中位4.945→3.5315秒，约1.40倍；包含验证、检查点、同步和反馈。短训端到端中位却为62.38→68.04秒，进程启动开销使本次短任务更慢；不能省略这个结果或把稳态倍数推广为整段训练收益。

最终修复版本另以B4/64³完成16次尝试、12次更新、4次AMP溢出跳步。暂停于第6次后从workers1恢复为0，130个模型tensor、128项优化器状态、scaler、随机状态与游标精确一致。真实容量probe峰值约1.39GiB，未因机器容量降低所选batch；它不代表B4/128³正式规格通过。当前本机是已有Torch2.12.1+cu126环境，新装默认Torch2.8.0/cu128与目标Linux/NCCL仍须现场检查。
