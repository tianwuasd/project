# 0.3.3预处理执行优化

本版保持原方法、强度拟合、目标spacing、影像非零裁剪、插值阶数、标签与角色不变。每折使用自身main-train统计；不共享已经按其他fold归一化的影像。只改执行、调度和完整校验的访问方式。

## 执行与资源

- 每例默认申请4个重采样线程，`--case-threads 1`可选原串行路径。所有病例线程之和受同一阶段CPU80%预算限制，实际准入还需实时CPU/RAM余量。Blosc2、Torch、BLAS/OpenMP仍为1线程。
- 仅将原SciPy C插值内核按互不重叠的输出区域执行。全局样条预滤波、zoom系数、插值顺序和输出数组均沿用原函数；线程共享输入和最终输出，不各复制一份体积。
- 该适配依赖私有API，目前只审核SciPy1.17.1，并在每个工作进程先做安装内核逐值探针。不支持的版本或探针失败时明确回退串行；异常退出还原钩子。不会修改安装库文件，不能在任意共享多线程应用中调用此适配器。
- 各fold完成独立拟合后共用一个资源队列。大工作量先尝试准入，放不下时扫描其他能放下的任务；前一折尚有慢任务时，后续折也能推进。相同病例在不同fold的结果仍分别生成、分别提交。
- 全数组读回校验对齐实际压缩chunk，包括末端不整块；每个逻辑体素仍校验一次。前景位置计数复用小型标签直方图，与本项目原有采样器的随机数、坐标和顺序一致。

来源是[server-engineering V2策略](v2-acceleration-provenance.md)和[SciPy1.17.1原内核](https://github.com/scipy/scipy/blob/v1.17.1/scipy/ndimage/src/ni_interpolation.c)的坐标计算及线程释放实现。后两项局部执行优化由本项目验证，不冒充模板原有功能。

## 运行与查看

```bash
python run.py prepare --method stunet-s-partial --fold all --case-threads 4 --output outputs/preprocessing/performance-new-run
python run.py status --output outputs/preprocessing/performance-new-run
```

实际服务器输入/输出默认路径仍由原配置提供；显式输出只用于展示新运行。需要SSH断开后继续时沿用外部`nohup`启动方式，本命令本身不自动转后台。

| 文件 | 内容 |
|---|---|
| `capacity_preview.json` | 所选病例各fold的预测shape、体素数、放大倍数和预留；纯元数据推算，非容量验收 |
| `logs/run.log` | 启动、完成、每20秒阶段反馈，最长活动病例及CPU累计秒数 |
| `logs/resources.jsonl` | 每秒资源历史、已预留线程、各阶段病例数、最长3个活动病例 |
| `status.json` | 有界最新反馈，避免查询必须重读全部历史 |
| `logs/foldN_CASE.log` | 每例详细阶段与申请/实际重采样线程、回退原因 |
| `fold_N/results/CASE.progress.json` | 当前阶段、最后实际进展、PID与出生身份 |
| `fold_N/results/CASE.progress.jsonl` | 该病例各次阶段事件和真实进展历史 |
| `fold_N/results/CASE.json` | 总耗时、阶段耗时、实际执行统计；仅成功病例有完成标记 |

进度文件中的`completed/total`只表示当前插值调用或读回数组；标签逐类处理可能含多个调用，不能把它当成整例百分比。某些原函数没有内部进度时只报告阶段、持续时间及CPU/I/O计数；无新stdout不等于死锁。没有默认长病例强制超时政策。

Windows原子JSON替换遇短暂读者共享冲突时作有界重试（最多额外等待0.315秒），不截断旧文件、不忽略持续权限错误。

## 验证范围

同一真实输入、同一fold计划、原尺寸，基线0.3.2与4线程候选各重复2次，顺序ABBA。以下是整例叶函数时间中位数，包含源校验、变换、写出和完整读回；不包含全队列审计或Python启动。

| 本机样例 | 基线秒 | 优化秒 | 倍数 |
|---|---:|---:|---:|
| 样例A | 26.28 | 11.79 | 2.23 |
| 样例B | 67.24 | 28.51 | 2.36 |
| 样例C | 51.12 | 26.55 | 1.93 |

三例的影像、标签、属性三文件SHA256均一致；观测峰值RSS差异小于0.2%。样例B基线两次为81.41与53.07秒，存在明显波动，不能将中位数倍数推广到全数据。组件优化单独只有约2%的整例收益，主要收益来自原插值内核并行。

另做相同四任务的队列ABBA对照：两种策略均使用已优化叶函数、每例4线程、最多3进程、读并发2和实际V2资源采集。逐折等待两次66.71/67.41秒，共用队列37.55/38.42秒，中位67.06→37.98秒，约1.77倍。后续折在大例结束前启动，16次任务的三文件SHA256一致。这是小型混合队列验证，不能与单例倍数相乘作为全数据收益。

Windows本机结果不能替代Linux/cgroup现场验收。超大目标可能超过20亿体素，本机内存不能完成巨例验收，`capacity_verified`保持false。旧运行保留冻结代码和签名；本版没有实现跨生产者缓存导入，不允许删除签名来强行恢复。短测的两个病例通过不等于全数据容量/吞吐通过。
