# 输入任务、主动重跑与可更新模板

目标：新建任务可选历史预处理作为输入；完成任务可主动选择步骤重跑；将面板、处理方法和升级方式同步到 server-engineering。

方案：延续现有命令行面板。普通续跑仍复用成功步骤；主动重跑创建有父任务记录的新 workflow，旧目录不变。相比清除成功标记并原地覆盖，此方案保留可对照结果。复用预处理使用历史最终缓存路径，不复制大体积数据，也不重新处理。

- [ ] `lineage.py`：读取并核对历史计划/状态、候选缓存、输入来源摘要；提交时复核来源，拒绝活跃任务、缺失或冲突输入。
- [ ] `rerun.py`：选择完成步骤，冻结原参数，新建输出；重绑本次生成的依赖，预处理重跑使用新缓存。旧产物字节和时间不变。
- [ ] `workflow.py` / `launcher.py` / `panel.py` / `jobs.py`：接入 `--input-job`、`--rerun-job`、`--rerun-tasks` 和面板入口；只读操作拒绝启动参数；保留锁、后台运行和返回/退出。
- [ ] 合成测试：正常复用、手动不用、坏缓存/来源变化/活跃任务拒绝；完成步骤确实执行；选择多步依赖重绑，单步使用原输入；CLI 与菜单一致，普通 resume 不改变。
- [ ] 说明、版本与模板同步；备份核验，Windows 与 Linux 相关验证；GitHub 发布与本机 skill 安装核对。

约束：不改变标签、Excel 间距约定、训练配置、模型算法、CPU 调优或 GPU 分配边界。简单缓存检查不宣称逐字节完整验证；各执行步骤保留自己的契约校验。只有本次选中步骤执行，旧权重不被复制为新完成状态。

模板：通用操作规范与医学处理方法分别记录；方法写明来源、适用数据、验证与兼容性。更好的做法先在独立输出验证，再更新模板版本、参考实现、测试及安装版。历史实验仍绑定自己的方法，不能自动改绑。
