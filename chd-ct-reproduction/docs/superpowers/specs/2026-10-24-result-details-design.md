# 分割结果来源与逐折明细

用户要求结果页明确每折分割效果以及这些分数对应哪些数据，并同步工程与 server-engineering 模板。

本次在既有中文终端 `o` / `--query results` 中扩展展示。采用读取已有 JSON 的方案：整体汇总、逐折七结构 Dice 和有效病例分母、已评估病例名单、数据/预测/模型来源、集合与推理协议解释。训练、预测、评估和合成演示分别标注；不把菜单编号与工作目录步骤序号混为一谈。

备选是修改评估器并要求重新生成报告，但会使旧任务失去直接查看能力；因此本次保持指标生产和训练算法不变。逐病例记录可补算显示均值，明确标注来源；没有折归属、有效分母或病例名单时显示未记录。三折集成结果不复制为三个独立折分数。默认完整展示各折和病例名单，无新增交互选择。

边界：仅标准库只读查询，不加载影像或权重，不更新历史清单/时间戳/最近任务指针，不连接服务器或运行模型。来源按历史记录解释，不宣称重新验证哈希或患者身份。新版本参考 0.19.0，服务器部署需单独确认。

用户补充要求最后决策模块更详细。展示已有 trainability.json、diagnosis.json 与 diagnosis-metrics.json 中的逐疾病样本/训练状态、逐病例真实树路径和规则证据、叶节点阳性/总数、逐疾病混淆与覆盖统计。区分证据不足、训练先验、软件验证和标签空白约定；不改变分类器、规则或阈值。
