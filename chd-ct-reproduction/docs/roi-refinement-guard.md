# 0.24.0：预测框一致性、验证后处理与显存保护

本次修复训练使用真值框、推理使用预测框的输入来源差异，并撤除正式预测中的血池硬删除。原始投票始终独立保存；有限补全和连通区域处理是验证集上的候选方法，只有满足下述条件才进入最终输出。没有在真实数据上重新训练，也没有证明 Dice 已改善。

## 每折实际流程

`crop64 + crop128 → roi → all64 / all128 / blood2d → blood_lstm → calibration`

前两个定位网络仍读取全图。`roi` 使用本折冻结的定位权重，仅凭影像为训练、验证病例生成框；后续四个网络读取这些框。预测复用同一定位函数，前景并集和边距算法未改变。空预测回退全图、框覆盖全图均记录告警，不使用标签强制缩框。这解决框来源失配，不等于定位网络已经学好。

训练病例的定位结果来自在这些训练病例上学习过的定位网络，属于 in-sample 定位；验证病例未参与梯度训练，但已有验证损失用于选检查点。这不是交叉拟合的定位器。测试病例不进入 ROI 训练输入或后处理选择。每折保存独立 `roi.json`，绑定定位权重、数据、病例划分、形状与 SHA256；框改变必须重新生成训练输入和训练后续网络，不能改摘要绕过恢复检查。

六个网络的 batch、最大 epoch、损失和优化器不变。**预测框深度会改变血池切片数和每轮优化步数**，不能声称训练采样量与旧真值框流程相同。模型训练前的 CPU 加载调优使用明确标记的全图基准，其缓存与正式 ROI 输入分开；全图短测不是实际吞吐保证。GPU 总并发上限不按折数增加，只有依赖已完成的任务才能派发。

## 保存与选择什么

| 产物 | 含义 |
|---|---|
| `*_vote.nii.gz` | 四路 1:1:2:2 加权投票，保持原始输出 |
| `*_limited.nii.gz` | 有限补全候选，无论是否采用均保存 |
| `*_seg.nii.gz` | 本折冻结策略决定的最终输出 |
| `*_grid.npz` | 预处理网格上的 `vote / limited / blood / prediction`，用于同一网格比较 |
| 模型目录 `postprocessing.json` | 本折验证病例、候选逐例逐类指标、采纳理由和来源校验 |

有限补全保留所有原有标签，包括血池预测漏掉的心腔和 MYO。仅允许既有血池结构种子向 `blood==1` 的背景扩展，默认最多 **2 次六邻域扩展**，不会跨过预测边界2；多个结构同时提出的平票体素保持背景。2 步是工程候选参数，单位是当前预处理网格的邻接步数，不是毫米或论文确定参数。完整小岛重分配、init64/init128 和 AO/PA 图优化没有在本次实现。

正式训练结束后，在**该折完整验证集**比较：

1. 原始投票与有限补全。七类平均 Dice 严格提升（大于 `1e-8`），每类平均均不下降，并且每类“真值存在但预测为空”的病例数均不增加，才选择补全。
2. 在选定结果上，逐类试验仅保留最大六连通区域。该类平均 Dice 严格提升且不增加空器官病例，才对该类采用。对其他类不做重标记。多个真实分离区域不必然属于错误，不能无条件删除。

选择时固定病例分母，双方均不存在的类记1，避免删除假阳性后改变有效分母造成虚假改善。公开评估仍沿用原口径：双方不存在为 null，ignore=255 不参与。两种分母须区分。标准约束的是验证集均值，不保证每个病例不下降。逐类连通区域操作互不修改其他类，可组合执行。

`smoke/preflight` 不做科学规则选择，策略标为未校准并保留投票。开发集 OOF 使用对应未见过该患者的折模型及其冻结策略。独立新患者的三折概率集成没有独立校准集，因此最终先保留集成原始投票，仍导出有限补全候选；不能用三折规则多数票冒充集成规则验证。已有 97 例结果用于问题诊断，不是本次改进的独立确认试验。

## 显存保护

0.24.1 修复无编号 `cuda` 在分配器预算接口中的兼容错误：在worker内解析当前逻辑设备编号，遵守 `CUDA_VISIBLE_DEVICES`，并在检查与恢复预算时保持该设备。显式指定的编号保持不变；CPU阶段不查询或初始化CUDA。此修复不改变0.24.0的科学协议、缓存或检查点格式。

保护覆盖训练、ROI、验证选择和推理。阶段启动前只释放本进程无用缓存，读取当前空闲显存，计算80%软预算（0.24.2起）：

`max(0, min(总显存 × 0.80, 空闲显存 − max(2 GiB, 空闲显存 × 0.20)))`

预算是提示线，不是分配上限；超过后记录一次提示并继续使用剩余显存，规划余量可用于峰值。旧配置高于80%的比例在运行时按80%计算，较低比例保留，不改冻结配置/检查点。PyTorch分配比例临时设为1.0，阶段结束恢复原设置。每个训练批次前后、推理网络前后和血池切片间检查，仅实际空闲低于0.5 GiB时按显存余量停止。在检查点上最多每5秒查询计算进程，发现非本任务计算 PID 则停止本阶段，不终止其他用户进程。检查失败同样停止；没有 GPU 监控证据时不假定安全。长时间 CUDA 算子期间不会额外启动抢占线程。

正常结束或异常都恢复此前分配器设置，记录 `*.gpu-memory.json` 的预算、峰值和错误；失败诊断不能覆盖最初 OOM。反向传播前的旧梯度提前清零，减少无用驻留。已有激活重算继续保留，不自动缩小 batch、跳过病例或调整科学参数。OOM/保护停止后沿用最后完整 epoch 恢复边界；当前 epoch 可重做。

这是软预算提示和实际余量检查，**不是显卡独占或绝对无 OOM 保证**。非 PyTorch 分配、CUDA工作空间、碎片和其他用户后续抢占仍可能触发OOM；算子内部的瞬时峰值可能先于下次检查耗尽显存。模型装不下真实可用容量时保留原OOM。没有自动改batch、混合精度或梯度累积。真实 zmic44/CUDA 峰值、吞吐和长期运行尚未验收。

## 兼容、更新与恢复

- 版本：模型 `imagechd7-chd-paper-v5`，三折集合 `imagechd7-threefold-v3`，训练输入缓存 `imagechd-training-inputs-v3`。旧权重不能接着采用新协议训练或预测；保留旧任务并新建实验。
- 原生或仅 Excel 物理重采样的预处理仍可复用；固定尺寸监督缓存继续执行0.23.0的采样对齐检查。改变预测框不会覆写原预处理。
- 已发布的 ROI/后处理 JSON 缺失、修改，或权重/划分不匹配，拒绝续用。未完成 ROI 没有可靠回执时重新生成；未完成验证选择重算该阶段。预测仅在原投票、候选、最终和网格产物校验齐全时记为完成。
- 面板 `u` 更新后重新打开。新任务选择兼容预处理作为输入，执行训练、测试或预测；更新代码不会重算旧任务。结果简洁页显示三阶段均值，详细页列总体与逐折各结构分数。旧结果没有的字段显示缺失，不补造候选结果。
