# 0.23.0：标签采样对齐与论文边界处理核对

## 修复什么

`geometry.resize` 以前使用 PyTorch `nearest` 缩放类别标签，而图像使用 `bilinear/trilinear` 和 `align_corners=False`。两者的采样位置约定不同，非整数缩放及多次往返会导致标签偏移。现在类别标签使用 `nearest-exact` 对齐像素中心；标签值仍离散，不对类别编号做线性插值。训练输入、四路预测对齐、血池标签缩放和原网格恢复共用此实现。

按用户要求重新核对了论文第 4.3 节（PDF 第 6 页）。原文先将各分割结果的 ROI 对齐并缩放到 128³，再做加权投票；随后提到移除血池及边界，并以融合结果为种子进行区域生长，最后做连通域和小岛重分配。论文没有指定插值库、像素中心约定、边界宽度，也没有给出该句对应的布尔掩膜和伪代码。因此不能把 `nearest-exact` 声称为作者原始实现，也不能仅凭正确标签经过边界处理后 Dice 下降，就判定边界约束必然是错误。

本次撤回“直接保留边界上已有标签”的试改，保留现有的边界排除实现：`blood_target` 的 1 为内部、2 为边界；细化只保留预测内部 1 中的心腔/大血管种子，并仅向内部空白体素生长，不越过边界 2；MYO、六邻域和平票优先级不变。这是本项目对论文边界约束的既有实现解释，**不能证明与原作者掩膜逐体素相同**。要消除歧义仍需原作者源码或说明，不能自行补造为“严格复现”。

保留论文明确的 ROI 128³ 对齐和加权投票。七结构数据没有初始血管段标签，故只运行四路 `crop64/crop128/all64/all128`，权重仍为 1:1:2:2；完整论文六路为 `crop128/crop64/all128/init128/all64/init64`，权重 1:1:2:2:2:2。完整小岛重分配的领域规则和 AO/PA 图优化仍未复现，本次不以任意规则替代。参见 [论文对应记录](paper-mapping.md) 与 [原文 DOI](https://doi.org/10.1016/j.media.2023.102953)。

Excel 间距来源、方向转换、中心对齐物理变换、影像线性/标签最近邻的物理重采样、强度归一化、数据划分、模型与训练参数均保持原设置。不能据此保证 Excel 本身的每例物理间距都准确。

## 缓存、权重与历史结果

| 已有内容 | 0.23.0 的处理 |
|---|---|
| 原生或仅 Excel 物理重采样、未额外缩成固定大小的预处理 | 可作为新训练的输入，清单和数组保持原字节 |
| 旧额外尺寸缩放的监督缓存，例如旧 96³ | 仍可读来查看/评估历史结果；新训练/新模型推理拒绝混用，须从原数据在新目录重新预处理 |
| 只有影像、不含监督标签的预测缓存 | 图像插值未变，可使用；按当前模型协议恢复输出网格 |
| 旧训练 mmap 张量缓存 | 新缓存使用 `imagechd-training-inputs-v2` 和明确采样标识，使用不同路径键，不覆盖旧文件 |
| 旧模型及优化器检查点 | 新方法须另建任务训练；不静默改用新采样或细化，也不在旧方法上接续新优化器更新 |
| 历史完成任务和结果面板 | 继续只读查看，已保存分数不变；更新程序不等于重算历史结果 |

新六阶段模型为 `imagechd7-chd-paper-v4`，三折集合为 `imagechd7-threefold-v2`。训练集合、每阶段权重、训练/预测接续契约保存 `processing_method`，包含 `nearest-exact-pixel-centers-v1` 和保留原行为的 `exclude-boundary-grow-interior-v1`。新固定尺寸预处理的清单、病例记录及预处理接续契约包含 `label_resize`。缺失或不同的方法不能通过修改版本字符串来迁移。

需要采用修复时，面板 `u` 更新并重新进入；新建任务选择兼容预处理作为输入，再选训练及测试/预测。旧额外尺寸缩放缓存应同时新建预处理。旧任务按原冻结代码保留和恢复，不能通过覆盖源码或检查点绕过契约。

本机软件回归与 GitHub 发布均不证明 zmic44 已部署；Linux 生命周期、真实 GPU 吞吐与正式分割准确率保持各自验证边界。
