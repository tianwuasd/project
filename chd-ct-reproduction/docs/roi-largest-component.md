# 0.25.0：每路最大连通区域取框

两路定位预测中的远端误检，即使只占少量体素，也会把逐轴极值框拉到整幅影像。此次按选定方案，只修改定位框的形成规则，不调整网络主干、优化器、batch、epoch、显存或磁盘预算。

## 规则

1. `crop64`、`crop128` 按原有标签缩放方式恢复到预处理网格。
2. 各路先合并七类非背景结构，再按三维 **26 邻域**分别找连通区域，各保留一个体素数最大的区域。不是逐类别保留最大区域，也不是先合并两路再找最大区域。
3. 并列最大时，固定保留 C 顺序扫描中首次出现的区域，并记录并列数。
4. 对保留的两路区域取并集、计算包围盒，按各轴框长 `L` 在两侧各扩 `ceil(L × 0.15)` 个预处理网格体素，再截在影像边界。正式和 smoke 配置统一为 `roi_margin_fraction: 0.15`，替代旧 `roi_margin`。例如轴长20体素，两侧各扩3；轴长30，两侧各扩5。未碰边界时总长度约为原来的130%（取整可能略大），不是总体只增加15%。
5. 一路为空就用另一路；两路均为空则回退全图并告警。实际框覆盖全图也记录告警。

清理后的二值区域只用来定框。原始多类别预测原样返回，继续参与框内的加权投票。训练、验证和预测共用 `roi_inputs.locate`，无需额外选择开关。

## 诊断与兼容

`roi.json` 及预测诊断记录方法标识、26 邻域、比例边距、各轴计划扩边体素数、清理前后框、每路区域数、保留/去除体素数、保留比例、并列数和回退原因。`raw_roi_slices` 与新框分别按各自框长扩相同的15%；`roi_margin_voxels` 是边界截断前每侧的计划扩边量，两路全空时记零。

方法标识升级为 `fold-localizer-largest-component26-relative-margin-roi-v2`，同时进入模型 processing 协议与 ROI 合同。原有模型文件容器格式不变，但方法协议不同会拒绝加载/续跑；不得修改旧 JSON、哈希或检查点以绕过验证。

采用新规则需独立新任务，重新生成 ROI 并训练后续阶段；现有入口会要求旧模型独立重训，不提供跨协议迁移捷径。兼容且校验通过的原始预处理缓存仍可复用。训练输入缓存绑定新框及 ROI 摘要，旧输入不会被无声替代。旧结果可继续查看，旧实验用原冻结代码继续；本次更新不自动重训、不改变既有结果。

## 验证与限制

针对性测试覆盖远端散点、先分路清理、对角连接、并列最大、单路/双路空预测、边缘截断、非法边距、原始类别保留及旧协议拒绝。合成 CPU 流程验证后续训练、预测与恢复接口。

最大连通区域能消除独立散点，但不能纠正与主体相连的误检，也不能保证保留断开的真实血管。应分别评价每例每类的标签覆盖率、框体积比例和下游分割成绩。诊断时可以用标签计算覆盖率；生成框不读取标签，不按测试病例改参数。

保存的旧定位结果回放只能检验几何变化，不能当作新训练模型的 Dice。框缩小后血池切片数与每轮优化步数可能变化，即使 batch 和 epoch 没变。正式质量结论仍须新任务训练及独立评价。

此改动属于本项目研究适配。最大区域后取框的思路可见 [Salgado 等 WHS++ 级联方法](https://nvblanco.github.io/assets/pdf/conferences/2024_miccai.pdf)，本项目按用户选择采用15%比例边距；每轴每侧扩边、向上取整及双路合并顺序是这里明确的实现定义，不能据此宣称与论文未公开实现逐体素相同。
