用户要求修改前保存旧实现。修改既有代码、配置或说明前，将相关原文件按相对路径保存到唯一的 `back/before-<主题>-<日期>/`，重名时加后缀，不能覆盖旧备份。

## 每次修改要同步什么

只更新受本次改动影响的部分；交付前逐项核对，不能只修改一个入口而遗漏它实际调用的模块。

| 改动类型 | 需要一起核对或更新 |
|---|---|
| 预处理、缓存和重采样 | `src/chd_ct/imagechd/`，服务器路径传递与恢复逻辑，相关测试，`docs/server-start.md`；输入、缓存、下游计划必须一致 |
| 训练、网络或科学参数 | 相关训练器与模型、`configs/`、适用的 `src/chd_ct/presets/`、论文对应说明；解释旧缓存和检查点兼容性 |
| 面板、查询、GPU 调度、中断或更新 | `src/chd_ct/server/`、调用入口、相关测试、服务器说明；可复用的工程规则同步 `server-engineering` skill |
| 发布版本 | `pyproject.toml` 与 `src/chd_ct/__init__.py` 保持一致，更新受影响的使用说明；纯文档维护不必提升程序版本 |
| 项目维护方式或用户长期约定 | 更新本文件；跨项目可复用的规则写入 skill 的对应参考文件，避免复制整段对话 |

方法说明要区分论文原设定、现有数据适配和工程优化。不要用过时的 15 epoch 等历史参数描述当前正式训练；读取当前配置。性能优化不顺带改变标签、划分、模型、batch 或训练轮数。

## 已确定的运行约定

- 预处理及其前置环境检查使用 CPU，不能因为 GPU 不足而等待；混合流程到实际 GPU 步骤才检查和申请显卡。
- 预处理默认尝试沿用，可主动新建。缓存不兼容或损坏时有提示地自动创建唯一的新目录，保留旧缓存及首次日志，并先保存最终路径，再交给后续步骤与中断恢复。
- 自动换目录最多重试一次；权限、磁盘、环境、原始数据错误和用户中断不能按缓存失败吞掉。后续已有模型或检查点时不能直接更换它们绑定的数据。
- 重采样按用户确定的 Excel 元数据约定，具体字段和几何处理读当前实现；不能擅自换回 NIfTI 头信息，也不能把尺寸缩放等同于物理重采样。
- GPU 数量是并发上限，少卡可运行、无卡等待；仅使用获准候选卡。显卡视图每 1 秒刷新，已取得的 GPU 按用户最新要求保留到所有所选 GPU 工作结束，在独立 CPU 后处理/评估开始前释放；失败或中断也清理。
- 三折 GPU 训练使用共享阶段队列，空闲卡可执行后续折独立模型，总并发不能按折数倍增；`fold_i/blood_lstm` 只依赖 `fold_i/blood2d`。保留各折数据、配置、检查点与日志独立；CPU 训练保持串行。
- 训练原有 CPU 调优算法、smoke/preflight 独立步骤和训练逻辑保持不变；本轮不能将它们合并或接入新的非训练 CPU 分配。其它任务内置轻量资源检查，病例并行受 CPU/内存预算限制；详细日志按实际完成病例/epoch 显示估算 ETA。服务器快速案例按用户要求放大 project 的并列 `server-resource-smoke/` 并同步本地，项目内保留回归测试。
- CPU 自动配置融入已有小样本测试/预检：合理初始值、有界比较、记录推荐依据，正式训练读取结果。不要另造一个需要用户反复手调的独立测试模式。
- `q/0` 退出面板，日志查看的 Ctrl+C 返回面板，后台任务继续；中断任务使用明确目标的独立操作并保留检查点。
- 面板更新使用多镜像、有界超时、更新前备份和快进合并。仓库身份识别与下载线路分开：认可 `gh-proxy.com` 历史 origin 不等于把它加入下载线路。保留已知同仓库地址兼容，不放行其他 owner/repository 或相似域名。
