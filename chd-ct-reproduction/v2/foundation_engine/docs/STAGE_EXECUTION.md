# 分阶段运行与诊断

菜单1预处理、2训练、3预测、a完整测评保持独立。新训练任务只接受与当前实现摘要一致的已完成预处理任务；旧版缓存仍严格校验，不自动迁移，也不会在训练板块暗中补跑预处理。实现身份同时核对主准备入口、数据管线、路径配置和实际病例执行器四个文件；只有辅助执行器变化也不能继续混用旧缓存。来源版本不兼容时，先在1新建预处理，再在2选择新来源。旧任务使用它自己的冻结程序续跑，不修改旧源码或产物。

准备入口、fit指纹、规划、病例派发、预测派发和GPU退出后的CPU收尾分别观察当前CPU/RAM。预算保持CPU80%、可用RAM80%。fit指纹仅来源训练8例，正式预处理处理fit+cal共12例，短测仅选定的2例fit+1例cal；没有通用8例并发上限。Blosc压缩和KDTree距离查询使用受预算约束的支持线程数，SciPy重采样仍单线程。NumExpr单独尊重其MAX_THREADS限制，不把这个库的上限套到全部资源。

每张参与预测的GPU保持一个模型，按冻结目标病例继续处理。CPU预处理最多提前一例，通过磁盘文件传递，不把完整体积放进无界进程队列。预算不足以同时容纳主进程和预取时串行准备。每例GPU结果独立提交；失败后可复用校验通过的已完成病例。全部GPU进程退出并释放保留卡后，才进入新的CPU预算下的原网格恢复、写出和指标计算。测评单例预测前停止继续发现卡并释放其余保留卡，预测退出后释放最后一张。

状态页显示当前阶段的获准/可用/分配预算和已应用供数反馈；缺少所属PID时间窗实际CPU用量时明确写缺失。训练与验证都显示自动batch引起的每轮采样量变化。250轮、每轮250次训练与50次验证、20GiB规划预算和原分割评价定义不变。短测功能通过不表示有充分持续吞吐或模型效果证据，测评配置不直接复用于正式运行。

新增菜单z：选择任务后直接生成本地ZIP，并显示完整路径。输出位于当前runtime的diagnostic-exports/diagnostics-时间-随机标识.zip。包包含诊断快照、阶段决策、事件、错误/traceback、rank日志、进度和报告等文本；排除影像、权重、预处理缓存、环境目录与凭据文件，常见凭据字段/令牌/私钥文本会脱敏。拒绝符号链接、Windows目录联接和越界路径。活动日志在读取时变化会提示稍后重试；成功包是各文件的稳定快照，不承诺运行中任务的跨文件事务一致性。

z只写本地，不上传。v继续走原SSH+Git LFS产物预览和确认流程，并收集新增诊断、阶段决策、优化/容量观察日志；完成的正式模型权重仍属于v明确预览的范围，绝不进入z诊断包。

本机验收使用合成体积、真实CPU库接口与控制面模拟；不等于目标Linux/CUDA/NCCL或真实CT性能验收。
