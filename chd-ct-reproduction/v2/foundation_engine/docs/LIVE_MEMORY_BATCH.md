# 实时主机内存保护与用户固定batch（0.7.0）

用户于2026-10-31要求：运行时调整内存使用；全局batch交给用户、默认4；batch4时从单卡4块到四卡每卡1块，最多四个非空训练rank。按局部补丁实施，不重构任务结构、预处理或研究算法。CPU80%、GPU显存至少4GiB余量、250轮×250训练/50验证保持。

## 用户操作

训练板块选择原成功预处理任务、模型，再选“固定全局batch”，直接回车为4；测评也提供该选择。非交互入口使用`--stage train --input-job /ABS/PREPARE --global-batch 4`，其他原参数继续使用。

| 所选全局batch4 | 逐卡batch | 每轮训练patch |
|---|---|---|
| 单卡 | [4] | 1000 |
| 两卡 | [2,2] | 1000 |
| 三卡 | [2,1,1] | 1000 |
| 四卡 | [1,1,1,1] | 1000 |

可选其他正整数，如1/2/8，训练卡数最多为所选batch和实际获准可见卡数的较小值。batch是本次优化器更新共同处理的随机patch数，不是训练病例数。预览、冻结计划、环境、容量/正式参数、签名、进度和日志均保留选择。每轮采样量=batch×250。

达到所选batch后不再加入训练卡，不继续增批。容量预检会真实验证所选配置。单卡放不下4时保持全局4，等待更多获准空闲卡，单次最多300秒；分配范围不足或等待超时则明确停止，不悄悄降为2。下次可调整选择或等待资源后重启。旧冻结任务及无新固定字段的旧接口保留其原合同，不把旧自动增批任务冒充新默认。

## 实时主机RAM保护

`memory_guard.py`每1秒在训练组的父监督循环检查实际MemAvailable及当前cgroup各层剩余量，取可用量的较小值；不反复做完整CPU拓扑探测。读取memory.max/current、memory.events及local事件（v1对应limit/usage/failcnt）；缺失信息写入日志。已知有限cgroup限制消失或改变时停止新的分配并重新准入，不把未知限制当作无限。

本阶段保留最初准入可用RAM的20%，至少4GiB。此处是主机RAM，与GPU显存4GiB余量分开。CPU预算仍为当次获准且可用份额的80%，不会因为本任务自身占用而重复扣减CPU预算。

供数扩容还必须通过新读到的主机/cgroup余量：预计全组新增开销不能侵入预留线。不能仅凭启动预算有剩余或取批等待高就把16个worker一路扩到94个。已有进程与队列的估计仍不是物理占用硬限额。

触及预留线或不能可靠读到内存时，监督器中止本组，清理本组rank及worker，再把保留的供数RAM预算缩到原估计/原预算较小值的60%，重新计算worker与队列。重新准入、短测成功后，从最近完整检查点继续。当前未保存完整轮次的更新会舍弃并重算；没有完整检查点则从原seed开始，不伪称恢复了部分轮次。

容量测试与正式训练的主机内存调整总次数有界，最多3次；缩小后的预算跨自然扩卡/退化回组保留，避免下一次重组又恢复大池。仍不能容纳任务时安全停止，保留日志和检查点。未知SIGKILL不会被冒充为已证实OOM，不无限盲重试。

## 清理与日志

Linux rank在导入训练库前创建独立session/process group，并登记PID、boot/start、PGID、SID。监督器只对本次调用及已核验的rank身份发信号，拒绝回收PID复用后的外部进程；rank退出后再次检查晚到的归属记录及剩余成员，封闭启动/登记竞态。

共享内存使用本次调用nonce构成的专用名称，创建前登记归属；所有本组进程退出后只回收该调用登记且核验身份的段，不扫描或删除全机`/dev/shm`。防止强制停止后旧段保留到外层resource_tracker退出，使重试继续积累内存。

正常样本约30秒写一次；当前详细证据位于`workspace/diagnostics/memory-guard-latest.json`，事件位于`workspace/diagnostics/events/*.jsonl`。包含主机/cgroup读数、预留量、OOM计数及本任务进程树的PSS/USS（权限不允许时明确缺失）；正常追加事件用汇总，详细PID表只保留最新快照和压力事件，避免重复拓扑膨胀。扩容窗口记录fresh live_memory，调整记录group.host_memory_recovery/capacity.host_memory_recovery。

## 验证边界与既有预处理

验证清单及实际结果见随版本维护的`LIVE_MEMORY_BATCH_VALIDATION.json`。CPU/Gloo验证使用合成张量，分别检验batch4的1/2/3/4进程损失、梯度和真实参数更新；这不代表目标3090/CUDA/NCCL已验收。

七个预处理身份生产文件未变；已有兼容全来源预处理可直接作为新训练输入。旧训练任务仍使用自己的冻结代码，更新不会热改正在运行或失败的旧任务。改变batch属于新的训练配置，不能改签名绕过旧模型兼容检查。

共享服务器上其他程序可能瞬间分配大量RAM，采样无法保证绝不发生OOM。本补丁不修改管理员cgroup、系统swap、全局代理或其他用户进程；检测余量、及时回收及有界恢复必须在目标Linux实际负载下验收。
