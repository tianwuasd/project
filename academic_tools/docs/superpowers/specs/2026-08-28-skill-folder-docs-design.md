# 科研 Skill 独立文档目录设计

## 目标

在保留现有 `docs/skill文档/*.md` 扁平文档的前提下，为 12 个科研 skill 分别建立独立文档文件夹。每个文件夹提供功能说明、详细使用指南、源码结构与构建分析、验证与风险说明，以及只依赖当前项目 `skills/` 目录的本地使用指南。

## 目录结构

```text
docs/skill文档/
└── <skill-name>/
    ├── README.md                  # 本 skill 文档目录导航
    ├── 01-功能说明.md              # 功能、工作流、输入输出和边界
    ├── 02-详细使用指南.md          # 分阶段使用、提示词、产物和检查点
    ├── 03-源码结构与构建.md         # 真实源码目录、入口、路由、依赖和构建
    ├── 04-本地使用指南.md           # 直接使用当前 skills/<repo>，不做完整安装
    └── 05-验证与风险.md             # 测试、核查、失败处理和安全边界
```

文件名保持稳定；若某仓库不提供传统编译步骤，`03-源码结构与构建.md` 应明确说明其实际构建方式是 Markdown 加载、宿主发现、脚本运行或插件打包，而不是虚构一个 build 命令。

## 本地使用指南边界

每个 `04-本地使用指南.md` 必须：

- 引用当前项目中对应的 `skills/<repo>` 路径；
- 说明如何让 Claude Code、Codex 或其他兼容宿主读取真实 `SKILL.md`；
- 提供最小可用的相对路径/绝对路径示例、输入准备和输出位置；
- 明确“只在本项目源码上使用”，不执行全局安装、插件注册、环境重构或远程部署；
- 需要依赖时只列出检查方式，不自动安装；
- 对网络、API、MCP、脚本和写入权限设置人工确认点。

## 增量推进

- 每轮处理 2–3 个 skill，每轮结束核验后再开始下一轮。
- 第 1 轮先处理 Academic Research Skills Claude 版、ARS-Codex、Claude Scholar，验证目录模板。
- 后续轮次复用模板，逐步处理其余 9 个 skill。
- 每轮在 `docs/skill文档/README.md` 记录已完成目录、源码分析范围和下一轮目标。
- 旧扁平 Markdown 不删除；必要时在其中加入新目录链接，但不破坏原有入口。

## 信息来源和可信度

源码结构、入口、依赖、构建命令和功能只来自对应本地仓库的 README、SKILL.md、配置文件、脚本和测试。知乎文章仅用于记录作者的评价和使用感受，不能当作源码事实或独立质量证明。无法从源码确认的内容必须标注“仓库资料未说明”。

## 验收标准

每个已完成 skill 目录必须存在上述 6 个文件；功能、使用、本地使用、源码构建、验证风险五类内容互相链接；本地指南不包含全局安装步骤；源码分析必须包含实际文件路径、入口关系和构建/加载方式；所有文档经过链接、占位符和路径核验。
