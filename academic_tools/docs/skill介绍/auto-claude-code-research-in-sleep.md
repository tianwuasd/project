## 一句话定位

ARIS 的核心不是某一个学科算法，而是让 Agent 按“计划 → 草拟/执行 → 对抗审查 → 迭代 → 持久化”的循环长时间推进研究任务，并在用户不持续盯着会话时继续工作。

## 核心功能

- **端到端研究流水线**：从研究方向、文献和参考代码出发，形成想法、运行实验、分析结果并产出论文。
- **定向改进模式**：可以同时提供参考论文和基础代码，让 Agent 根据论文弱点与代码库生成改进方向并实验。
- **Rebuttal 模式**：读取论文与审稿意见，跟踪每个 reviewer concern，生成受字符数约束的回复；README 明确列出不编造、不越权承诺和完整覆盖等门槛。
- **Research Wiki**：持久化论文、想法、实验、结果、主张及其关系，帮助后续会话恢复上下文。
- **跨模型审查**：Claude Code 负责执行，Codex MCP 或其他配置的模型负责批判性审查，目标是避免单模型自审的盲点。
- **多宿主适配**：仓库提供 Claude Code、Codex CLI、Cursor、Trae、Antigravity、Copilot CLI、OpenClaw 等适配说明，并有 ARIS-Code 独立 CLI。
- **自动化与质量工具**：包含输出审计、研究记忆、实验排队、图表/论文相关 skill 和多种确定性辅助工具。

## 适用场景

适合已经有明确研究任务、代码或论文素材，且希望把多轮重复工作交给 Agent 慢慢执行的 ML/AI 研究者。它尤其适合实验迭代、论文改稿和审稿回复，不适合把未经审核的夜间产物直接提交。

## 优势

1. 方法论轻量：skill 层主要是纯 Markdown，不强制额外框架、数据库或 Docker。
2. 任务循环完整，能把研究执行、评审和记忆连起来，而不是只生成一段答案。
3. 跨模型审查和多轮 gate 为长任务提供了比单轮生成更强的检查结构。
4. 代码库持续记录版本、测试和适配文档，适合研究者按需裁剪。

## 局限与风险

- 无人值守会放大错误：如果联网检索或数据来源不可用，Agent 可能生成看似合理但未经证实的数字、引用或结论。
- 跨模型、MCP、API 和后台进程涉及凭据、费用、网络和本地文件权限，应先明确审批策略。
- “自动跑一整晚”不代表实验可复现或论文可投稿；仍需检查代码、日志、统计假设、数据和每个引用。
- 仓库包含较多功能和版本适配，首次使用应从小任务或只读审查开始。

## 文章评价

文章作者评为“人上人”，认可其无人值守改稿和跨模型审查思路，同时特别指出：若 API 没有实时检索能力，夜间流程可能现场编造数据。因此文章建议将 ARIS 与 Academic Research Skills 的引用验证配合使用；这一组合逻辑合理，但仍需人工打开原始来源核查。

## 推荐组合

- ARIS 夜间完成结构调整和初稿迭代，白天用 ARS-Codex 检查引用、证据和审稿风险。
- 用 Scientific Agent Skills 执行科学计算，把真实实验日志和参数交给 ARIS 组织，而不是让它凭空生成结果。
- 用 PaperSpine 做最终贡献、结果映射和投稿关卡，避免自动改稿偏离论文主张。

## 使用前核查

1. 从最小任务开始，限制可写目录、联网工具、模型和运行时长。
2. 为关键数据和文献设置可追溯来源；没有来源的内容必须标记为待验证。
3. 保存每轮变更、实验日志和审查报告，夜间结果先 diff 再合并。
4. 阅读仓库的 `AGENT_GUIDE.md`、宿主适配文档和安全相关说明。
