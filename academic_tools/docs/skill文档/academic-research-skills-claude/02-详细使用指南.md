# 详细使用指南

> 版本说明（2026-10-19）：源码已更新；正文保留此前整理的指南，功能与安装入口以当前上游 README 为准。见[本次更新记录](../../../UPDATE-2026-10-19.md)。

## 1. 开始前准备

```text
project/
  question.md
  materials/              # PDF、笔记、模板、审稿意见
  results/                # 真实实验结果和日志
  references.bib
  constraints.md          # 语言、格式、字数、权限
```

提示词中明确本轮目标、允许读写的目录、是否允许联网、已确认事实和必须保留的数字/术语。

## 2. 研究问题收敛

```text
请使用 ARS deep-research 的 Socratic 模式。
主题：生成式 AI 对高校质量保障的影响。
我有 12 篇论文，但研究问题尚未确定。
只询问收敛问题，并输出 2–3 个候选问题、可行性和证据缺口。
不要生成论文大纲或正文。
```

**检查**：每个候选问题要有可获得的数据/文献和清楚的研究范围。

## 3. 文献综述

```text
请使用 ARS deep-research 的 systematic-review 模式。
主题：……；范围：2020–2026；语言：中英文。
输出检索策略、纳入/排除标准、筛选记录、主题矩阵和未验证项。
所有论文标题、作者、年份、DOI 和结论都必须可追溯，找不到的不要补写。
```

**检查**：区分“未检索到”与“没有研究”，逐篇核对原文。

## 4. 论文规划与写作

```text
请使用 ARS academic-paper 的 plan 模式。
输入：question.md、materials/、results/。
先输出 IMRaD 蓝图、章节职责、claim-evidence 表和缺失证据清单。
等我确认蓝图后再写 Introduction，不要新增实验或引用。
```

确认后：

```text
只撰写 Introduction。
每个主要 claim 标注证据和引用状态，保持原始限定词。
输出段落、论证链和需要我确认的句子。
```

## 5. 引用核验

```text
/ars-citation-check manuscript.md
```

要求区分：文献是否存在、文献是否讨论该主题、文献是否支持当前句子。无法核验的条目保持 `unverified`。

## 6. 同行评审

```text
/ars-reviewer manuscript.pdf
```

```text
请从贡献、方法、统计、引用完整性、可复现性和目标 venue 六个角度评审。
每条意见指向具体段落、表格或图；材料不足时写无法判断。
输出主要/次要问题、必须修改项和编辑决定信草稿。
```

## 7. 分阶段 pipeline

```text
请使用 ARS academic-pipeline，从 Stage 0 intake 开始。
本轮只完成材料清单和 pipeline dashboard，展示缺失项后停止等待确认。
```

每次只推进一个阶段；保存阶段产物、人工决定和阻塞原因。

## 8. 推荐产物

- `question.md` / 研究问题简报；
- 检索与筛选记录；
- 阅读笔记与引用支持表；
- 论文蓝图和 claim-evidence 矩阵；
- reviewer reports、rebuttal 和完整性报告；
- Material Passport、实验 provenance 和过程日志。

## 9. 人工确认点

- 研究者确认研究问题、方法和核心贡献；
- 研究者确认每条关键引用和数据；
- 研究者确认可写入论文的实验结果；
- 研究者确认 reviewer 修改路线和最终稿。
