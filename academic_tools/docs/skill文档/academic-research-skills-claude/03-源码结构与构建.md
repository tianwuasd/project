## 架构摘要

ARS 是一个由四个顶层 Skill 组成的 Claude Code 研究插件：

```text
用户请求
├── deep-research              研究问题、检索、核验和综合
├── academic-paper             论文结构、论证、起草和修订
├── academic-paper-reviewer    多角色同行评审和复审
└── academic-pipeline          调度前三者、维护状态和质量门
```

项目的主要源码是 `SKILL.md`、Agent prompt、references、templates 和 shared contracts。Python/Shell 脚本为引用检查、Schema、patch、镜像和 CI 等需要可重放结果的工作提供确定性实现。Pipeline 是编排器，不替代研究、写作或审稿本身。

## 新手最快入口

如果只想在当前项目使用，不需要安装插件。直接指定本地入口：

```text
请先读取 skills/academic-research-skills/deep-research/SKILL.md。
只读取 local-ars/materials/，只写 local-ars/output/。
本轮使用 socratic 模式，先收敛研究问题。
不要安装插件、修改全局配置、联网或调用外部 API。
```

完整的项目级用法、`.claude/skills/` 发现方式和目录结构见[新手使用与扩展](03-架构文档/05-新手使用与扩展.md#仅在当前项目使用不进行全局安装)。

## 关键边界

- 四个 Skill 可独立使用，单一任务不必运行完整 Pipeline；
- Stage 2.5 和 4.5 完整性门禁不能静默跳过；
- `data_access_level: raw` 是输入等级声明，不是系统权限；
- Hooks 是辅助保护，不是安全沙箱；
- 引用记录存在不等于正文 claim 获得支持；
- 根 `agents/` 是同步镜像，生成的能力矩阵也不应直接修改；
- 本轮只说明源码和已有验证结构，没有安装依赖或运行仓库测试。
