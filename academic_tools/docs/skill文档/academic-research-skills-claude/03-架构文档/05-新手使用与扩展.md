# 新手使用与扩展

> 版本说明（2026-10-19）：源码已更新；正文保留此前整理的指南，功能与安装入口以当前上游 README 为准。见[本次更新记录](../../../../UPDATE-2026-10-19.md)。

## 1. 新手先记住三条规则

1. **一个任务先选一个入口。** 只做文献就用 Deep Research，只写大纲就用 Academic Paper，不要默认启动十阶段 Pipeline。
2. **Skill 源码与项目材料分开。** `skills/academic-research-skills/` 只读；输入、状态和输出放到独立工作目录。
3. **每次先完成一个阶段。** 检查产物和未验证项后再继续，不把“自动完成”理解成跳过 gate。

## 2. 仅在当前项目使用：不进行全局安装

这是推荐的新手路线。它不写 `~/.claude/skills/`，不注册全局插件，不影响其他项目。

### 2.1 推荐项目结构

```text
academic_tools/
├── skills/
│   └── academic-research-skills/   # 本地源码快照，默认只读
├── local-ars/
│   ├── question.md                 # 研究目标和本轮停止条件
│   ├── constraints.md              # 权限、网络、语言、venue 等
│   ├── materials/                  # 论文、笔记、书目等副本
│   ├── results/                    # 真实结果和日志副本
│   ├── manuscript/                 # 稿件副本
│   ├── reviews/                    # reviewer comments 和审稿产物
│   ├── state/                      # Passport、checkpoint 和 run 状态
│   └── output/                     # Agent 唯一输出位置
└── .claude/
    └── skills/                     # 可选：项目级自动发现
```

### 2.2 方式 A：直接指定本地 `SKILL.md`

不复制、不链接、不安装。提示词明确告诉 Agent 入口、输入和输出。

#### 收敛研究问题

```text
请使用当前项目本地的 Academic Research Skills。

先读取：
skills/academic-research-skills/deep-research/SKILL.md

使用 socratic 模式处理：
local-ars/question.md
local-ars/materials/

只写：
local-ars/output/

本轮只生成研究问题候选、范围边界和待确认项。
不要安装插件、修改全局配置、联网或调用外部 API。
```

#### 只生成论文大纲

```text
请先读取：
skills/academic-research-skills/academic-paper/SKILL.md

使用 outline-only 模式。
读取 local-ars/materials/ 和 local-ars/results/。
只生成 local-ars/output/outline.md 和 evidence-map.md。
不要生成完整正文，不新增引用，不修改原始材料。
```

#### 模拟同行评审

```text
请先读取：
skills/academic-research-skills/academic-paper-reviewer/SKILL.md

只审阅 local-ars/manuscript/manuscript.md。
将独立审稿意见、编辑决定和修改路线写入 local-ars/output/review/。
保持稿件只读；无法核验的引用和数字标记为 unverified。
```

#### 完整 Pipeline，但先只做入口判断

```text
请先读取：
skills/academic-research-skills/academic-pipeline/SKILL.md

读取 local-ars/question.md、materials/、results/、manuscript/ 和 reviews/ 的现有内容。
先只输出：
1. current stage
2. required inputs
3. missing inputs
4. expected artifact
5. next gate type

写入 local-ars/output/intake.md 和 local-ars/state/。
未经我确认，不进入下一阶段。
不要安装插件、启用 hooks、联网或修改 skills/。
```

### 2.3 直接读取方式的能力边界

可以使用：

- 四个 `SKILL.md` 的模式和阶段；
- 对应 Agent prompt；
- references、templates 和 shared contracts；
- 经人工批准的本地辅助脚本。

不会自动启用：

- `/ars-*` Commands；
- SessionStart 公告；
- PreToolUse 写入 guard；
- 插件公开的三个 Agents；
- 自动更新检查；
- marketplace 管理。

这不妨碍核心工作流使用。新手先掌握入口和产物，比一开始启用全部控制层更重要。

## 3. 项目级自动发现：仍不做全局安装

如果同一项目频繁使用，可以把所需 Skill 放到：

```text
<project>/.claude/skills/
```

正确形状：

```text
.claude/skills/
├── deep-research/
│   └── SKILL.md
├── academic-paper/
│   └── SKILL.md
├── academic-paper-reviewer/
│   └── SKILL.md
└── academic-pipeline/
    └── SKILL.md
```

错误形状：

```text
.claude/skills/academic-research-skills/deep-research/SKILL.md
```

多嵌套一层仓库名后，宿主可能无法按 `<skill-name>/SKILL.md` 发现四个入口。

### 3.1 复制还是链接

- **复制**：兼容性高，但上游更新后需要人工同步；
- **目录链接**：保持源码单一，但 Windows 权限和不同客户端兼容性需核对；
- **直接指定路径**：不产生副本，最适合学习和一次性任务。

无论哪种方式，运行产物都不应写回 Skill 目录。

### 3.2 项目级发现不等于插件安装

项目级 `.claude/skills/` 主要解决 Skill 发现。以下能力仍可能缺失：

- commands 注册；
- plugin agents；
- hooks；
-更新公告。

若只需要工作流正文，不必为这些附加能力做全局安装。

## 4. 按任务选择入口

| 当前材料和目标 | 入口 | 建议 mode/命令概念 | 第一份产物 |
|---|---|---|---|
| 只有宽泛主题 | Deep Research | `socratic` | RQ Brief 候选 |
| 有明确 RQ，要全面研究 | Deep Research | `full` | 方法蓝图和来源计划 |
| 要快速简报 | Deep Research | `quick` | 有限范围简报 |
| 做系统综述/Meta | Deep Research | `systematic-review` | protocol、检索与筛选结构 |
| 只写大纲 | Academic Paper | `outline-only` | Outline + Evidence Map |
| 已有材料，写完整论文 | Academic Paper | `full` | Configuration + Draft |
| 只改摘要 | Academic Paper | `abstract-only` | 摘要版本和证据定位 |
| 查引用或格式 | Academic Paper | `citation-check` | 引用状态报告 |
| 根据 reviewer comments 修稿 | Academic Paper | `revision` | Revised Draft + Response |
| 对现有稿件独立审稿 | Reviewer | `full` | 5 reports + Decision |
| 验证修稿是否响应 | Reviewer | `re-review` | Response checklist + residual issues |
| 从主题到最终稿 | Pipeline | full workflow | Intake / Stage detection |
| 已有稿件，想进入 Pipeline | Pipeline | mid-entry | 先进入 Stage 2.5 integrity |
| 只转换最终格式 | Academic Paper | `format-convert` | 目标格式文件或说明 |

## 5. 新手怎样阅读源码

不建议一次打开整个仓库。按以下顺序：

```text
1. MODE_REGISTRY.md
2. 目标 Skill 的 SKILL.md
3. 当前 mode / phase
4. 该 phase 指定的 Agent
5. Agent 引用的 reference / template
6. 需要跨阶段时再看 shared contract
7. 需要确定性检查时再看 script
```

### 示例：理解论文大纲

```text
MODE_REGISTRY.md
→ academic-paper/SKILL.md 的 outline-only
→ structure_architect_agent.md
→ outline/evidence-map references
→ 如需交给 Pipeline，再看 shared handoff schema
```

### 示例：理解 Stage 2.5

```text
academic-pipeline/SKILL.md 的 Stage 2.5
→ integrity_verification_agent.md
→ ai_research_failure_modes.md
→ shared/handoff_schemas.md 的 integrity/Passport 字段
→ 如需程序化引用检查，再看 scripts/verification_gate
```

## 6. 第一次完整使用的推荐节奏

### 第一次：只做一个小任务

- 选择 `deep-research:socratic` 或 `academic-paper:outline-only`；
- 限制 3–5 篇材料；
- 只写一个 output 文件；
- 不联网、不执行脚本；
- 人工检查字段和边界。

### 第二次：加入 handoff

- 保存 RQ Brief 或 Evidence Map；
- 检查来源和未知项；
- 将它作为下一阶段输入；
- 比较前后产物是否保持约束。

### 第三次：有限 Pipeline

- 让 Pipeline 检测入口；
- 只推进一个阶段；
- 查看 state 和 checkpoint；
-确认后再继续。

新手不建议第一次就启用跨模型、自动更新、全部 hooks 和完整十阶段无人值守流程。

## 7. 常见项目级故障

| 现象 | 原因 | 解决方法 |
|---|---|---|
| Agent 没读取 ARS | 没显式给 `SKILL.md`，也没有项目级发现 | 在提示词中写真实入口路径 |
| 找不到 `.claude/skills` 中的 Skill | 目录多嵌套一层 | 让 `SKILL.md` 直接位于 `<skill-name>/` 下 |
| `/ars-*` 不可用 | 只做了项目级 Skill，没有插件 commands | 直接描述 mode，不必全局安装 |
| Hook 没有公告/guard | 项目级直接读取不注册插件 hooks | 使用宿主权限和明确输出目录 |
| Pipeline 直接写完整稿 | 没限制本轮阶段和停止点 | 要求先输出 stage、inputs、artifact、gate |
| 输出写回 `skills/` | 未指定输出目录 | 只允许写 `local-ars/output/` 和 `state/` |
| 引用看似完整但不可核验 | 未联网或只有标题匹配 | 保留 `unverified`，回到原文/DOI 核查 |

## 8. 扩展与二次开发

### 8.1 新增 Mode

推荐顺序：

```text
MODE_REGISTRY.md
→ 对应 Skill/SKILL.md 的 mode protocol
→ 必需 Agent / reference / template
→ 可选 command wrapper
→ SessionStart announce（若暴露命令）
→ tests / invariants / CHANGELOG / version
```

`MODE_REGISTRY.md` 是模式真源，不能只新增 `commands/foo.md`。

### 8.2 新增 Agent

放到所属 Skill 的 `agents/`：

- 写清职责、输入、输出和禁止事项；
- 只负责一个 phase；
- 不越权修改下游产物；
- 如需跨 Skill 使用，定义 handoff contract；
- 添加 fixtures 和测试。

三个插件公开 Agent 的 canonical source 位于 `deep-research/agents/`。根 `agents/` 是同步镜像，不能单独改。

### 8.3 新增 Reference 或 Template

- Skill 专属协议：放对应 Skill 的 `references/`；
- Skill 专属产物结构：放对应 `templates/`；
- 跨 Skill 协议：放 `shared/references/` 或 `shared/contracts/`；
- 可机读 Schema：优先 JSON Schema，并提供 validator 和示例。

### 8.4 新增 Command

Command 应保持薄：

```text
command name
→ target skill
→ target mode
→ minimal input contract
```

不要在 Command 中复制一整套工作流。新增后同步 command invariants、公告、文档和版本记录。

### 8.5 新增 Hook

Hook 适合：

- 会话公告；
- 写入范围提醒；
- 快速、失败可降级的检查。

Hook 不适合：

- 替代 Stage 2.5/4.5 integrity；
- 自动发送稿件到外部 API；
- 隐式修改论文；
- 依赖长时间网络请求；
- 失败时锁死所有用户操作。

### 8.6 新增确定性脚本

脚本应明确：

- 输入格式；
- stdout/JSON 输出；
- exit code；
- 是否读写文件或联网；
- 缺依赖时的行为；
- fixtures、unit tests 和 CI manifest。

生成性判断不要伪装成确定性 PASS；确定性脚本也不要替代研究者对科学意义的判断。

## 9. 不能直接修改或绕过的部分

- 根 `agents/` 镜像；
- 生成的 `docs/STAGE_CAPABILITY_MATRIX.md`；
- Passport append-only reset/read/adjudication ledger；
- Stage 2.5 和 4.5 完整性门禁；
- reviewer 的独立席位和少数意见保留；
- gold labels、answer keys 和 ground-truth isolation；
- handoff schema 字段而不更新消费者；
- 平台 adapter 直接改写核心 Skill 语义；
- 未经用户同意的跨模型传输或自动发表。

## 10. 项目级使用检查清单

- [ ] 使用的是 `skills/academic-research-skills/<skill>/SKILL.md` 真实入口。
- [ ] 源码目录只读，运行材料位于 `local-ars/`。
- [ ] 本轮目标、输入、输出和停止点明确。
- [ ] 没有要求全局安装、插件注册或修改用户配置。
- [ ] 网络、脚本、API 和跨模型默认关闭，需用时单独确认。
- [ ] 当前 stage、required inputs、artifact 和 next gate 可见。
- [ ] 引用、数字、实验和结论有来源或 `unverified` 状态。
- [ ] 人工确认后才进入下一阶段。
