# 运行环境、构建与验证

> 版本说明（2026-10-19）：源码已更新；正文保留此前整理的指南，功能与安装入口以当前上游 README 为准。见[本次更新记录](../../../../UPDATE-2026-10-19.md)。

## 1. 先理解“构建”的含义

ARS 的主要源码是 Markdown、YAML/JSON contracts 和辅助脚本，没有一个必须编译的后端服务。因此应区分四种不同操作：

| 操作 | 含义 | 典型文件 |
|---|---|---|
| Skill 加载 | 宿主发现并读取 `SKILL.md` | `.claude-plugin/`、`skills/`、四个 Skill 目录 |
| 插件安装 | 注册 Skills、Commands、Agents 和 Hooks | marketplace/plugin manifest |
| 确定性验证 | 运行 schema、引用、镜像、命令和一致性检查 | `scripts/`、tests、CI |
| 文档产物构建 | 将稿件转换成 DOCX/LaTeX/PDF | Pandoc、tectonic、字体 |

“Markdown 被加载”不是传统编译；“生成 PDF”也不是构建 ARS 插件本身。

## 2. 最小环境

### 2.1 直接读取本地源码

最小条件：

- 一个可以读取本地文件的 Agent 宿主；
- 当前项目中的 `skills/academic-research-skills/`；
- 明确的输入和输出目录。

直接读取 `SKILL.md` 不要求：

- 全局安装插件；
- 启用 hooks；
- 安装 Pandoc/tectonic；
- 配置外部 API；
- 安装开发测试依赖。

### 2.2 完整 Claude Code 插件

完整插件通常需要：

- Claude Code；
- 可用的 Claude 认证或 API 配置；
- 插件市场/插件安装能力；
- 新会话或重新加载以发现 Commands、Agents 和 Hooks。

插件安装后才能按 manifest 自动暴露完整控制层。只复制四个 Skill 时，核心工作流可用，但 commands、hooks 和插件 Agent 不一定自动注册。

## 3. 可选运行依赖

| 依赖 | 用途 | 缺失时如何降级 |
|---|---|---|
| Pandoc | 直接生成 DOCX，部分格式转换 | 输出 Markdown 和转换说明 |
| tectonic / LaTeX | 构建 PDF 和 Process Record | 保留 LaTeX/Markdown 源或说明 |
| Times New Roman / Source Han Serif TC / Courier New | 中英论文和代码字体 | 使用可用字体并人工检查版式 |
| Python | Adapter、gate、validator、测试和 hooks guard | Markdown 工作流仍可用；脚本能力不可用 |
| Git Bash（Windows） | 运行部分 `.sh` hook/脚本 | 直接读取 Skill；hook 可能 pass-through |
| `pdf-inspector` | 可选 PDF 内容分类 | 退回基础 PDF 预检；不得伪称已 OCR/分类 |
| 外部学术 API | 程序化查验 DOI/arXiv/记录 | 标记未验证，使用人工/浏览器来源 |

开发和校验依赖见：

- `requirements-dev.txt`；
- `requirements-pdf-content-classifier.txt`；
- `pyproject.toml`。

本架构文档不执行安装。

## 4. 配置和环境变量

### 4.1 行为开关

| 变量 | 作用 | 默认理解 |
|---|---|---|
| `ARS_PASSPORT_RESET=1` | FULL checkpoint 写 reset boundary | 默认不写 |
| `ARS_CLAIM_AUDIT=1` | 启用 L3 claim-faithfulness audit | 默认关闭 |
| `ARS_INQUIRY_LEDGER=1` | 启用 inquiry branch ledger | 选择性能力 |
| `ARS_SOCRATIC_READING_PROBE=1` | Socratic 阅读探针 | 可选 |
| `ARS_MODEL_TIERING` | economy / quality-boost 建议 | 宿主不支持 per-dispatch 时仅 advisory |
| `ARS_UPDATE_CHECK=0` | 关闭更新检查 | 不影响核心 Skill |

### 4.2 Cache

| 变量 | 作用 |
|---|---|
| `ARS_VERIFICATION_CACHE_PATH` | 设置本地 SQLite cache 路径 |
| `ARS_CACHE_STALE_ADVISORY_DAYS` | 定义 stale 提醒天数 |
| `ARS_CACHE_REVALIDATE=1` | 要求重新核验 cache 条目 |

Cache 只保存查验记录，不能把历史 `verified` 自动提升为当前证据。

### 4.3 跨模型

代表变量包括：

- `ARS_CROSS_MODEL`；
- `ARS_CROSS_MODEL_TRANSPORT`；
- `ARS_CROSS_MODEL_SAMPLE_INTERVAL`；
- provider API keys。

重要边界：

```text
已配置 provider
≠ 当前会话同意发送数据
≠ 可以发送整篇未公开稿件
≠ 跨模型结果自动可信
```

每次跨模型传输应说明发送材料、服务提供方、目的、费用和隐私影响。

## 5. 三种加载方式

### 5.1 直接读取源码

```text
Agent
→ skills/academic-research-skills/<skill>/SKILL.md
→ 按当前 phase 读取 agents/references/templates/shared
```

优点：最小影响、无需安装、适合学习和单项目试用。限制：不自动提供 `/ars-*`、hooks 和插件 Agents。

### 5.2 项目级 Skill 发现

```text
<project>/.claude/skills/deep-research/SKILL.md
<project>/.claude/skills/academic-paper/SKILL.md
<project>/.claude/skills/academic-paper-reviewer/SKILL.md
<project>/.claude/skills/academic-pipeline/SKILL.md
```

只影响当前项目。Skill 目录必须直接位于 `.claude/skills/` 下，不能多嵌套一层仓库名。

### 5.3 完整插件安装

完整插件会注册：

- 4 Skills；
- `/ars-*` Commands；
- 3 个插件公开 Agents；
- SessionStart 与 PreToolUse Hooks。

适合频繁使用和需要完整控制层的用户。具体命令以仓库当前 `docs/SETUP.md` 为准，不在本架构文档执行。

## 6. 平台能力差异

`docs/CONTROL_AVAILABILITY.md` 说明不同载体可用能力并不相同：

- Claude Code Plugin：完整 commands、agents、hooks；
- 项目级 Skills：主要工作流正文；
- standalone clone：适合直接读取和开发；
- Cowork / claude.ai Project：通常偏只读、缺少 Claude Code orchestration；
- Pi wrapper：通过 `pi/wrapper.js` 提供适配，能力依宿主；
- 其他平台 port：应增加外层 adapter，而不是重写核心 contracts。

不要根据某个平台的安装说明推断另一个平台也会自动注册同样的 hooks 或 commands。

## 7. 输入、网络和本地存储

### 7.1 可能发送到外部的数据

根据任务和显式配置，以下内容可能离开本机：

- DOI、arXiv ID、标题查询；
- Semantic Scholar、OpenAlex、Crossref、arXiv 请求；
- 跨模型审查材料；
- 用户要求的浏览器检索内容。

ARS 不应自主发表、上传或发送稿件。外部访问必须受宿主权限和用户批准约束。

### 7.2 本地状态

可能产生：

- verification SQLite cache；
- update-check state；
- 用户指定位置的 Material Passport；
- inquiry/read-scope/reset ledgers；
- optional retraction cache；
-稿件、报告、审计和 Process Record。

这些是运行产物，不应写回 Skill 源码目录。

## 8. Hooks 的运行边界

### SessionStart

用途：公告 Skill/commands 和有界更新提示。失败应静默，不阻断工作。

### PreToolUse Guard

用途：在 Write/Edit/MultiEdit/Bash 前检查写入范围。其安全模型是辅助保护：

- launcher 有超时；
-缺运行环境时 pass-through；
- guard 故障时不锁死用户；
-不能替代 Claude Code 权限、项目备份和人工审查。

只直接读取本地 `SKILL.md` 时，这些 hooks 不会自动启用。

## 9. 测试与质量保障结构

### 9.1 测试真源

主体测试位于：

```text
scripts/test_*.py
```

统一 pytest 调用清单位于：

```text
scripts/_ci_pytest_manifest.toml
```

Runner：

```text
scripts/run_ci_pytest_manifest.py
```

Manifest 检查路径、id、参数和调用形状，避免多个 CI workflow 各自维护一份逐渐漂移的 pytest 列表。

### 9.2 CI 分类

仓库工作流大致分为：

| 类别 | 作用 |
|---|---|
| Blocking | 失败时阻止合并，例如 spec/schema/pytest 一致性 |
| Advisory | 提供趋势或风险提醒，不直接阻断 |
| Administrative | 发布、标签、元数据管理 |
| Post-push detection | 合并后检测需要跟进的问题 |

代表工作流：

- `spec-consistency.yml`；
- `pytest.yml`；
- command invariants；
- repository hygiene；
- eval harness；
- test-count monotonic；
- changelog/version checks。

### 9.3 确定性与生成性验证

- Schema、hash、路径、版本、引用 lookup 可以确定性检查；
- 研究综合、论文质量和 reviewer judgment 不能承诺字节一致；
- 生成性输出需要保留输入、版本、提示角色和人工裁定；
- 测试通过不证明原始数据、引用内容或论文结论正确。

本轮没有运行仓库测试，因此本文只描述测试结构，不声明当前测试通过。

## 10. 构建和发布维护

### 10.1 新版本需要同步的表面

- `.claude-plugin/plugin.json` 版本；
- Skill frontmatter 版本（按实际变更）；
- `CHANGELOG.md`；
- `MODE_REGISTRY.md`；
- commands 和 SessionStart 公告；
- root agent 镜像；
- generated capability docs；
- tests / fixtures / CI manifest。

### 10.2 版本纪律工具

`tools/release-discipline/` 和 `.command-invariants.toml` 用于检查：

- command roster；
- announce 中的命令是否同步；
-插件版本与 CHANGELOG；
-命令 frontmatter 名称；
-发布时必须保持的不变量。

## 11. 常见环境故障

| 现象 | 根因方向 | 处理 |
|---|---|---|
| 找不到 Skill | 多嵌套一层、入口没在发现目录、会话缓存 | 检查 `.../<skill>/SKILL.md` 形状并新开会话 |
| `/ars-*` 不出现 | 只加载了 Skill，未安装插件/commands | 直接指定 `SKILL.md` 或使用完整插件 |
| DOCX/PDF 没生成 | Pandoc/tectonic/字体缺失 | 保留 MD/LaTeX，按说明转换 |
| Hook 没拦截写入 | 直接读取模式、平台不支持、guard pass-through | 依赖宿主权限和明确输出目录 |
| 引用查验为空 | 未联网、无 provider、限流、输入不完整 | 标记 unverified，不补造来源 |
| Cache 显示历史结果 | stale 未重验 | 检查时间/来源，按需 revalidate |
| Resume 失败 | hash 错误、boundary 已消费、未产生 boundary | 查 Passport reset ledger 和 pending decision |
| 跨模型未调用 | 只有配置，没有当前会话同意或 transport | 先列数据和费用，再显式批准 |
