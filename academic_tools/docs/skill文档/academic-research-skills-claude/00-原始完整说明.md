# Academic Research Skills（Claude Code 版）详细使用文档

> 版本说明（2026-10-19）：源码已更新；正文保留此前整理的指南，功能与安装入口以当前上游 README 为准。见[本次更新记录](../../../UPDATE-2026-10-19.md)。

## 0. 文档范围

本指南对应 Claude Code 版本，不是 [ARS-Codex](../ars-codex/00-原始完整说明.md) 的安装指南。上游仓库将 AI 定位为副驾驶：它负责检索、格式化、核验和一致性检查；研究问题、方法选择、结果解释和最终论断仍由研究者负责。

- **本地源码**：[`skills/academic-research-skills`](../../../skills/academic-research-skills/)
- **上游仓库**：[Imbad0202/academic-research-skills](https://github.com/Imbad0202/academic-research-skills)
- **当前 README 版本**：v3.21.1
- **文章评价**：第二篇知乎文章评为“夯”；这是文章作者的体验性评价，不是本指南独立复现的结论。

## 1. 能解决什么问题

ARS 是一套 Claude Code 学术研究 skill，覆盖：

1. **Deep Research**：研究问题收敛、文献综述、系统综述/PRISMA、元分析、事实核查和论文质量审查。
2. **Academic Paper**：论文大纲、摘要、章节草稿、引用格式转换、AI disclosure、修改和 rebuttal。
3. **Academic Paper Reviewer**：多视角同行评审、期刊适配、方法审查、复审和编辑决定信。
4. **Academic Pipeline**：从研究问题到论文的分阶段编排，带 Material Passport、完整性门禁和过程记录。
5. **Experiment Agent 衔接**：ARS 本身不替你执行实验；实验应在外部完成，再把 provenance 和结果带回写作/审查阶段。

## 2. 前置条件

### 必需

- Claude Code（建议使用支持插件安装的近期版本）
- 可用的 Claude 账号/API 配置
- Git（如果采用仓库克隆或项目级安装）

### 可选

- **Git Bash**：Windows 上运行可选 `.sh` hook 时使用。
- **真实 Python**：写入范围 guard、revision patch、submission verifier 和缓存/阅读标记命令会用到；核心 prompt-driven 流程不依赖 Python。
- **Pandoc**：需要 DOCX 输出时安装。
- **tectonic + Source Han Serif TC**：需要 APA PDF 时安装。
- **联网能力**：文献检索、来源核验和外部元数据需要网络；离线时必须接受输出会减少或标记未验证。

## 3. 安装方式

### 3.1 推荐：Claude Code 插件市场

在 Claude Code 中逐行运行：

```text
/plugin marketplace add Imbad0202/academic-research-skills
/plugin install academic-research-skills
```

安装后重新打开或 reload Claude Code，然后运行：

```text
/ars-plan
```

输入论文主题，ARS 应先通过 Socratic 对话询问研究问题、范围和素材，而不是立即输出完整论文。

### 3.2 项目级 skill

如果只想在当前项目使用，按仓库 [`docs/SETUP.md`](../../../skills/academic-research-skills/docs/SETUP.md) 的项目级方法，把需要的 skill 目录放到项目的 `.claude/skills/`。不要把整个仓库随意复制后期待所有 hook 和 slash command 自动生效。

### 3.3 验证安装

执行两个最小测试：

```text
/ars-plan
```

输入：

```text
我想研究生成式 AI 对高校质量保障的影响，但研究问题还不清楚。
请先用 Socratic 模式帮助我收敛问题，不要写大纲。
```

再执行：

```text
/ars-lit-review "生成式 AI 高等教育质量保障"
```

检查 Agent 是否明确列出检索范围、来源和待核验项目。若直接生成确定性结论而没有来源，不要继续扩大任务。

## 4. 输入准备

开始复杂任务前，准备一个最小输入包：

```text
project/
  question.md              # 当前研究问题与已知限制
  materials/               # PDF、笔记、数据说明、审稿意见
  references.bib           # 已有引用（可选）
  results/                 # 真实实验结果和日志（如有）
  constraints.md           # 语言、格式、字数、截止日期、禁止事项
```

提示词中明确：

- 目标读者和目标期刊/会议；
- 你希望本轮只完成哪个阶段；
- 哪些内容是已确认事实，哪些只是猜想；
- 是否允许联网、运行脚本、读取/写入哪些目录；
- 引用格式和是否需要保留 DOI、页码、段落定位。

## 5. 典型使用示例与主要工作流

### 5.1 研究问题收敛

**输入**：主题、已有兴趣、学科范围、可用数据/方法和时间约束。

```text
/ars-plan

主题：生成式 AI 对高校质量保障的影响
已有材料：我有 12 篇 PDF 和一份初步笔记
约束：教育政策方向，半年内完成，暂时没有明确数据
本轮目标：只通过 Socratic 对话收敛 2–3 个可研究问题，不写论文大纲
```

**预期产物**：研究问题候选、范围边界、关键变量/概念、待查证证据和下一步决策。

**人工检查**：确认问题不是把相关性写成因果性，确认数据和方法真的可获得；不要因为 Agent 给出“有意义”就直接选题。

### 5.2 文献综述与事实核查

```text
/ars-lit-review "生成式 AI 高等教育质量保障"
```

或：

```text
请使用 ARS deep-research 的 systematic-review 模式。
主题：……
范围：2020–2026，英文和中文，关注可验证的实证研究。
输出：检索策略、纳入排除标准、PRISMA 风格筛选记录、主题矩阵和未验证项。
不要虚构论文、DOI、样本量或结果。
```

**预期产物**：检索与筛选记录、论文摘要/笔记、主题矩阵、研究缺口候选和引用来源。

**人工检查**：逐篇打开原文核对标题、作者、年份、DOI 和结论；对“论文没有讨论”“首次提出”等负面/新颖性判断尤其谨慎。

### 5.3 引用核验

```text
/ars-citation-check manuscript.md
```

也可以限定范围：

```text
请检查 manuscript.md 中 Introduction 和 Related Work 的每条引用。
对每条引用输出：引用是否存在、元数据、原文定位、是否支持当前 claim、仍需人工检查的地方。
不能确认的项目标记为 unverified，不要用相似论文替代。
```

**预期产物**：引用检查表、来源/定位信息、支持关系和阻断或警告项。

**人工检查**：ARS 的“存在性”检查不等于“主张被原文支持”。必须区分：文献真实存在、文献讨论了该主题、文献真正支持你的这句话。

### 5.4 论文写作

```text
请使用 ARS academic-paper 的 plan 模式。
输入：question.md、materials/、results/
目标：先产出 IMRaD 论文蓝图、章节职责、claim-evidence 表和缺失证据清单。
约束：不要补写不存在的实验结果，不要在我确认蓝图前生成完整正文。
```

确认蓝图后再写：

```text
继续使用 ARS academic-paper。
只撰写 Introduction 初稿。
每个主要 claim 后保留引用占位和证据状态；不增加输入材料中不存在的定量结论。
输出段落、论证链和待我确认的句子。
```

### 5.5 同行评审

```text
/ars-reviewer manuscript.md
```

推荐加约束：

```text
请从方法、贡献、相关工作、统计报告、引用完整性和期刊适配六个角度评审。
只根据稿件、附录和我提供的材料判断；证据不足时写“无法从材料判断”。
输出：主要问题、次要问题、必须修改项、可选修改项和编辑决定信草稿。
不要把猜测写成事实。
```

**预期产物**：多角色 reviewer reports、优先级、修改路线和决定信。

**人工检查**：确认每条意见指向稿件中的具体段落/表格，并区分真正的科学问题与风格偏好；审稿模拟不是目标期刊的真实决定。

### 5.6 端到端 pipeline

只有当问题、材料、实验状态和权限都清楚时才使用：

```text
/ars-full

目标：从现有 question.md、materials/ 和 results/ 开始推进论文。
请每完成一个阶段就停下，展示阶段产物和阻塞项，等待确认后再进入下一阶段。
```

更安全的方式是：

```text
请使用 ARS academic-pipeline，从 Stage 0 intake 开始。
本轮只完成 intake、材料清单和 pipeline dashboard，完成后停止。
```

## 6. 结果核查与输出审查

### 引用和证据

- [ ] 每条引用都能回到真实来源。
- [ ] DOI、作者、年份、期刊和页码未被改写或编造。
- [ ] 引用存在性与 claim-faithfulness 分开检查。
- [ ] 未验证来源保持 `unverified`，没有被格式化成确定事实。

### 方法和结果

- [ ] 方法描述与真实代码/协议一致。
- [ ] 结果数字来自实验日志、表格或用户确认材料。
- [ ] 图表、统计量、样本量、单位和显著性标记一致。
- [ ] 任何外部完成的实验都记录 provenance；ARS 不证明实验真的被执行。

### 文字和流程

- [ ] 没有把建议写成已完成工作。
- [ ] 没有把相关关系、预测能力或机制假设升级成因果结论。
- [ ] 每个阶段的人工确认点都已经处理。
- [ ] 最终稿经过人类作者逐段审阅。

## 7. 失败处理

| 现象 | 处理 |
|---|---|
| Skill 没有触发 | 明确写 `/ars-*` 命令或“请使用 ARS 的某模式”，确认插件已 reload。 |
| 找不到论文 | 保留未找到状态，检查标题、作者、年份和 DOI 格式；不要用相似论文替代。 |
| 只做了存在性检查 | 继续要求 claim–source 对齐和原文定位，必要时手动打开论文。 |
| 输出了不存在的数据 | 停止传播，回到原始结果/日志并标记错误；不要通过润色掩盖。 |
| Windows hook 报错 | 确认 Git Bash 和真实 Python；核心流程可先不启用可选 guard。 |
| 端到端流程过重 | 改为单阶段运行，例如先 intake 或只做 citation-check。 |

## 8. 与其他 skill 的衔接

- **Claude Scholar**：负责 Zotero/Obsidian 文献库和结构化笔记，ARS 负责研究流程与证据门禁。
- **Scientific Agent Skills**：负责真实科学计算、数据库和分析代码，ARS 负责研究问题、论文和完整性审查。
- **PaperSpine**：负责贡献优先、投稿和审稿轨迹；ARS 可提供引用/证据核验。
- **ARIS**：可长时间执行任务，但夜间产物必须回到 ARS 做证据和引用复核。

## 9. 已知边界

ARS 检查的是报告出来的过程、引用、claim-source 关系、方法描述、实验 provenance 和图表/包的一致性；它不证明原始数据真实、不证明实验实际发生，也不保证结果可复现。任何“引用验证通过”“审稿通过”都应理解为一个有范围的检查结果，而不是学术真理或投稿承诺。
