# 详细使用指南

> 版本说明（2026-10-19）：源码已更新；正文保留此前整理的指南，功能与安装入口以当前上游 README 为准。见[本次更新记录](../../../UPDATE-2026-10-19.md)。

## 1. 先确定具体 skill

不要把仓库名当成单一总入口。先把任务拆成一个可验证目标，再从 `skills/scientific-agent-skills/skills/` 选择具体目录，例如：

- 文献或数据库信息：`paper-lookup`、`database-lookup`；
- 单细胞分析：`scanpy`；
- 分子/药物任务：查看 RDKit 或 drug-discovery 相关目录；
- 写作和报告：查看 scientific-writing、clinical-reports 等目录。

如果任务跨多个领域，先分别读取相关 `SKILL.md`，明确每个阶段的输入输出，不要一次授权整仓库写入。

## 2. 准备输入契约

```text
project/
  question.md          # 研究问题与停止条件
  data/
    matrix.h5ad
    sample-metadata.csv
  references/          # 论文、数据库记录或 accession
  results/              # 只放允许读取的既有结果
  output/               # Agent 唯一写入位置
  constraints.md       # 环境、隐私、联网和输出格式
```

`constraints.md` 应说明是否允许联网、是否可以执行 Python/Java/R/Nextflow、是否允许访问 API key，以及哪些文件不可覆盖。

## 3. 文献或数据库检索

先读取对应入口：

```text
请先读取 skills/scientific-agent-skills/skills/paper-lookup/SKILL.md。
根据 project/question.md 查询指定主题，只使用允许的来源。
把检索式、时间、来源 URL/标识符、筛选理由和未验证项写入 project/output/search-log.md。
不要把搜索摘要直接当成论文事实，不修改 references/。
```

检查重复条目、版本、DOI/accession 和原文定位，再把合格材料交给后续分析。

## 4. 数据分析

以 Scanpy 为例：

```text
请读取 skills/scientific-agent-skills/skills/scanpy/SKILL.md。
只读取 project/data/，先检查矩阵、元数据、样本数和缺失值。
先输出 project/output/data-audit.md，再按约定生成 project/output/analysis.ipynb、图和日志。
不要删除或覆盖原始数据；缺少基因注释、批次信息或单位时停止并列出缺失项。
```

分析应分成数据审计、预处理、主分析、敏感性分析和解释五步，每步保存参数、软件版本、随机种子和输入摘要。

## 5. 科学报告

要求报告同时给出方法、实际参数、样本/排除数量、失败运行、图表来源和局限。任何“显著”“改善”“因果”措辞都要与统计设计相匹配；Agent 生成的生物学解释需要研究者和原始文献复核。

## 6. 人工检查点

- 检查输入文件是否属于同一实验批次和单位体系；
- 检查脚本是否改变过滤阈值、随机种子或分组定义；
- 对关键图表从原始结果重算或抽样复核；
- 记录环境版本和错误日志；
- 先在小样本/副本上运行，再扩大范围；
- 不把成功生成文件等同于科学结论成立。
