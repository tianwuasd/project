# Scientific Agent Skills 详细使用文档

> 版本说明（2026-10-19）：源码已更新；正文保留此前整理的指南，功能与安装入口以当前上游 README 为准。见[本次更新记录](../../../UPDATE-2026-10-19.md)。

## 0. 文档范围

本指南对应 [K-Dense-AI/scientific-agent-skills](https://github.com/K-Dense-AI/scientific-agent-skills)。它是一个遵循 Agent Skills 标准的科学计算与科研工作流集合，不是单一的生物信息学程序或统一分析平台。

- **本地源码**：[`skills/scientific-agent-skills`](../../../skills/scientific-agent-skills/)
- **README 当前标注**：163 个 skill、100+ 数据库、70+ Python 包技能；数字随上游更新变化
- **文章评价**：两篇知乎文章均评为“夯”；这是体验性评价，不是逐项独立验证

## 1. 适合什么任务

Scientific Agent Skills 让 Agent 在专业科学库、数据库和实验平台上工作时有更具体的文档、示例和边界。主要方向包括：

- 生物信息学与基因组学：序列、单细胞、基因调控、变异和系统发育；
- 化学信息学与药物发现：RDKit、分子性质、虚拟筛选、ADMET、对接和先导优化；
- 蛋白质组学、质谱和多组学；
- 医学影像、数字病理、临床研究和 PK/PD 建模；
- 机器学习、强化学习、时间序列、贝叶斯分析和科学 ML；
- 材料、物理、天文、工程仿真、地理空间与遥感；
- 实验自动化、LIMS/Benchling/Opentrons 等平台；
- 科学写作、文献检索、同行评审、PPT/海报/示意图。

## 2. 前置条件

### 通用

- 一个支持 Agent Skills 标准的宿主，例如 Claude Code、Codex、Cursor 或其他兼容客户端；
- Git 或 `npx skills`；
- 根据目标 skill 安装相应 Python 包、命令行程序和数据访问凭据。

### 可能需要的资源

| 任务类型 | 典型依赖 |
|---|---|
| 单细胞/基因组 | Scanpy、Biopython、gget、AnnData、NCBI/CellxGene 等数据源 |
| 化学/药物 | RDKit、DeepChem、PyTDC、PubChem/ChEMBL |
| 图像/病理 | pydicom、PathML、DICOM 或切片数据 |
| 地理空间 | GeoPandas、栅格/矢量数据、坐标系定义 |
| 实验平台 | 平台账号、API key、组织权限和设备状态 |
| 科学写作 | 原始论文、数据字典、实验日志、目标期刊要求 |

## 3. 安装

### 3.1 标准安装

```bash
npx skills add K-Dense-AI/scientific-agent-skills
```

这是常用的标准化安装方式。安装前先确认当前 CLI 将 skill 放到哪个目录，以及是否执行全量或项目级安装。

### 3.2 只安装某个 skill

如果只要 Scanpy：

```bash
npx skills add K-Dense-AI/scientific-agent-skills scanpy
```

使用其他 Agent 宿主时可以显式指定：

```bash
npx skills add K-Dense-AI/scientific-agent-skills --agent claude-code
npx skills add K-Dense-AI/scientific-agent-skills --agent codex
npx skills add K-Dense-AI/scientific-agent-skills --agent cursor
```

### 3.3 版本固定

为可复现研究固定 tag 或 commit：

```bash
npx skills add K-Dense-AI/scientific-agent-skills --pin v2.64.0
# 或按仓库说明使用具体 commit SHA
```

如果当前 `npx skills` 版本不支持某个参数，按本地 CLI 的 `--help` 和仓库 README 调整；不要把示例命令当成所有宿主的永久接口。

### 3.4 Git/插件安装

作为本地插件或 skill 目录使用：

```bash
git clone https://github.com/K-Dense-AI/scientific-agent-skills.git
```

然后按宿主要求把整个插件或目标 `skills/<skill-name>` 放入配置的 skill 搜索目录。不要默认把仓库根目录当成一个单独的科学 skill。

## 4. 输入准备

每个科学任务都建议准备一个明确的数据包：

```text
project/
  data_raw/              # 原始数据，只读保存
  data_processed/        # 可重建的处理结果
  metadata/              # 数据字典、样本说明、单位和版本
  scripts/               # 清洗、分析、绘图脚本
  results/               # 表格、图、统计输出和日志
  environment.yml        # 环境与版本
  question.md            # 研究问题、假设和限制
```

提示词中写清楚：

- 样本、单位、坐标系、实验条件和数据版本；
- 允许读写的目录；
- 目标分析、预期指标、基线和统计假设；
- 是否允许联网、数据库 API、远程平台和包安装；
- 结果要生成脚本、表格、图、报告还是下一步建议。

## 5. 典型使用示例

### 5.1 单细胞数据分析

```text
请使用 Scanpy 相关 scientific skill 分析 data_raw/pbmc.h5ad。
先读取 metadata/schema，检查样本、缺失值、批次和基因命名。
本轮只完成 QC 计划和可复现脚本草稿，不修改原始文件、不生成最终生物学结论。
列出每个阈值的依据和需要我确认的假设。
```

**预期产物**：QC 检查清单、脚本草稿、环境/版本要求和待确认假设。

**暂停检查**：确认细胞过滤阈值、批次设计、物种/基因标识、归一化策略和统计单位，不要把聚类标签直接解释成生物学亚型。

### 5.2 化学结构与性质

```text
请用 RDKit skill 读取 data_raw/compounds.csv。
检查 SMILES 合法性、重复结构、盐形式和单位；输出清洗报告和失败行。
然后只对通过检查的结构计算指定性质，并保存可复现脚本。
不要根据预测性质声称药效或临床安全性。
```

**预期产物**：结构清洗日志、性质表、失败样本列表、版本信息和脚本。

**暂停检查**：核对 SMILES、立体化学、盐/溶剂处理、单位、描述符定义和包版本。

### 5.3 科学数据库查询

```text
请从指定的权威数据库检索与 [实体/基因/药物] 相关的记录。
输出数据库名、查询条件、访问时间、记录 ID、原始 URL 和字段含义。
只使用这些来源，不要把模型记忆补成数据库结果。
```

**预期产物**：带 provenance 的查询表、原始记录标识和未命中/冲突记录。

**暂停检查**：确认 API 返回的是当前版本，核对分页、筛选条件、物种、单位和许可；重要结果回到数据库页面复查。

### 5.4 统计与出版级图表

```text
请分析 results/runs.csv，比较预先定义的组别和指标。
先检查数据结构、重复测量、缺失值和统计假设，再选择分析方法。
输出分析脚本、统计表、图表源文件和一份区分“结果/解释/限制”的报告。
不能把显著性直接写成机制或因果证明。
```

**预期产物**：可运行脚本、统计表、图源文件、结果报告和限制清单。

**暂停检查**：核对样本数、独立性、效应量、置信区间、多重比较、图例、单位和原始数据映射。

### 5.5 实验平台或外部 API

```text
请先列出执行这个 Benchling/Opentrons/API 任务所需的权限、网络、凭据和副作用。
只生成 dry-run 计划和请求参数，不实际提交或启动实验。
等我确认后再执行，并保存返回 ID、时间戳、版本和原始响应。
```

任何会改变远程数据、启动设备、产生费用或上传敏感数据的操作，都先停在 dry-run。

## 6. 结果核查

### 可复现性

- [ ] 原始数据只读保存，处理结果可由脚本重建。
- [ ] 记录 Python、包、模型、数据库、代码 commit 和硬件环境。
- [ ] 保存参数、随机种子、失败运行、警告和完整日志。
- [ ] 对关键指标用独立脚本或抽样手算复核。

### 科学有效性

- [ ] 数据字典、单位、物种、样本量和批次设计正确。
- [ ] 方法与数据结构匹配，统计假设已经检查。
- [ ] Agent 没有把相关性、预测或模型输出升级成因果或临床结论。
- [ ] 图表每个数字、颜色、标签、坐标轴、误差线和来源都可追溯。

### 数据访问

- [ ] 数据库查询保存了时间、条件、记录 ID 和原始链接。
- [ ] API key、个人数据、患者数据和受限数据未被写入日志或上传到不必要的服务。
- [ ] 外部平台、数据集和软件许可证允许当前用途。

## 7. 失败与风险处理

| 现象 | 处理 |
|---|---|
| 包安装失败 | 记录 Python/OS/CUDA 版本，按目标 skill 的依赖说明逐项解决，不要静默换版本。 |
| 数据库无结果 | 检查 ID、物种、分页、过滤和 API 限制；保持未命中，不让 Agent 猜记录。 |
| 结果与论文不一致 | 回到原始数据、脚本、参数和日志，区分代码错误、数据错误和解释错误。 |
| 临床/实验平台建议过度 | 将输出限定为研究分析或证据准备，交由合资格人员作决定。 |
| skill 请求联网/执行脚本 | 先审查 `SKILL.md` 和脚本，再确认域名、凭据、读写目录和副作用。 |
| 全量 skill 上下文过大 | 按领域或单包安装，减少会话噪声和错误路由。 |

## 8. 与其他 skill 的衔接

- **Claude Scholar**：管理论文、Zotero、Obsidian 和研究记忆；本 skill 执行专业计算。
- **ARS / ARS-Codex**：定义研究问题、证据和论文审查边界。
- **AI Research Skills**：专注深度学习模型训练、后训练、推理和评测工程。
- **Auto-Empirical**：专注社科计量和实证流水线。
- **Paper Craft / Nature Skills**：把已核验的数据和结果转成图解、图表、英文图注或汇报材料。

## 9. 安全边界

仓库明确提醒：skill 可以执行代码、安装包、联网和修改文件。K-Dense 的安全扫描和测试是有价值的信号，但不是对每个版本、每个社区贡献和每种运行环境的绝对保证。安装前应阅读目标 `SKILL.md`、脚本、外部服务和许可证，按最小权限运行并自行复核结果。
