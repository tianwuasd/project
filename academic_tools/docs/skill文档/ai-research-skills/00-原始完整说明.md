# AI Research Skills（Orchestra Research）详细使用文档

> 版本说明（2026-10-19）：源码已更新；正文保留此前整理的指南，功能与安装入口以当前上游 README 为准。见[本次更新记录](../../../UPDATE-2026-10-19.md)。

## 0. 文档范围

本指南对应 [Orchestra-Research/AI-Research-SKILLs](https://github.com/Orchestra-Research/AI-Research-SKILLs)。它服务于 AI/ML 研究工程，不等同于泛化的“AI 帮我做研究”提示词集合。

- **本地源码**：[`skills/AI-Research-SKILLs`](../../../skills/AI-Research-SKILLs/)
- **README 当前标注**：98 个 skill、23 个类别
- **文章评价**：第二篇知乎文章评为“顶级”；这是文章作者的体验性评价

## 1. 能解决什么问题

仓库将 AI 研究拆成两层：

1. **研究编排层**：autoresearch、ideation、ML paper writing 和 agent-native research artifact，负责从问题/文献走向实验和论文。
2. **工程技能层**：模型架构、tokenization、微调、后训练、分布式训练、优化、评测、推理、RAG、MLOps、multimodal 和 mechanistic interpretability。

主要类别包括：

- Model Architecture：LitGPT、Mamba、RWKV、NanoGPT、TorchTitan；
- Fine-Tuning：Axolotl、LLaMA-Factory、PEFT、Unsloth；
- Post-Training：TRL、GRPO、OpenRLHF、SimPO、verl、slime；
- Distributed/Optimization：Megatron-Core、DeepSpeed、FSDP2、Accelerate、Flash Attention、bitsandbytes、GPTQ、AWQ、HQQ、GGUF；
- Evaluation/Inference：lm-evaluation-harness、BigCode、NeMo Evaluator、vLLM、TensorRT-LLM、llama.cpp、SGLang；
- Agents/RAG/Prompt：LangChain、LlamaIndex、CrewAI、AutoGPT、Chroma、FAISS、Qdrant、DSPy、Instructor、Guidance、Outlines；
- Multimodal、安全、可观测性、MLOps、机械可解释性和新兴方法。

## 2. 前置条件

- 支持 Agent Skills 的宿主和 Node.js/npm；
- Python、PyTorch、CUDA/ROCm、GPU 驱动或远程计算资源（取决于目标 skill）；
- 数据集、模型权重、训练/评测脚本和硬件约束；
- W&B、MLflow、Hugging Face、云 GPU 或数据库等外部服务时，需要单独配置账号和权限。

开始前先确认：

```text
研究目标：比较两种微调方法在同一数据集上的性能
模型：GPT-2 small
数据规模：……
硬件：单张 24GB GPU
预算/时限：……
允许的网络和写入目录：……
评测指标与基线：……
```

## 4. 输入准备

针对 AI/ML 实验，建议把以下内容放在项目中：

```text
project/
  research_question.md       # 研究问题、假设、贡献候选
  data_card.md               # 数据来源、许可、切分、统计
  model_card.md              # 模型、权重、许可证、限制
  configs/                   # 训练/评测配置
  scripts/                   # 数据、训练、推理、评测脚本
  baselines/                 # 基线定义和运行方式
  runs/                      # 每次运行配置、日志和指标
  reports/                   # 表格、图和实验报告
  environment.yml            # 软件/硬件环境
```

给 Agent 的任务应限制为一个可验收的阶段：数据检查、配置草案、单个实验、评测、消融或论文表格，不要直接要求“自主完成全部研究”。

## 5. 典型使用示例

### 5.1 微调策略规划

```text
请使用 fine-tuning 相关 skill，为 GPT-2 small 设计一个可运行的微调实验计划。
约束：单张 24GB GPU，训练数据 50k 条，目标是比较 LoRA 与全量微调。
先输出：数据格式检查、显存估算、超参数范围、评测指标、基线和失败条件。
不要安装包、下载权重或启动训练。
```

**预期产物**：硬件约束下的配置草案、数据/模型要求、评测计划和风险。

**检查点**：核对模型许可、序列长度、batch/gradient accumulation、显存估算、训练步数、数据泄漏和验证集设计。

### 5.2 执行一个可复现训练 run

```text
根据已确认的 configs/lora.yaml 执行一次训练。
只读 data_processed/，只写 runs/exp-001/。
运行前展示最终命令、依赖版本和预计成本；运行后保存 stdout、stderr、配置、commit、随机种子和指标。
如果资源不足或脚本报错，停止并报告，不要自动换模型或修改实验目标。
```

**预期产物**：运行目录、日志、配置快照、checkpoint 标识、指标和失败信息。

**检查点**：确认输出目录正确，训练参数与计划一致，日志没有泄漏密钥，指标来自评测脚本而不是模型自述。

### 5.3 评测与消融

```text
请使用 evaluation skill 比较 baseline、lora 和 full-ft 三个 checkpoint。
使用同一个冻结测试集和同一评测脚本，保存原始预测、聚合指标和错误样例。
先检查标签、数据切分、评测指标和长度截断，再运行评测。
输出只包括结果、统计不确定性和可复查的限制，不下“方法更好”的最终结论。
```

**预期产物**：统一评测表、预测文件、错误分析、脚本和环境信息。

**检查点**：核对 checkpoint、测试集 hash、指标实现、prompt/template、随机性、置信区间和多重比较。

### 5.4 RAG/Agent 实验

```text
请用 RAG 相关 skill 设计一个检索增强生成对照实验。
比较 no-retrieval、BM25 和向量检索；冻结模型、问题集和回答评分规则。
输出数据流、索引构建、检索 top-k、评测 rubric 和消融矩阵。
先给设计和风险，等待确认后再建立索引或调用外部服务。
```

**预期产物**：数据流图、对照组、检索参数、评测标准和运行计划。

**检查点**：检查索引是否含测试集泄漏、文档版本、embedding 模型、top-k、引用/来源呈现和人工评分一致性。

### 5.5 评测结果转论文材料

```text
请根据 reports/evaluation.csv、runs/ 和 research_question.md，
生成 Results 表格草稿、图表规范和 claim-evidence 矩阵。
所有数字必须来自文件；缺失基线、未完成实验和不确定性要显式列出。
不要生成“state of the art”或因果结论。
```

## 6. autoresearch 使用方式

`autoresearch` 是编排层，不是“无限自动改代码”的许可。建议采用小循环：

```text
请使用 autoresearch 设计一个受限实验循环。
目标：在固定数据、预算和评测脚本下比较两个优化策略。
每轮只允许修改 configs/ 和指定训练脚本，必须保留 diff、运行日志和指标。
预算：最多 5 轮，每轮完成后报告假设、变化、结果和下一轮建议；不要自动扩大搜索空间。
```

每轮人工检查：

1. 修改是否仍服务原研究问题；
2. 是否偷偷改变数据、测试集或评测脚本；
3. 指标变化是否超过噪声和运行方差；
4. 是否出现过拟合 benchmark、泄漏或把 bug 当成发现。

## 7. 结果核查

### 实验可复现性

- [ ] 数据、代码、模型、依赖、硬件、commit 和配置已记录。
- [ ] 训练/评测命令、随机种子、checkpoint 和失败运行已保存。
- [ ] 基线和对照组使用一致的数据、指标和评测脚本。
- [ ] 关键数字可以从原始日志或脚本重新得到。

### 研究有效性

- [ ] 研究问题、假设和实验变量没有被 Agent 擅自改写。
- [ ] 结论区分观察到的指标、解释、局限和待验证假设。
- [ ] 消融、统计不确定性和失败结果没有被隐藏。
- [ ] 论文 claim 与真实实验结果一一对应。

### 工程安全

- [ ] 训练/评测脚本没有把 API key、用户数据或私有路径写入日志。
- [ ] 包、模型、数据集和远程服务许可证允许当前用途。
- [ ] Agent 只写入批准目录，不覆盖原始数据或既有基线。
- [ ] 下载模型、启动云资源或外部 API 前已确认成本和权限。

## 8. 失败与风险处理

| 现象 | 处理 |
|---|---|
| 依赖冲突 | 保存环境版本，按目标 skill 的官方来源解决；不要静默降级或换框架。 |
| GPU/显存不足 | 先报告实际资源，再由研究者确认 batch、模型或精度变化。 |
| 指标突然提升 | 检查数据泄漏、测试集污染、评测脚本、prompt 和 checkpoint，而不是立即宣布发现。 |
| autoresearch 越界改动 | 停止循环，审查 diff 和运行清单，从最近一个可信版本恢复。 |
| 外部服务不可用 | 标记实验未完成，不用模型记忆或合成数字补齐结果。 |
| 生成了论文结论 | 退回到结果表和证据矩阵，由研究者确认 claim 强度。 |

## 9. 与其他 skill 的衔接

- **Claude Scholar**：管理论文、项目知识和实验记录；本 skill 负责 AI/ML 工程细节。
- **ARS / ARS-Codex**：负责研究问题、证据和论文审查，避免“工程跑通”被误当作研究成立。
- **Scientific Agent Skills**：处理跨学科科学数据、数据库和专业 Python 包。
- **PaperSpine / Research Paper Writing Skills**：把经过核验的实验结果转为贡献、章节和审稿回复。
- **Paper Craft / Nature Skills**：把真实结果做成方法图、图表、图注和汇报材料。

## 10. 版本和安全边界

该仓库覆盖范围很广，安装前不要一次性加载全部 skill。README 提供的 skill 数量、类别和示例会随版本变化；每个具体 skill 的依赖、脚本和外部连接应单独审查。Agent 可以生成训练代码和配置，但不能替代实验设计、统计判断、数据许可审查或论文作者责任。
