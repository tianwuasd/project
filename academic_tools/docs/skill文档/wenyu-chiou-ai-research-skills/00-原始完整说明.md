# WenyuChiou AI Research Skills 详细使用文档

> 版本说明（2026-10-19）：源码已更新；正文保留此前整理的指南，功能与安装入口以当前上游 README 为准。见[本次更新记录](../../../UPDATE-2026-10-19.md)。

## 0. 文档范围

本指南对应 [WenyuChiou/ai-research-skills](https://github.com/WenyuChiou/ai-research-skills)。它是围绕“研究缺口是否值得做”的 skill catalog 和插件集合，重点是研究状态、证据边界、阶段门禁以及 Claude/Codex/Gemini 等工具之间的交接。

- **本地源码**：[`skills/WenyuChiou-ai-research-skills`](../../../skills/WenyuChiou-ai-research-skills/)
- **README 当前标注**：17 个 skill、5 个插件
- **文章评价**：第一篇文章介绍该项目，但未分档；第二篇文章未重点测评
- **核心原则**：先通过 open、contribution、feasibility 三道门，再让文献、设计、实验、写作和投稿继续流转

## 1. 能解决什么问题

项目针对五类常见问题：

1. **跨会话失忆**：通过 `.research/`、`.paper/`、manifest 和 YAML 产物保存研究上下文。
2. **虚构引用**：用 Evidence Records、claim 状态和反泄漏 schema，缺证据的 claim 不能标记为 supported。
3. **模糊 gap 分析**：用候选选题 dossier 追问 gap 是否仍开放、是否构成贡献、是否在时间内可完成。
4. **AI 味和论证漂移**：通过 claim 状态、写作 skill 和 reviewer workflow 控制表达强度。
5. **跨 AI 工具交接损耗**：按机械工作、长上下文工作和判断/治理工作选择 Codex、Gemini、Claude，并写入 coordination 文件。

## 2. 前置条件

### 纯 skill 使用

- Claude Code、Codex CLI、Cursor、Windsurf、Gemini CLI、Hermes、OpenClaw 或能读取 `SKILL.md` 的客户端；
- 项目目录有研究问题、论文、数据说明、实验记录和写作材料；
- Git（如果希望 manifest、schema 和阶段产物进入版本控制）。

### 需要 runtime 的功能

仓库把 skill catalog 与可执行的 `research-hub` runtime 分开。文献自动化和某些批量流程可能需要：

- Python/pip；
- `research-hub-pipeline`；
- Zotero、Codex、Gemini CLI 或外部文献 API；
- 网络、密钥和可写的研究工作区。

不要把“有一个 SKILL.md”理解为运行时和外部服务已经配置完成。

## 3. 安装

### 3.1 Claude Code 最快路径

```bash
claude plugin marketplace add WenyuChiou/ai-research-skills
claude plugin install research-workspace@ai-research-skills
```

这会安装核心 `research-workspace` 插件。按需要追加：

```bash
claude plugin install academic-writing-skills@ai-research-skills
claude plugin install zotero-skills@ai-research-skills
claude plugin install codex-delegate@ai-research-skills
claude plugin install gemini-delegate@ai-research-skills
```

验证：

```bash
claude plugin list
```

### 3.2 Python 文献流水线（可选）

```bash
pip install research-hub-pipeline
research-hub setup --persona researcher
research-hub doctor
research-hub auto "agent-based modeling" --max-papers 3 --no-nlm
```

运行前先查看 `docs/runtime-contract.md`，确认哪些功能会联网、写入文件或调用外部服务。

### 3.3 直接克隆与其他宿主

```bash
git clone https://github.com/WenyuChiou/ai-research-skills.git
```

Codex、Cursor、Windsurf、Gemini、Hermes、OpenClaw 或通用 API 客户端可以按 `docs/install.md` 加载原始 `SKILL.md`。仓库本身是 registry；各插件的源仓库分开维护，需要修改某个插件时应进入对应源仓库，而不是假设本目录是全部实现的 monorepo。

## 4. 输入准备

建议使用可提交、可审计的项目结构：

```text
project/
  .research/
    project_manifest.yml
    topic_dossier.gaps.yml
    evidence_records.yml
  .paper/
    claims.yml
    outline.md
  Sources/Papers/             # 原始论文和阅读笔记
  Knowledge/                  # 经过确认的长期知识
  Experiments/                # 运行记录、配置、失败和结果
  Writing/                    # 稿件和审稿回复
  question.md
  constraints.md
```

每个候选题目至少准备：

- 已知问题和研究范围；
- 初步 gap 及其文献来源；
- 预期贡献，不要只写“做一个系统”；
- 数据、时间、硬件、技能和伦理约束；
- 允许联网、委托和写入的范围。

## 5. 典型使用示例

### 5.1 研究缺口与选题 gate

```text
请使用 WenyuChiou research-workspace。
主题：生成式 AI 在高校质量保障中的应用。
我有 12 篇论文和一份初步笔记。
请先建立候选 topic dossier，分别回答：gap 是否仍开放、关闭它是否构成贡献、
我能否在 6 个月内完成。输出证据、反例和需要我确认的 gate；不要写论文大纲。
```

**预期产物**：topic dossier、gap 来源、open/contribution/feasibility 判定理由和下一步。

**检查点**：确认“没找到论文”不等于“没有相关工作”，确认可行性依据来自真实数据/资源和时间约束。

### 5.2 文献发现与筛选

```text
请使用 research-hub 和 literature-triage-matrix。
目标：整理与 [主题] 相关的论文。
输出：检索条件、纳入/排除标准、每篇论文的 Key Findings、方法差异、研究缺口和来源。
每条结论记录 DOI/URL/原文定位；不能核验的条目标为 unverified。
本轮不生成最终综述。
```

**预期产物**：`.bib`、逐篇笔记、筛选矩阵和候选 gap dossier。

**检查点**：核对元数据、预印本/正式版本、去重、检索边界和排除理由。

### 5.3 研究设计和项目 manifest

```text
请根据已经通过三道 gate 的 topic_dossier.gaps.yml，
生成 design_brief.md 和 project_manifest.yml。
每个设计决定注明来源、gap_verdict、假设、数据需求、识别策略、风险和下一步。
不要把尚未批准的 topic 或推测写成确定贡献。
```

**检查点**：manifest 的 `provenance.from_gap` 是否指向正确 dossier，研究问题和设计是否一致。

### 5.4 跨 AI 委托

```text
请为当前研究阶段生成 delegation brief：
机械任务交给 Codex，长文献综合交给 Gemini，研究判断保留在当前 Claude 会话。
每个 brief 只包含完成任务所需的材料、来源、输出 schema 和禁止事项。
先生成 coordination 文件，不实际调用外部 CLI。
```

确认后：

```text
按 coordination 文件执行一次委托。
只写指定的 output/ 目录，保存输入摘要、工具/模型、时间、返回结果、失败信息和人工决定。
不要把委托结果直接提升为 supported claim。
```

### 5.5 论文 claim 与证据

```text
请使用 academic-writing-skills 和 paper-memory-builder。
读取 .paper/claims.yml、Sources/Papers/、Knowledge/ 和 Experiments/。
为每条 claim 输出 status、evidence_artifacts、来源定位、证据强度和建议措辞。
如果 evidence_artifacts 为空，保持 status: gap 并写 gap_reason，不要标记 supported。
```

### 5.6 从实验到投稿

```text
请读取 project_manifest.yml、Experiments/、.paper/claims.yml 和 reviewer_comments.md。
按“分析 → 结果报告 → 稿件 → 审稿回复”顺序推进，每个阶段完成后停止。
保存版本化产物和 provenance；未经确认不新增实验、引用、结论或投稿承诺。
```

## 6. 阶段交接规则

典型八阶段及其交接产物：

| 阶段 | 主要 skill | 交给下一阶段 |
|---|---|---|
| 1. Discover literature | `research-hub`、`paper-summarize` | `.bib` 和逐篇 Key Findings |
| 2. Find the gap | `gap-to-topic`、`literature-triage-matrix`、Zotero curator | `topic_dossier.gaps.yml` |
| 3a. Frame the RQ | `research-design-helper` | `design_brief.md` |
| 3b. Plan the project | context compressor、project orienter | `project_manifest.yml` |
| 4. Build model | Codex delegate 或 Claude | 项目代码和变更记录 |
| 5. Run & validate | context compressor、project orienter | `.research/` run manifests |
| 6. Visualise & interpret | Codex/Gemini delegate | 图表、脚本和分析记录 |
| 7. Draft manuscript | paper memory、academic writing | `.paper/claims.yml` |
| 8. Submit/respond | academic writing、context compressor | 投稿稿件和 reviewer-response |

跨阶段交接使用 schema 和字段，不用“模型应该知道前文”这种隐含约定。

## 7. 结果核查

### Gate 与证据

- [ ] topic dossier 记录 open、contribution、feasibility 三道门的理由和证据。
- [ ] gap 的“未发现”与“已证明不存在”被明确区分。
- [ ] claim 的证据文件、来源定位、状态和强度完整。
- [ ] 没有证据的 claim 保持 gap，并写出 gap_reason。

### 项目连续性

- [ ] manifest、run、paper 和 delegation 产物已版本化。
- [ ] 每个阶段的输入、输出、工具、模型和人工决定可追溯。
- [ ] 新会话能从 `.research/` 和 `.paper/` 恢复，而不依赖聊天历史。
- [ ] 跨 AI 委托只传输必要材料，返回结果经过人工接收和复核。

### 学术正确性

- [ ] 引用、数据、实验、代码和图表回到原始来源。
- [ ] 研究设计与实际执行没有被混为一谈。
- [ ] 结果报告没有扩大为因果、机制或普遍结论。
- [ ] 投稿和回复中的承诺都有真实修改或已完成结果。

## 8. 失败与风险处理

| 现象 | 处理 |
|---|---|
| Gap 分析过于笼统 | 回到论文级证据和反例，要求列出具体未解决问题。 |
| manifest 状态冲突 | 以版本化的原始产物和来源字段为准，暂停 downstream 写作。 |
| claim 没有证据 | 保持 gap，补证据或降低措辞，不直接发布。 |
| 跨工具交接丢失上下文 | 缩小 brief，补 provenance、schema 和输出契约，而不是复制整段聊天。 |
| Zotero/研究 runtime 未配置 | 先运行 doctor 或手动准备输入，不能把空结果当成无文献。 |
| 自动写作越过 gate | 删除未批准的 downstream 产物，回到最近一个通过的阶段。 |
| OpenClaw/Hermes 等未验证支持 | 仅按仓库明确支持的 raw `SKILL.md` 方式试用，保留兼容性不确定性。 |

## 9. 与其他 skill 的衔接

- **Claude Scholar**：管理 Zotero、Obsidian 和论文笔记；Wenyu 版本负责 gap、manifest 和阶段交接。
- **ARS/ARS-Codex**：负责深度研究、引用/证据门禁和审稿流程。
- **Scientific Agent Skills / AI Research Skills / AERS**：执行专业科学、AI/ML 或社科实证任务。
- **PaperSpine**：把通过 gate 的贡献、结果和 claim 组织成最终论文。
- **ARIS**：可以承接长时间执行，但其产物应回到 manifest、evidence 和人工 gate。

## 10. 责任边界

Manifest、schema 和 gate 能让研究状态更清晰、让无证据产物更难混入下游，但不能自动证明 gap、数据、实验或结论正确。研究者仍需确认研究问题、贡献、方法、结果和投稿决定。
