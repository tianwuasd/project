# 源码结构与构建

> 版本说明（2026-10-19）：源码已更新；正文保留此前整理的指南，功能与安装入口以当前上游 README 为准。见[本次更新记录](../../../UPDATE-2026-10-19.md)。

## 1. 顶层结构

Claude Scholar 的核心目录包括：

```text
skills/claude-scholar/
  skills/                 # 研究、写作、分析、项目和工程 skill
  commands/               # Claude Code 命令入口
  agents/                 # paper miner 等角色配置
  hooks/                  # session/security/write guard 等钩子
  rules/                  # coding、agents 等规则
  scripts/                # setup、uninstall 和辅助脚本
  docs/                   # Zotero、Obsidian、MCP、安装和工作流说明
  CLAUDE.md               # Claude Code 项目约束
  settings.json.template  # 可选配置模板
  README.md
```

实际 skill 目录以当前分支为准；主分支是 Claude Code workflow，Codex/Kimi/OpenCode 版本通过独立分支维护。

## 2. 加载关系

1. 安装器或插件加载 `skills/` 下的 skill；
2. commands 将自然语言/命令路由到具体 skill；
3. agents 提供角色提示，hooks 在会话/写入等时机提供保护；
4. rules 是需要人工合并的宿主规则，不由插件自动代替用户配置；
5. Zotero MCP、Obsidian vault 和可选 Python 工具为外部运行层；
6. reports、notes 和 knowledge 文件成为后续阶段的输入。

## 3. 构建和安装方式

Claude Scholar 没有把研究 skill 编译成单一二进制的传统构建步骤。其“构建”分为：

- Markdown `SKILL.md`、references 和模板的宿主发现；
- `setup.sh` 按 manifest 增量复制、备份和配置 hooks/skills/agents；
- 插件 manifest 让 Claude Code 发现 skills、commands、agents、hooks；
- 可选 Python/uv、Zotero MCP、Obsidian 和分析包提供运行依赖；
- `uninstall.sh` 根据安装状态清理本项目管理的文件。

源码开发或安装调试前阅读 `docs/`、`settings.json.template` 和目标 skill 的 README；不要假设插件会自动合并 `CLAUDE.md`、rules 或 settings。

## 4. 分支边界

- `main`：Claude Code；
- `codex`：Codex CLI；
- `kimi`：Kimi Code CLI；
- `opencode`：OpenCode。

分支有不同配置、命令和路径，使用时保持同一分支内的文件组合。
