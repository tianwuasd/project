# 验证与风险

> 版本说明（2026-10-19）：源码已更新；正文保留此前整理的指南，功能与安装入口以当前上游 README 为准。见[本次更新记录](../../../UPDATE-2026-10-19.md)。

## 验证清单

- [ ] `skills/claude-scholar/skills/` 中目标 `SKILL.md` 真实存在。
- [ ] 当前使用的是同一宿主分支，没有混用 main/codex/kimi/opencode 配置。
- [ ] Zotero/Obsidian 中的原始论文和知识条目分区清楚。
- [ ] 每条摘要、claim、引用和实验结果都有来源或待核验状态。
- [ ] 文件写入、hook、MCP、API 和外部联网都在批准范围内。
- [ ] 输出经过作者逐项抽查后才进入长期知识或论文。

## 本地验证命令

```bash
test -f skills/claude-scholar/README.md
test -f skills/claude-scholar/skills/research-ideation/SKILL.md
test -f skills/claude-scholar/skills/obsidian-literature-workflow/SKILL.md
test -f skills/claude-scholar/skills/results-analysis/SKILL.md
test -f skills/claude-scholar/settings.json.template
```

如果具体 skill 名称在当前版本不同，以 `skills/` 中实际目录为准，不要猜路径。

## 常见失败

| 现象 | 处理 |
|---|---|
| Skill 不触发 | 明确写本地 `SKILL.md` 路径和任务，不依赖自动发现。 |
| Zotero 为空/不完整 | 检查是否真的授权 MCP、附件路径和集合；空结果不等于没有论文。 |
| Obsidian 写错 vault | 停止批量写入，确认 vault 和输出目录，优先从只读副本恢复。 |
| 摘要没有原文定位 | 回到 PDF/论文笔记逐条抽查，删除无法定位的断言。 |
| 分支配置冲突 | 只保留当前宿主对应的分支说明，重新检查 commands/rules/settings。 |
| Agent 修改全局文件 | 立即停止，审查写入日志和备份；本地指南默认不允许此行为。 |

## 风险边界

Claude Scholar 能改善文献组织、项目记忆和写作流程，但不能证明论文、数据、实验和结论正确。Zotero/Obsidian 的自动化尤其要遵循最小权限；任何自动摘要、研究 gap、统计解释或审稿回复都要由研究者回到原文和真实结果核验。
