# Claude Scholar 详细使用文档

> 版本说明（2026-10-19）：源码已更新；正文保留此前整理的指南，功能与安装入口以当前上游 README 为准。见[本次更新记录](../../../UPDATE-2026-10-19.md)。

## 0. 文档范围

本指南对应 [Galaxy-Dawn/claude-scholar](https://github.com/Galaxy-Dawn/claude-scholar) 主分支的 Claude Code 工作流。仓库也维护 Codex CLI、Kimi Code CLI 和 OpenCode 分支；如果使用这些宿主，应切换到对应分支并遵循其 README，不要把配置文件混用。

- **本地源码**：[`skills/claude-scholar`](../../../skills/claude-scholar/)
- **定位**：半自动研究助理，特别适合计算机科学、AI 和软件型研究
- **文章评价**：第二篇知乎文章评为“顶级”；这是文章作者对文献管理体验的主观评价
- **核心原则**：AI 加速沉重、重复和结构敏感的工作，但选题、重要论文、假设、结果可信度和投稿决策由研究者保留

## 1. 能解决什么问题

Claude Scholar 的主线是：

```text
研究问题 → 证据 → 实验 → 分析 → claim → 写作
```

它重点解决：

- 多轮会话反复解释研究背景；
- 文献导入、整理、去重、摘要和标签耗时；
- 论文笔记与项目实验分散；
- 实验结果没有形成可写入论文的报告；
- 文献、代码、分析、写作和审稿回复之间缺少稳定交接。

## 2. 前置条件

### 必需

- Claude Code
- Git
- 可访问的本地项目目录

### 可选

- **Python + uv**：开发、统计和部分工具工作流。
- **Zotero + zotero-mcp**：文献导入、集合管理、全文阅读、引用导出和去重。
- **Obsidian**：持久化项目知识库、论文笔记、实验和写作材料。
- 论文 PDF、BibTeX/RIS、实验结果、数据字典和审稿意见等真实输入。

## 3. 安装

### 3.1 全量安装（推荐）

在 Git Bash 或 WSL 中：

```bash
git clone https://github.com/Galaxy-Dawn/claude-scholar.git /tmp/claude-scholar
bash /tmp/claude-scholar/scripts/setup.sh
```

Windows 用户按仓库说明使用 Git Bash 或 WSL。安装器是增量式和备份友好的：会备份被覆盖文件、保留已有 `CLAUDE.md` 和配置中的 API key、权限、模型/provider 与 MCP 值，并写入安装 manifest 和 state。

### 3.2 最小安装

只需要研究核心功能时，可复制 hooks 和目标 skill：

```bash
git clone https://github.com/Galaxy-Dawn/claude-scholar.git /tmp/claude-scholar
mkdir -p ~/.claude/hooks ~/.claude/skills
cp /tmp/claude-scholar/hooks/*.js ~/.claude/hooks/
cp -r /tmp/claude-scholar/skills/research-ideation ~/.claude/skills/
cp -r /tmp/claude-scholar/skills/results-analysis ~/.claude/skills/
cp -r /tmp/claude-scholar/skills/results-report ~/.claude/skills/
cp -r /tmp/claude-scholar/skills/review-response ~/.claude/skills/
cp -r /tmp/claude-scholar/skills/writing-anti-ai ~/.claude/skills/
```

最小安装不会自动合并 `settings.json`；只复制自己需要的 hook 或 MCP 配置，并检查 `settings.json.template`。

### 3.3 选择性安装

例如只安装架构设计和论文模板：

```bash
git clone https://github.com/Galaxy-Dawn/claude-scholar.git /tmp/claude-scholar
cd /tmp/claude-scholar
cp hooks/*.js ~/.claude/hooks/
cp -r skills/latex-conference-template-organizer ~/.claude/skills/
cp -r skills/architecture-design ~/.claude/skills/
cp agents/paper-miner.md ~/.claude/agents/
cp rules/coding-style.md ~/.claude/rules/
cp rules/agents.md ~/.claude/rules/
```

### 3.4 插件市场

```text
/plugin marketplace add Galaxy-Dawn/claude-scholar
/plugin install claude-scholar@claude-scholar
```

插件会加载 skills、commands、agents 和 hooks，但 Claude Code 插件不能自动分发 rules；需要按仓库说明把需要的 rules 复制到 `~/.claude/rules/` 或项目 `.claude/rules/`。插件也不会自动合并你的 `CLAUDE.md` 或 `settings.json`。

### 3.5 更新与卸载

```bash
cd /tmp/claude-scholar
git pull --ff-only
bash scripts/setup.sh
```

卸载：

```bash
bash scripts/uninstall.sh
```

卸载器依据安装状态删除自己管理的文件，不应通过手动删除整个 `~/.claude` 来清理。

## 4. 验证安装

新开 Claude Code 会话，先做一个不改文件的请求：

```text
请帮我梳理这个项目的研究问题和现有材料。
只输出：需要补充的材料、候选研究问题和下一步计划，不写论文，不修改文件。
```

确认 Claude Scholar 能识别相关 skill 后，再做一个有边界的文献任务：

```text
请使用 Claude Scholar 的研究流程。
只分析我提供的 3 篇论文，输出主题分组、每篇核心贡献、方法差异和待核验引用。
不要访问或引用未提供的论文。
```

## 5. 输入准备

推荐项目结构：

```text
project/
  Sources/
    Papers/             # 原始论文和论文笔记
  Knowledge/            # 已确认的长期知识
  Experiments/          # 实验线、配置和运行记录
  Results/              # 原始结果与报告
  Writing/              # 论文、审稿回复和投稿材料
  question.md           # 当前研究问题
  constraints.md        # 目标 venue、语言、格式、权限
```

开始任务时明确：

- 本轮目标和停止点；
- 允许读取/写入的目录；
- 哪些文件是原始来源，哪些是已确认结论；
- Zotero/Obsidian 是否可用；
- 是否允许联网检索或 MCP 调用；
- 输出要保存为笔记、报告、论文段落还是审稿回复。

## 6. 典型使用示例与核心流程

### 6.1 从模糊主题开始

```text
Help me start research on [主题].
I want a literature-grounded plan, the key open questions,
and the next concrete steps.
Use only the files in this project unless I approve external search.
Stop after proposing the questions and plan.
```

**预期输出**：研究问题候选、文献方向、假设/计划和待确认事项。

**检查点**：人类选择要研究的问题；不能把 Agent 的“值得研究”当成新颖性或可行性证明。

### 6.2 复查 Zotero 集合

配置好 Zotero/MCP 后：

```text
请复查我 Zotero 中关于 brain foundation models 的集合。
输出：主题分组、主要研究方向、方法差异、研究缺口和下一步可执行问题。
每条结论指向论文标题或笔记来源，找不到原文支持的内容标记为待核验。
```

**预期输出**：按主题分组的论文清单、综合摘要、gap 分析和研究方向。

**检查点**：确认导入的 DOI、作者、年份、PDF 和集合归属正确；检查重复条目和预印本/正式发表版本关系。

### 6.3 生成结构化论文笔记

```text
请把 Sources/Papers/ 中的 10 篇论文做成结构化阅读笔记。
每篇包含：研究问题、数据/样本、方法、核心结果、局限、与其他论文的差异、
可支持的 claim、原文定位和未解决问题。
不要补写论文没有报告的数字或因果结论。
```

建议每篇笔记先落在 `Sources/Papers`，经过人工确认后再把稳定知识提升到 `Knowledge`，不要直接覆盖原始笔记。

### 6.4 分析实验结果

```text
请分析 Experiments/exp-03/ 和 Results/ 中的真实结果。
比较各 run 的指标、配置和数据版本，标出稳定发现、异常、尚未支持的解释，
然后给出下一步实验建议。
只使用文件中存在的数值；缺少日志或基线时明确说明。
```

**预期输出**：指标对比、消融/误差分析建议、结果报告和下一步决策。

**检查点**：核对运行配置、样本数、随机种子、评测脚本、基线和失败 run；不要让相关变化自动变成机制或因果解释。

### 6.5 写论文或 rebuttal

```text
请根据 Sources/Papers/、Knowledge/ 和 Results/ 中已经确认的材料，
起草 related work 的结构和初稿。
输出 claim-evidence 对照表，并把证据不足的句子标成待补充。
不要新增引用，不要编造结果。
```

审稿回复：

```text
请读取 reviewer_comments.md 和 manuscript_v2.pdf，生成逐点回复草稿。
每条回复包含：审稿意见、作者回应、实际修改位置、证据来源和仍需我确认的内容。
不要承诺尚未完成的实验，不要把推测写成已经完成的修改。
```

## 7. Zotero 与 Obsidian 核查

### Zotero

- 确认 Zotero Desktop 已运行并允许 MCP 访问。
- 导入前用 DOI、arXiv ID 或其他稳定标识符；不要仅凭标题创建条目。
- 导入后执行去重和元数据核对，特别是预印本、正式版本和不同数据库记录。
- PDF 路径、全文权限、附件和集合变化要在本地先检查，再交给 Agent 批量处理。
- 引用导出后核对 BibTeX 字段、特殊字符、作者顺序和年份。

### Obsidian

- 先绑定正确的 vault 和项目范围，确认 Agent 不会写入其他 vault。
- 原始论文放在 `Sources/Papers`；稳定结论、实验结果和写作材料分区保存。
- 约定 frontmatter、标签、链接和文件命名，避免同一论文产生多个不可追踪副本。
- 任何自动重命名、批量移动和覆盖操作先要求 Agent 输出计划并等待确认。

## 8. 结果核查与输出审查

### 文献

- [ ] 每篇论文真实存在且元数据与原文一致。
- [ ] 摘要、方法、结果和局限没有超出原文。
- [ ] 引用关系、他引数量和研究者身份等动态数据已回到权威来源核验。
- [ ] 原始笔记和 Agent 综合判断分开保存。

### 实验与分析

- [ ] 指标来自真实日志、表格或脚本输出。
- [ ] 样本、数据切分、基线、随机种子和环境可追溯。
- [ ] Agent 没有将建议、相关性或异常解释写成已证实机制。
- [ ] 结果报告与论文 claim 逐条对应。

### 写作与项目记忆

- [ ] 每个主要 claim 有来源、结果或“待补证据”状态。
- [ ] 版本化保存论文、回复、笔记和变更记录。
- [ ] 生成内容经过作者逐段确认后才提升到长期知识或对外材料。
- [ ] 没有把半自动流程误解成自动投稿或研究结论认证。

## 9. 常见失败与风险处理

| 现象 | 处理 |
|---|---|
| Skill 不触发 | 明确写“使用 Claude Scholar 的 research-ideation/results-analysis”等目标，并新开会话。 |
| Zotero 结果不全 | 检查 MCP、桌面端状态、集合权限、附件路径和去重结果；不要让 Agent 猜缺失论文。 |
| Obsidian 写错位置 | 立即停止批量写入，确认 vault、项目绑定和允许目录，必要时从备份恢复。 |
| 文献摘要很流畅但无定位 | 要求每条结论回指原文页码、段落或笔记，并人工抽查。 |
| 本地 Markdown 与仓库版本冲突 | 按安装器备份和 manifest 查清所有权，手动合并自己的 CLAUDE 文件。 |
| 任务越做越大 | 回到一个明确目标，例如只做 3 篇论文笔记或只分析一个实验目录。 |

## 10. 与其他 skill 的衔接

- **ARS / ARS-Codex**：Scholar 管理材料、笔记和项目记忆，ARS 做研究流程、引用和完整性门禁。
- **Scientific Agent Skills**：Scholar 组织项目与结果，Scientific Agent Skills 运行专业数据库、Python 包和科学计算。
- **AI Research Skills**：用于 AI/ML 训练、推理、评测和 RAG 工程；Scholar 保存实验上下文。
- **PaperSpine**：用已确认的 claim、结果和素材生成贡献优先的论文、投稿包和审稿回复。
- **Nature Skills**：在证据确认后做发表风格英文和科研图表达，不替代内容核查。

## 11. 人类决策边界

Claude Scholar 是半自动研究助理，不是“全自动科学家”。使用者必须决定研究问题、论文重要性、假设价值、结果是否令人信服以及是否投稿。Zotero/Obsidian 让证据和状态更容易追踪，但不会自动证明来源、数据或结论正确。
