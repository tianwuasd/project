# PaperSpine 详细使用文档

> 版本说明（2026-10-19）：源码已更新；正文保留此前整理的指南，功能与安装入口以当前上游 README 为准。见[本次更新记录](../../../UPDATE-2026-10-19.md)。

## 0. 文档范围

本指南对应 [WUBING2023/PaperSpine](https://github.com/WUBING2023/PaperSpine)。PaperSpine 是以“贡献为先、面向审稿人”为核心的学术写作编排 skill，不是单纯的语法润色器。

- **本地源码**：[`skills/PaperSpine`](../../../skills/PaperSpine/)
- **主入口**：`paper-spine`
- **源码真源**：`src/skill/`；`dist/` 由同步脚本生成，不要手工修改
- **文章评价**：第一篇文章介绍了它的贡献优先和动机追踪，但没有分档；这是资料性评价

## 1. 能解决什么问题

PaperSpine 将一篇论文或报告视为一组可审计的 manuscript units：每个单元都要有目的、贡献映射、证据和审稿人视角。它支持两条主流程：

- **Rewrite Existing**：改进已有论文/报告，不把任务降级为逐句润色；
- **Build From Materials**：从 PDF、图片、数据摘要、实验描述、笔记或部分初稿构建稿件。

目标场景：

- `journal`：期刊论文；
- `conference`：会议论文；
- `report_review`：课程报告、技术报告或综述；
- `competition`：竞赛论文或报告。

## 2. 前置条件

- Python 3；
- Claude Code、Codex、OpenClaw 或 Hermes CLI 之一；
- 论文、数据、实验结果、引用、目标 venue 要求和样例材料；
- LaTeX/PDF/Word 工具链（按输出需求配置）；
- 如使用本地 PDF、BibTeX、RIS 或下载论文，需要相应文件可读。

PaperSpine 不绕过付费墙或私有数据库权限。网络检索和外部下载必须遵循你的权限和数据政策。

## 3. 安装

### 3.1 Windows

```powershell
git clone https://github.com/WUBING2023/PaperSpine.git
cd PaperSpine
.\install.ps1
```

### 3.2 macOS/Linux

```bash
git clone https://github.com/WUBING2023/PaperSpine.git
cd PaperSpine
bash install.sh
```

安装器会从 `src/` 生成 `dist/`，再把同一个 `paper-spine` skill 安装到支持的宿主。旧版本残留清理：

```powershell
.\install.ps1 -CleanLegacy
```

或：

```bash
bash install.sh --clean-legacy
```

### 3.3 Claude Code 插件

```text
/plugin marketplace add https://github.com/WUBING2023/PaperSpine
/plugin install paper-spine
/reload-plugins
```

### 3.4 安装后确认

在 Claude Code/Codex 中使用：

```text
/paperspine
```

OpenClaw 和 Hermes 没有同样的 slash 入口，直接调用 `paper-spine`。重新安装或 reload 后检查当前宿主实际发现的 skill，避免旧 worker skill 副本重复触发。

## 4. 输入准备

推荐项目目录：

```text
paper-project/
  paper_spine_config.json   # 目标场景、语言、研究深度和参考路径
  manuscript/               # 初稿、章节、图表和附录
  references/               # PDF、BibTeX/RIS、模板和 venue 要求
  results/                  # 数据摘要、实验日志和真实结果
  reviewer_comments/        # 审稿意见与回复历史
  paper_rewriting_output/   # PaperSpine 阶段产物
```

配置前明确：

- 目标场景：journal、conference、report_review 或 competition；
- 工作流：rewrite existing 或 build from materials；
- 研究深度：`flash` 或 `pro`；
- 输出语言：`en`、`zh`，是否额外生成中文翻译包；
- 目标期刊/会议、格式、字数和投稿材料；
- 哪些结果已经由作者确认，哪些仍是候选解释；
- 参考材料只读路径和可写输出路径。

## 5. 典型使用示例

### 5.1 新建项目 Intake

```text
/paperspine

目标：把当前 materials/ 中的研究素材整理成一篇 conference paper。
流程：Build From Materials
语言：英文，额外生成中文翻译包
研究深度：flash
参考材料：references/ 中的目标会议要求、3 篇样例论文和我的结果摘要
本轮只完成 intake、素材索引和配置确认，不开始写正文。
```

**预期产物**：`paper_spine_config.json`、配置说明、参考材料索引和下一阶段计划。

**检查点**：目标 venue、语言、研究深度、素材范围和输出目录是否正确；缺配置时先完成 intake，不要绕过。

### 5.2 贡献优先的论文蓝图

```text
请继续使用 paper-spine。
先学习 references/ 中的目标场景要求和样例论文，读取 results/ 中已确认结果。
输出：confirmed_contribution、motivation 选项、章节蓝图、claim-evidence 矩阵和缺失证据清单。
在我确认 contribution 之前，不生成实质性正文。
```

**预期产物**：研究档案、样例学习、风格档案、gap map、贡献确认文件和写作蓝图。

**检查点**：贡献必须是用户确认的，不能由 Agent 擅自选定；每个主要 Results 单元都应映射到贡献承诺。

### 5.3 改写已有论文

```text
请使用 Rewrite Existing 流程处理 manuscript/draft.tex。
目标场景：journal；目标读者：……；参考要求：references/venue-guide.pdf。
先输出结构审计、贡献-结果映射和 reviewer 风险，不直接改写全文。
保留所有真实数字、引用、限定词和实验结果；等待我确认蓝图后再写。
```

**预期产物**：稿件结构诊断、审稿人价值图、问题登记和修改路线。

### 5.4 论文阶段写作

```text
根据已确认的 contribution 和 blueprint，只写 Results 的第 2 个子节。
输入：results/table2.csv、results/run-log.md、references/。
每个段落先列 claim、证据、限制和对应贡献，再写正文。
不能补写数据、引用或没有运行的实验。
```

**检查点**：结果数字来自真实文件，写作强度不超过证据，段落目标与贡献映射一致。

### 5.5 审稿回复

```text
请使用 paper-spine 的 Review Response 阶段。
读取 reviewer_comments/round1.md、manuscript_v1.pdf 和 results/。
生成逐条回复、修改位置、证据来源和需要作者确认的承诺。
不要承诺尚未完成的实验，不要把推测写成已完成修改。
```

### 5.6 最终审计与输出

```text
请运行 PaperSpine 的 Final Audit。
检查 contribution、results validation、reviewer audit、引用、图表、LaTeX/PDF/Word 和投稿材料。
只报告通过、失败和无法判断的项目；不要把失败项标成可投稿。
```

## 6. 12 阶段工作流

1. **Intake**：校验 `paper_spine_config.json`；
2. **Research**：学习目标场景、参考材料和样例；
3. **Citation**：建立 claim 级引用支持库；
4. **Motivation Confirmation**：停止等待用户确认控制性 motivation；
5. **Humanize**：按需处理语言和 AI 痕迹；
6. **Writing/Drafting**：根据蓝图进行 rewrite 或 build；
7. **Integrity Audit**：LaTeX 组装前做完整性审计；
8. **LaTeX/PDF/Word**：生成并检查目标格式；
9. **Submission Package**：按需生成 highlights、cover letter 等；
10. **Translation Package**：生成英文稿对应的中文翻译包；
11. **Review Response**：生成审稿意见回复；
12. **Final Audit**：硬性完成度检查，失败时不能宣布完成。

`progress_check.py --gate <stage>` 用来检查阶段状态。遇到失败应回到对应阶段，不手写缺失产物绕过 gate。

## 7. 结果核查：关键产物和检查

一次完整运行应留下可审计记录，例如：

```text
paper_rewriting_output/
  paper_spine_config.json
  paper_spine_config.md
  reference_materials/source_index.md
  research_dossier.md
  exemplar_learning_dossier.md
  style_profile.md
  sota_gap_map.md
  confirmed_contribution.md
  citation_support_bank.md
  results_validation.md
  reviewer_audit.md
  submission/
  translation_zh/
```

检查重点：

- [ ] `confirmed_contribution.md` 存在且经过作者确认。
- [ ] 每个主要 Results 子节至少验证一条贡献承诺。
- [ ] `reviewer_audit.md` 覆盖审稿人价值图、异议和 venue 匹配。
- [ ] 引用支持库包含来源、年份、BibTeX/参考信息和支撑句。
- [ ] LaTeX、PDF、Word 的数字、公式、图表和引用一致。
- [ ] 投稿材料和翻译包没有引入原稿中不存在的事实。

## 8. 失败与风险处理

| 现象 | 处理 |
|---|---|
| 缺少配置 | 先运行 intake/wizard，补齐目标、语言、路径和研究深度。 |
| Contribution 未确认 | 停在 Motivation/Contribution 阶段，不让 Agent 自行选定核心贡献。 |
| Results 无法映射贡献 | 标记失败并回到研究/实验解释，不为通过 gate 强行改标题。 |
| 引用支持不足 | 保持候选或待核验状态，回到原文和数据库核对。 |
| PDF/Word 编译失败 | 检查 LaTeX、Pandoc、字体和路径；不要手工修最终文件后跳过审计。 |
| 审稿回复过度承诺 | 只写已完成或作者明确批准的行动，把未来实验标为计划。 |
| `dist/` 与 `src/` 不一致 | 重新使用同步流程生成，不直接编辑 `dist/`。 |

## 9. 与其他 skill 的衔接

- **WenyuChiou AI Research Skills**：先做研究缺口、贡献和可行性，再把通过的候选交给 PaperSpine。
- **ARS/ARS-Codex**：提供引用、证据和完整性审查；PaperSpine 负责稿件结构、贡献和投稿产物。
- **Scientific Agent Skills / AERS / AI Research Skills**：生成真实计算、计量和模型实验结果。
- **Nature Skills**：在 claim 和证据确认后改善发表风格英文和图注。
- **Paper Craft Skills**：将贡献和真实结果转为方法图、长文或汇报 deck。

## 10. 责任边界

PaperSpine 的 gate 主要检查结构、产物、贡献映射、报告一致性和审稿风险，不证明原始数据真实、实验确实执行或投稿一定成功。作者仍需逐项确认研究结论、引用、图表、格式和最终提交内容。
