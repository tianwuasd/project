# 详细使用指南

> 版本说明（2026-10-19）：源码已更新；正文保留此前整理的指南，功能与安装入口以当前上游 README 为准。见[本次更新记录](../../../UPDATE-2026-10-19.md)。

## 1. 准备研究包

```text
local-spine/
  question.md
  contribution.md
  papers/
  results/
  figures/
  logs/
  manuscript/
  output/
  constraints.md
```

先写 `contribution.md`：研究问题、相对已有工作的差异、证据、不能声称的内容和目标读者。把实验结果、样本量、配置和失败运行放在可定位的文件中。

## 2. 按阶段推进

1. **Intake**：读取问题、材料和停止条件；
2. **Spine**：形成贡献、主张和证据链；
3. **Evidence**：核对结果、图表、引用和数据来源；
4. **Structure**：确定章节职责和段落顺序；
5. **Draft**：按章节起草，不补造实验；
6. **Audit**：做 claim、引用、数字和格式检查；
7. **Review**：模拟审稿人和编辑意见；
8. **Revise**：逐条回应并记录改动；
9. **Output**：生成最终稿、附录、清单和过程摘要。

实际阶段名称和数量以当前 `src/skill/SKILL.md` 与 references 为准，不用文档外推内部版本。

## 3. 最小提示词

```text
请读取 skills/PaperSpine/src/skill/SKILL.md。
只使用 local-spine/question.md、contribution.md、results/ 和 papers/。
先输出 output/spine.md：贡献、claim、证据、反证和缺口；不要起草正文。
缺少定位或证据的内容标记待核查，不写入原始文件。
```

通过人工确认 spine 后再要求章节草稿：

```text
根据 output/spine.md 起草 manuscript/introduction.md。
每段先列 claim 与证据文件，再写正文；不要新增引用、数字或因果措辞。
将未决问题写入 output/open-items.md。
```

## 4. 审稿和修改

把审稿意见、稿件版本和改动日志作为独立输入；逐条输出“意见—回应—实际修改—证据—仍需确认”。不承诺尚未完成的实验，也不把审稿模拟当成真实期刊决定。

## 5. 检查点

每一阶段保存版本和输入清单；对正文中的数字、引用、图表、贡献强度和局限做人工回源。最终只将通过检查的 claim 提升到对外稿件。
