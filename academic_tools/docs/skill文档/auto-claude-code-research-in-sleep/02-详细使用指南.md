# 详细使用指南

> 版本说明（2026-10-19）：源码已更新；正文保留此前整理的指南，功能与安装入口以当前上游 README 为准。见[本次更新记录](../../../UPDATE-2026-10-19.md)。

## 1. 定义一次有界 run

```text
local-aris/
  question.md
  materials/
  experiments/
  output/
  state/
  constraints.md
```

`question.md` 写研究目标和当前阶段；`constraints.md` 明确允许读写目录、最大迭代次数、时间/GPU预算、联网/API/跨模型权限、通知和停止条件。不要把“持续研究”当成无限授权。

## 2. 先计划再执行

```text
请读取 skills/Auto-claude-code-research-in-sleep/skills/research-pipeline/SKILL.md。
只读取 local-aris/question.md、materials/ 和 constraints.md。
先生成 local-aris/output/plan.md 和 state/run-boundary.md，不运行实验、不联网、不跨模型、不修改源码。
```

确认计划后，按 idea-discovery、experiment-bridge、auto-review-loop 和可选 paper-writing 的阶段逐步放行。每阶段结束保存输入、输出、命令、日志和人工决定。

## 3. 实验阶段

只允许读取指定代码/数据副本，把运行结果写入 `local-aris/output/experiments/`，限制运行次数和资源。记录 GPU、环境、随机种子、数据版本、失败日志和实际指标；不要只保留成功 run。

## 4. 审查与跨模型

要求 reviewer 输出 claim、证据、反例、风险和修改建议。Codex/Gemini/API/通知都要单独批准，并将发送的数据和目标域名写入日志；跨模型意见是辅助证据，不是独立事实证明。

## 5. Resume 与最终检查

恢复任务前先读取 state 和最近一次日志，确认状态没有过期或被其他进程修改。最终逐项核验引用、数据、实验、图表、论文段落和自动生成的修改，关闭未完成任务，不把自动状态当成研究结论。
