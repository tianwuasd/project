## 运行核查

- [ ] run 边界、最大迭代、预算和停止条件明确；
- [ ] 每个阶段的输入、输出、命令、版本和日志可追溯；
- [ ] 数据、引用、实验指标和论文 claim 逐项回源；
- [ ] 自动写入只发生在批准目录；
- [ ] 跨模型、MCP、API、GPU、SSH 和通知权限已单独批准；
- [ ] resume 前确认状态未过期或被其他进程修改；
- [ ] 测试环境实际具备 pytest 和平台依赖，不能把未运行当作通过。

## 常见失败

| 现象 | 处理 |
|---|---|
| pipeline 不停推进 | 停止进程，检查 AUTO_PROCEED、迭代上限和状态文件。 |
| 研究输出缺证据 | 回退到 evidence/quality gate，删除无法定位的 claim。 |
| GPU/SSH 任务失败 | 保留日志，检查资源和凭据，不自动重试无限次。 |
| venue 配置冲突 | 以当前 pipeline 的显式配置为准，记录 README 漂移。 |
| pytest 不可用 | 报告环境缺失，不伪造测试通过。 |
| 外部服务或通知误发 | 立即停止，审查域名、数据和发送日志。 |

## 风险边界

ARIS 的广泛 Bash/写入工具、自动 GPU、跨模型和外部 API 能产生费用、隐私泄露和越权写入。默认最小权限、人工 gate、隔离副本和有限预算；无人值守状态或审查报告不能替代研究者对事实和结论的验证。
