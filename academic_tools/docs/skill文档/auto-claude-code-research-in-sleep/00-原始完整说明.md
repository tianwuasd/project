# Auto-claude-code-research-in-sleep（ARIS）详细使用文档

> 版本说明（2026-10-19）：源码已更新；正文保留此前整理的指南，功能与安装入口以当前上游 README 为准。见[本次更新记录](../../../UPDATE-2026-10-19.md)。

## 0. 文档范围

本指南对应 [wanshuiyin/Auto-claude-code-research-in-sleep](https://github.com/wanshuiyin/Auto-claude-code-research-in-sleep)。ARIS 是以 skill 为核心的自主研究工作流，也提供 ARIS-Code CLI；它适合让 Agent 在限定条件下持续推进任务，不等于无人监督的自动科学家。

- **本地源码**：[`skills/Auto-claude-code-research-in-sleep`](../../../skills/Auto-claude-code-research-in-sleep/)
- **文章评价**：第二篇知乎文章评为“人上人”，但同时提醒无人值守时可能编造缺少实时检索支持的数据
- **核心循环**：plan → draft/execute → adversarial review → iterate → persist

## 1. 能解决什么问题

ARIS 将研究任务拆成可持续推进的工作流：

- 从研究方向或参考论文开始，形成研究问题和实验计划；
- 读取论文并按需要使用已有代码库；
- 执行或组织实验、记录结果、发现弱点并重写叙事；
- 让另一个模型通过 Codex MCP 或其他 provider 进行批判性检查；
- 用 Research Wiki 保存论文、想法、实验、结果、claim 和关系图；
- 在论文、rebuttal、图表和长期研究记忆之间继续迭代。

适合把一项复杂工作拆成夜间可以执行的若干轮，但每轮都应该有明确边界、产物和停止条件。

## 2. 前置条件

- Claude Code、Codex CLI、Cursor、Trae、Antigravity、Copilot CLI、OpenClaw 或其他支持文档中适配方式的宿主；
- Git；
- 论文、代码、数据、实验脚本和目标输出；
- 如果使用 CLI，需要 Rust/Node/包管理或仓库对应的构建依赖；
- 如果使用跨模型审查，需要 Codex MCP、API provider 或明确可用的 ChatGPT/其他订阅连接；
- 如果执行实验，需要真实计算资源、环境、日志和可追踪数据。

## 3. 安装与启动

### 3.1 Claude Code/Codex skill

保留仓库 clone，在目标宿主按仓库说明加载 skill：

```bash
git clone https://github.com/wanshuiyin/Auto-claude-code-research-in-sleep.git
```

仓库提供不同宿主的适配文档；不要把 Claude Code hook、Codex skill 和其他 CLI 的配置直接混用。Codex、Cursor、Trae、Antigravity、Copilot CLI 和 OpenClaw 的入口分别以仓库对应文档为准。

### 3.2 ARIS-Code CLI

仓库提供独立 CLI 的安装包和 release。最安全的做法是先阅读：

```text
docs/ARIS-Code-README_CN.md
docs/ARIS-Code-README_EN.md
```

再选择匹配系统的 release 或从源码构建。首次启动使用 setup/doctor 类命令检查 provider、模型、权限、MCP 和本地路径，不要直接把全量任务交给默认配置。

### 3.3 Research Wiki

Research Wiki 是持久研究记忆层，保存论文、想法、实验、结果和 claim 关系。启用前明确：

- wiki 的根目录；
- 哪些文件可读取和写入；
- 原始材料与 Agent 总结的分区；
- 是否允许自动创建/修改条目；
- 如何备份、版本化和清理历史。

## 4. 输入准备

推荐为每次 ARIS run 准备独立目录：

```text
aris-run/
  brief.md                 # 研究目标、范围、停止条件
  references/              # 论文、代码库链接和目标样例
  code/                    # 已授权使用的项目代码
  data/                    # 数据说明与版本
  experiments/             # 脚本、配置和环境
  reviews/                 # 外部审查和历史反馈
  outputs/                 # 本轮允许生成的文件
  run-state.md             # 已完成、阻塞、下一步和人工决定
```

`brief.md` 至少写清：

- 研究问题和当前假设；
- 本轮只允许做哪些操作；
- 预算、时间、GPU、API 和并发限制；
- 允许联网、克隆仓库、安装依赖和修改文件的范围；
- 完成判定标准；
- 何时必须停止并等待人类确认。

## 5. 典型使用示例

### 5.1 只做研究计划

```text
请使用 ARIS 的研究工作流。
目标：研究 factorized gap in discrete diffusion language models。
当前材料：references/ 中的 3 篇论文和 brief.md。
本轮只输出研究问题候选、实验计划、证据缺口和风险，不运行代码、不联网、不修改原始材料。
完成后停止等待确认。
```

**预期产物**：研究问题、假设、实验线、证据缺口和下一步。

**检查点**：研究问题是否来自材料，实验是否可执行，不能把新颖性或有效性当成已证明事实。

### 5.2 参考论文 + 基础代码的定向改进

```text
请使用 ARIS targeted mode。
参考论文：references/paper.pdf
基础代码：code/base-repo/
目标：只寻找能针对论文中已确认弱点的 2 个改进方向。
先读取论文和代码，输出弱点-改进-实验映射；不要修改代码、下载额外模型或运行实验。
```

确认后：

```text
继续执行已确认的第 1 个改进方向。
只写 code/experiment-01/ 和 outputs/experiment-01/。
每次修改前展示 diff；运行后保存命令、环境、seed、日志、指标和失败信息。
达到预算或出现越界需求立即停止。
```

### 5.3 受限的多轮实验循环

```text
请运行一个受限 research loop：最多 3 轮，每轮只允许改 configs/ 和指定训练脚本。
固定数据集、测试集、评测脚本和预算。
每轮结束输出：本轮假设、变更 diff、运行结果、失败原因、证据状态和下一轮建议。
不要因为指标上涨就自动扩大搜索空间或修改研究问题。
```

**检查点**：检查测试集泄漏、过拟合 benchmark、运行方差、配置漂移和指标来源。

### 5.4 审稿回复

```text
请使用 ARIS rebuttal 模式。
输入：manuscript/、reviews/、results/。
为每条 reviewer concern 建立追踪表，生成不超过 5000 字符的 PASTE_READY.txt 和扩展草稿。
每条回应必须来自论文、审稿意见或我确认的结果；不编造实验、不越权承诺、不遗漏意见。
先输出 coverage 和证据检查，最后再写回复。
```

### 5.5 夜间运行的安全配置

```text
请为今晚的 ARIS run 生成执行计划，不立即启动。
任务：只做论文结构改写、引用候选整理和 reviewer concern 分类。
禁止：新增数据、虚构引用/数字、提交外部服务、修改原始 PDF、自动投稿、扩大文件写入范围。
每 30 分钟保存 run-state.md；遇到无来源的数字、需要新实验或权限不明确时停止并记录阻塞。
```

早晨先做：

```text
请只读取昨晚的 run-state.md、diff、日志和审查报告。
列出所有新增/修改内容、来源、未验证项和需要我决定的事项，不要继续执行。
```

## 6. 跨模型审查

ARIS 的设计强调执行模型和批判模型分工：

- 执行模型负责读取材料、写代码、生成草稿和运行工作流；
- reviewer 模型负责找漏洞、检查证据、攻击实验和审查叙事；
- 最终决定仍由研究者做，不把 reviewer 的“通过”当成事实证明。

跨模型前确认：

- 使用哪个 provider/model 和审查目标；
- 会发送哪些文本、代码、数据或日志；
- 是否包含私有、未发表或敏感材料；
- API/订阅费用、超时、重试和失败时的降级行为；
- 返回结果如何标记来源和 provenance。

同一模型自审不能替代真正的独立复核；多个模型也不能替代领域专家。

## 7. 结果核查

### 研究与实验

- [ ] 每轮变更、假设、配置、命令、环境、seed 和日志已保存。
- [ ] 结果数字来自真实输出，不是 Agent 总结或记忆。
- [ ] 失败运行、负结果、异常和未完成项没有被隐藏。
- [ ] 代码、数据、测试集和评测脚本没有被自动循环偷偷改变。

### 文献与写作

- [ ] 每条引用真实存在并能回到原文。
- [ ] 引用存在性、原文是否支持 claim、claim 是否过度概括分别检查。
- [ ] reviewer concern 全部进入追踪表，回复没有超出已完成工作。
- [ ] 夜间改稿经过 diff、原文和证据逐条审阅。

### 自动化与安全

- [ ] 文件写入、联网、MCP、包安装和远程执行都在批准范围内。
- [ ] 凭据、私有数据和个人信息没有进入日志或外部审查。
- [ ] 运行预算、时间和并发限制有效。
- [ ] Research Wiki 原始材料、推断和作者决定分区保存。

## 8. 失败与风险处理

| 现象 | 处理 |
|---|---|
| 找不到实时来源 | 标记未验证并停止相关结论，不用模型记忆补数字。 |
| 自动改稿越过范围 | 停止 run，审查 diff 和写入日志，从最后可信版本开始。 |
| 指标异常上涨 | 检查数据泄漏、测试集、代码 diff、seed 和评测脚本。 |
| 外部审查不可用 | 记录 reviewer 缺失，不伪造第二模型结果；改为人工审查或暂停。 |
| 夜间任务需要新权限 | 写入阻塞状态，等待人类批准，不通过默认配置绕过。 |
| Research Wiki 产生重复/错误条目 | 保留原始条目，检查 provenance 和变更记录后人工合并。 |
| 依赖/API/模型失败 | 保存错误和环境，禁止自动更换研究问题、数据集或模型目标。 |

## 9. 与其他 skill 的衔接

- **ARS/ARS-Codex**：白天复查 ARIS 的引用、证据、claim 和审稿报告。
- **Claude Scholar**：管理 Zotero/Obsidian 文献与项目知识，提供稳定的输入材料。
- **Scientific Agent Skills / AI Research Skills / AERS**：执行真实科学计算、AI/ML 工程或社科实证。
- **PaperSpine**：把经过人工确认的贡献、结果和 reviewer concern 组织成最终稿。
- **Nature Skills / Paper Craft**：在内容确认后处理英文表达、图件和汇报。

## 10. 责任边界

ARIS 能自动推进流程、保存状态和组织审查，但不能证明数据真实、实验确实执行、引用支持 claim 或论文适合投稿。无人值守只代表 Agent 在限定权限内继续运行；任何早晨看到的改稿、数字、引用和实验结论都必须先验证。
