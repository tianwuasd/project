# Paper Craft Skills 详细使用文档

> 版本说明（2026-10-19）：源码已更新；正文保留此前整理的指南，功能与安装入口以当前上游 README 为准。见[本次更新记录](../../../UPDATE-2026-10-19.md)。

## 0. 文档范围

本指南对应 [zsyggg/paper-craft-skills](https://github.com/zsyggg/paper-craft-skills)。它负责把论文和技术材料转成方法图解、深度解读文章和视觉幻灯片，重点是科学传播与视觉表达，不替代研究设计和事实核验。

- **本地源码**：[`skills/paper-craft-skills`](../../../skills/paper-craft-skills/)
- **包含的核心 skill**：`paper-comic`、`paper-analyzer`、`paper-deck`
- **文章评价**：第一篇文章介绍其论文视觉化能力，但没有分档；第二篇文章未重点测评

## 1. 能解决什么问题

| Skill | 输入 | 主要输出 |
|---|---|---|
| `paper-comic` | arXiv 链接、PDF、论文方法/结果 | 方法图、机制图、论文级 figure 或 sketchnote |
| `paper-analyzer` | 论文 PDF/文本和可用源码 | 带公式、代码对照、图表和 Mermaid 的 HTML 深度长文 |
| `paper-deck` | 论文、技术笔记、真实图表 | deck brief、逐页大纲、16:9 slide image、PPTX/PDF |

共同流程是：先读懂材料 → 规划视觉叙事 → 用户确认范围/风格 → 生成 → 逐项审查 → 导出。

## 2. 前置条件

- Codex、Claude Code、Cursor 或 Windsurf 等兼容宿主；
- 论文 PDF、arXiv URL 或本地 Markdown；
- 如果使用真实图表，需要原始图片/表格及许可；
- 浏览器/HTML 公式渲染和 PPTX/PDF 导出环境；
- 图像生成或其他外部服务（如果目标风格/实现需要），以及明确的网络和费用许可。

README 宣称不需要 API key 的基础安装并不意味着每个外部图像生成、下载或导出能力都无需依赖；实际以目标 skill 的 `SKILL.md` 和本地环境为准。

## 3. 安装

### 3.1 Agent 安装

```text
请帮我安装 zsyggg/paper-craft-skills
GitHub：https://github.com/zsyggg/paper-craft-skills
只安装到当前项目，不要全局安装；先列出将复制的 skill 和依赖，等待确认。
```

### 3.2 npx 安装

```bash
npx skills add zsyggg/paper-craft-skills
```

安装后新开会话，确认 `paper-comic`、`paper-analyzer`、`paper-deck` 被宿主发现。

## 4. 输入准备

### 4.1 论文图解

```text
paper.pdf
figures/                  # 论文原图、表格和许可信息
notes.md                  # 作者确认的方法/结果解释
figure-constraints.md     # 语言、尺寸、颜色、期刊要求
```

### 4.2 深度长文

```text
paper.pdf
source-repo/              # 论文对应的 GitHub 源码（如有）
notes/                    # 术语、读者背景和重点
output-constraints.md     # HTML、语言、篇幅、公式和代码要求
```

### 4.3 幻灯片

```text
paper.pdf
real-figures/             # 可复用的真实实验图
results.csv               # 如需重绘，保存来源
slide-constraints.md      # 页数、比例、读者和风格
```

提示词始终注明：真实结果与示意内容的边界、不要生成的内容、原图来源、目标读者和本轮停止点。

## 5. 典型使用示例

### 5.1 paper-comic：先规划再生成

```text
/paper-comic https://arxiv.org/abs/1706.03762
```

当 Agent 读完论文并提出图解计划时：

```text
只生成 1 张总览图，不生成未经我确认的细节图。
保留论文中的真实模块名、公式符号和数据结论。
风格：paper-figure；语言：English。
先输出图中元素、箭头关系、来源和可能误读点，等待确认后再生成。
```

**预期产物**：图解计划、元素清单、方法/结果映射和图像草稿。

**检查点**：逐个对照论文正文、算法图和公式，确认箭头方向、模块关系、术语和数据没有被视觉化过程改变。

### 5.2 paper-analyzer：论文到 HTML 长文

```text
/paper-analyzer /path/to/paper.pdf
```

更有边界的请求：

```text
请使用 paper-analyzer 生成 academic 风格 HTML。
读完整论文，并只用 source-repo/ 中确认存在的代码做对照。
输出公式的符号解释、方法流程、实验表格和局限。
对论文没有报告的内容标记为“未说明”，不要根据常识补写。
```

可选风格：

- `storytelling`：适合公众号、博客和面向公众的讲解；
- `academic`：适合组会、综述和技术分享；
- `concise`：适合预读、速查和高密度概览。

**预期产物**：含 KaTeX 公式、Mermaid 图、代码对照和表格的 HTML。

**检查点**：代码是否真的对应论文版本，公式渲染是否改变符号，表格数字是否来自原文，HTML 是否保留引用和来源。

### 5.3 paper-deck：从论文到 PPT

```text
/paper-deck /path/to/paper.pdf --style journal-minimal --slides 12
```

或：

```text
/paper-deck notes.md --style liquid-glass
```

推荐先拆两步：

```text
请先读取 paper.pdf 和 real-figures/，只生成 deck brief、逐页大纲、
每页核心结论、需要使用的真实素材和来源，不生成图片或 PPT。
```

确认大纲后：

```text
继续生成 12 页 16:9 幻灯片。
真实实验图只能来自 real-figures/，生成图只能用于背景或示意。
每页保留来源、单位、图例和方法/结果边界；完成后先输出逐页 QA 报告，再导出 PPTX/PDF。
```

可选风格：

- `journal-minimal`：Nature/IEEE 风学术汇报、答辩和组会；
- `business-research`：行业分析、客户或投资人汇报；
- `warm-notes`：课程和论文学习笔记；
- `liquid-glass`：高冲击视觉封面和章节页。

**检查点**：每页只有一个核心观点，真实图表与生成背景分开，数字/单位/引用/页码/字体/比例正确。

## 6. 结果核查

### 科学事实

- [ ] 方法图与论文正文/源码结构一致。
- [ ] 公式、变量、模型名、数据集和指标未被改写。
- [ ] 表格、曲线、样本量、误差线和颜色含义来自真实来源。
- [ ] 论文没有报告的内容标为未说明，不由图像或类比补全。

### 视觉表达

- [ ] 箭头方向、层级、流程、因果和时间顺序没有歧义。
- [ ] 每页 deck 有一个明确的结论式标题。
- [ ] 图例、坐标轴、单位、字体、对比度和可读性通过检查。
- [ ] 手机、桌面、投影和 PDF/PPTX 导出后显示一致。

### 来源与版权

- [ ] 每张真实图片、图表、代码截图和外部素材有来源。
- [ ] 论文图、GitHub 源码、字体和生成图片的许可允许当前用途。
- [ ] 生成内容没有冒充论文原图或真实实验结果。
- [ ] HTML、PPTX/PDF、图像源文件和 prompt 已保存，可重新生成。

## 7. 失败与风险处理

| 现象 | 处理 |
|---|---|
| 图看起来专业但结构不对 | 以论文正文、源码和公式为准，逐元素重审，不直接投稿或汇报。 |
| 生成图出现错误文字/公式 | 改用可编辑矢量/HTML/PPT 元素，或由作者手工替换并记录来源。 |
| PPT 堆满文字 | 回到 deck brief，每页保留一个观点，用真实图表承载证据。 |
| 图表数字与论文不一致 | 删除生成副本，重新从结果文件导入，禁止手工改数字。 |
| HTML 公式/图表不渲染 | 检查 KaTeX/Mermaid/浏览器环境，并保留纯文本替代说明。 |
| 外部素材无许可 | 改用用户提供或许可明确的素材，不能默认网络图片可商用。 |
| 论文内容无法确认 | 标记未说明/待核验，不让 Agent 用常识填空。 |

## 8. 与其他 skill 的衔接

- **Claude Scholar**：先做论文导入、结构化笔记和证据整理，再交给 Paper Craft。
- **Scientific Agent Skills / AI Research Skills / AERS**：提供真实计算、模型或计量结果及图表源文件。
- **PaperSpine**：先确认贡献和 Results 映射，再制作方法图或投稿汇报。
- **Nature Skills**：优化英文图注和学术表达，保持术语与正文一致。
- **ARS/ARS-Codex**：核验引用、证据和论文 claim，避免视觉化掩盖证据缺口。

## 9. 责任边界

Paper Craft 优化的是理解和沟通，不是科学结论本身。方法图、HTML 和幻灯片即使视觉质量很高，也不能证明算法实现、实验数据、统计推断、引用或论文结论正确；最终发布前必须由作者逐项核对。
