# Auto-Empirical Research Skills（AERS）详细使用文档

> 版本说明（2026-10-19）：源码已更新；正文保留此前整理的指南，功能与安装入口以当前上游 README 为准。见[本次更新记录](../../../UPDATE-2026-10-19.md)。

## 0. 文档范围

本指南对应 [brycewang-stanford/Auto-Empirical-Research-Skills](https://github.com/brycewang-stanford/Auto-Empirical-Research-Skills)。AERS 面向社科实证研究，把选题、识别策略、估计、稳健性、表图、写作和投稿组织成可介入的工作流。

- **本地源码**：[`skills/auto-empirical`](../../../skills/auto-empirical/)
- **README 当前入口**：中文 README + `docs/CONTENT_ZH.md`
- **文章评价**：第二篇知乎文章评为“顶级”；这是作者的体验性评价，不是本指南独立复现
- **重要边界**：统计代码可以被自动生成和运行，但研究设计、识别假设、数据质量和最终解释必须由研究者确认

## 1. 能解决什么问题

AERS 的主线是九个阶段：

1. **选题精炼**：把模糊 idea 变成可证伪、可执行的研究问题。
2. **文献综述**：检索、筛选、PRISMA、批判性阅读和主题分析。
3. **数据获取**：公开数据库、API、抓取和数据清洗。
4. **识别策略**：DiD、RD、IV、SCM、DML、matching 等。
5. **估计建模**：Python、Stata、R 三套计量栈和大量估计器。
6. **稳健性审计**：复现包检查、HonestDiD、R&R 和稳健性体检。
7. **表格与图形**：期刊级表格、图形和 LaTeX 嵌入。
8. **写作与同行评审**：LaTeX/Quarto、审稿模拟、校对和结果解释。
9. **降 AIGC 与投稿**：学术表达、投稿材料和 AI 痕迹审查。

仓库既有单独合集，也有把多个阶段串起来的 Paper-WorkFlow/元编排能力；推荐先单阶段验证，再逐步扩大范围。

## 2. 前置条件

### 软件

- Claude Code、Codex 或其他支持 skill 的 Agent；
- Python 或 R；
- Stata（如果使用 Stata 合集）；
- Quarto/LaTeX（如果输出可编译论文或表格）；
- Git 和基本的命令行环境。

### 研究材料

```text
project/
  question.md                 # 研究问题和假设
  literature/                 # 论文、检索记录、BibTeX
  data_raw/                   # 原始数据和许可说明
  data_processed/             # 可重建的清洗结果
  code/                       # Python/Stata/R/Quarto 代码
  configs/                    # 样本、模型和稳健性配置
  outputs/                    # 表、图、日志和报告
  replication/                # 复现包和环境文件
  constraints.md              # 目标期刊、字数、截止日期、权限
```

开始前写清楚：因变量、处理变量、时间/个体维度、处理发生时间、预期识别策略、聚类层级、控制变量、样本排除、数据来源和目标 estimand。

## 3. 安装

### 3.1 让 Agent 安装

把仓库地址和作用域交给 Agent，并明确是当前目录、项目级还是全局：

```text
请安装 https://github.com/brycewang-stanford/Auto-Empirical-Research-Skills
只在当前项目使用，不要全局安装；先列出将安装的 skill 和需要的 Python/Stata/R 依赖，等待确认。
```

### 3.2 Claude Code 插件

```bash
claude plugin marketplace add brycewang-stanford/Auto-Empirical-Research-Skills
claude plugin install aer-skills@auto-empirical-research-skills
claude plugin install empirical-analysis-python@auto-empirical-research-skills
claude plugin install empirical-analysis-stata@auto-empirical-research-skills
claude plugin install empirical-analysis-r@auto-empirical-research-skills
```

可以只安装一个语言栈或一个阶段。安装后新开会话并检查 skill 是否被发现。

### 3.3 直接克隆/复制单个 skill

```bash
git clone --recurse-submodules https://github.com/brycewang-stanford/Auto-Empirical-Research-Skills.git
cd Auto-Empirical-Research-Skills
cp -R skills/00.1-Full-empirical-analysis-skill_Python .claude/skills/
```

被复制的目录必须包含 `SKILL.md`；有些合集的 `SKILL.md` 在下一层，不要复制错误层级。

## 4. 输入准备与运行原则

### 4.1 先定 estimand，再写代码

向 Agent 提供：

```text
研究问题：政策 X 对结果 Y 的平均处理效应是什么？
处理：policy_treatment，发生在 2022 年，处理组为……
结果：outcome_y，单位为……
面板：个体 id、年份 year，2018–2025
识别：初步考虑 staggered DiD；请先审查前趋势和处理时点
数据：data_processed/panel.parquet
本轮目标：只输出识别审查和诊断计划，不运行回归
```

Agent 应先暴露识别假设、数据需求和失败条件，而不是直接给出一个回归式。

### 4.2 每轮限定一个阶段

推荐顺序：

1. 数据审计；
2. 识别与样本审计；
3. 主估计；
4. 稳健性与异质性；
5. 表图和报告；
6. 论文写作。

每轮固定输入、输出目录和停止点，保存运行日志与配置。

## 5. 典型使用示例

### 5.1 数据清洗审计

```text
请使用 Python empirical-analysis skill 审计 data_raw/panel.csv。
先输出列名、类型、缺失值、重复键、极值、单位、处理组比例和时间覆盖。
生成 data_audit.md 和只读的清洗脚本草稿；不要覆盖原始数据，不要运行任何模型。
对每个清洗规则写出理由和可能改变的样本范围。
```

**预期产物**：数据审计报告、清洗规则、失败行/异常表和待确认事项。

**检查点**：核对重复键、缺失处理、异常值、样本过滤、单位换算、时间编码和处理变量定义。

### 5.2 事件研究/DiD

```text
请基于已确认的 data_processed/panel.parquet 设计 staggered DiD。
比较 TWFE 与适合分期处理的估计方法，说明各自 estimand、平行趋势要求、
处理时点、事件窗口、聚类层级和可能的负权重问题。
先生成识别审查和运行计划，等待我确认后再执行估计。
```

确认后：

```text
按已确认的识别计划运行主估计和事件研究。
只读 data_processed/，只写 outputs/did-2026-08-28/。
保存完整命令、环境、样本、系数、置信区间、图源文件和日志；失败时停止，不更改 estimand。
```

**检查点**：确认前趋势、处理时点、事件窗口、参考期、标准误聚类和样本变化；不要把显著的事件研究系数自动解释为政策因果效应。

### 5.3 IV/RD/SCM 识别策略

```text
请评估这个研究设计是否适合 IV：
处理变量：…… 工具变量：…… 结果变量：……
只输出相关性、排除限制、单调性/局部效应解释、可检验诊断、潜在违反方式和所需数据。
不要把“第一阶段显著”写成工具变量有效性的充分证明。
```

RD/SCM 也应先要求带宽、阈值、操纵检验、预处理期、对照构造和敏感性分析计划，之后再运行代码。

### 5.4 稳健性与复现包审计

```text
请审计 replication/ 中的代码、数据说明和输出。
检查依赖、相对路径、随机种子、表格数字、样本数、主结果与代码是否一致，
并列出能复现、不能复现和无法判断的项目。
不要替复现失败补写结果。
```

**预期产物**：复现日志、差异表、环境文件、失败原因和修复建议。

**检查点**：主结果与日志/表格逐项匹配；确认数据许可、路径、包版本、Stata ado、R 包和 Python 环境。

### 5.5 表格、图形和论文结果

```text
请根据 outputs/did-2026-08-28/ 生成 Table 1–3 和事件研究图。
所有表图数字必须从已保存结果读取；保留变量标签、单位、样本量、固定效应、聚类方式、
置信区间、数据来源和脚本。先输出表图规范和 claim-evidence 对照，再生成文件。
```

**检查点**：图表与源数据一致，误差线/置信区间含义明确，图例和轴单位完整，不能为了“期刊风格”隐藏负结果或调整坐标误导读者。

### 5.6 写作与投稿

```text
请根据 question.md、literature/、outputs/ 和 replication/ 起草 Results。
每个段落先列 claim、证据文件、统计量和限制，再写正文。
不新增引用、不扩大因果措辞、不把建议实验写成已完成实验。
输出结果段落、claim-evidence 表和需要我确认的句子。
```

## 6. 结果核查

### 计量识别

- [ ] estimand、处理、结果、样本和时间窗口已明确。
- [ ] 平行趋势、排除限制、阈值连续性、工具变量有效性或 SCM 对照要求已单独审查。
- [ ] 标准误聚类层级、权重、固定效应、缺失和多重比较处理有记录。
- [ ] 主结果、负结果和敏感性分析都被保存。

### 可复现性

- [ ] 原始数据只读，清洗脚本可重建 processed 数据。
- [ ] Python/R/Stata/Quarto/LaTeX/包/ado 版本和系统环境已记录。
- [ ] 每个表、图和数字能回溯到脚本、结果文件和运行日志。
- [ ] 复现包在干净环境或第二次运行中通过抽样核对。

### 论文表述

- [ ] 相关性、预测、局部效应和平均处理效应没有混为一谈。
- [ ] 估计结果和统计显著性没有被写成机制或普遍因果结论。
- [ ] claim-evidence 表完整，证据不足的 claim 标为待补充。
- [ ] 论文、表图、代码和数据版本一致。

## 7. 失败与风险处理

| 现象 | 处理 |
|---|---|
| 回归无法运行 | 先保存数据审计、环境和错误日志；不要自动更换 estimator 或样本。 |
| 样本数变化 | 输出每个过滤规则的样本差异，人工确认是否改变研究问题。 |
| 前趋势不佳 | 报告诊断结果，重新讨论识别策略；不要通过改变窗口或参考期隐藏问题。 |
| 结果显著但不稳健 | 先检查代码、聚类、样本、权重和多重比较，再决定如何解释。 |
| 表格和代码不一致 | 回到结果文件和脚本重新生成，禁止手工改数字。 |
| AIGC/投稿检查要求改写 | 先保护 claim、限定词和证据，不要为了降低检测分数改变科学含义。 |
| 自动流水线越过人工检查 | 停止在当前阶段，核对 manifest、日志和产物后再继续。 |

## 8. 与其他 skill 的衔接

- **Claude Scholar**：管理文献、Zotero、Obsidian 和项目知识；AERS 负责实证分析。
- **WenyuChiou AI Research Skills**：先做 gap、contribution 和 feasibility gate，再进入 AERS。
- **ARS / ARS-Codex**：负责引用、证据、论文和审稿完整性。
- **Scientific Agent Skills**：用于非社科的科学数据库、专业计算和分析包。
- **PaperSpine**：将实证结果映射到贡献、Results、投稿包和审稿回复。

## 9. 版本、质量与责任

AERS README 提供 benchmark、行为评测和安全审计等信任信号，但它们不能自动证明你的数据、识别设计或结果正确。仓库统计的合集/skill 数量会变化；使用时应固定 commit，保留运行环境，并由熟悉研究设计和计量方法的人复核。
