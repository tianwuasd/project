# ARS-Codex 详细使用文档

> 版本说明（2026-10-19）：源码已更新；正文保留此前整理的指南，功能与安装入口以当前上游 README 为准。见[本次更新记录](../../../UPDATE-2026-10-19.md)。

## 0. 文档范围

本指南对应 [Imbad0202/academic-research-skills-codex](https://github.com/Imbad0202/academic-research-skills-codex) 的 Codex 原生分发版。它与 Claude Code 版 ARS 共享主要研究工作流内容，但插件身份、路由、版本和运行时适配独立维护。

- **本地源码**：[`skills/academic-research-skills-codex`](../../../skills/academic-research-skills-codex/)
- **仓库入口**：`skills/academic-research-suite/SKILL.md`
- **当前 README 版本**：0.1.27，所 vendored 的 ARS 内容追踪 v3.21.1
- **文章评价**：第二篇知乎文章将 ARS 评为“夯”；该评价是体验性参考。

## 1. 能解决什么问题

ARS-Codex 将研究任务路由到一个可安装的 `$academic-research-suite` skill，覆盖五条路径：

| 路由 | 适合任务 | 主要产物 |
|---|---|---|
| `deep-research` | 收敛研究问题、综述、系统综述、元分析、事实核查 | 研究问题、检索/筛选记录、证据和缺口 |
| `academic-paper` | 论文结构、章节、摘要、引用格式、披露和修订 | 大纲、草稿、引用检查、修订路线 |
| `academic-paper-reviewer` | 模拟同行评审、决定信、复审 | reviewer reports、优先级和决定信 |
| `academic-pipeline` | 从选题到论文的分阶段推进 | pipeline dashboard、阶段产物和最终审计 |
| `experiment-agent` | 实验计划、研究协议、统计解释和复现检查 | 实验计划、统计核查和复现清单 |

它的工作原则是：研究者提供问题、材料和判断，Agent 做结构化的检索、组织、检查和草拟；不能验证的来源、数据、统计或期刊政策必须标记为未验证。

## 2. 前置条件

- Codex CLI 或支持 Codex 插件的客户端。
- Git；直接安装 skill 时需要 Python 3 安装器脚本。
- 能访问外部来源时，才可做联网文献核验；离线任务应明确接受“未验证”。
- 如要使用跨模型审查，需配置对应 provider，并单独确认外部上传、费用和权限。

## 3. 安装

### 3.1 插件安装（推荐）

在 Codex CLI 中运行：

```bash
codex plugin marketplace add Imbad0202/academic-research-skills-codex --ref main
codex plugin add ars-codex@ars-codex
```

更新：

```bash
codex plugin marketplace upgrade ars-codex
codex plugin add ars-codex@ars-codex
```

Codex Desktop 可将以下仓库作为插件市场源：

```text
Marketplace source: https://github.com/Imbad0202/academic-research-skills-codex.git
Branch/ref: main
Plugin: ars-codex
```

### 3.2 直接安装单个 skill

```bash
python3 "$HOME/.codex/skills/.system/skill-installer/scripts/install-skill-from-github.py" \
  --repo Imbad0202/academic-research-skills-codex \
  --ref main \
  --path skills/academic-research-suite \
  --method git
```

Windows 如果只有 `python` 命令，将 `python3` 替换为 `python`。安装后新开 Codex 会话，并用 `/skills` 确认只出现一个 `academic-research-suite` 或 ARS-Codex 入口。

### 3.3 安装边界

ARS-Codex 不应被拆成多个同名独立 skill。仓库内的 `ars-*.md` 是 prompt recipe/别名，Codex 通过一个 router skill 处理，不会原样注册成 Claude Code slash command。

## 4. 输入准备

推荐先准备：

```text
project/
  question.md              # 当前问题、范围和假设
  materials/               # PDF、笔记、模板、审稿意见
  results/                 # 外部实验结果、日志、表格
  references.bib           # 已有引用（可选）
  constraints.md           # 语言、格式、字数、时间和权限
```

每次调用时说明：

- 目标阶段和本轮停止点；
- 哪些内容已经由人确认；
- 是否允许联网/脚本/跨模型；
- 需要输出什么文件以及保存位置；
- 是否有 DOI、页码、句子级引用定位要求。

## 5. 基本调用方式

明确点名路由：

```text
Use $academic-research-suite.
Goal: write a systematic review on AI adoption in higher-education quality assurance.
Current materials: ./materials/ and ./question.md.
This turn: produce the review protocol only, then stop for my approval.
```

如客户端把 `$` 或 slash 输入当普通文本，也可以直接写：

```text
Use $academic-research-suite: ars-plan my paper on AI governance in universities.
```

常用别名：

| 别名 | 路由/模式 |
|---|---|
| `ars-plan` | `academic-paper` 的 plan |
| `ars-outline` | 论文大纲 |
| `ars-abstract` | 摘要 |
| `ars-lit-review` | 文献综述 |
| `ars-citation-check` | 引用检查 |
| `ars-reviewer` | 完整同行评审 |
| `ars-full` | `academic-pipeline` 完整流程 |
| `ars-revision` | 论文修改 |

## 6. 典型使用示例与分阶段操作

### 6.1 Socratic 研究问题收敛

```text
Use $academic-research-suite.
I want to study generative AI in higher-education quality assurance,
but my research question is not clear.
Use deep-research in Socratic mode.
Ask narrowing questions first; do not write an outline or paper draft.
Stop after presenting 2–3 candidate questions and their feasibility concerns.
```

**预期产物**：候选问题、范围边界、关键概念、现有证据和待确认事项。

**暂停核查**：确认每个问题对应可获取的数据/文献，区分描述、预测和因果目标，再批准进入下一阶段。

### 6.2 生成论文蓝图

```text
Use $academic-research-suite.
Route: academic-paper, mode: plan.
Materials: question.md, materials/, results/.
Output: IMRaD blueprint, claim-evidence matrix, missing-evidence checklist.
Do not write full prose until I approve the blueprint.
```

**预期产物**：章节职责、论证顺序、claim-evidence 表、缺失证据和写作决策。

**暂停核查**：看每个主要 claim 是否有真实证据；没有证据的 claim 应保持 gap/未验证，不允许只靠语言变得更确定。

### 6.3 引用检查

```text
Use $academic-research-suite: ars-citation-check.
Check manuscript.md section by section.
For each reference report metadata, source availability, locator, and whether it supports the exact claim.
If verification fails, mark unverified and do not substitute a similar paper.
```

**预期产物**：引用元数据、来源可用性、原文定位、claim 支持关系和阻断项。

**暂停核查**：存在性、主题相关性和主张支持性是三件事；看到“存在”不等于看到原文确实支持这句话。

### 6.4 同行评审与复审

```text
Use $academic-research-suite: ars-reviewer.
Manuscript: manuscript.pdf
Focus: contribution, method, statistics, citation integrity, and venue fit.
Return evidence-anchored reviewer reports and an editorial decision letter.
State explicitly when the manuscript does not provide enough evidence.
```

修改后：

```text
Use $academic-research-suite: ars-reviewer in re-review mode.
Compare manuscript_v2.pdf against reviewer_reports/ and the change log.
Check whether each major concern was actually addressed; do not infer unseen experiments.
```

**暂停核查**：确认审稿意见指向稿件中的具体位置，区分作者必须修正的问题和仅供考虑的风格建议。

### 6.5 完整 pipeline 的安全启动

不要一开始就让 Agent 静默跑完整流程，建议分段：

```text
Use $academic-research-suite to start an academic-pipeline run.
Begin with Stage 0 intake and stop after producing the pipeline dashboard.
Show inputs, missing materials, permissions, and the next checkpoint.
```

确认后：

```text
Resume the existing academic-pipeline run.
Complete only the next stage, preserve all artifacts, and stop at the next checkpoint.
```

## 7. Codex 特有运行边界

- **一个 router skill**：五类工作流内容被 vendored 到 `academic-research-suite`，不是五个独立自动触发入口。
- **Claude 文件的角色变化**：仓库中的 agents、commands、hooks 主要用于角色/阶段提示、追溯或适配；Codex 不会自动执行所有 Claude Code hook。
- **外部核验不是默认副作用**：普通主题发现使用 Codex 浏览和权威来源；程序化 Crossref/OpenAlex/Semantic Scholar/arXiv 验证要有明确请求和适用条件。
- **跨模型审查需要同意**：cross-model handoff 是传输请求，不是现成的审查结论；配置 provider 前确认数据范围和外部上传。
- **实验边界**：ARS-Codex 可规划和审计实验 provenance，但不能凭报告证明实验实际运行或原始数据真实。
- **缓存不是证据**：缓存的元数据和 stale advisory 只能帮助复用结果，不能替代当前来源核验。

## 8. 结果核查与输出审查

- [ ] `/skills` 中只出现预期的 ARS-Codex 单一入口。
- [ ] 每个引用都有真实来源和明确的验证状态。
- [ ] 每个定量结果对应用户提供的结果、日志或可复查数据。
- [ ] 外部完成的实验带有 provenance；没有实验时显式声明 no experiments declared。
- [ ] pipeline 每个 checkpoint 都已由研究者批准，没有静默跳过。
- [ ] 生成的论文、审稿报告和修改建议与输入版本有变更记录。

## 9. 常见问题与风险处理

| 问题 | 处理 |
|---|---|
| 看不到 skill | 新开 Codex 会话，检查插件安装和 `/skills`，确认没有混装 Claude 版目录。 |
| 自动写了完整稿 | 重置为单阶段请求，要求先出 blueprint 并在 checkpoint 停止。 |
| 引用找不到 | 保持 unverified，检查标识符/格式并人工访问原文。 |
| 结果看似合理但无日志 | 退回结果输入，要求 provenance 和原始文件，不让 Agent 补写数字。 |
| hooks 或 slash command 行为不同 | 按 Codex router 和 README 的适配说明使用，不照搬 Claude Code 假设。 |
| 跨模型调用被阻断 | 明确 provider、数据范围、费用和用户同意；不能用模拟结果代替真实审查。 |
