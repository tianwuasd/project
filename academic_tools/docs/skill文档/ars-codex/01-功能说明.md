# 功能说明

> 版本说明（2026-10-19）：源码已更新；正文保留此前整理的指南，功能与安装入口以当前上游 README 为准。见[本次更新记录](../../../UPDATE-2026-10-19.md)。

## 定位

ARS-Codex 是 ARS 的 Codex 原生分发版。它把多个学术研究工作流 vendored 到一个 `academic-research-suite` skill，通过 router 根据任务选择路径；不是把 Claude Code 的插件文件原样搬过去。

## 五条工作流

| 工作流 | 功能 |
|---|---|
| `deep-research` | 研究问题收敛、综述、系统综述、元分析、事实核查和缺口分析 |
| `academic-paper` | 大纲、章节、摘要、引用格式、AI disclosure 和修订 |
| `academic-paper-reviewer` | 多视角同行评审、编辑决定信和复审 |
| `academic-pipeline` | 从研究问题到论文的阶段编排、checkpoint 和最终审计 |
| `experiment-agent` | 代码/人类研究实验规划、统计解释和复现检查 |

## 证据和路由

- 一个 `SKILL.md` 入口读取 vendored workflow 的 `WORKFLOW.md`、references 和角色提示；
- `ars-*` 是 Codex 内的意图别名，不是原生 Claude slash command；
- 普通主题发现使用 Codex 浏览和权威来源；显式程序化验证才会按条件调用 Crossref/OpenAlex/Semantic Scholar/arXiv；
- 不可验证的引用、数据或期刊政策必须保持未验证；
- cross-model handoff 是传输协议，不是自动可信的第二意见。

## 输入输出

**输入**：研究问题、论文/PDF、笔记、代码、实验 provenance、审稿意见、期刊约束和用户批准的权限。

**输出**：问题简报、检索记录、论文蓝图、引用/证据表、reviewer report、pipeline dashboard、修订路线和审计产物。

## 不适用

- 只想改一个句子；
- 期待 Codex 自动验证原始数据或替你决定研究结论；
- 没有来源却要求生成具体数字、DOI 或“首次”结论；
- 把 Claude Code 的 hooks、agents、slash commands 当成 Codex 必然可用功能。

## 与 Claude 版的区别

Claude Code 版以多个原生 skill、commands 和 hooks 工作；ARS-Codex 以单一 router、Codex plugin/skill 目录和适配层工作。研究工作流内容相近，但安装身份、版本和运行边界独立。
