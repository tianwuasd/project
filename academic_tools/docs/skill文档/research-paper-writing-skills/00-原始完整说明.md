# Research Paper Writing Skills 详细使用文档

> 版本说明（2026-10-19）：源码已更新；正文保留此前整理的指南，功能与安装入口以当前上游 README 为准。见[本次更新记录](../../../UPDATE-2026-10-19.md)。

## 0. 文档范围

本指南对应 [Master-cai/Research-Paper-Writing-Skills](https://github.com/Master-cai/Research-Paper-Writing-Skills)。它是面向 ML/CV/NLP 论文写作的规则和参考资料包，适合在已有草稿、实验结果和文献材料基础上做结构化写作与审查。

- **本地源码**：[`skills/Research-Paper-Writing-Skills`](../../../skills/Research-Paper-Writing-Skills/)
- **核心入口**：`research-paper-writing/SKILL.md`
- **知识来源**：仓库说明大部分经验整理自彭思达老师公开学习笔记，并经过结构化适配
- **文章评价**：第二篇知乎文章评为“NPC”；这是作者的主观分档，不代表不能使用

## 1. 能解决什么问题

主要帮助作者完成：

- Abstract、Introduction、Related Work、Method、Experiments、Discussion、Conclusion 的撰写或重写；
- 段落衔接、章节逻辑、术语一致性和 claim-evidence 对齐；
- 从 reviewer 视角做提交前自审；
- 根据已有草稿和实验整理更清晰的论证链；
- 使用章节修辞指南、写作清单、图表模板和 brainstorming guide。

它不负责替代研究设计、实验运行或文献真实性核验。

## 2. 前置条件

- Codex、Claude Code 或兼容 skill 的宿主；
- 论文草稿、实验结果、图表、引用和目标 venue 要求；
- LaTeX/Overleaf（如果目标是 LaTeX）；
- 对中文/英文、引用格式、字数和输出范围有明确要求。

输入最好分开保存：

```text
paper-project/
  draft/                   # 当前稿件
  figures/                 # 真实图表和源文件
  results/                 # 真实实验结果
  references.bib           # 引用数据库
  reviewer_comments.md     # 审稿意见
  venue.md                 # 目标期刊/会议要求
  claims.md                # claim 与证据清单
```

## 3. 安装

### 3.1 Codex

在仓库根目录执行：

```bash
mkdir -p "$CODEX_HOME/skills"
cp -R research-paper-writing "$CODEX_HOME/skills/"
```

### 3.2 Claude Code

全局安装：

```bash
mkdir -p "$HOME/.claude/skills"
cp -R research-paper-writing "$HOME/.claude/skills/"
```

项目级安装：

```bash
mkdir -p .claude/skills
cp -R research-paper-writing .claude/skills/
```

安装后新开会话，并在提示词中明确：

```text
Please use the research-paper-writing skill.
```

### 3.3 Gemini 或其他宿主

按宿主规则把 `research-paper-writing` 目录放入 skill 搜索路径。仓库说明的核心目录结构是：

```text
research-paper-writing/
  SKILL.md
  references/
  agents/openai.yaml
```

不要只复制 `references/` 而漏掉 `SKILL.md`。

## 4. 使用原则

每次任务先指定“本轮只做什么”：

- 只做结构诊断，不改原文；
- 只改 Introduction，不生成其他章节；
- 只检查 claim-evidence，不润色；
- 只生成 outline，等待确认后再写段落；
- 只处理 reviewer comments，不承诺尚未完成的实验。

同时告诉 Agent：

- 目标读者和 venue；
- 文章语言和引用格式；
- 可读取/写入的文件；
- 哪些数据和结论已经确认；
- 哪些句子、术语、数值和引用不能改动。

## 5. 典型使用示例

### 5.1 先做论文结构诊断

```text
请使用 research-paper-writing skill。
读取 draft/、claims.md、results/ 和 venue.md。
本轮只输出：论文主张、章节职责、论证链、claim-evidence 缺口和结构问题。
不要改写正文，不要新增引用，不要补写实验结果。
```

**预期输出**：章节诊断、主要 claim、证据缺口、结构建议和待确认问题。

**检查点**：确认建议来自输入材料，而不是模型自行构造的新贡献。

### 5.2 写 Introduction

```text
请使用 research-paper-writing skill 起草 Introduction。
输入：draft/outline.md、references.bib、claims.md、venue.md。
先列出每段的 rhetorical move，再写 4–6 段草稿。
每个主要 claim 保留引用和证据状态；不编造 DOI、论文结论、数据和 novelty。
```

**预期输出**：段落结构、过渡逻辑、Introduction 草稿、claim-evidence 表和未解决引用。

**检查点**：逐条打开文献，确认“已有工作表明”“首次”“仍缺乏”等措辞有足够证据。

### 5.3 重写 Method/Experiments

```text
请只重写 Method 和 Experiments 的表达，不改变算法、数据、参数和结果。
对照 code/configs/、results/run-log.md、figures/ 和 draft/method.md。
输出改写前后差异，并列出任何输入材料无法支持的句子。
```

**检查点**：核对数据切分、训练参数、基线、评测指标、样本量、随机种子、图表编号和实验限制。

### 5.4 Claim-evidence 审查

```text
请审查 claims.md 和 manuscript.md 的 claim-evidence 对齐。
对每条 claim 输出：原文位置、证据文件、证据强度、缺失证据、建议措辞。
把没有直接证据的 claim 标为 gap；不要通过改写把 gap 伪装成 supported。
```

**预期输出**：逐条主张审计表、证据强度、需要补充的材料和更谨慎的可选措辞。

### 5.5 审稿意见回复

```text
请根据 reviewer_comments.md、manuscript_v1.pdf、results/ 和 change-log.md，
生成 point-by-point rebuttal 草稿。
每条包含 reviewer concern、作者回应、实际修改位置、证据来源和需要我确认的行动。
不要承诺还没有完成的实验，不要虚构页码、行号或新增结果。
```

### 5.6 只做 Abstract

```text
请只生成 Abstract 的两个版本：结构化版和投稿版。
严格使用 results/ 和 claims.md 中的真实数字，保持研究问题、方法、结果和限制准确。
列出每个数字和主要 claim 的来源，不要引入参考文献或新的结论。
```

## 6. 结果核查与输出审查

### 内容与证据

- [ ] 所有数字、数据集、模型、基线和实验条件都能回到结果或代码。
- [ ] 所有引用真实存在，且原文支持当前 claim；写作 skill 本身不等于引用验证。
- [ ] “首次”“最佳”“显著”“有效”等强断言有可核查标准。
- [ ] 证据不足的句子保留为 gap/待补充，而不是被语言润色掩盖。

### 结构与表达

- [ ] 每个段落有明确功能，段间过渡服务于论证。
- [ ] Introduction 的 gap、贡献和方法/结果相互对应。
- [ ] Method 与真实代码/协议一致，Experiments 与日志一致。
- [ ] 图表、公式、变量、章节编号、引用和附录保持一致。

### 修改控制

- [ ] 保存原稿、修改稿和 diff。
- [ ] 只改动本轮批准的章节和文件。
- [ ] 未经确认没有新增实验、数据、引用、作者或页码。
- [ ] rebuttal 中的每个承诺都有对应的实际修改或已完成结果。

## 7. 失败与风险处理

| 现象 | 处理 |
|---|---|
| 文字变流畅但论证更强 | 对照原稿和证据，恢复过度确定的语气。 |
| AI 添加不存在的引用 | 停止使用该段，运行独立引用核验，删除无法证明的条目。 |
| 章节建议与实验不一致 | 以代码、日志和结果为准，先修正事实再修辞。 |
| Rebuttal 承诺新实验 | 改为明确的计划，或等实验完成后再写回应。 |
| 风格规则与 venue 冲突 | 以目标期刊/会议作者指南和领域惯例为准。 |
| 输入材料不完整 | 输出缺失清单，不让 Agent 用常识或记忆填空。 |

## 8. 与其他 skill 的衔接

- **ARS/ARS-Codex**：先做研究问题、引用和证据门禁，再用本 skill 组织论证。
- **Claude Scholar**：提供 Zotero/Obsidian 中的文献笔记和项目材料。
- **Scientific Agent Skills / AI Research Skills / AERS**：提供真实计算、模型或计量结果。
- **PaperSpine**：处理贡献优先、阶段 gate、投稿包和 reviewer audit。
- **Nature Skills**：进一步优化发表风格英文，但不能改变本 skill 已确认的科学含义。

## 9. 文章评价与责任边界

第二篇知乎文章将它评为“NPC”，认为它更像一份公开写作笔记：规则扎实但不会自动适应具体研究情境。这个判断可作为选型提示。实际使用中，它最适合作为稳定的写作与自审底座；它不能证明研究新颖性、引用真实性、实验正确性或投稿成功。
