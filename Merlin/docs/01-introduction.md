# Merlin 项目介绍

Merlin 要解决的是：如何利用医院已有的三维 CT、报告和诊断编码，训练一个可以服务多个影像任务的模型，而不是为每种任务从零建立一套独立模型。

它的主体是三维图像编码器和文本编码器。CT 经图像编码器得到特征，报告经文本编码器得到特征，训练时使同一次检查的图文表示彼此靠近；同时用电子病历中的表型标签监督图像表示。推理时可以只使用图像，不要求每例都同时提供报告和诊断编码。

## 模型的三部分

### 三维 CT 编码器

图像分支从二维 ImageNet 预训练的 ResNet-152 出发，把二维卷积扩展为三维卷积。输入是整个经过预处理的 CT 体积，不是只挑一张切片。骨干网络池化后产生 2048 维特征，再接不同的输出头。

“整个体积”仍经过重采样和中心裁剪。当前代码把输入处理成 `224 × 224 × 160`，并不意味着保留了原扫描的全部空间范围和分辨率。

源码：[build.py](../upstream/merlin/models/build.py)、[i3res.py](../upstream/merlin/models/i3res.py)、[预处理](../upstream/merlin/data/monai_transforms.py)。

### 报告编码器

文本分支使用 Clinical Longformer，把报告映射为 512 维特征。当前实现会小写化和分词清理文本，最多处理 1024 个 token，取最后一层首个 token 的 768 维表示，再线性映射至 512 维。

图像分支也有一个 512 维投影头；默认模式对两端特征作归一化，得到可用于余弦相似度比较的图文表示。2048 维图像特征不直接等同于这个图文对齐空间。

源码：[TextEncoder 与 MerlinArchitecture](../upstream/merlin/models/build.py)。

### 表型监督

论文把诊断编码映射为 PheWAS 表型，用多标签监督帮助模型学习健康状态相关特征。公开模型的表型头有 1692 个输出，但这不代表论文所有结果都评价了全部 1692 类；论文按样本数量筛选了评价类别。

源码：[分类头](../upstream/merlin/models/i3res.py)、[表型名称表](../upstream/documentation/phenotypes.csv)。论文口径详见[精读笔记](05-paper-notes.md)。

## 能做什么

| 使用方式 | 输入与输出 | 代码入口 |
| --- | --- | --- |
| 图文表示 | CT＋文本 → 图像与文本的 512 维表示，以及表型 logits | `Merlin()` |
| 图像表征 | CT → 池化后的 2048 维表示 | `Merlin(ImageEmbedding=True)` |
| 表型预测 | CT → 1692 维 sigmoid 概率 | `Merlin(PhenotypeCls=True)` |
| 五年疾病预测 | CT → 6 维 sigmoid 概率，使用另一份权重 | `Merlin(FiveYearPred=True)` |
| 报告生成 | CT＋提示词 → 生成文本，涉及 RadLLaMA-7B | `Merlin(RadiologyReport=True)` |
| 分割 | 图像骨干＋解码器，在 nnU-Net 中使用 | [独立分割仓库](https://github.com/ashwinkumargb/Merlin-nnUNet) |

模式开关、权重文件和调用入口统一位于 [load.py](../upstream/merlin/models/load.py)。

## 当前源码公开到哪一步

已包含模型架构、权重加载、标准预处理、推理示例、报告生成模块，以及 CVPR 2026 CT 基础模型挑战的特征提取代码。源码中有报告生成的损失计算，但没有原论文图文与 EHR 联合预训练的完整数据组织、损失组合、优化器和训练主循环。

因此，这份代码适合三个层次的学习：

1. 读懂网络与预处理，查看论文方法在代码中如何落地。
2. 使用公开权重提取特征，训练自己的轻量下游分类头。
3. 在理解数据划分和损失之后，自行实现新的训练流程，或者研究独立分割仓库。

不要把第二步的“使用预训练模型”写成“已复现论文预训练”。完整复现还要匹配数据、标签、报告处理、训练策略和评价协议。

## 对先心研究有什么价值

值得借鉴的是利用临床报告学习表征、在少标签条件下迁移编码器，以及把模型放到不同任务和外部数据上评价。先心 CT 的关键问题常常是细小结构和异常连接关系，整卷池化表示可能丢失这些信息。

因此，Merlin 可以作为待验证的表征基线。是否需要心脏局部输入、更高分辨率或结构化拓扑特征，要由目标任务的对照实验决定。具体思路见[先心 CT 迁移思考](04-chd-transfer-notes.md)。
