# AAOCA 原始 CT 粗分割与医生编辑

版本 0.4.0。直接读取有 HU/mm 来源依据的原始三维 CT，依次使用 TotalSegmentator 2.18.0 三个任务，输出原始 CT 网格上的 `aaoca_11.seg.nrrd`。医生加载原始 CT 和该文件，在 3D Slicer 的 Segment Editor 中修订。

## 启动和新任务

在 AAOCA 目录运行：

```bash
bash start_segmentation.sh --runtime /srv/private/aaoca-seg-terminal
```

1. `e` 安装独立环境、检查环境并验证许可，`a` 查看日志。
2. `c` 设置原始 HU/mm CSV 清单、独立结果目录和资源预算，`d` 选择获准 GPU，`w` 保存。
3. `n` 命名任务，来源默认 `0` 原始 HU 清单；按需限定体积代号，默认步骤 `1,2,3`。
4. `s` 查看进度，`l` 或 `f` 查看日志，`o` 查看结果。退出面板或断开 SSH 后后台继续运行。

每个三维期相对应清单一行。确认 HU 和毫米单位需要来源依据。输入、结果和运行环境分别保存。清单格式见[粗分割说明](tools/coarse_segmentation/README.md)。

## 执行和保存内容

| 阶段 | 行为 |
|---|---|
| 输入核验 | 检查三维空间、毫米单位、HU 来源和完整 SHA256 |
| 模型推理 | total 三种静脉、heartchambers_highres 七结构、coronary_arteries |
| 标签导出 | 保留名称、颜色、全部重叠区域和原始 CT 空间，原子保存 .seg.nrrd 并完整回读 |
| 清理 | 最终文件核验成功后，删除本任务十一份中间掩膜及临时解压 CT |

外部不生成重采样 HU 或归一化 CT 副本。模型内部执行其需要的重采样、裁剪和标准化，预测输出恢复到输入网格。没有 fast 模式，不自动补接血管。

每个体积保留一个 `aaoca_11.seg.nrrd`，以及必要的小型私人结果、来源、质检和日志。`result.json` 记录原图引用、最终文件哈希、结构体素数与体积、空掩膜和待审核状态；这些记录与输入清单不发布。

相互不重叠的结构共用标签层；重叠结构使用独立层。名称采用上游英文结构名，编号与颜色固定。医生另存审核版本，重点检查冠脉开口、近端走行、血管连接和细小分支。程序质检不表示临床准确性已验证。

## 恢复、历史任务及更新

- `r` 沿用输入、冻结代码、环境和输出。完整最终标签经输入/输出哈希核验后复用，已清理的掩膜不参与复用检查。源文件、配置或最终标签损坏时明确停止。
- 推理完成但导出未完成时保留掩膜，可继续 CPU 导出；推理中断时重新执行该体积的模型任务。
- `k` 在新目录重跑已完成任务，保留旧成果。中间掩膜已清理的任务不能仅重新合并。
- `x` 仅请求停止选中任务；等待相关进程退出后再进行清理。
- 既有冻结任务沿用原冻结代码。显式旧来源和旧格式读取保留原合同，旧结果不被自动转换或清理。
- `u` 将新版安装到运行目录内的独立发布目录，历史任务代码不变。旧环境应安装更新后的 `requirements-inference.txt`。

GPU UUID 分配、CPU/RAM/I/O 共用预算和后台身份检查沿用现有队列。内存与磁盘为程序估算，实际峰值随体积和重叠层数变化。模型与许可保存在私人运行目录。

```bash
python3 start_segmentation.py --runtime /srv/private/aaoca-seg-terminal --query status
python3 start_segmentation.py --runtime /srv/private/aaoca-seg-terminal --query history
```

GitHub 仅发布源码、格式验证和通用说明。影像、真实病例代号与路径、清单、输出、许可、权重、日志和私人验收记录保留在本机。
