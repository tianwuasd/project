# AAOCA 子目录代码更新

目标：采用 v2 的目录元信息、精确文件清单、完整对象校验及先验证后应用顺序，更新既有 AAOCA 目录。用户要求使用镜像，只更新本项目并清理残留。

实现使用独立标准库程序 update_aaoca_code.py 和已有 Git。确认过滤能力，以浅层 blob:none 获取公开仓库的提交及目录元信息，再枚举 AAOCA 子树并显式分批获取缺失 blob；本地读取禁止隐式联网，库存必须仅包含该清单的 blob。每份文件核对大小与 Git blob SHA1，Python 文件只编译而不执行。下载及准备总上限900秒，单文件最大512 KiB、完整代码上限8 MiB、本地读取并发4路。

全部新文件核验完成后，在目标磁盘预写全部候选文件，原代码通过同盘改名保留，逐文件原子替换。应用失败通过改名恢复本次已修改文件；数据、环境、模型、Git 元信息、冻结任务及其他项目路径均不属于文件清单。已有更新回执管理的退役源码，只有当前字节仍匹配旧回执时才删除。未知文件保留。

临时下载、备份及原子写入文件具有明确归属，成功、失败或可处理的中断后清理。更新锁使用独占目录，避免并发应用；未知锁不自动删除。最小来源回执保存在代码目录，供下次清理退役源码及查询版本。原来的管道下载没有保存归档文件，部分解压代码通过完整源码清单覆盖并验证。

文件：新增更新程序、通用使用说明与两个真实源码目录的检查入口；更新 README、分割说明及 .gitignore。维护源码与公开副本保持一致，只发布这些文件。

验证：获准的 back/aaoca-code-update-check-20261113 目录、两份源码目录、总量小于20 MiB，不读取CT、不执行模型。实际验证镜像元信息/文件下载、字节校验、重复更新、退役源码清理、未知文件保留、坏快照拒绝及下载失败后的清理。完成后记录数量、大小、耗时并删除整个测试目录。
