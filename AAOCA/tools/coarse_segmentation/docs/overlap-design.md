# Bounded CPU preparation and export overlap

The direct runner uses a CPU prepare stage, a bounded ready queue, GPU inference and CPU export. Preparation hashes the immutable source, validates original HU/mm geometry and finite voxels, and losslessly decompresses gzip NIfTI once. It does not resample, crop or normalize CT. A receipt binds the source and prepared file hashes to the owned case attempt. GPU workers verify that receipt before using it. Successful inference removes its owned decompression file.

The scheduler admits one owned inference case per selected GPU. Other jobs may share that GPU under the existing free-memory-plus-reserve policy. Preparation and export have separate worker caps; total CPU/RAM/I/O budgets still bound all active processes. Ready and preparing cases share a prefetch cap. Ready files remain reflected in actual filesystem free space; active stages reserve conservative additional disk allowances separately for preparation, inference and export. A new phase must fit alongside active reservations. With no active phase and insufficient space, execution fails explicitly and retains reusable caches. Preparation receives a slab-based memory allowance; inference and export keep the full case allowance.

Defaults are one prepare worker, one export worker, prefetch equal to selected GPU count, and total workers/I/O equal to GPU count plus prepare and export caps. Arguments can reduce these limits. Two selected GPUs therefore default to up to four active processes, including CPU stages. Resource limits may reduce actual overlap. First inference still initializes model caches serially before multi-GPU inference begins.

Source headers and stat identities are checked first; expensive source hashes and decompression run in CPU prepare processes. Prepared source hashes are durably frozen as preparation completes. Resume prioritizes final labels and inference checkpoints, then validates any prepared receipt; damaged sources or cache files fail explicitly. Interrupted preparation removes only its partial file. Stopped ready inputs remain bounded and reusable until the task resumes.

Stage start/end events and ready-wait durations are private runtime records. The three trained models, their numerical operations, original-grid segmentation, names/colors/overlaps, final verification and mask cleanup remain the same. Model-internal resampling is still performed by TotalSegmentator. This change makes no guaranteed throughput claim.

An empty ROI returned by TotalSegmentator may omit the NIfTI spatial unit. The runner restores millimetres only with the model's explicit empty-crop log, an all-zero mask, an exact source shape and matching affine from a known-millimetre CT. It atomically writes and verifies the metadata before freezing mask hashes. Nonempty or spatially inconsistent unknown-unit masks fail. Repairs and empty structures remain explicit in QC; an all-empty export does not establish useful anatomical segmentation.

An explicit --continue-from option creates a new task for remaining volumes after an old task stops. It audits the old frozen request, source files, tracked dependency versions, unchanged model/label/export algorithm files, original input hashes and final label hashes. Verified completed labels remain in their original task directories and are referenced by the immutable continuation record. Old tasks keep their own code and are not rewritten. Continuation chains are bounded, cycle-checked and recursively validated.

Validation uses two small format fixtures and two authorized native CT volumes, zero training updates. It checks real preparation bytes/geometry, cached reuse and corruption rejection, event overlap, final label readback and resumed reuse. All approved temporary artifacts are removed after recording measurements. Source-only publication excludes private inputs, identifiers, credentials, weights and results.
