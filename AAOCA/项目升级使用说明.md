# AAOCA 资料整理与增量项目

## 日常使用

双击 `一键处理.cmd` 打开本地面板。输入为本批次资料所在目录，输出为固定的项目结果目录。CT、超声、PDF、患者主表可以任意组合，不要求四种资料同时存在。一个编号没有某类资料时，已有资料仍会处理。

支持多个输入目录或单个文件；在输入栏用 ` | ` 分隔路径。文件发现范围为 `.dcm`、`.dicom`、`.pdf`、`.xlsx`，不自动解压压缩包，也不扫描链接目录。

1. **添加资料 / 继续处理**：首次用空结果目录；以后仍选这个结果目录，只填写新增资料目录。已登记的旧资料不会因本次未提供或旧盘离线而消失。
2. **修复数据…**：点击主界面独立按钮打开修复窗口。三种修复选项均在此窗口选择，不与普通处理混用。输入留空时使用已登记的源路径；需要补充资料时可另填。与本次处理无关的旧源目录无需在线。
3. **仅更新报告**：无需原始资料目录，使用已保存的记录更新汇总及分类。
4. **只检查，不转换影像**：登记资料、提取 PDF 文字、检查影像头和几何；不把未解码的影像当作转换成功。

可限定本次转换的编号；报告仍保留整个项目，未选中的新资料显示“已登记，尚未处理”。暂停、安全停止和再次开始均保留已经完成的处理单元。安全停止后可单独更新报告。

## 可选修复及边界

在独立修复窗口勾选所需方法，点击 **执行修复 / 重试**；不勾选任何方法时仅按现有规则重试。窗口显示阶段进度、本次处理/复用数量和运行日志；完成后显示 CT、超声、PDF 的成功、失败、待关联数量前后变化。此对比是**全项目报告统计**，不等同于本次修复成功项数；首次没有旧报告时以“—”表示未知。

修复窗口可暂停、安全停止，并通过 **查看结果与问题** 打开详细报告。关闭正在执行的修复窗口或主窗口时，会先安全停止任务。主界面与修复窗口同一时间只运行一个任务。打开修复窗口本身不会开始修复，也不会自动重新扫描主界面的资料目录。

修复窗口首次打开时带入主界面的结果目录和限定转换编号；再次点击按钮会返回已经打开的窗口，保留其中的选择。编号仅限制转换处理，身份关联仍核对整个项目，报告也覆盖全项目。普通处理不启用新的可选修复；此前已确认的修复依据仍按原规则保留。

- **唯一姓名匹配**：优先使用主表或此前已确认的姓名/姓名别名，要求唯一命中；不做拼音推测、近似字匹配或同名多患者合并。编号与姓名分别指向两个已登记患者时保留待核实。
- 已接纳的姓名关联与副本选择会保存；下次不勾选也继续有效。源文件身份依据变化、新主表引入同名歧义或原修复验证不再成立时重新核实。历史确认不能仅凭同一路径套用到新患者。
- **完整副本选择**：同一 SOP 编号的多份文件中，身份、几何、像素解释参数必须一致；完整副本须实际解码；多个完整副本的像素必须逐点相同。不同内容的有效影像不随意取舍。
- **明确期相拆分**：仅使用明确的心动期相、时间位置或触发时间标签；每组至少 3 张，切片数量相同、位置规则且各组覆盖同一空间网格。遇到一致但矛盾的层间距标签，仅在上述条件验证通过后按实际坐标输出，原标签及处理证据保存在修复日志。
- 不修补缺失像素，不补切片，不猜超声时间向量，不自动 OCR，不确认临床诊断或同次就诊对应。
- 某次更新失败时保留以前的成功输出，并另记本次失败。身份依据被否定、输出丢失等情形不会继续计为当前可用成功结果，原文件和历史记录仍保留。

已有明确身份规则可通过命令行 `--policy` 导入 JSON。`id_aliases` 为“旧编号 → 主编号”；`roster_overrides` 为已确认的主表合并记录（可含 name、name_aliases、aliases、fields）。编号均用字符串以保留前导零。该规则只能来自实际核对，不能以猜测生成。

## 分类和报告

患者目录按编号命名，分为：三类结果齐全、缺 PDF、缺 CT、缺超声、缺 PDF 和 CT、缺 PDF 和超声、缺 CT 和超声、三类结果均缺。齐全组另标 CT 部分失败、文档待核实、超声标定待核实等子类。

“缺”是**没有对应的成功成果**，报告另外区分尚未提供、已有但失败、待关联、已检查未转换。三类齐全不代表所有序列成功，也不代表临床扫描范围或超声切面完整。PDF 文字提取不足仅作备注，不计错误。

- `查看结果.html`：累计概况、分类、编号关联/数据本身/资料缺失三类问题、本次变化。
- `患者分类表.csv`、`详细问题表.csv`、`处理单元表.csv`：可检索的明细及输出路径。原始序列、期相体积、超声文件、帧、PDF 页是不同统计单位。
- `项目数据快照.json`、`report_history`：当前与每批历史报告；历史报告用于查看当时数据，后续分类调整可能使旧报告中的路径改变，当前报告以最新路径为准。
- `details/project.sqlite`：项目登记、编号映射、处理单元和历史；请与患者结果一同备份，不要单独删除。
- 患者目录的 `ct` / `us` 下保存输出版本，版本内的 `repair_log.json` 记录修复证据；旧版本保留，不静默覆盖。
- PDF 文字与逐页信息先保存在 `documents`，可靠关联后在患者报告中列出。原 PDF 保留在输入目录。

## 旧结果接纳

旧目录必须有 `processing_manifest.json` 和 `患者总表.csv`。首次接纳读取当前结果表、患者记录、头信息索引和输出元数据，不重新解码原始影像；保留已确认编号关联、完整副本恢复、期相恢复和原有输出。迁移核对输出存在性与文件大小，沿用此前回读验证记录，不声称重新完成全部像素验证。

新项目采用独立状态文件 `project_run_status.json`。原始 DICOM、PDF、主表从不改写。分类目录改变使用移动日志；中断后再次刷新报告会继续完成登记。不要让旧版单批脚本直接重跑已升级目录。

## 命令行

在代码目录使用本项目 Python 环境：

```text
python run_project.py --input "D:\本批资料" --output "D:\项目结果"
python run_project.py --input "D:\补充CT" --input "D:\补充文档" --output "D:\项目结果"
python run_project.py --output "D:\项目结果" --action retry --match-names --recover-copies --split-phases
python run_project.py --output "D:\项目结果" --action report
```

源文件路径改变后：只刷新报告不受影响；若要扩充原序列，需要原切片在线，或在新目录找到与登记 SHA256 完全一致的副本。仅凭文件名相同不能替代离线源文件。

Windows 环境建议使用短的项目根目录，例如 `D:\AAOCA_results`。本次验证使用实际 AAOCA 项目路径；未对所有系统的超长路径配置作兼容保证。
