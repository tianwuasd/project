# 病例＋CTA/CT＋超声，一键统计和转换

## 最简单的用法

双击本文件夹的 **一键处理.cmd**，会打开中文操作窗口，选择或粘贴两个路径：

1. 输入路径：例如 `D:\AAOCA_input`。选择同时包含 AAOCA 影像和患者病历文书的共同文件夹。
2. 输出路径：例如 `D:\AAOCA_results\run_01`。首次使用可选空文件夹或填写新路径；继续上次任务时，选择原来的结果文件夹。

点击 **开始 / 续跑**。窗口显示总进度、当前阶段进度、已用时间，以及本次转换和跳过的数量。完成后点击 **打开结果**，查看汇总页和中文 CSV 表格。“处理完成，请查看问题清单”不代表脚本崩溃；它表示有缺失影像、坏文件、待确认病例等，应查看问题清单。

默认会处理输入范围内全部患者：统计、检查、提取病例文本，再转换可用影像。数据多时可能需要较长时间和足够的磁盘空间。处理时请勿修改原始文件。

## 暂停、停止和下次继续

- **暂停**：暂时停住，窗口保留；点击 **继续** 恢复。
- **安全停止**：保存已经完成的工作，然后结束本次任务。正在运行时关闭窗口，也会先请求安全停止。
- **下次继续**：选择相同输入、输出路径，以及相同的限定患者范围，再点 **开始 / 续跑**。成功且核验通过的项目自动跳过；上次失败或没做完的项目重新尝试。

暂停和停止需要等到安全检查点，当前一次解码、压缩或系统读写可能要先完成；窗口会显示正在等待，不应直接强制结束进程。进度按处理阶段估算，不代表精确剩余时间。

续跑会检查原文件的路径、大小、修改时间，并核验已生成文件的校验值。源文件变化或结果损坏时，只重做受影响的项目，旧结果放入输出目录的 `back/`。若修改原文件后刻意保持大小和修改时间不变，请勾选 **强制重做**。日常运行不要勾选它。

保留原输出目录中的 `details/resume.sqlite` 等文件，才能快速续跑。旧版结果第一次续跑需要额外核验，可能稍慢。换一套输入数据或更改限定患者范围时，请使用另一个输出文件夹；同一个输出文件夹不能同时开两份任务。

## 遇到错误会怎样

坏片、缺少解码插件、某个超声文件失败、某位患者处理异常，会记录原因并继续处理其他可处理项目。异常 CT 仍按整组序列拒绝，避免把缺片结果当成完整 CT。修复源文件或环境后，使用原路径续跑即可重试。

磁盘已满、进度数据库无法使用、输入子目录读不全等影响整次结果可靠性的问题，会安全停止并显示原因。已完成的结果保留；修复原因后再续跑。脚本不会自动修复损坏影像，也不会把失败项标成成功。

## 得到什么

| 文件 | 内容 |
|---|---|
| 查看结果.html | 不联网也能打开的患者汇总页 |
| 患者总表.csv | 每位患者的病例关联、CT/CTA数量、超声数量及转换状态 |
| CT序列表.csv | 每个CT序列的切片数、层厚、实际层间距、宽高、像素间距、设备、管电压/电流、重建参数、CTA判定依据和失败原因 |
| 超声文件表.csv | 每个超声文件的静态/视频类型、帧数、宽高、颜色、时间信息、物理标定和压缩历史 |
| 病例文档表.csv | PDF对应的患者、关联依据、页数、缺少文字的页码和提取文本位置 |
| 问题清单.csv | 缺影像、坏片、关联冲突、需OCR、重复文件等问题 |
| patients/ | 每位患者的CT `.nii.gz`、超声PNG/NPZ、病例文本和patient.json |
| pending_documents/ | 仅姓名匹配、尚未通过编号确认的文档；不当作已核实的患者病例 |
| processing_manifest.json | 本次运行范围、读取数量、最终状态 |
| details/ | 文件索引、续跑进度数据库、来源清单、JSON明细；日常不用打开，续跑时请保留 |
| back/ | 重做时归档的旧输出，不是原始影像 |

CSV 可用 Excel 打开；JSON 和文件索引保留原始编号字符串。含前导零的编号在 Excel 中应按“文本”导入，避免 Excel 自动删零。

## “完整性”到底检查什么

- **有没有文件**：输入范围内有没有该患者的 CT、超声、病例、检验资料。
- **文件是否可用**：有没有空像素、长度异常、位置重复或间隔异常，能否实际解码并转换。
- **临床检查是否齐全**：仅凭现有文件不能证明冠脉扫描范围完整、超声标准切面齐全，或所有原始切片都已导出，因此明确写“未知/需人工核对”。

CT 和 CTA 分开记录。带明确 CTA/冠脉造影描述的归为“CTA描述明确”；只有心脏增强证据的归为“疑似CTA”；其他CT不冒充CTA。判定来自文件标签，不是对图像作诊断。

超声静态图与多帧文件分别计数，总帧数包含静态图。超声 `.npz` 是给程序读取的全帧数据包，不是可双击播放的 MP4。

## 病例如何与影像对应

Excel 的门诊号/患者编号与 DICOM PatientID 对应，住院号作为独立别名保留。PDF 中明确的患者编号用于核对，并检查全文页面是否存在编号冲突。只有姓名相同而无编号证据时进入待确认；同名、不同编号、表格记录冲突不会自动合并。

关联层级是“同一患者”，不是“同一次就诊”。不同日期的影像会保留各自检查UID、日期和序列。PDF全文按页提取并规范空白和字符，不把手术同意书中的风险条款当作患者诊断。

无文字层/无有效文字的页面会标记为待核对或需OCR；本版本没有自动OCR，也无法还原原PDF中已被截断的文字。

## 清理做了什么

原件只读。字节完全相同的重复DICOM只在输出选取一次，并记录被略过的副本；同SOP编号但内容不同的文件会阻断相关转换。异常CT拒绝整个序列，不补片。超声按文件独立处理。成功转换保留数值、时间与空间信息，并做写回读取验证。

首/中/末切片或帧会计算基本数值指标，恒定图像提示复核。这不是医学图像质量评分；不自动降噪、美化、补帧、生成分割标注或正式脱敏。病例和图像上的姓名/文字可能仍在输出中。

## 输入支持范围

当前支持：后缀 `.dcm` 的常规CT及2D超声文件、带患者编号列的 `.xlsx` 患者表、`.pdf` 病例。压缩包只记录，不自动解压。其他格式列入输入目录清单；无后缀DICOM不扫描。

不扫描本脚本目录、back、test_outputs、.venv、__MACOSX、符号链接，以及有 processing_manifest.json 的旧结果目录。输入可以是包含多个数据子目录的总目录，输出也可以是总目录下的新目录，程序会排除它。

## 可选命令

不想双击，也可以在本文件夹运行：

```powershell
& './.venv/Scripts/python.exe' -X utf8 './run_pipeline.py' --input 'D:/AAOCA_input' --output 'D:/AAOCA_results/run_01'
```

只测少量指定患者，在命令末尾加 `--patients 000123 000456`。该筛选根据患者目录名/文件名执行，避免打开其他患者影像；需要输入保持这种编号组织方式。

只想快速清点，可加 `--audit-only`。此时仍提取匹配病例，但影像只检查文件头和像素长度，不解码、不转换，会明确标“像素未全检”。

命令行再次使用相同路径会自动续跑；加 `--force` 可强制重做。命令行按 Ctrl+C 中断后也可续跑；窗口里的暂停按钮只在图形界面提供。

退出码：0完成且无问题；2完成但有待处理问题；1运行失败；130手动中断。不要把状态仍为running/interrupted/failed的结果当作完整结果。

## 环境

需先安装 Python 3.12 或以上（Windows 安装时包含 Tcl/Tk），在本目录创建 `.venv` 并安装 `requirements.txt`，步骤见 README。压缩DICOM可能另外需要对应解码插件；缺少插件会记录失败。PDF与Excel处理均在本机进行，不上传外部服务。


## 公开版本说明

文档中的路径及患者编号均为虚构示例。本仓库不包含真实病例、影像、患者清单、转换产物或本机运行记录。测试使用程序临时生成的模拟资料，运行方法见 README。
