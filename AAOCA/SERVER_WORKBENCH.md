# AAOCA 中文服务器工作台（1.3）

独立的 Linux 服务器终端入口，结构参考 CHD CT 项目的“任务主页 → 新建并命名 → 步骤 → 配置”面板。当前只接入 **图像强度归一化 + 重采样**，后续步骤尚未接入。无需 Tk、浏览器或 GPU。

1.3 每例另存同网格的未截断 HU 配套影像。预处理完成后，单独打开 [分割工作台](SEGMENTATION_WORKBENCH.md)，选择这次预处理任务即可进行粗分割；两个入口及各自的运行环境仍然独立。

## 安装与启动

在本仓库 `AAOCA` 目录中，使用独立的 Python 3.10+ 预处理环境：

```bash
python3 setup_aaoca_environment.py --env /path/to/aaoca_env --runtime /path/to/aaoca_panel
export AAOCA_PREPROCESS_PYTHON=/path/to/aaoca_env/bin/python
bash start_aaoca_server.sh \
  --input /path/to/hu_nifti \
  --results /path/to/preprocessed \
  --runtime /path/to/aaoca_panel
```

三个目录需彼此独立，不能互相包含。示例路径需替换；输入必须是已经转换、保留 HU 的 NIfTI CT。DICOM 整理和转换仍由原来的资料处理入口完成。

已有环境可设置 `AAOCA_PREPROCESS_PYTHON=/path/to/venv/bin/python` 后运行脚本。也可执行 `python start_aaoca_server.py`，安装后执行 `aaoca-server` 或 `python -m aaoca_server`。启动脚本只打开面板，不安装依赖，不启动处理。请固定后台任务所用的代码与环境。

```text

    2  结果根目录

    4  CPU 总预算           auto
    5  内存预算 GiB         auto
    6  输入清单             可选
    7  临时根目录           可选，建议本地快盘
    8  病例并发             auto
    9  每病例计算线程       auto
   10  读取并发             auto

```

主页 `c` 可单独保存配置。`p` 只读头信息，`w` 只保存配置。新任务的 `s` 展示间距、病例数、输出体积估算及资源预算，输入 `y` 才启动。主页回车查看状态。各输入支持 `b` 返回、`q` 退出；名称只用于展示，目录使用时间和随机 ID。

`l` 显示最近最多 64 KiB 日志，`f` 持续查看，Ctrl+C 返回面板。退出面板或断开 SSH 后，已提交任务继续运行。`x` 请求停止当前选定任务，可能等待正在进行的压缩写入完成；`r` 续跑并校验、复用完成的病例。停止/续跑前会显示具体任务和路径。

## 数据处理进度条

主页 `s` 查看一次，`p` 每秒刷新；也可直接运行：

```bash
bash start_aaoca_server.sh --runtime /path/to/aaoca_panel --watch
```

显示示例（示意数值）：

```text
病例进度 [##############----------] 60.0% (6/10)
新完成 3 | 复用 2 | 失败 1 | 剩余 4
case_a：重采样 [########--------] 50.0% (40/80) 层
```

病例进度计入已完成、复用和已失败病例，失败单列，100% 不代表全部成功。切片进度只展示后台已记录的重采样/归一化计数；解压、压缩和校验阶段显示实际阶段，不虚构百分比。没有统计时显示等待统计。后台进度通常在阶段改变或约 2 秒后落盘，因此每秒刷新不代表每秒都有新数据。Ctrl+C 只结束查看，后台任务继续。

## 按顺序更新与镜像配置

主页 `u` 或 `--update` 更新预处理工作台，`m` 配置顺序。默认代码线路为 **GH-Proxy.com → GHfast → GitClone → GitHub 原站**。这是可调整的优先级，不是 zmic44 的速度测量结果；不会先遍历所有镜像测速。配置保存到面板目录的 `mirrors.json`，例如：

```json
{"code": ["gh-proxy", "ghfast", "gitclone", "official"], "pypi": ["tuna", "sjtu", "aliyun"]}
```

更新先限时 12 秒查询官方提交，再按顺序下载。每个线路的 Git 获取与按需代码提取分别限时 45 秒。**首个通过提交关系、归档和入口检查的版本即停止尝试其他镜像**；若与当前版本相同也立即结束。官方可达时拒绝落后镜像；官方不可达时明确提示“官方最新状态未确认”。全部失败时保留当前代码，并在 `update-last.json` 记录原因。

更新要求已下载的 `main` Git 工作副本、干净工作区，以及在仓库外的 `--runtime`。已知历史镜像 origin 可识别，无需重写 origin。安装后的 `aaoca-server` 可用 `--checkout /path/to/project` 指定 Git 工作副本。存在本面板登记的运行任务时不更新；未知状态也不放行。

只把预处理代码安装到 `<runtime>/releases/<提交号>/`，不替换共享 Git checkout，不更新独立分割面板或原始资料整理模块。旧代码保存在 `<runtime>/backups/`；任务历史记录原代码和 Python 路径，续跑仍核对原实现与依赖。其他打开的旧面板不能继续提交新任务，需重新打开。更新成功退出面板，使用原启动命令和相同 runtime 再次打开即可载入新版。下载工作目录保存在 `<runtime>/downloads/` 供核查，当前不自动清理。

### 环境安装单独进行

`setup_aaoca_environment.py` 只创建**尚不存在的新环境**，按清华 TUNA → 上海交大 SJTUG → 阿里云顺序尝试，单次安装最多 300 秒，连接超时 20 秒、重试一次。每次只使用一个包索引，安装及导入检查成功后停止；不使用 `extra-index-url` 同时请求多个镜像，不改全局配置。镜像地址依据 [TUNA 文档](https://mirrors.tuna.tsinghua.edu.cn/help/pypi/) 和 [SJTUG PyPI](https://mirror.sjtu.edu.cn/pypi/web/simple/)。

程序更新不运行 pip。需要新依赖时用独立安装入口和新的环境目录；它读取同一 runtime 当前发布目录作为安装来源。安装记录在新环境的 `install-report.json`；失败环境保留供排查，重试选择新目录。历史环境继续留给历史任务，不在运行时升级。安装后按输出的 Python 路径设置 `AAOCA_PREPROCESS_PYTHON`。

旧版本尚无 `u/m/p` 时，需要先下载包含本功能的 GitHub 代码；旧面板不会自动获得新菜单。

## 自动间距与强度

- 默认 `auto`：使用本批输入原始 RAS 头信息的各轴间距中位数，明显各向异性时采用既有模块的第 10 百分位修正。计划先展示结果，再将具体三轴间距写入任务。
- 这是借鉴 nnU-Net v2 中位数/各向异性规则的几何策略，不是完整实验规划；不推断网络、patch、标签统计或最佳效果。
- 输入清单可限定统计范围。训练研究应在训练集选定间距，再手动给验证/测试集使用同一间距，避免各数据集分别拟合。
- 保留完整扫描视野和物理坐标关系，按 RAS 排列轴并保留斜切/剪切；在 HU 域线性重采样后执行 `clip(HU, -1000, 1000) / 1000`，输出 float32 `[-1,1]`。
- 尺寸取整后，以完整体素覆盖范围和中心不变计算实际 spacing，实际值可能与目标值略有差异，记录在 affine 和病例记录中。没有自动裁剪、配准或抗混叠滤波。
- 续跑保持原输入清单和具体间距，新菜单设置不改变旧任务。自动间距遇到无效头信息会报错，需修正输入清单或选择明确间距后查看逐病例错误。

## 自动 CPU 和内存

默认采用偏吞吐的估算，取消固定单病例、单线程、8 GiB 的自动模式上限：

1. 结合进程可见核心与 Linux cgroup 当前组、祖先组配额。采样可见核心约 0.2 秒，自动 CPU 预算为 **可见容量 × 空闲比例 × 90%**，向下取整，最低一个执行线程；采样失败时按可见容量的 90%。小于一个 CPU 的配额仍由操作系统限流。
2. 内存结合系统当前可用量与 cgroup 剩余额度，自动预算为其中的 **90%**，留出 10% 余量；自动单病例上限随该预算变化，不再固定 8 GiB。
3. 用病例工作内存估算的第 75 百分位、CPU 和内存选择病例并发（最多 32）。剩余 CPU 分配到每病例分块计算（自动最多 8 线程）；读取并发单独控制（自动最多 8），避免 NAS 过多同时解压读取。单病例时也最多自动分配 8 线程，可在配置页手动增加。
4. 实际调度按各病例的估算内存之和排队，大病例不要求所有病例都按最大值预留；超预算病例记录失败。若并行分块使原本能容纳的病例超预算，会先降低自动计算线程。

手动数值是用户上限，仍受可见资源和病例数约束；手动 CPU 不再乘短时空闲比例，其他 `auto` 字段继续自动计算。预算是估算，不是系统硬隔离或资源预留，不保证最优速度。后台保留阶段耗时与采样峰值内存，可用已有 `benchmark` 比较实际吞吐。

每次启动/续跑重新读取资源状态，将选择写入 `resources.json`，预览与实际选择可能不同。资源变化不影响冻结的间距和 HU 映射。运行中不持续调节线程数，病例内存队列一直生效。原 `aaoca-preprocess` CLI 的显式资源默认值保留，新工作台启用自动策略。

## 状态与结果

```text
aaoca_panel/                  面板配置和历史
  settings.json
  history.json
preprocessed/
  时间-ID/                   影像、病例记录、dataset/progress/failures
    cases/<代号>/image.nii.gz      float32 [-1,1]
    cases/<代号>/image_hu.nii.gz   同网格、未截断 HU，供分割使用
  时间-ID.runtime/           冻结输入/参数、进程身份、worker.log
    preview.json             启动前显示的计划
    resources.json           最近一次后台实际资源选择
```

默认面板目录 `~/.local/state/aaoca-server`，可用 `AAOCA_SERVER_RUNTIME` 或 `--runtime` 指定。多终端应使用同一目录，它会串行提交并拦截已登记的活动任务。其他面板目录或面板外提交的任务不在此登记范围内。

只读查询不会扫描整个数据盘：

```bash
aaoca-server --runtime /path/to/aaoca_panel --status
aaoca-server --runtime /path/to/aaoca_panel --logs
```

帮助、配置显示、历史和日志读取不导入数值库；实际处理需安装依赖，进程确认需要 psutil。PID 与创建时间一起核对，不能凭锁文件存在判断任务运行。进程已退出而记录仍在运行时会显示中断，可检查后续跑。

1.3 增加 HU 配套输出并改变实现指纹，**旧任务须使用原代码和环境续跑**。原有归一化成果仍可按原用途使用；要进入新的分割路径，请从原始 HU 新建 1.3 任务。新任务的磁盘估算包含两份影像。不绕过校验，任务执行期间不要替换其代码或环境。

本版使用合成 NIfTI 验证菜单、资源边界、后台生命周期和数值一致性。Windows 测试与 Git Bash 入口检查不等同于目标 Linux 服务器实测；当前未声称服务器已部署或真实数据已处理。
