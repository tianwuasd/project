# v0.3.5：更新后无法新建任务

用户完成task4表单的GPU设置后，程序报“请选择本项目专用子目录”，尚未进入RUN提交预览。该任务没有创建，也没有从历史中丢失；更早的历史输入列表仅用于选择旧输入，不能用来确认新任务是否提交。

原因：GitHub更新把新版本放在`<runtime>/releases/<40位提交SHA>`，而新建任务的通用路径保护禁止runtime成为代码目录的祖先。它把更新器的合法布局也误判了。修复仅为runtime提供明确例外：当前代码直接位于该runtime的releases下、目录名为40位小写提交SHA且存在release_manifest.json。根目录、用户主目录、代码目录及其内部、普通检出的代码祖先仍拒绝；结果与原始数据的独立性规则保持。

新建输入页同时明确“尚未提交”和旧输入列表的含义，步骤默认值按逗号列表显示。没有增加新计算模式、修改GPU资源范围或训练协议。

## 使用

在原面板选择`u`更新并重开，确认标题v0.3.5或更新；原runtime不变。该错误不影响更新入口。重新用`n`填写task4，旧输入选0，核对设置，看到提交预览后输入RUN。确认“已提交：task4”和唯一任务目录，再用`s`或`h`查询。不要删除runtime、history.json或旧任务目录，也不修改受管release源码/清单。

旧入口网络问题另按[手动Git升级](SERVER_GIT_UPDATE.md)。CPU规划修复和检查点恢复保留；旧任务仍使用冻结代码，不自动迁移。
