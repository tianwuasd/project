# 运行期间更新代码

任务开始时，在短代码读取锁内复制已经登记的项目源码，随后完全从快照导入。训练、预处理、验证和预测期间释放维护代码的锁。更新器保留自身互斥锁与短代码写锁，同一运行目录的业务锁继续防止重复训练。

维护目录继续为 `/data4/zhangruichen/code/chd-segmentation`。快照位于 `/data4/zhangruichen/course/chd-segmentation/code-snapshots/<提交SHA>-<内容摘要>/code`，仅包含源码、配置、脚本和文档；原始病例、预处理数组、权重、环境及日志均沿用各自路径。同一版本共享一份快照。启动时核验快照内容；快照不自动删除，以便子进程和阶段接续使用。确认相关任务全部退出后，可单独清理不再需要的版本目录。

`CHD_RUNTIME_DIR` 可以指定本机过程目录，必须位于维护代码之外。`CHD_CODE_SNAPSHOT` 由启动器向子进程传递，继承时检查来源路径；普通新任务使用独立终端启动即可选择当前维护版本。Python 包模块入口也会选择快照，覆盖 Total 的模块及 nnU-Net 子进程、Q 分阶段入口和训练进程。安装到环境中的独立 wheel 保留其安装版本，维护目录的更新不修改环境。

`python -B run.py --code-info` 返回实际快照路径、源维护目录、完整提交 SHA、内容摘要与修改状态。业务启动日志的 `code_ready` 记录相同信息。后续维护目录更新不会修改既有任务的快照。新代码中的修复通过停止任务、从完整检查点重新启动生效；运行期间更改环境依赖不属于代码更新隔离范围。

首次采用本机制前，需要停止仍然直接读取维护目录的旧任务。完成首次更新并重新启动后，后续可以在任务运行期间执行 `python3 -B update.py --force --mirror auto`。`--force` 仅用于维护目录同步，不修改快照或训练检查点。旧版任务持有的代码读取锁仍会阻止这次首次更新。
