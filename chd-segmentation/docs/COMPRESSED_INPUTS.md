# STU-Net 与 Q 的压缩输入

新建预处理任务默认使用无损 Blosc2/ZSTD，写出 `image.b2nd`、`label.b2nd`、`locations.npz` 与 `case.json`。数组 dtype、形状、轴序、归一化、标签、缺标监督及空间恢复信息保持原有语义。现有 `.npy` 目录继续按其清单读取。原始 `.nii.gz` 输入和预测结果文件格式沿用原设置。

配置可手动指定：

```yaml
preprocessing:
  storage_format: b2nd
  compression_chunk_bytes: 4194304
  compression_level: 3
```

`storage_format: npy` 保留非压缩写出。读取器按照目录清单自动选择格式，训练和预测无需额外设置解压目录。已有输出描述保持其原数据版本并继续复用；需要新建压缩版本时指定新的预处理输出描述文件。不会自动转换或删除用户已有 `.npy` 数据。

预处理工作数组可以暂存为磁盘数组；压缩完成、数组头检查和病例原子提交结束后，工作数组会清理，仅保留压缩成品。压缩写出按块复制连续内存，内部压缩与解压默认单线程，避免与病例并行相乘。压缩读写缓冲进入资源估算，日志容量使用实际文件字节数；正式写出不增加逐体素整例读回扫描。

STU-Net 训练随机取块、分块滑窗预测、Q 定位监督/池化及局部候选取块可直接读取压缩区域。原有整例路径按已经准入的预算将影像解压到内存，不产生完整非压缩磁盘副本。压缩降低磁盘占用，不减少模型概率、特征和整例预测结果自身的内存需求。

仅切换存储容器不生成新训练、验证或测试划分，不重新拟合归一化。MedSAM2 的专用预处理保持原有 NPY 成品；Total 独立 nnU-Net 流程保持原接口。需要 `blosc2>=3.0`；本地实际使用4.14.1，服务器环境须检查依赖版本。

验证使用 ct_1003、ct_1012 的32³原始区域，实际缓存为1×32×31×31及1×32×32×32。已核验默认压缩、手动NPY写出和读取、整例及分块预处理、完成病例复用、取消后重写、定位监督与池化、带边界局部裁剪、同权重网络输出、STU/Q各一次CPU更新及模型/优化器读回。完整CT压缩率、服务器读盘速度、CUDA/NCCL和正式全量模型预测未实测。
