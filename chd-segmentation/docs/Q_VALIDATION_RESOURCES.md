# Q 验证资源与恢复

本次实现依据：2026-11-20 用户要求，验证参照预处理按项目100 GB上限自动使用大块，并由已分配的多张显卡共同执行。全局训练batch、验证名单、模型、损失和训练预算保持既有配置。

## 实现行为

- [x] 在完整病例边界重新申请验证内存；计入训练驻留状态、其他任务登记和整机80%可用范围，计算占用后增加50%余量。实际需求达到预算时才扩大预留。
- [x] 按病例尺寸分担验证，全部rank参与，最后按原病例顺序汇总患者或病例损失。每个rank连续处理本组病例；无病例的rank参与CPU就绪和结果汇总。
- [x] 数组及计算临时空间可全部容纳时使用内存；超出时使用磁盘映射。块尺寸按剩余预算增大，支持手动限制块大小；GPU分层计算另受实时显存余量限制。
- [x] 每例释放临时数组和病例预留；整轮验证结束恢复训练额度。已完成组的额度可在其他rank的下一病例边界参与分配。取消或异常结束清理本次工作目录。完整检查点继续恢复已有模型、优化器及逐rank随机状态。
- [x] 日志输出病例分配、请求和实际内存、存储方式、块尺寸和块进度；外层同时展示各rank验证状态。
- [x] 两例真实影像、两个CPU/Gloo进程、合计两次全局训练更新；验证与单进程损失一致、缺失心肌标签、预算边界、恢复及清理。CUDA/NCCL和完整大病例吞吐另在服务器核验。

## 手动设置

Q配置的`execution`支持以下设置。默认自动模式按实际可用预算选择块大小，取消512 MiB固定上限；100 GB额度包含整个任务组及其安全余量，并与同项目其他任务共同核算。

```yaml
execution:
  validation_auto_blocks: true
  validation_block_bytes: 67108864
  validation_max_block_bytes: null
  validation_storage: auto
```

`validation_auto_blocks: false`固定使用手动起始块上限；`validation_max_block_bytes`可填写最大计算缓冲字节数。`validation_storage`可选`auto`、`memory`、`disk`，显式选择memory但无法容纳时终止并报告原因。手动配置通过`run.py models train --config`读取；已有训练增加`--resume`。验证分配到本任务已获准的显卡，最后剩余病例数不足卡数时部分rank等待汇总。

正式任务保留整机80%限制。本地Windows CPU技术短测可显式使用`ram_fraction: 1.0`，对应用户已允许的本地测试内存规则；该设置不改变Linux服务器和GPU任务的80%限制。

## 已验证范围

ct_1003和ct_1012的64³以内真实区域：内存与磁盘分块损失差低于`2e-5`；两个CPU/Gloo进程完成两次全局更新、保存和恢复，最终代码零更新恢复后检查点内容未改变。两进程验证与同模型单进程验证损失差约`3.02e-7`。三个Q阶段的内存数组结果通过原计算路径比较；完整原始尺寸仅使用文件头做预算检查，未处理整例体素。

## 文件职责

- `models/q_route1/validation_runtime.py`：病例分配、阶段额度调整、多进程结果汇总。
- `models/q_route1/validation_store.py`：内存或磁盘数组、临时空间预留、GPU块预算和进度。
- `models/q_route1/validation.py`：单病例验证及保持原科学归约的结果记录。
- `models/workflow.py`、`models/execution.py`：训练验证切换、所有者重规划服务、进度展示。
- `config.py`、`models/memory.py`：配置和各rank最低可运行预算。
- `tests/verify_q_validation_adaptive_real.py`：有界真实病例验证入口。

## 检查重点

病例数小于卡数、病例尺寸不均、同患者有多个病例、手动小块、预算无法容纳完整数组、验证期间取消，都必须保持名单及归约正确。磁盘工作目录属于可清理的过程产物；模型检查点保留在各阶段原目录。
