# Q定位器显存与低显存训练

定位器的 `q_vram_estimate` 记录粗网格估算、实际空闲显存、PyTorch已分配与保留显存及安全余量。估算只供参考，不阻止病例前向和反向计算。主机内存准入继续执行项目100GB、整机80%与既有预留策略。

实际 CUDA OutOfMemoryError 触发定位器低显存重试。各rank完成当前供数轮次，清空整次更新的梯度，恢复更新开始前的逐rank随机状态，重放相同病例抽样。成功完成全部梯度累积后才归约梯度并更新优化器；显存失败不计作完成的更新。

低显存路径保留完整粗网格、全部监督及模型参数。卷积在原GPU上按输出区域分块，读取真实卷积邻域；中间结果放在CPU，GroupNorm按整个病例共同计算统计量及反向，插值和损失在CPU完成。卷积使用PyTorch检查点在反向时重算工作区。模型权重与优化器格式保持兼容，执行模式无新增科学配置字段。

`execution.low_vram_block_bytes` 默认134217728（128MiB），表示卷积块工作区的估算目标，不是硬显存限额。低显存模式再次出现实际显存不足时，所有rank将该目标减半，最小为1；最小卷积仍不足时保持等待并重试，可主动取消，显式等待时限仍有效。其他错误按原规则停止，不隐藏数据、数值或设备故障。

`q_low_vram_retry` 记录失败病例、实际显存信息、整批梯度清理、随机重放及应用块预算。CPU活动内存受同一资源登记管理。该模式增加CPU计算与数据传输，实际速度依病例和设备决定。

本地验收脚本：`tests/verify_q_low_vram_real.py`，限定两例真实影像的≤128³区域、两个CPU进程各一次更新，CUDA仅检查前向、反向、真实额度不足后的恢复，不进行GPU参数更新。测试目录及报告目录由脚本固定，结束清理临时数组与检查点。
