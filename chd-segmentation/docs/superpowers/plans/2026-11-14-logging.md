# 实时阶段日志 Implementation Plan

**Goal:** 让预处理、训练、预测和评价的运行位置、进度、耗时及异常可以及时查询。

**Architecture:** 复用 `observability/events.py`，用阶段上下文记录开始、结束与错误，用有界心跳报告长步骤。共享日志采用文件锁和既有轮转上限，病例常规细节只写过程文件。

**Tech Stack:** Python 标准库、filelock、现有 MONAI/STU-Net 真实流程。

**Spec:** 用户要求每个部分生成详细日志，代码保留于本项目，过程产物保留于 course，结果保留于 result。

## 实施

- [x] 统一时间、PID、阶段、心跳、异常传播与并发轮转。
- [x] 在命令启动、模块加载、清单、计划拟合/复用和病例变换中记录进度与耗时。
- [x] 在资源、模型、供数、训练验证、检查点、预测评价中记录实际执行信息。
- [x] 为仅增加日志的版本记录精确代码兼容边，保留原始训练身份及完整数据、环境和配置校验。
- [x] 使用两例真实病例、每例累计两次训练更新验证日志、恢复、复用与失败记录，记录后清理。
- [x] 准备本项目代码同步清单、服务器更新命令和日志查看入口。

验证采用 CPU；未执行目标 Linux CUDA/NCCL、真实繁忙显卡等待、旧服务器检查点迁移或正式负载性能验收。兼容审计验证精确源码摘要对及未知差异拒绝；旧服务器检查点恢复仍需目标环境的实际回执。
