# 自动预处理计划

`run.py prepare --config <配置> --output <描述文件>` 默认自动生成计划，无需从本地上传旧计划。计划拟合与模型权重加载相互独立；准备阶段不读取预训练权重，不申请 GPU。

## 输入和划分

每份清单明确病例路径、训练/验证/测试角色、患者身份、文件 SHA256、可靠毫米间距与标签规则。自动计划仅使用 train 病例。正式任务先检查患者角色互斥；每折使用该折清单，fold 仅标识折数，不自动重新划分患者。两套数据分别拟合，按数据集、折数和 formal/technical 范围保存计划。

CHD1282 沿用清单中有依据的 Excel 毫米间距与共享数组网格；ImageCHD 沿用其空间规则。程序核对文件摘要、尺寸、affine、标签值和未知类别，遇到不满足协议的数据立即报告。它不猜测标签语义或自动补画缺标，也不推断尚未确认的 HU 偏移。

## 拟合和执行

1. 顺序读取每个训练病例，在当前技术区域或正式全卷内调用 nnU-Net 非零区域裁剪。
2. 从已标注有效前景抽取确定性随机样本，ignore 与背景不进入统计。缺标类别不被当作已标注前景。
3. 按各病例相同样本数计算均值、标准差及 0.5%/99.5% 截断分位数。默认每例 100000 点、总计最多 2000000 点；总预算不足时等量减少每例样本，预算小于训练病例数时停止。
4. 根据训练病例的间距和裁剪后尺寸调用已安装 nnU-Net 的目标间距规则。高间距轴调整和轴顺序保存在计划中。
5. 后续预处理读取同一计划，执行 CTNormalization 与图像/离散标签重采样。MONAI 负责数据流程与滑窗预测。

采样在原始前景灰度上拟合，CTNormalization 使用计划中的截断、均值、标准差；手动改变截断范围时，均值和标准差仍按原始前景样本拟合，除非同时显式覆盖。计划不决定 STU-Net 网络、训练 patch、batch 或显存容量。

## 配置

```yaml
planning:
  mode: auto
  samples_per_case: 100000
  max_samples: 2000000
  seed: 1234
  target_spacing_xyz: null
  clip_range: null
  mean: null
  std: null
```

上述四个 null 字段默认自动计算，可以分别手动覆盖。target_spacing_xyz 使用 XYZ 毫米顺序，例如 `[0.4, 0.4, 0.8]`；计划内部使用转换后的轴顺序。clip_range 是递增的两个原始灰度值，std 必须大于零。修改设置后使用新的计划及预处理描述路径。

省略 plan 时，默认输出为 `work_root/plans/<dataset>/fold_<fold>/<scope>/preprocessing_plan.json`。显式 plan 在 auto 模式表示生成位置，必须位于 work_root 下，且不与原始数据、清单、权重或源码重叠。

明确复用外部既有计划时配置：

```yaml
plan: /path/to/audited-plan.json
planning:
  mode: existing
```

existing 模式不重新拟合或修改计划；手动覆盖字段保持 null。正式清单需要 `plan_scope: formal`，并且不能使用标记为 technical 的计划。外部计划的实际拟合来源由使用者核查，scope 声明不能验证其全部历史。

## 复用、恢复与产物

自动计划记录拟合病例及文件身份、数据集、范围、折数、技术区域、采样设置、手动覆盖、依赖版本和内容摘要。重复 prepare 核验身份及原件后直接复用，不改写计划。身份不符或内容损坏立即停止，使用新的输出路径重新生成，避免覆盖旧训练所需计划。

训练恢复与预测仅核验并使用已保存的计划，不重新拟合。新预测病例不会进入灰度统计。技术计划最多包含两个病例，限定用于接口短测；正式任务使用其训练划分重新生成。

每份计划只保存一份 JSON 与一个操作锁文件，预处理描述包含所使用计划的快照。记录拟合总耗时、逐例读取/处理耗时与实际采样数；CLI 报告本次准备耗时与计划复用情况。病例数组及灰度样本仅驻留内存，RAM 不足时停止。

`smoke.py` 自动生成技术计划并核验重复准备不改写，随后执行两次更新、保存/恢复、预测复用与独立评价。短测配置的每个 experiment 提供 dataset、data_root、pretrained、roi_xyz、case；无需 plan。短测结束按独占目录归属自动清理临时计划、配置、模型、掩膜，仅保留报告。
