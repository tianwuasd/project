# Q局部训练的分块上游准备

普通Q-r2的local阶段使用已有base与localizer检查点，按病例生成冻结上游结果，再读取当前候选区域进行训练。模型结构、损失、优化器、患者分组、采样与随机状态格式保持原有定义。

## 计算与存储

- 基座沿用原patch、50%重叠、Gaussian融合，先融合logits再计算softmax。可用内存充足时向公共资源管理器申请内存数组；其余病例使用有额度的磁盘缓冲，计算和读取以块为单位。最终冻结结果保存为同一缓存格式。
- 定位器复用分层推理，卷积保留邻域，GroupNorm按整个粗网格计算统计量。候选保留原阈值、配额、去重与稳定排序。分块浮点归约的数值容差通过真实数据对照核验。
- 局部裁剪和上下文采样继续使用原函数，只访问当前区域需要的概率与特征。
- 候选准备按病例分配到各个rank，各自使用已分配设备。完成后通过原CPU就绪屏障汇合，再按原训练名单和候选序号重建抽样器；病例、候选权重与随机状态格式保持一致。
- 上游准备通过原CPU线程管理器申请线程，并提前准备下一个窗口。内存数组持续复用；磁盘映射按缓冲量及实际压力释放，避免每个窗口都刷盘。局部输入读取保留有额度的热数据缓冲。
- 病例锁按任务显式等待时限执行；无限等待任务持续检查取消状态。缓存目录容量锁继续使用原短操作时限。
- 病例日志记录存储方式、CPU线程数、窗口准备等待、网络前向及传输、融合与刷盘耗时。
- `work_root/q-training-cache/local-blocks`保存磁盘结果；原`local`目录的`.pt`缓存保持原状。新缓存协议独立绑定prepared、上游模型参数、形状、间距、缺标类别及相关配置。
- `training_cache.enabled`和`local_bytes`继续控制缓存。可保留结果采用病例生成锁、读者登记及LRU容量管理；活动读者保护文件不被淘汰。超出保留额度时使用当前病例临时目录，最后一个读者退出后删除。
- 创建前登记磁盘峰值估算并核对空闲空间；中断工作区位于已登记的pending目录内，后续访问会按进程出生身份与文件归属回收。

## 内存保护与继续训练

local独立核算计算块、局部张量、模型/检查点、供数及解压工作区。完整概率和原空间恢复数组的逻辑尺寸不再计入每个训练进程的最低RAM需求；磁盘估算单独记录。映射驻留页仍受实际内存监测约束，分块存储不保证任意规格病例均可运行。

项目100GB、整机80%、现有资源预留、GPU选择和取消策略继续执行。原配置和prepared描述继续使用；base与localizer已完成阶段可复用，local已有完整检查点继续走原恢复入口，不重新训练上游。

测试入口为`tests/verify_q_local_memory_real.py`和`tests/verify_q_local_speed_real.py`。速度检查使用两例原始≤128³区域、零训练更新，核对分块结果、CPU多进程候选汇合、共享缓存、耗时及RSS。小区域验证与完整CT、Linux/CUDA/NCCL验证分别记录。正式服务器启动前核对实际加载的源码快照与配置，更新维护代码不修改正在运行的冻结任务。
