# 运行日志

`run.py prepare/train/predict/evaluate/test` 启动时立即刷新终端，记录解释器、代码位置、命令入口及模块加载。过程日志统一追加到当前配置的 `run_dir/events.jsonl`；服务器上位于 `course/chd-segmentation/runs/` 中对应任务目录。预测掩膜与评价结果继续保存在 `result`。

每条事件包含 UTC 时间、进程 PID、阶段及相关字段。阶段记录开始、结束、耗时；失败记录异常类型、信息和完整调用路径，异常继续传播。长步骤默认每 15 秒记录一次心跳，心跳只说明当前进程仍在执行该阶段。病例完成数与训练进度由实际完成事件独立记录。

| 部分 | 记录内容 |
| --- | --- |
| 输入和划分 | 清单位置、fold、各角色病例数、预处理描述身份 |
| 计划生成 | 每例开始与完成、已完成/总数、读取耗时、病例速度、间距和灰度参数 |
| 计划复用 | 逐病例来源核验进度、复用路径 |
| 病例变换 | 来源摘要核验、解压、原始尺寸和间距、裁剪归一化及重采样耗时 |
| 资源 | 请求与实际显卡、CPU 进程、缓存预算、等待原因、释放 |
| 训练 | 模型构建、权重加载、分布式初始化、供数等待、缓存命中、训练/验证 loss、学习率和进度 |
| 检查点 | 加载、复用、写入、独立读回、提交、容量与进度 |
| 预测和评价 | 每例开始/结束、滑窗、恢复、写出、已有结果复用、有效监督类别和分组报告 |

病例读取和变换的常规细节保存到结构化文件。终端保留阶段进度、心跳和训练摘要，避免把重复变换细节全部写入外部重定向日志。每个 `events.jsonl` 上限 16 MiB，最多保留三个轮转文件，合计约 64 MiB；多个进程的追加和轮转使用同一文件锁。轮转后完整历史分布在当前文件及编号备份中。

可在实验配置中手动修改两项设置：

```yaml
logging:
  heartbeat_seconds: 15
  case_details: true
```

`case_details: false` 关闭病例读取/变换的细节事件，保留阶段、进度、异常和汇总。外部 `nohup` 重定向文件由启动命令管理，其容量不受结构化日志轮转控制。日志不会额外同步 GPU 或复制模型输出以收集显示数据。

正在运行的进程继续使用启动时的代码。更新入口持有代码写入锁，活动任务结束后才能更新；运行中的任务不会自动获得新增日志。

本次日志更新通过包内 `code_compatibility.json` 记录完整旧/新源码摘要对。经过审查的日志变更允许原训练继续恢复及预测；数据、划分、计划、训练参数、模型、权重和依赖仍逐项核验，原训练记录及身份保持原值。其他源码摘要差异继续拒绝。

## 服务器命令

任务退出后更新代码：

```bash
python3 -B /data4/zhangruichen/code/chd-segmentation/update.py
```

沿用后台训练命令时，实时进度会进入原先的终端日志：

```bash
tail -f /data4/zhangruichen/course/chd-segmentation/logs/imagechd_fold0.log
```

逐病例读取、解压和变换的完整细节，查看实验配置中 `run_dir` 对应的 `events.jsonl`。日志配置不参与训练参数身份，修改日志间隔不会改变抽样和模型计算。
