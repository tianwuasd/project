# ImageCHD模型与数据问题：困难病例图文分析报告

**日期：2026-10-30｜对象：2026-10-29正式三折实验CHD_1029_1｜用途：研究诊断与复现核查**

## 1. 先明确结论：不能说“我们的模型没有问题”

当前模型在这份数据上存在真实的识别失败，融合与后处理还会进一步放大错误。检查证明了部分结构能够学习、程序能够执行，但没有证明已经训练出可靠模型，也没有证明与原论文逐层完全一致。

需要分开看三个层次：

| 层次 | 本轮证据 | 能得出的结论 |
|---|---|---|
| 网络结构与梯度是否能够学习 | 原模型、原损失经过单例诊断拟合，可以把PA/LV/MYO的同例Dice提高到约0.99 | 相应通道和监督能够驱动学习；不是这些实例中完全断路 |
| 现有训练得到的参数是否可靠 | 有分支在训练中见过的病例上仍然很差；外折病例出现严重类别混淆 | 当前学习结果与泛化均未达到要求 |
| 组合流程能否保住正确结果 | 正确分支预测被加权投票压掉，较小的正确区域被最大区域规则删除 | 融合和后处理存在已证实的失败机制 |

数据方面，ct_1170有明显的源灰度异常，另有13例缺少心肌标签。全量核查没有发现文件整体错配或重建监督中丢类，不能把所有低分归咎于“整批数据不对”。

![问题在整条链路中的位置](assets/01_failure_map.png)

图1中，红色环节有直接的丢失正确预测证据；训练适配不足有强线索。尚未证明某个骨干结构差异是全部问题的唯一原因。

## 2. 检查范围、指标和读图方式

检查覆盖全部110例ImageCHD源影像及标签，其中97例纳入当前正式实验。补做了776组四路监督检查、18阶段训练历史核对、4例困难病例的32次GPU前向，以及3例固定300步的训练病例拟合探针。另复用了此前97例评价复算、区域归因和两例本机完整推理重放。

正式97例外折结果的平均Dice约0.5522，LV约0.6583，PA约0.1109。流程状态“完成”表示任务执行完成，不代表这些分割质量已经合格。

- **LV/RV**：左室/右室；**LA/RA**：左房/右房；**MYO**：心肌；**AO/PA**：主动脉/肺动脉。
- **Dice**衡量预测与参考标注重叠，越接近1越好；0表示该评价网格上没有正确重叠。图中的参考标注不是本轮专家重新标注的临床金标准。
- **外折模型**没有用该病例训练；**见过该例的模型**仅用于诊断学习情况，其成绩不能当作外折测试成绩。
- 分支分数在各自64³或128³输入网格上计算；最终正式分数在预处理评价网格上计算。跨网格的数值不直接混作同一指标。
- CT配图来自本次研究的公开ImageCHD病例。绿色始终指参考LV，蓝色和红色含义由面板标题说明。切片按参考LV面积较大处选择，放大和显示窗只用于读图，不参与模型取框或推理；原始灰度不在此确认成HU。

## 3. ct_1051：模型把左室判成了右房

![ct1051的类别混淆](assets/02_ct1051_class_confusion.png)

左图绿色是参考左室；中图红色为最终预测的左室，明显偏到了别处；右图蓝色为预测右房，却覆盖了大部分绿色参考左室。此前在正式评价网格中，参考LV约99.2%被判为RA。

这类错误已经出现在模型前端，不是简单的“最后删块删错了”。取消最大区域处理，也不能凭空恢复本来没有正确识别的LV。

本机四路重放进一步区分了学习和泛化：

| 模型来源 | crop64 | crop128 | all64 | all128 |
|---|---:|---:|---:|---:|
| 外折fold2，未用ct_1051训练 | 0 | 0 | 0 | 0 |
| fold1，实际用ct_1051训练 | 0.003 | 0.127 | 0.651 | 0.169 |

表中为各分支网格的LV Dice。crop输入跨折相同；精分割各折使用自己的预测ROI，因此跨折差异也包含ROI变化。

**问题定位：现有参数学得不稳，多数分支对见过的病例也没有学好，外折识别进一步失败。** 目前未发现该例源文件错配或全局LV编号写反。究竟有多少来自优化不足、形态差异或输入信息，需要后续固定条件的对照，不能只凭这张图认定骨干结构错误。

## 4. ct_1126：不是所有分支都没识别出来，而是组合时丢掉了

![ct1126的完整视野、参考、单路和最终结果](assets/03_ct1126_branch_vs_final.png)

第一幅展示完整视野，后面三幅是同一切片的局部放大。crop128蓝色区域与绿色参考LV有明显重叠；最终预测却没有正确LV重叠。crop128自身仍有误检，因此不能直接把它作为最终结果。

### 4.1 已经量到的取样难度

本例预处理网格为470×470×750，当前定位框覆盖全图。压到64³时，LV监督只剩216体素。大视野包含很多胸腹部背景，心脏在网络输入中占比小，小结构和边界信息被明显压缩。这属于输入表示的难度，并不等于源影像文件损坏。

较高分辨率的crop128仍识别到部分LV，分支Dice约0.615，说明现有输入里并非完全没有可识别信息。

### 4.2 已确认的融合问题

把四路结果按正式流程统一到128³网格后，参考LV有1,810体素：

| 分支 | 投票权重 | 正确LV重叠体素 |
|---|---:|---:|
| crop64 | 1 | 0 |
| crop128 | 1 | **1,356** |
| all64 | 2 | 0 |
| all128 | 2 | 0 |
| 融合输出 | — | **0** |

![ct1126正确重叠在投票后归零](assets/04_ct1126_vote_loss.png)

在这些位置，正确的crop128只有1分，而错误精分割分支单路就有2分。因此正确分支无法胜出。这例连平票都达不到，单改“平票时如何选类别”不能修复它。

融合后，参考LV中的1,780体素被判成RV。Slicer原生空间复核也一致：crop128与参考LV相交84,397体素，正式最终结果相交0体素。原生空间与128³网格的体素数不同，不应混用。

**问题定位：大视野压缩增加识别难度，固定加权硬投票又直接抹掉了已有正解。** “越高权重的分支越可靠”在这例不成立。

### 4.3 肺动脉为什么在其他路经常不出现

fold2的32例正式外折结果中，PA Dice全部为0，其中29例预测PA完全为空。对该折训练、验证和测试代表病例的分支重放显示，crop64/crop128/all64没有产生PA硬标签，而all128仍能局部检出。因此同时存在前端分支未学好和后端融合丢失，不能只怪最后的区域处理。

某个位置若只有all128投PA，它只有2分；all64投其他类别也至少给该类2分。其他类别票数更高时PA会输，即便最高分恰好平票，当前选择较小编号，PA=7仍会输。第9节的训练例探针能把PA从0拟合到0.989，说明该类通道可学习，但现有正式权重没有充分学好、组合规则也没有保护孤立的正确分支。

## 5. ct_1004等五例：最大块不等于正确主体

![ct1004最终处理前后的对照](assets/05_ct1004_component_error.png)

中图蓝色预测包含两部分：一部分贴合绿色参考LV，另一部分落在参考RV区域。最终规则只保留体积最大的LV连通区域，于是右侧图留下错误块，删掉了正确部分。

本机GPU重放中的区域组成如下：

![按体积选块为何出错](assets/06_component_sizes.png)

- 保留错块：67,123体素，正确LV重叠0，其中59,757体素位于参考RV。
- 被删主要候选：20,049体素，其中19,971与参考LV重叠。

规则比较的是“谁更大”，没有判断“谁更像LV”。这是该例从非零Dice变成零分的直接原因。

正式保存结果中，五例均出现相同模式：

| 病例 | 最终最大区域处理前LV Dice | 处理后 |
|---|---:|---:|
| ct_1004 | 0.3238 | 0 |
| ct_1035 | 0.4127 | 0 |
| ct_1047 | 0.4283 | 0 |
| ct_1110 | 0.1810 | 0 |
| ct_1135 | 0.3303 | 0 |

上表是原正式网格结果；图中的ct_1004体素数来自本机GPU重放。两者最终预测一致率为99.99924%，存在52体素差异，故具体数量略有不同，但错误机制完全相同。原生还原的5个边界重叠体素也不改变正式评价网格Dice为0的结论。

### 为什么验证没有拦住？

fold2验证病例ct_1135的LV从0.311降到0，但其余9例改善使平均分仍从0.5902升到0.5978，策略因此被接受。“缺失”检查只看预测是否完全为空，错误大块仍非空，所以没有报警。

同时，最大区域处理在97例上总体提高了LV均值，约0.6480→0.6583。因此不能把全局关闭它直接称作整体改进，需要增加逐例严重退化检查，并在开发集重新比较策略。

## 6. ct_1148：现有训练没有学好，不代表结构不能拟合

外折fold2四路LV分支Dice约为0.004、0、0.030、0.005；即使是训练过该例的fold0，也只有0.032、0.004、0.185、0.040。

从fold0原all64最佳权重开始，用相同输入、原Dice+CE损失进行独立单例诊断，LV可从0.185提高到第300步0.990。这个观察说明：模型有能力调整参数来拟合这例，现有学习结果远未利用到这项能力。

但该诊断反复使用同一训练病例，关闭增强、batch改为1、使用恒定初始学习率。它只能证明可学习性，不能量化这些因素各自的贡献，也不能证明正式外折模型只需增加300步就会恢复。

## 7. ct_1170：源数据异常真实存在

全110例检查中，仅ct_1170的前景类别出现超过50%的单一源灰度占比：

| 参考类别 | 单一源灰度 | 该值占此类体素比例 |
|---|---:|---:|
| LA | 3196 | 62.92% |
| MYO | 2492 | **95.59%** |
| AO | 3039 | 72.21% |
| PA | 3582 | **74.47%** |

这是对整数源灰度的精确统计，不是把相近数值合并后造成的高峰。源影像SHA256与冻结记录吻合，说明大片常值已在提供给本流程的源文件中；其更早处理历史尚未查明。

![ct1170与对照病例的源灰度分布](assets/07_ct1170_source_intensity.png)

蓝线是ct_1001对照，红线是ct_1170。对照用于展示灰度分布差异，不把它视为所有正常病例的分布标准。

本例P99=3196，大量PA灰度3582会被归一化截顶。这里有两个不同问题：源图内大片纹理已消失，百分位截断又使部分剩余高灰度差异消失。调大截断上限只能保留仍存在的信息，不能恢复常值区域丢失的纹理。

在训练过该例的fold0中，all64的LV/MYO/PA Dice约0.136/0.130/0.423；同例300步诊断拟合后可达到0.995/0.988/0.996。**网络能记住异常图，不证明图像质量合格，也不证明参考标注完全正确。** 本例应继续查找未加工原件，保留质量复核标记。

## 8. 为什么少数病例特别难：现有证据指向不同原因

| 观察到的困难 | 对应证据 | 目前能说到哪里 |
|---|---|---|
| 大视野、小结构被压缩 | ct_1126，LV在64³仅216体素 | 表示难度已确认；它不是唯一原因，融合还丢掉了已有正确分支 |
| 类别关系没有学稳 | ct_1051的LV→RA，ct_1148的LV→LA | 模型前端混淆已确认；具体形态、对比度及训练样本覆盖的贡献尚未分离 |
| 部分分支学习较慢或学习不足 | 训练病例上仍低分，短程单例拟合可大幅改善 | 训练适配不足有强线索；不能由单例记忆推断总体泛化 |
| 罕见失败被平均分掩盖 | 验证ct_1135降到0仍通过 | 策略选择缺少逐例灾难保护已确认 |
| 灰度信息异常 | ct_1170 | 源分布异常已确认，原件处理历史/真实HU未确认 |

病例之间的形态、视野和对比度不同，原论文也强调这些变化。但不能在没有临床资料核实的情况下给某例指定疾病名称，或把一切归结为“先心形态太复杂”。

## 9. 训练预算与单例探针怎样解读

![同样15轮对应不同更新预算](assets/09_training_budget.png)

原论文的3D设置确实是15轮、batch4。本项目每折仅54—55个训练病例，约210次更新，112次后首次降学习率；原论文约727例/折，对应约2730次更新。保留相同轮数，实际优化预算已经不同。

12个3D模型中8个最佳轮次位于最后一轮，全部12个的最后5轮验证损失均净下降。二维血池的最佳轮次却是3/4/6轮，所以不能给所有阶段一律加轮数。

![单例诊断拟合曲线](assets/08_single_case_learning.png)

这些曲线只评价同一训练病例，不是新增独立测试成绩：

| 病例/类别 | 原分支Dice | 固定300步后同例Dice |
|---|---:|---:|
| ct_1030 / PA | 0 | 0.9887 |
| ct_1148 / LV | 0.1850 | 0.9901 |
| ct_1170 / MYO | 0.1305 | 0.9877 |

三例均从原最佳权重开始，原结构和原损失，batch1、无增强、恒定初始学习率0.0002。原始权重文件哈希前后未变，没有保存为新的正式模型。

曲线排除了相应实例中“通道完全断路、标签不能驱动学习、结构根本不能拟合”的解释。它不证明训练步数是唯一根因，更不证明异常数据应该保留使用。能够背下训练样本，与能够识别未见样本，是两个问题。

## 10. 论文复现还存在哪些缺口

当前项目应称为论文启发的ImageCHD适配实现，不宜称为已严格完整复现作者系统。

| 项目 | 当前状态 | 可能影响及边界 |
|---|---|---|
| 初始血管两路init64/init128 | 缺少初始血管标注，未实现 | 六路变四路；不能用整段AO/PA伪造缺失监督 |
| 小岛重归属、AO/PA图优化 | 未完整实现 | 当前有限补全、删除非最大区域不等价于论文完整流程 |
| 位置分支激活、损失组合、增强幅度 | 部分依赖实现假设 | 需要作者源码/补充细节；目前不能断言其中某项导致全部错分 |
| 参数数量 | 与论文不完全一致 | 尤其2D和循环网络，不能声称逐层相同 |
| 队列与结构数 | 本项目97例、七结构；论文队列规模和结构数不同 | 不能直接对比论文整体成绩或临床准确率 |

参数核对：当前3D base64约90.45M、base48约50.94M、2D约497.78M、循环层约0.369M；论文分别约84.9M、51.2M、452.9M、0.2M。类别数差异不足以解释全部差距，但也不能仅凭参数量不同就判定网络错误。

## 11. 数据已经查清什么，还有什么没查清

| 检查项 | 结果 |
|---|---|
| 全部110例影像/标签网格 | 匹配 |
| 影像有限值、标签整数存储 | 通过；影像int16，标签int8，无额外标签数值缩放 |
| 纳入97例源影像摘要与P1/P99 | 与冻结记录全部一致 |
| 完全相同的影像或标签体素副本 | 未检出 |
| 未纳入13例 | 缺少MYO标签；不能直接把未标注MYO当背景加入监督 |
| 三折194组病例-折，四路776组监督 | 七类均存在；没有发现重建监督完全丢类 |
| 训练ROI覆盖 | LV全部100%；PA平均99.789%，fold2训练ct_1117最低86.040% |
| 明显类内常值异常 | ct_1170，需查原件 |

通过这些检查，不等于专家已确认所有参考标注正确。精确重复未检出，也不等于排除了同患者不同期相/重复检查。真实物理尺度、HU来源、作者未公开结构细节，以及服务端当时训练mmap缓存的逐字节内容，仍未独立核实。

## 12. 修复顺序与验收方式

1. **先修已证明会抹掉正解的组合环节。** 在开发/验证集比较融合与LV区域策略，加入逐例严重退化和零正确重叠检查。预测时只能使用模型分歧和影像信息，不能拿参考标签挑区域。ct_1126需要处理分支可靠性，不能只改平票；五例LV误删需要处理主体选择和验证接受条件。
2. **再做分支训练对照。** 固定患者划分、种子和评价规则，比较更新预算/学习率日程，记录每分支逐类训练和验证曲线；区分3D欠学习线索与2D过拟合线索。不根据已看过的外折病例随意调权重后再宣称独立改善。
3. **同步处理数据质量。** ct_1170查未加工源件，ct_1117复核被ROI漏掉的PA；13例缺MYO若要使用，另立部分标注监督方案。不按测试得分删除病例，不猜测补全真实纹理。
4. **最后补齐论文复现边界。** 取得作者实现或更详细结构说明后逐层核对；缺失的初始段任务需真实监督，完整图优化需独立验证。现阶段不宜把更换骨干当作已经证明必要的修复。

验收应同时看逐类均值、逐例严重失败、类别缺失和分支分歧。仅看到平均Dice升高或程序显示完成，不能说明困难病例已经解决。

## 13. 证据、图像与可复核性

本报告是既有正式结果和诊断实验的解释，不是新方法性能发布。本轮没有更改正式算法、原始影像、原权重、旧预测或正式分数。
