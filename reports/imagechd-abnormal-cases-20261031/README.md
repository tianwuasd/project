## 如何解释问题来源

- **数据问题**：ct_1170源MYO95.59%体素为2492，PA74.47%为3582，类内大片常值；当前110例QC中仅此例满足已检查的极端类内常值条件。灰度纹理无法靠最大区域或扩边恢复。缺MYO的13例是标注不完整，不能把未标区域监督为正常背景。
- **训练与泛化问题**：ct_1051/1148把LV混成其他心腔。ct_1148单训练例300步拟合可达约0.990，说明网络能记住该例，不证明独立样本泛化良好。旧实验每个3D模型15轮、约210次更新，预算明显短；继续训练的收益需外折验证。
- **流程问题**：7例的LV在最大连通区域后严重下降。ct_1126只有crop128分支识别到部分LV，却被融合压掉。PA若只有一个权重2的分支投PA，其余权重2票并列时，固定类别优先会压掉PA。全图压成64³/128³也丢失小结构细节。

因此，不能得出“模型没有问题”或“全部是数据问题”。前述证据已分别定位数据完整性、学习不足、融合和后处理问题。冻结权重与原始影像均未改变。

## 新基础模型选择：STU-Net-S 预训练分割基座

第一候选选 **STU-Net-S**，以官方TotalSegmentator预训练权重微调七结构，保留同架构随机初始化作为必要对照。它是预训练3D分割基座，不能把小型S称成14亿参数模型。官方S约14.6M参数，适合先在有限显存下完成真实加载与微调验证。[官方代码及论文入口](https://github.com/uni-medical/STU-Net)、[论文](https://arxiv.org/abs/2304.06716)。

选择依据是任务匹配与可验证性，而非已经获得更高Dice：官方预训练标签含左右房、左右室、心肌、主动脉和肺动脉。[官方标签表](https://github.com/uni-medical/STU-Net/blob/main/label_orders.json)。原始标签顺序为LV25、RV26、LA22、RA23、MYO24、AO3、PA48；目标顺序仍为背景0及1–7，不直接把编号当标签值套用。默认迁移编码器/解码器并重新初始化8类输出头，避免两套标注边界差异被隐式当成真值。

本地文献库的VISTA3D原文已核读。它仍适合后续自动/交互分割研究；但本次检查的VISTA官方全局标签字典只见整体heart/aorta等，未提供本任务七结构一一对应定义。要做七结构，需要明确的新语义嵌入/输出适配，不能把所有心腔都映射到heart，也不能把PA映射成pulmonary vein。[官方研究实现](https://github.com/Project-MONAI/VISTA/blob/main/vista3d/README_research.md)、[字典](https://github.com/Project-MONAI/VISTA/blob/main/vista3d/data/jsons/label_dict.json)。这项结论只针对已检查版本，不泛指全部NV-Segment/CTMR模型。

此前文献研究中的MedicalNet方案服务AAOCA/TAPVC病型分类，本次用户确认先分割，所以不将分类网络当作当前分割基座。

## 预处理、训练和评价契约

1. 从原图建立新任务。以已核实间距来源建立独立影像/标签副本及记录，不在源文件改头；HU偏移未证实前不套固定HU截断。强度归一化与间距规划只用训练集拟合。
2. 采用3D局部patch训练、全体积滑窗预测，并还原至原网格；不再把整个胸腔直接压成64³。缺MYO的13例先维持排除；ct_1170记录源QC与敏感性分析方案，不因测试分数差而任意删例。
3. 沿用当前已冻结的三折case划分作为对照口径；训练内部再固定验证集。七类Dice、PA零分/空预测、LV混淆与逐例分布必须一起报告；多类别平均分不能掩盖单类塌缩。病例ID去重不等于已证明患者层面独立。
4. 官方预训练权重固定作者发布提交与SHA256，缺权重或迁移层不匹配时明确失败；不能静默退成随机初始化。随机初始化对照另建任务和身份。
5. 七类softmax Dice+CE与deep supervision；微调学习率/训练预算单独冻结，验证最优模型和完整续跑状态均保存。新基线默认不使用旧的多路硬投票或LV删块；任何后处理依据训练内部验证选择。
6. 面板复用更新完成后的skill v2。等待其固定提交和安装版校验完成后，在独立新工程接入，保留旧实验。用户选全局batch默认4，生产任务不得静默缩小；本机诊断小试与正式训练分别记录。
