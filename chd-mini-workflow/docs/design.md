# 小样本完整流程工具

目标为从真实冻结划分选择2例训练、1例验证、1例内部测试，执行最多两轮、每轮两次尝试的完整流程并收集计时及错误证据。

工具保存在独立目录及独立 Git 仓库，分支 `codex/chd-segmentation-mini-workflow`。生产依赖固定为助手1公开提交 `277c11a97ab0f2d666d1d8e669fcdb6c9900c611`，对应本机提交 `d68e11c11bd854c436ee45f29eeddf3aae0038be`，生产源码树一致。用户已批准该设计及 `.runs` 中500文件、4 GiB工作上限与20 MiB日志上限，并要求直接实施。

独立工具通过子进程加载生产项目公开 Python 接口；生产源码及配置只读。配置记录目标路径、完整提交和 Python。每个阶段前后检查版本及未提交修改，生产依赖变化直接拒绝继续。工具使用唯一工作目录，并在全程持有自身锁，更新器只允许自己的独立 Git 根目录执行快进。

选择使用固定种子和稳定排序，保留冻结源角色、患者、标签协议、空间政策及文件摘要；角色互斥和患者互斥均检查。CHD1282 使用已有患者映射；ImageCHD 无可靠患者映射时拒绝声称患者独立。输入通过已有路径引用，不复制影像。统计拟合仅接收两例主训练病例；后续四例准备显式引用本次拟合计划，核对 fit_ids。

技术配置使用32³训练块及共同图像中心子区域，CPU/CUDA设备显式指定；完整配置使用128³块及完整体积。两者均保持全局batch 4、1–2轮、每轮最多2次尝试、一次验证。先在第一次尝试后保存，再恢复到有界终点；验证累计尝试与更新、恢复完整状态和源文件摘要。预测及评价仅接收冻结测试病例。

逐阶段记录冷启动、读取解压、重采样、供数等待、计算、保存恢复、预测评价耗时；并行嵌套阶段的时间不能相加作为墙钟。父进程采样本任务进程组RSS，CUDA训练使用生产接口返回的实测显存峰值。未测指标写明未测量。

离线接口采用 `chd-offline-npy-v1` 和 `stunet-ct-nnunet-bounded-v1`。先生成原始准备描述，生产接口写出独立data，并逐例检查内容摘要及只读映射。相同配方改变轮数、GPU数量、日志后全部复用；只删本次独占验证数组后确认补做一例，保护其他有效文件。训练与预测消费离线数组，最终事件检查整例重采样为零。不同折和统计来源只检查配方身份分离，不生成额外正式数据。

仿真接口来自 `D:/projects/test`，仅调用资源与路径接口。实际CPU有界流程和实际CUDA权重专项分别报告；CUDA专项为8类别适配器、零前向、零更新。GPU训练、128³容量及服务器性能需各自获得实测证据。

工作文件只位于 `.runs/<run_id>/work`，日志位于同运行的 `logs`。成功、失败、正常中断均记录实际清单、容量、进程身份并清理本任务工作文件。未知路径、链接及仍在使用的文件拒绝删除。源影像、共享权重、环境及生产工作目录均受保护。

采用外部接口编排是用户明确要求的更新边界。生产接口需要变化时记录需求交用户协调。独立更新器通过本仓库独立远端分支执行固定提交快进。集中交付登记新增文件及原地引用，大文件保持原路径；上传状态依据实际回执。用户授权只推送本工具独立分支。
