# GitHub更新链路对照检查：v0.3.6

范围是更新链路，不是新增训练模式。以CT0.22.1/88bc928为完整母版，核对AAOCA当前8d0dc5f的updater/download，以及VISTA原0.3.5实现。没有自动修改CT、AAOCA或运行中的实验。

| 项目 | CT详版 | AAOCA参考 | VISTA本轮结果 |
|---|---|---|---|
| 网络与认证 | 原runtime的官方认证、子进程代理、拒绝URL重写 | 同一原则 | 保留；不换已匹配密钥，不走私有仓库公共镜像 |
| 下载内容 | 原检出的分支更新 | 先blob:none元信息，再批量取指定文件对象 | 采用按需方式，只取05_src、06_configs、清单README和两个启动脚本 |
| 历史与完整性 | 分支/快进检查 | 保留提交图做祖先检查 | 保留完整提交/目录元信息，排除无关及历史文件内容；不是浅克隆后跳过祖先校验 |
| 本地归档 | 有界阶段/日志 | 已修复属性触发的隐式拉取 | 归档禁用网络和全局属性，指定运行路径；备份从已加载代码直接本地打包 |
| 超时与进度 | 分阶段总时限、真实输出，日志封顶/脱敏 | 实时读管道、真实进度和总时限 | 30/900/180秒；新增120秒无可见计数/字节推进停止，重复旧计数不续命，不重播旧速度 |
| 发布 | 快进共享检出 | 独立release和原子指针 | 保持独立发布；先核对必需文件和Python语法，再写指针 |
| 旧任务 | 原流程/检查点契约 | 保留旧代码和解释器 | 原任务冻结代码不改；r仍使用旧快照；没有自动恢复训练 |
| 更新后可用性 | 原面板流程 | 需核对入口和任务路径 | 复核受管runtime祖先例外、运行目录转交，以及新建/历史/最近任务可见性 |

VISTA日志实现仍是communicate累积输出，不据此宣称具有CT同等的日志封顶/脱敏层；CT继续作为通用详版。部分克隆保留整个分支的提交和目录元信息，因此不是Git层面零开销的子目录仓库；显著缩小的是文件内容对象。依据：[Git partial clone](https://git-scm.com/docs/partial-clone)、[git fetch --filter](https://git-scm.com/docs/git-fetch)。不以sparse-checkout或“只取一个分支”冒充内容过滤。

实际GitHub HTTPS只读验证在Windows经临时7897代理进行：发布快照3004172的59个运行文件，归档378880字节，缓存pack1015354字节（含提交/目录元信息），没有切换运行版本。与服务器SSH/17891代理和真实部署分开。112项控制回归107通过5条件跳过；纯本地Git覆盖大文件排除、缓存移出重建、字节一致、语法失败保留指针、小下载引导及更新后任务创建。详见[验证JSON](CODE_ONLY_UPDATE_VALIDATION.json)。

用户日志只能证明156—196秒之间对象计数和字节没有可见变化，旧速率来自历史输出；实际网络出口/代理或Git内部停顿原因仍须服务器同次日志，不能凭心跳断言正在传输，也不能说本补丁修好了代理本身。
