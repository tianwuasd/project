# CT 母版面板适配设计

用户要求：理解现有项目，按 server-engineering 的 CT 母版更新中文终端面板，环境安装参考母版，完整显示任务过程；完成后更新 GitHub，交付服务器更新命令。

## 方案选择

采用扩展现有标准库控制面的方式，保留任务源码快照、runtime 锁、输入缓存与 B0 科学协议。整体移植 CHD 会引入不相关的多模型诊断步骤，新增网页会改变用户已指定的终端入口，因此不采用。用户已指定母版及交付方式，本轮直接实施模板适配。

## 交付与边界

- 主面板按运行/空闲显示任务名称、中文状态、步骤、运行时间、目录及下一步。新增环境入口；新建表单分组、显示 GPU 与最终配置，取消不提交。
- 状态页有单次/持续查看；显示按真实完成步骤计算的进度、当前安装子阶段、预处理病例、正式模型 epoch/loss、预测病例以及排队原因。无足够计时不造 ETA。
- 日志中心选择总日志、步骤、单模型/队列文件，初次读有界尾部；持续跟随动态文件、替换与截断，Ctrl+C 返回。进程页显示本任务身份核验进程及其本用户后代，CPU/RAM/运行时间；可另查本用户全部进程。
- 安装仅在提交计算/环境任务后执行。独立 Miniforge、固定依赖、哈希校验、私有缓存；清除 pip 目标重定向；安装进度落盘并显示真实子阶段与字节下载进度，安装凭证绑定依赖配置，校验通过才写凭证。不修改其他环境。
- 保留 runtime 受管更新入口；更新明确显示保护范围与旧任务快照不变。网络继承服务器已有官方 GitHub SSH/HTTPS 凭据，不能将 Windows 7897 当服务器默认代理。
- 暂不增加产物上传 v 或服务器代码上传 w：用户本轮要求由当前会话发布代码，无新增模型产物发布需求；避免空菜单。GPU 保留/自动调参、下游诊断不属此次面板改造；已有资源上限与训练配方保持。

## 验收

标准库查询不创建 runtime、不导入 ML；旧任务无新字段仍可读；取消不写配置；安装失败落盘阶段与日志；无 GPU 的 CPU 前置正常；日志有界且随新文件变化；PID 复用与别人的进程不被归入任务。运行既有控制面/缓存/训练协议回归，并以 Linux CI 真实进程测试验证新生命周期。没有服务器连接，不宣称服务器已部署或真实训练通过。

## CT 母版对应

|---|---|---|
| 中文菜单/返回/取消 | task_panel.py；分层查询、日志、历史、环境 | 导航脚本测试 |
