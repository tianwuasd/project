# CT 完整母版逐项落实：v0.3

用户纠正：GPU选择不等价、没有已知路径、缺少面板上传GitHub，子任务内部和方法也要逐项遵循skill。用户明确要求设立目标并逐项检查。本设计取代 v0.2 设计中对 c/w/v 的排除；直接按用户已指定母版实施。

母版固定为技能携带的 CT 0.22.0 / 46b5425f。逐项验收覆盖界面、参数、worker、数据与缓存、资源、日志、恢复、发布，不用菜单文字替代实现。

## 核心改造

1. 配置顺序严格采用命名→步骤→runtime/结果/数据路径→历史输入→仅配置所选步骤参数→冻结预览→提交。zmic44 配置预填已知 Wholeheart 原始数据路径；VISTA独立runtime/结果目录作为明确配置约定展示，不伪称服务器现场已验证。原CLI与原runtime优先，允许generic配置。
2. GPU采用母版的并发上限优先、候选编号/UUID或auto，候选数量与并发上限独立。显示型号/空闲显存/利用率/计算进程和分配可见范围；auto表示用户授权本次可见分配范围作为候选，有卡即运行、无卡等待。保持进程占用/6000MiB/10%门槛，启动前复核，不扩大CUDA/SLURM范围。
3. c保存原runtime非秘密网络设置；默认私有官方SSH/HTTPS，不使用公共镜像。同一SSH密钥+可选回环HTTP CONNECT代理用于u/w/v；不更改系统和全局Git。已知zmic代理17891与密钥路径作为可编辑建议，不冒充联网验证。
4. w严格复用母版“已提交代码上传”契约：工作区干净、预览逐提交文件与范围、大小、快进、二次校验、官方SSH上传main并回执；不自动提交、不强推、不带论文、数据库、患者数据或其它项目提交。
5. v严格复用母版“完成任务→允许的配置/日志/指标/权重→不可变分卷tar+SHA256→预览确认→同SSH密钥Git LFS孤立分支→回执/同包重试”。VISTA适配自己的输出布局，原始影像/预处理缓存/密钥不进入包。只实现功能，不在本会话发布真实患者产物。
6. u采用原runtime新网络设置、官方认证线路、源码身份核对、备份与快进关系；保留原独立release设计，旧任务快照不变。受管版本面板w定位原Git检出，提示路径。
7. 明确每个任务的资源、依赖、参数、产物、完成判据、恢复、方法与日志。软件合成短测与正式尺寸预检区分；正式训练不得跳过正式尺寸/环境兼容凭证；已有nnU-Net少标注协议保持，不能照抄CHD的不同模型/归一化。
8. 核对并落实CPU预算传递、GPU弹性跨折队列、非训练CPU尾部、资源释放、输入复用/主动重跑的依赖重绑、原任务检查等级。若母版方法不适用于B0，列出具体技术原因及等价证据，不再笼统标“本轮不适用”。

## 架构

扩展现有标准库控制面。网络、代码发布、不可变归档/LFS核心优先适配skill携带的源码，保留来源提交和逐文件改动说明。任务/数据/进程接口映射为Vista现有冻结plan/state/workspace。配置由server_profile与原runtime管理，不引入全局状态。
