# CHD1282 内存预处理分支

分支：`chd_1282_monai`。独立维护，与 `main` 共用现有模型、冻结划分和训练结果。

## 输入与科学参数

MONAI Dataset/Compose 负责按需读取，nnU-Net 2.8.1 的 `run_case_npy` 负责应用已拟合的裁剪、重采样和归一化参数。原始 CT 与标签保持只读，Excel 毫米信息只在内存中应用。训练集拟合结果、患者划分和部分标签监督完整继承已完成预处理的合同；开发集与留出集不参与拟合。

紧凑预处理结果保留请求、计划、划分、摘要、空间信息和监督信息；不包含 CT 副本或全量压缩数组。每次使用原图都检查来源摘要。旧 `.b2nd` 输入仍可使用，模型结构、全局 batch、随机种子与采样顺序不变。

STU-Net 输入通过相同读取接口取得病例属性和前景坐标。标准 nnU-Net 数据目录必须提供已审核的标签对应关系、冻结划分和训练计划，不能仅凭文件扩展名认定与十类 CHD 权重兼容。SAM 保留自己的 1.5 mm、128³ 提示块处理。

## 资源与保留规则

内存缓存按数组实际字节收费；CPU 准备过程另计解压、重采样峰值和在用数组，采用现有主机/cgroup 余量。一个进程串行准备整例，现有有界线程预取负责与 GPU 运算重叠。缓存命中不会写磁盘，借用中的病例受到保护。容量不足时驱逐空闲缓存；单例工作量无法满足时发出已有资源事件，由调度器保存状态并等待重新准入。

GPU 可见性、外部进程检查、分支并发和显存上限继续使用现有调度器。缓存预算计入每个工作进程的份额，不能按整机空闲内存给所有进程重复分配。

训练保留最新可续跑检查点、选定最佳权重、必要日志和结果。短测结束后只保留验收日志。数据与私人元数据不进入 GitHub。

## 验收范围

只使用两例现有真实病例。比较在线读取与已完成预处理的数值、空间和采样结果；测试三个模型入口的有限更新及保存重载。每个网络最多两次更新。记录冷读/热读时间、实际内存缓存字节、峰值 RAM/VRAM、临时文件数量和容量；未测项目明确标注。完成后清理本次临时依赖、检查点和缓存，保留一个验收日志。
