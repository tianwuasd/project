# 留出集评价日志

`scripts/xu_predict.py evaluate --output RUN` 在取得该任务的操作锁后记录评价进度。每次执行追加到 `RUN/evaluation.log`，并同时立即输出到终端；`RUN/evaluation-progress.json` 原子更新当前快照。日志和进度使用独立名称，保留原预测的状态文件。

记录内容包括：评价输入检查、病例序号/总数、病例编号、参考标签读取、预测读取、各结构的开始/完成、真实边界提取、预测边界提取、双向最近点查询、病例耗时、整组汇总和报告写出。逐结构完成记录包含该结构的原始指标。未标注、明确缺失和空预测沿用原有指标定义。

长步骤每15秒输出心跳，显示当前阶段、阶段持续时间、进程累计CPU时间和RSS。`last_progress_at` 只在实际步骤完成时更新；心跳本身不表示病例取得进展。预计剩余时间在至少一例完成后按已完成病例的平均耗时估算。

高频结构阶段只追加日志；进度快照在病例边界、主要阶段和心跳更新。异常和操作员终止记录到相同日志及快照，原始异常继续向外报告。重复启动未取得操作锁时仍直接报告锁冲突，不改写当前活动评价的日志状态。

日志包含病例编号和实际错误路径，应保留在私有运行目录。监测程序如需读取新文件，白名单应明确包含 `evaluation.log` 和 `evaluation-progress.json`。

评价最终仍生成 `RUN/evaluation.json`。进度快照属于运行日志，不是可续算的指标检查点；重新启动按现有评价逻辑从头计算。此次修改保持原有CPU指标算法与数值定义。
