# 六网络融合预测

`scripts/xu_predict.py run --mode six-way`使用crop64、crop128、all64、all128及两个已完成的init模型；存在已登记auto-init扩展时使用对应auto-init权重。必须六个模型齐全，输出停在原融合投票结果，不加载血池模型，不运行血管修正。原20%取框、患者划分和标签语义保持。

该模式通过已提交request、QC、病例pkl及计划读取空间信息，不读取staged。pkl仍须通过process提交记录验证，尺寸、裁剪框、原工作affine、Excel间距与监督信息必须一致。原图还原采用既有本地Excel毫米空间约定，不声明DICOM患者坐标已恢复。原输入、训练目录及预处理合同仍须保留。

可加`--reuse-prediction <原预测目录>`。新旧病例记录、预处理计划、六个权重、取框和融合实现一致才准入；保留原结果，通过同文件系统硬链接复用预处理数组和分支预测。实际分支数组校验记录摘要，写入独立新任务标记；缺少分支继续模型推理。新目录的`cache-reuse.json`记录来源和数量。复用目录必须是正常目录，不接受软链接。原预测目录换模式时应新建输出；同一新任务续跑使用`--resume`。

所有分支缓存齐全时进入CPU融合及原图还原，不申请GPU；存在缺失分支时按现有隔离和资源调度执行。显存估算采用six-way需求，不纳入血池需求。

输出仍为cases中的原空间压缩分割、融合网格、质控、complete及日志；评价沿用`xu_predict.py evaluate --output <新目录>`。输入config/policy与原测试分组保持一致。此模式不自动删除任何旧数据或缓存。

本机真实短测覆盖一个64³区域、已训练crop64权重推理、属性几何读取、分支硬链接与重复复用、还原尺寸。其余五个完整权重本机缺少，六网络完整推理及服务器GPU运行尚未验证。
