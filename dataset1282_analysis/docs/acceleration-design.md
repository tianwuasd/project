# Xu CPU/GPU 资源与吞吐设计

目标：在固定模型、划分、损失、batch、采样和优化器的前提下，提高已获准设备的有效吞吐。沿用 v1 的训练前测量、派生输入复用和外部任务避让，采用 v2 的阶段预算、实时余量、顺序供数、传输生命周期及来源记录。

## CPU 数据准备

- 正式入口默认开启有界预取，提供明确的关闭参数用于实测对照。
- 多个持久线程并行准备完整批次，按原批次序号交付。增强和随机数仍只在消费线程执行。
- worker 数量同时受阶段 CPU 份额、数值线程数、显式上限和预取 RAM 预算限制；每个 worker 必须有可派发槽。阶段预算包括全部待消费批次，实时 RAM 再限制新增任务。
- 计算线程和供数线程共同满足 `(供数 worker 数量 + 1) × 数值线程数 ≤ 阶段 CPU 份额`。单 CPU 工作槽无法准入并行预取；显式 `--no-prefetch` 可以顺序执行。
- 队列从阶段主存中扣除已知模型需求，并保留至少 1 GiB 或阶段主存的 20% 给消费线程；队列上限仍受显式 MiB 设置约束。系统余量独立保留至少 4 GiB 或可用内存的 20%。
- 每个训练目录保存经过来源及内容校验的网络尺寸输入副本。重复轮次复用相同的插值结果；源数据和原预处理不修改。输出采用 NumPy 格式，文件完整写入后才发布记录。
- CUDA 输入使用固定页内存及非阻塞复制，保持主机输入存活至复制结束。先消费已经可用的当前批次，禁止为了等待下一批而阻塞当前计算。

## GPU 与主机保护

- 通过 NVIDIA 官方 CUDA Driver Python API 取得可见逻辑编号与 UUID，查询阶段不建立 CUDA 计算上下文；显存和进程使用 nvidia-smi 只读查询，CSV 使用标准库解析。
- 继承可见范围和显式分配；任何无法核实归属的计算 PID 均作为外部任务处理。核实 PID 和创建时间，保留 GPU 显存余量 max(4GiB,10%)。
- 选择、正式启动前和子进程内均检查；父进程运行期间定期检查外部 PID 和主机/cgroup 余量。发现冲突时终止本次持有的子进程，保留完整 epoch 检查点，写清楚原因；不向外部进程发信号。
- 程序检查无法阻止其他用户随后启动同一 GPU。完整记录检查时刻、UUID、进程身份、分配及终止原因。

## 验收

1. 使用真实 NumPy/Blosc2/SciPy/PyTorch 计算与本机实际资源；新增验证不使用 mock。
2. 串行和并行供数保持病例顺序、张量、loss、梯度/Adam 更新及暂停恢复一致。
3. 在真实预处理病例上测量冷读取、派生缓存复用、CPU 等待及端到端时间，报告实际 worker/队列/内存和 CUDA 复制。
4. 用实际独立进程验证归属拒绝、启动失败以及检查者不持有 GPU 上下文；设备被占用时只运行只读检查与 CPU 验收。
5. 保留当前服务器的两轮试跑目录；新实验记录新实现来源，不修改旧运行合同。
