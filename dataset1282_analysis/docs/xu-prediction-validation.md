# 预测兼容与技术验收

## 兼容边界

预测直接读取已完成的训练结果，冻结文件副本到独立输出目录；不改写训练记录或权重。`best.pt` 必须通过原模型加载器的训练身份、类别、结构及选中 epoch 检查。各模式所需阶段的收据和全部列出产物逐项核验 SHA256。

| 来源 | 完成记录 | 兼容条件 |
| --- | --- | --- |
| 当前训练 | `xu-model-run-4` / `xu-stage-2` | 完整源码相同，或现有 `xu-resume-compat.json` 的精确审查映射 |
| `e1aa831` 技术短测 | `xu-model-run-1` / 原始 stage 摘要 | 完整旧源码映射摘要与当前技术源码映射摘要同时匹配 |
| `7ab17d9` 技术短测 | `xu-model-run-2` / 原始 stage 摘要 | 同上，并保留旧双设备阶段参数规则 |

旧短测源码映射已逐文件与对应 Git 提交比较。两版本的几何、网络结构、标签语义和 ROI 实现与当前相关定义一致；融合使用的 `grid_prediction`、`vote`、`blood_grow`、`_refine_shape`、`_save_case` 及血池预测函数 AST 相同。run-1 的 init 加载差异是新增精确版本兼容检查，模型结构和预测运算保持一致。原模型加载器继续执行自身检查。

未知源码映射、改变过的训练输入、缺失完成收据和未完成血池训练均会明确报错。服务器历史结果需要保持原训练环境；CPU/GPU设备可由预测入口重新分配，病例划分、预处理统计量及权重保持冻结。

## 检查范围

- 三组选择：原 `included/index_scan` 规则，患者互斥，排除重复、非法编号及训练/development 病例。
- 官方预处理：合成 CT 应用冻结 nnU-Net 计划，无标签输入；对比训练相同 CT 的归一化结果，检查恢复与修改检测。
- 来源：真实旧技术训练目录的收据、全部权重和原记录只读检查；拒绝未完成训练及未知版本。
- 预测：已完成短训练的权重实际前向、六分支与血池/血管完整子进程、CPU 预取、隔离入口、重复恢复。
- 导出评价：原数组尺寸、Excel 毫米网格、逐体素恢复比较；预测时参考标签不可读，提交预测后独立评分。
- 资源：既有 GPU 隔离、动态重新准入及供数队列相关回归。

本地验收使用 CPU 和合成输入，正式三组留出数据未用于调试。既有早期技术定位权重仅用于检查接口与恢复，不代表已充分训练的定位精度。真实短训练四分支另行检查前向和导出。CUDA 实测和正式留出集效果仍须使用服务器已完成的模型及对应研究环境验证。

## 2026-11-08 本地结果

`prediction_acceptance.py` 实际执行五个测试模块，16 项检查全部通过，总耗时约 202 秒：选择 7 项、官方预处理 2 项、来源与保护边界 5 项、既有模型子进程及恢复 1 项、四分支导出评价 1 项。两个旧版本的原训练记录分别完成只读验证。既有资源相关回归 35 项通过，其中包含上述选择测试 7 项。

本地使用 Python 3.11.15、PyTorch 2.12.1+cu126，实际推理设备为 CPU。独立验证使用已有短训练权重；本机额外重新训练尝试出现 PyTorch 原生访问异常，该尝试不计作通过的验收。发布范围的 181 个文件通过清单摘要与 Python 编译检查。
