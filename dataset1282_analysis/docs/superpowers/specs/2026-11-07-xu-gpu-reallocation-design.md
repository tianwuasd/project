# Xu GPU 统一启动与重新分配

用户已确认：排除服务器物理 GPU 0、1，统一查询、分配、登记进程，再允许 GPU 运算；外部占用变化后重新分配。

## 执行顺序

以 NVIDIA 物理编号对应的 UUID 排除 0、1，保留当前可见范围。一次完整 GPU 快照供同组分支选择互不重叠的设备。子进程先在输入管道等待；父进程登记全部启动者并完成资源复查，随后统一放行。进程归属使用 PID、创建时间和父子关系，未知 PID 在再次采集后判定。

外部占用或 GPU 显存余量不足时，清理本组已核实的进程，确认退出后重新查询和分配，再执行容量检查和训练。完整 epoch 的检查点、优化器、数据合同和训练计划保留；未完成 epoch 重算。完成阶段的产物和设备记录保持原身份，未完成阶段的设备变更追加历史。

## 约束与实现选择

- 默认排除物理 0、1，可由显式参数修改；CPU 检查不依赖 GPU。
- 默认最多自动重新分配 3 次，每次查询沿用 `--wait-seconds`；未知资源、数据/模型错误直接停止。
- 新空闲卡在下一次阶段分配或故障重新分配时纳入，执行中的健康组保持当前成员。
- 重新分配允许设备数量变化，固定全局 batch 和全局损失归约不变；GPU 浮点归约的逐位一致性不作承诺。
- 新实验记录执行策略，卡数属于运行记录；研究合同仍校验输入、模型、loss、划分、源码。旧实验继续使用其冻结代码。
- 现有线程式双分支调度继续使用；增加阻塞启动包装器与有界恢复控制，不改变模型实现。
- 只发布代码和去标识测试；数据、环境与运行结果保持在私有目录。

## 验收

使用真实 CPU 子进程验证等待、统一放行、失败撤销及外部进程保留；使用真实进程创建时间验证归属；用实际轻量 Xu 网络验证中断恢复的权重和 Adam 状态。GPU UUID 查询和排除进行本机只读验收。Linux 多 GPU 的实际重分配仍由服务器验证，不把纯函数输入和 CPU 测试称作 CUDA 验收。
