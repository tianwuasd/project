# Blood 单卡供数与恢复优化

**目标：** blood 使用一张获准 GPU，接入有界 CPU 预取，记录完整轮次和供数耗时，精确审核旧代码的恢复兼容后发布。

**结构：** 采用现有 BatchSupply 队列、资源监督和独立工作进程；新增 xu_blood_supply 管理二维输入与计时。调整 blood 调度、阶段预算和精确源码兼容。保持现有模型、损失、batch、轮数、病例顺序及增强随机序列。

**依据：** server-engineering 的 v2 vista-v2-performance.md 中阶段预算与实时余量、完整检查点恢复；v1 归档中实际 worker、生效日志与检查点续跑要求。沿用工程入口、配置和日志边界；不需要新项目或新环境。

## 实施与验收

- [ ] xu_blood_supply.py：二维批次 CPU 读取、缩放、线程预取，复用现有内存预算及传输路径。训练主线程按原顺序消耗并生成增强参数。真实压缩文件检查串行与并发数组、未知标签及随机序列完全一致；单批预算也可连续完成。
- [ ] xu_blood.py、xu_supply_budget.py、xu_dispatch.py、xu_fleet.py：blood 固定单卡，二维供数估计与实际队列一致；CPU 余量不足时按需串行，内存不足走既有释放与等待。每例日志含轮号，每轮含训练/验证耗时、CPU 等待与吞吐，日志不推断整任务结束时间。
- [ ] xu_resume_compat.py、xu_pipeline.py：审核精确旧源码与新源码映射，保留原任务合同、产物与检查点。新增执行身份记录；变更数据、监督、模型、未知源码均拒绝。真实旧实现产出的权重与 Adam 状态在更新后继续训练，与同设置连续运行比较。
- [ ] 在本地真实压缩输入、真实网络上执行数值与资源边界回归；测量供数对照。GPU 0/1 与外部占用卡继续排除；无获准 GPU 时只报告 CPU 实测范围。同步发布副本、更新发布清单、GitHub 提交与合并，交付短更新及原输出目录恢复命令。

## 重点边界

每例末尾不足四张切片、全未知标签批次、预取不足一个批次的实时余量、工作进程中断、旧任务多卡分配记录、原始文件损坏以及执行期间代码变化均须有明确验证。热更新运行中的任务不属于本次部署方式。
