# Xu 进程级 GPU 隔离实施与验收

目标：GPU 工作进程只可见本次分配的物理 UUID；物理 0、1 默认排除，外部占用卡不准入。管理进程和 CPU 阶段的 CUDA 可见范围为空。保留固定 batch、模型、预处理，资源不足时等待及恢复完整 epoch。

## 设计

管理入口在导入计算模块前保存原授权范围并隐藏全部 GPU；资源查询使用 NVIDIA 管理接口，不初始化 CUDA。工作进程启动环境使用分配 UUID 的明确顺序，局部索引从 0 开始。启动参数、准入凭据和多卡成员同时转换；父进程读取容量报告时恢复管理侧设备名称。工作进程在计算前核验真实 CUDA UUID、可见数量与准入凭据，并写证据。运行监控同时检查本任务进程是否出现在分配范围以外的卡上，发现即停止。

授权范围尊重 CUDA_VISIBLE_DEVICES 与 NVIDIA_VISIBLE_DEVICES；不支持的或含糊的标识直接拒绝。所有 GPU 工作组仍在放行前确认无外部计算 PID。更新使用新的实验目录，复用已有预处理，旧实验保留。

## 任务及接口

1. `xu_gpu_isolation.py`：`launch_scope(argv, overlay, devices, environment)` 返回局部参数、局部环境和映射；`coordinator_environment(environment, inventory)` 保存授权池并隐藏 CUDA；`report_for_parent(report, devices)` 还原容量报告中的设备字段。真实子进程及纯函数测试先失败，再实现。
2. `xu_gpu_probe.py`、流水线和 fleet 入口：管理枚举改用管理快照，工作进程 CUDA 枚举保留单独函数。`xu_worker.py` 在放行后验证实际 UUID。父进程监控全卡上的本组 PID；CPU 工作进程必须不可见 GPU。
3. `xu_stop.py`：按输出目录、主机、PID 创建身份及任务入口验证旧流水线，发送正常停止信号并等待登记进程退出；保留无关进程。真实进程测试。
4. 运行隔离专项、真实 CUDA 空掩码与禁用设备负向检查、完整回归；独立代码审查；更新发布清单，分支发布合入 main。提供简短停止、更新、重新训练命令。

## 重点验证

- 非连续或重新排序的设备映射，以及单卡、CPU、缺少或篡改凭据。
- 一对并发分支不能看见彼此的 GPU，管理进程不可见任何 GPU。
- 子进程启动与重新分配都采用新环境；容量和推理报告映射一致。
- 被排除卡或已有外部进程的卡不出现本任务新增计算 PID。
- 停止命令核对任务归属，PID 复用、跨主机、错误目录都拒绝。

## 资源压力下持续运行

采用 v1 的空闲卡等待和依赖队列、v2 的阶段总预算与实时新增余量分开核算、完整 epoch 恢复与私有进程清理。已就绪批次立即交给训练；下一批无法预取时先缩小队列。启动前读取真实病例尺寸，至少为单批解压与转换保留足够内存，记录配置上限和实际预算。恢复依次减少供数 worker、缩小队列、串行执行两分支；调整保留到后续恢复。仍无法准入时，主任务保留锁并定期查询资源，等待期间不保留 GPU 工作进程。保持全局 batch、模型、数据和训练日程不变。资源事件可恢复；数据、数值、身份和隔离错误停止。记录实际失败阶段的日志。

验收增加真实数组供数、单批预算下有序消费、下一批不足仍交付已就绪批次、真实子进程内存准入拒绝后的清理与自动续跑、等待期间正常停止和损坏数据禁止重试。已有 CPU 数值训练与检查点恢复回归继续执行。

## 验证边界

本机 GPU 0 已有桌面任务且按要求排除；可真实测试零可见设备、管理查询和拒绝占用。多卡实际计算隔离由同一生产入口的启动核验与运行监控在服务器执行，不能以 CPU 测试代替多卡现场结果。
