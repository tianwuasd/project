# 多GPU执行约定（2026-09-24）

用户要求：可选择显卡数量，再填写空闲显卡编号。沿用已确认B0/B1研究范围，不新增模型方法或重复种子。

实现：向导交互输入或 `--gpu-count 2 --gpus 0,3`；校验数量、去重、显存、利用率与计算进程，用UUID固定设备。正式阶段每卡独立运行一个模型，空闲后动态领取下一项，不采用多卡共同训练单一模型。单卡默认、旧 `--gpu 0` 参数保留。

执行顺序：独立子进程逐卡GPU检查 → 来源预处理及第一张卡工程短测 → 各方向数据准备完毕 → 正式训练动态队列 → 全部成功后第一张卡统一目标评价。工作区锁覆盖整个过程。每个模型单独写日志和状态。

不变条件：5GiB规划预算、CT250/MRI300轮、每轮250训练/50开发步骤、seed0、同模态同方向共享规划、配对初始权重检查、排除5例、全模型冻结后目标评价。

恢复：某模型失败后停止新任务，运行中的模型正常收尾；再次启动使用同一工作区和未改变的代码/环境继续。可重新选择空闲卡数和编号。已完成的模型由正式训练入口校验后跳过。代码或环境变化仍拒绝混用原正式结果。

独立审查修复：模型交接时，只对没有计算进程而利用率统计仍高的情况最多等待10秒；外部计算进程立即拒绝使用。队列收到SIGTERM后清理并等待自己创建的训练进程，恢复原信号处理器；强制SIGKILL、主机断电不承诺正常清理。

验证：42项测试中41通过、1项第三方参考对照跳过；涵盖真实CPU子进程环境隔离、模拟多GPU并发、失败与信号清理、配对初始化和全成功评价顺序。没有服务器多GPU实测或新增研究效果分数。
