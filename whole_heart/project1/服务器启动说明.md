# Whole-heart 服务器任务面板

更新：2026-10-25。按 `server-engineering` 2026-10-24 模板适配。`start_server.sh` 与 `run_zmic44.sh` 打开同一个中文面板，查询仅用系统 Python，不安装训练环境，也不要求先选择显卡。

```bash
bash run_zmic44.sh
# 或
bash start_server.sh
```

## 模型多选

当前只有两个模型配置：

| 选择 | 含义 |
|---|---|
| `1` / `B0` | 基线 nnU-Net |
| `2` / `B1` | nnU-Net + BiasField/单调 Bezier 外观增强 |
| `1,2` / `B0,B1` / `all` | 两者都运行 |

模型选择同时用于短测、正式训练和预测，保存在任务 `plan.json` 与工作区 `00_admin/model_selection.json`。B0、B1共用架构，属于两种实验配置。以后增加模型须同时核对注册表、训练器与科学协议，不只添加菜单文字。

范围可选 `ct-first`（CT留出G）、`mr-first`（MRI留出E）、`all`（五个留出方向），也可用 `--folds ct_holdG,ct_holdA`。只选一个模型不会运行另一个；单模型结果不生成B1−B0配对统计。新任务只等待选定范围全部完成。没有选择清单的旧完整实验仍按原十模型约定校验。

## 操作

- `n` 新建并命名：多选步骤，选择历史输入或从头开始，配置本次模型/范围和所需资源。
- `r` 选择历史续跑；完成任务可追加尚未执行的后续步骤。沿用原模型、数据和源码快照。
- `k` 已完成任务独立重跑：新名称、新目录；原结果保留。
- `s/g/m/l/p/h` 分别查看状态、显卡、每模型训练记录、详细日志、当前用户进程、历史。
- `o` 选择任务查看结果；按分割摘要、病例/七结构、训练数据、文件来源分层。`d/s`切换详细/简洁，`n/p`翻页，`b/0`返回。
- `x` 显示目标并输入STOP后中断该任务，保留上次完整提交的检查点；已请求不等于已经退出。
- `u` 多线路检查并选择独立代码版本，保存旧版本备份；不改共享仓库里的其它项目，不自动恢复训练。
- 普通输入页 `b`返回、`q`退出；主面板`0/q`退出。默认回车只查询状态。退出面板或查询不停止后台任务。

步骤编号为 `0环境 / 1预处理 / 2短测 / 3训练 / 4预测与逐例评估 / 5已有评价汇总`，可逗号多选；始终按依赖顺序运行。当前预测与逐病例指标沿用同一实现，未拆成新的科学算法。纯CPU步骤不询问显卡；CPU数据准备先运行，GPU步骤在进入时等待获准范围内的空闲卡。

## 命令行示例

以下路径和卡号需替换成本次真实路径及获准资源；命令会提交实际任务。

```bash
# 只跑B1；先准备，再训练和预测。CPU准备不会等显卡。
bash run_zmic44.sh --runtime /个人目录/wholeheart_runtime \
  --results /结果目录/wholeheart_jobs --data-dir /原始数据/Wholeheart_Train_Dataset \
  --name 'CT B1实验' --tasks prepare,train,predict \
  --models B1 --scope ct-first --gpus 0,1 --gpu-count 1 --non-interactive

# 同时选两模型
bash run_zmic44.sh --tasks prepare,smoke,train,predict \
  --models B0,B1 --scope all --gpus 0,1 --gpu-count 2 --non-interactive

# 新任务只预测：从完成任务独立复制输入/所选权重，不改旧结果
bash run_zmic44.sh --input-job /完整旧任务目录 --tasks predict \
  --models B1 --scope ct-first --gpus 0 --gpu-count 1 --non-interactive

# 查询不启动计算。自定义runtime时，各命令加相同 --runtime。
bash run_zmic44.sh --query status
bash run_zmic44.sh --query models
bash run_zmic44.sh --query logs --follow
bash run_zmic44.sh --query gpu --follow
bash run_zmic44.sh --query results --job /旧任务或旧工作区 \
  --result-section cases --result-detail detailed

# 原任务继续、或追加后续步骤
bash run_zmic44.sh --resume-job /完整任务目录 --resume-check simple
bash run_zmic44.sh --job /完整完成任务目录 --append-tasks predict
```

`--gpus`是明确候选池，`--gpu-count`是总并发上限；不得超过继承的CUDA/调度器范围。训练一卡一个模型，预测仍受原配置最多三卡限制及本次更小上限约束。空闲检测不是管理员的资源预约。没有实现跨阶段CUDA保留，不承诺同一张卡一直归本任务。

`--foreground`用于前台调试；默认后台提交。返回提交信息不代表训练完成，需再查询状态。断开SSH不等于服务器重启，重启或调度器清理仍会中断计算。

## 输入、缓存、续跑

- 新任务目录为时间戳加随机ID；名称相同也不覆盖。结果根目录与原始数据、运行环境目录相互独立。
- 新任务可选择同runtime的历史任务，或手工输入旧whole-heart工作区。来源仍运行、清单改变或原始数据不符时拒绝。
- 复用采用独立文件复制，避免后续恢复改写原缓存；大缓存复制需要空间与I/O时间。来源、最终路径和验证范围写入计划与回执。
- 选择预处理时可尝试沿用或新建。已识别的缓存缺失、计划/实现/显存预算不兼容可在独立新目录重建；原始数据/权限等普通错误不循环换目录重试。后续任务使用本次工作区。
- 续跑检查`simple`：小文件SHA256、大文件大小/修改时间；`full`：全部已登记产物SHA256；`none`：跳过历史产物检查。所有等级都保留源码/计划完整性检查、进程锁及执行阶段自身契约。
- 续跑使用原源码快照。历史旧训练没有本次快照时，不放宽原训练签名；可只读查看，或在新任务复用兼容数据/已完成权重。不能把旧best检查点冒充完整续训点。
- 已完成步骤不自动重跑。改模型选择、范围或数据，请新建任务；主动重跑保留旧输出。

## 输出

```text
<runtime>/history.json, last-job.json, settings.json
<results>/<时间戳_ID>/
  plan.json, state.json, launcher.log
  code/, code_manifest.json
  logs/, processes/, receipts/, revisions/
  workspace/
    00_admin/    选择与来源
    04_data/     原划分清单、派生缓存
    06_configs/ 环境记录
    07_experiments/formal/   所选模型权重与training.log
    08_results/             预测与病例指标
    09_reports/final_evaluation/  CSV与summary.json
```

每轮原子检查点、训练预算、来源开发选best、原网格输出、Dice/HD/HD95、空预测失败计数保持。模型变化或性能结论不属于这次模板升级。

当前仅本地实现与软件合成验收；Linux后台锁/信号测试、真实CT/GPU和zmic44部署须分别验证。详见 [验收记录](docs/server-panel-validation.md)。
