# 服务器启动说明：Linux / Ubuntu + NVIDIA + Conda

**zmic44 用户请优先看 [2026-09-22 一键实验说明](zmic44_一键实验说明.md)，执行 `bash run_zmic44.sh`。** 新入口自动安装个人 Conda，使用已提供的本地/NAS路径，并可完成全部训练与评价。以下是保留的通用 `start_server.sh` 菜单说明，适用于已经有 Conda 的环境，菜单编号不同。

这份入口用于已经确定的 project1：CT 和 MRI 分别建模，比较基线 B0 与外观增强 B1。你只需要提供**原始训练数据的文件夹路径**。脚本会创建独立环境、匹配病例、准备数据，并运行你选定的阶段。

本次仅提供启动工具，没有替你启动正式训练。已有 Windows 短测记录保留在原位置；服务器的新记录全部写入独立工作区。

## 1. 第一次只需这样操作

服务器需要已经安装 Conda 和可用的 NVIDIA 驱动，并能访问 Conda 软件源、PyPI、PyTorch 下载站。首次安装会下载数 GB 的依赖，需要耐心等待。不要使用 `sudo` 启动脚本。

先把 GitHub 项目下载到服务器；已有副本则更新它：

```bash
git clone https://github.com/tianwuasd/project.git
cd project/whole_heart/project1
bash start_server.sh
```

看到提示后，粘贴原始数据文件夹的**完整路径**，例如 `/data/Wholeheart_Train_Dataset`。然后在菜单选择 **2：短测 CT+MRI**，也可以直接按回车选择默认值。

如果已经知道路径，可以一次传进去：

```bash
bash start_server.sh "/data/Wholeheart_Train_Dataset"
```

路径含空格时保留引号。这里的路径是服务器上的路径，不能直接填写本机的 `D:\...`。

原始数据必须先解压。这个目录及其子目录中应包含完整的 106 对文件，例如 `Case1001_image.nii.gz` 和 `Case1001_label.nii.gz`。中心文件夹层级可以不同，病例文件名和文件内容需保持原样。原始数据在服务器上单独传输，不包含在 GitHub 仓库内。

## 2. 菜单各项做什么

| 选项 | 含义 | 是否开始正式长训练 |
|---|---|---|
| 1 只检查 | 匹配 106 例及文件哈希；检查环境、显存和一次小型 GPU 反向计算 | 否 |
| 2 短测（首次推荐） | 准备 CT 留出 G、MRI 留出 E；两种模态各测试 B0/B1，验证短步训练、恢复和预测文件流程 | 否 |
| 3 CT 正式训练 | CT 留出 G：B0、B1 顺序运行 | 是，2 次 |
| 4 MRI 正式训练 | MRI 留出 E：B0、B1 顺序运行 | 是，2 次 |
| 5 完整正式训练 | CT 留出 A/B/G，MRI 留出 C&D/E，各运行 B0/B1 | 是，共 10 次 |
| 6 继续上次正式训练 | 读取上次队列，跳过已完成实验，从同一实验检查点继续 | 是 |

短测包含完整来源数据的首次预处理，因此不一定几分钟结束。四个训练短测分别最多允许 30 分钟；预处理没有这个限时。看到 `短测通过` 后，查看生成的 `09_reports/短测与预算.md`，再决定是否开始正式训练。短测 Dice 不能用来判断方法效果。

正式训练 CT 为 250 轮，MRI 为 300 轮，每轮 250 个训练步骤及 50 个来源开发集验证步骤。本机过去估算全 10 次核心计算约 155 小时，服务器时间以自己的短测估计为准。每轮写检查点也会增加耗时。

本页旧菜单的 `train/resume` 只保存模型与来源开发集记录。新增加的 `--mode experiment --scope all` 会完成短测、全部训练和评价；`--mode evaluate` 会要求全部10个正式模型完成后继续评价。zmic44 用户直接使用新向导的选项3或4即可，不用目标中心结果反复调参。

## 3. 输出在哪里

默认 Conda 环境在 `project1/.server_env`，默认工作区在 `project1/server_work`，均已排除在 Git 上传之外。

```text
server_work/
  00_admin/                 数据路径、显存预算、上次训练队列
  04_data/manifests/        服务器病例路径和原来冻结的划分
  04_data/derived/          转换后的副本、nnU-Net 预处理缓存
  06_configs/              服务器环境、依赖清单、GPU 检查记录
  07_experiments/           独立短测记录
    formal/                正式训练；每个实验含 run.json、training.log、fold_0/
  09_reports/              准备记录、短测日志和时间预算
```

模型在对应实验 `fold_0/` 的 `checkpoint_best.pth`、`checkpoint_latest.pth` 或 `checkpoint_final.pth`。正式结束后 nnU-Net 会移除 latest，保留 final；继续训练优先使用 final 或 latest，不使用短测模型或 best 来续训。

原始文件只读取，不修改。程序核对全部 106 例，但仍按既定记录排除 `Case2009、Case2017、Case3010、Case5006、Case5015`，实际合格数据共 101 例（CT 58、MRI 43）。外层目标中心不参加训练数据准备、强度统计和网络规划，来源开发集也不参加指纹拟合。

如果希望结果放到容量更大的磁盘：

```bash
bash start_server.sh "/data/Wholeheart_Train_Dataset" --work-dir "/scratch/heart_project1"
```

以后检查状态、继续训练时，都要带上同一个 `--work-dir`。输出目录必须与原始数据目录分开。脚本的 10 GiB 剩余空间检查只是最低拦截条件，不代表足够完成实验；建议事先留出充足的 SSD 空间，例如 100 GiB 起，并观察首次预处理后的实际占用。

## 4. 正式训练时防止 SSH 断线

如果服务器装有 `tmux`，先启动持久会话，再启动脚本：

```bash
tmux new -s heart
cd /你的下载目录/project/whole_heart/project1
bash start_server.sh
```

菜单选 3、4 或 5；看清提示后输入 `TRAIN`。暂时离开时按 `Ctrl+B`，松开后按 `D`。下次登录用 `tmux attach -t heart` 回到会话。不要用 `Ctrl+C` 当作退出会话，它会中断程序。

训练进程确实中断后，重新运行并选 6。只断开 SSH、tmux 中仍在训练时，不要重复启动训练。也可另开终端查看任务状态：

```bash
bash start_server.sh --mode status
```

强制断电或结束进程后，旧状态可能仍显示 running；它是最后记录，并非实时进程探测。以 tmux 会话和实际进程状态判断是否仍在运行。

## 5. 熟悉以后可直接使用的命令

```bash
# 仅检查；首次填写数据路径。
bash start_server.sh "/data/Wholeheart_Train_Dataset" --mode check

# 短测两种模态。
bash start_server.sh --mode smoke

# 只做 CT 留出 G 的基线和增强（会提示输入 TRAIN）。
bash start_server.sh --mode train --scope ct-first

# 只做 MRI 留出 E 的基线和增强。
bash start_server.sh --mode train --scope mr-first

# 完整 10 次正式训练。
bash start_server.sh --mode train --scope all

# 继续最近一次正式训练队列。
bash start_server.sh --mode resume
```

数据路径会被保存在工作区，所以后续可以省略。需要无人值守运行且已经明确接受训练时间时，增加 `--yes-train` 跳过输入 TRAIN。多卡服务器可在命令前加 `CUDA_VISIBLE_DEVICES=0` 选择其中一张卡；本入口不做多卡并行训练。

默认 nnU-Net 规划显存预算是 5 GiB，与本机方案一致，运行前要求至少约 5.5 GiB 空闲显存。可以在**新工作区首次运行**时用 `--gpu-memory 8` 等修改，但这会改变网络规划，需要记录为实验配置变化。实际内存峰值以短测为准，预算不是硬性显存上限。系统内存不足或 GPU 被别人占用仍可能失败。

## 6. 常见停止原因

- **找不到 Conda**：先安装 Conda，或者 `export CONDA_EXE=/实际安装目录/bin/conda`。脚本不会帮你安装系统驱动。
- **下载失败**：检查服务器网络和软件源。没有写入这台 Windows 电脑的代理地址。首次环境创建被中断且 Conda 报已有不完整目录时，先保留错误信息，人工确认后处理该独立环境，不要删除原始数据。
- **GPU 检查不通过**：核对驱动、显卡是否可见及空闲显存。脚本安装的是 PyTorch 2.8.0 CUDA 12.8 构建，不会自动转为 CPU 训练，也不会自动更换研究依赖版本。
- **文件缺失、重名或哈希不同**：请提供更准确的原始数据目录。即使体素相同，重新压缩过的 `.nii.gz` 也可能哈希不同；不要自行跳过校验或把 421 改为 420。
- **准备阶段中断**：再次选择原来的任务，会保留已完成的病例缓存，继续准备。
- **正式训练中断**：选择“继续”，恢复模型、优化器等官方检查点状态；最多通常回退约一轮。数据抽样与增强的随机序列不保证与未中断训练逐位一致，需要在研究记录中保留中断事实。
- **第一轮还没结束就失败**：可能没有可恢复的正式检查点，不能用短测权重代替。保留错误日志排查原因，再用新工作区重新开始。
- **代码、依赖、数据路径、划分或显存预算改变**：拒绝混用旧实验。新实验请用新的 `--work-dir`，不要覆盖旧结果。

需要排查时，提供终端最后的错误、对应 `run.json` 与日志路径即可。脚本失败后会停止，不会无限重试。
