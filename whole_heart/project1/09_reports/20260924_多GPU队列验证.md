# 多GPU队列工程验证

本次只验证新启动和调度代码，没有启动GPU正式训练，不构成B0/B1效果结论。

执行 `python -B -X utf8 -m unittest discover -s tests -v`：共42项，41通过，1项跳过（GitHub未分发第三方增强参考脚本）。向导 `--help` 已显示显卡数量与编号参数，Git差异检查通过。

新增验证覆盖：

- 显卡数量与编号一致、中文或英文逗号、UUID别名去重、拒绝外部计算任务。
- 每个训练子进程只收到一个CUDA_VISIBLE_DEVICES，队列不向子任务传递嵌套调度列表。
- 模拟两卡时先完成的卡领取下一模型；同一张卡不会同时启动两个模型。
- 真实CPU桩程序通过实际Popen启动三项任务，逐一验证GPU环境变量与独立日志；此项没有调用CUDA。
- 全部预处理完成后才进入训练队列；队列报错不调用目标评价。
- 失败停止派发、允许其他已运行模型收尾；正常停止信号清理所属任务并恢复信号处理器。
- 任务交接仅对无计算进程但利用率滞后进行有上限重查，不重试抢占外部任务。
- 两组同时初始化时先发布再比较初始权重哈希，另一组尚未发布不误报；哈希不同仍拒绝。

尚未验证：服务器真实多GPU吞吐量、NFS负载及长训练资源占用。当前短测预算仍是单卡顺序累计核心时间，多卡不保证按数量线性加速。研究设定与目标中心隔离规则未改变。
