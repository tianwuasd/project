# 采用的 academic_tools 流程与成本约定

主来源：`D:/code_project/academic_tools/skills/academic-research-skills`。主流程 academic-pipeline v3.21.1，当前仅 Stage 1 RESEARCH 的 scoping/方法设计；deep-research v2.12.1 负责研究问题与方法论。Codex 适配器只补充“角色内联执行、按需读文件”的运行方式。experiment-agent v1.0 仅使用 plan 模式组织实验，不调用 run 或启动模型训练。

## 本次实际使用

| 角色/skill | 用途 | 执行方式 |
|---|---|---|
| academic-pipeline | 阶段、决策和交付边界 | 主助手记录 |
| deep-research / research_question_agent | 把任务缩成可检验问题 | 主助手按角色要点完成，不另开 agent |
| research_architect_agent | 对照、数据策略、有效性与局限 | 主助手内联 |
| devils_advocate_agent | 检查泄漏、混杂、过强结论 | 同一主助手的一次自查，不称独立同行评审 |
| ARS-Codex / experiment-agent plan | 执行顺序、输入输出与资源约定 | 仅设计 |
| web-access、pdf-reader | 精确核对已有方法和官方来源 | 少量定向网页/本地文本读取 |

选定原文件与 SHA256 在 registry.json；skill_snapshots 与 agent_roles 为只读来源存档，保留原版权许可。它们不是一个已安装完全部依赖的独立插件，不能因为存档里写了命令就自动执行。完整套件仍在 academic_tools。

上游通用角色中量表、元分析、全文写作、多轮审稿、法律辖区决策等不适合当前计算方案的部分不展开。FINER 在本项目采用带依据的定性判断，不用缺乏校准的总分证明创新或合规。材料状态用项目自己的清晰字段记录，没有运行 ARS 全套 schema/hook 校验，不声称通过了那些自动审计。

## 已完成的方法自查

1. 控制初始化、优化预算、后处理；避免把预训练收益归于增广。
2. 外层目标组与内部开发集分开；冻结来源统计与候选超参数。
3. MRI C&D 只作为合并组，不虚构中心身份。
4. 隔离问题病例有清单，并报告改变的数据分母。
5. CT/MRI 分别报告；有限中心和病例相关性限制泛化推论。
6. 保留失败、无效距离和不同随机种子；不挑选最好数字。

剩余待确认：初始化路线、完整 GPU 时长、官方评价实现/血管截断、数据授权具体条款、预训练来源（若使用）。这些限制不阻止交付研究设计，但阻止声称已复现模型结果。

## 成本规则

- 本轮没有启动新的子 agent。简单的文件清点和校验使用脚本，不让大模型反复阅读长文件。
- 后续确有独立简单任务才考虑轻量子 agent，例如元数据整理；复杂设计保留主助手处理，不做无目的多人互评。
- 不启用 13-agent 全队、全套论文流水线、持续监控、跨模型审稿或自动重试循环。
- 本轮进行一次集中设计自查；只因具体问题修改相应部分。
- 进入成批全文精读、多轮审稿、多代理任务、额外模型训练之前，先说明为什么需要和预期工作量。
- 无精确的本任务 token 计数可供此流程读取，不虚报已用 token 或费用。通过来源缓存、状态文件和变更记录减少下一轮重复工作。

## 人工确认点

已确认的范围、模态策略、复现方向和隔离策略不重复询问。学术方向改变、测试集使用方式改变、初始化路线改变、数据修复规则与明显增加成本时询问。

academic-pipeline 的阶段要求为：“After each stage completion, proactively prompt and wait for user confirmation”。本轮交付可审阅方案后再进入训练实现；这里也符合用户要求“重要方向不确定一定询问”。不启动 WRITE、审稿或论文发布阶段。
