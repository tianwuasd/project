# 候选评估的状态转换验收

这是任务 3、4 的接口和使用验收补充，**尚未执行**。它细化已有 U07–U11，不增加新的学术能力或来源权限。实际通过结果需有相应命令、产物或定向测试记录。

评估有三个不同的依赖：原候选及其生成时依据、每轮实际查询记录、当前可用的文献证据。旧候选作为历史设想保留；查询当时的状态与现在的筛选/阅读状态分别展示。不能只读最近一个候选版本，也不能用旧查询收据判断一篇文献现在是否已经读完。

| 场景 | 操作与独立判定依据 |
|---|---|
| A01 未执行反例查询 | 从原创 A、B 的已复核材料生成候选后直接评估。即使模型对新颖性很有信心，宿主仍显示未检索及待人工判断；不存在全球首次状态或总分。 |
| A02 零命中与来源失败 | 一条查询成功返回零条，另一条限流。保留两条各自来源、时间和边界；空结果不能覆盖失败。恢复失败查询后，成功查询的调用计数仍为 1，原失败记录保留为历史。 |
| A03 新命中尚未筛选 | 返回原创记录 C 的确切已保留 ID，先不给正文、不纳入。评估显示针对 C 的筛选/补充文本待办；元数据不能成为受支持的反例陈述。 |
| A04 同一命中后来已阅读 | 明确纳入 C、添加原创文本并完成阅读和复核后，再评估同一个候选 ID。新评估引用 C 的当前有效链，旧候选和旧评估字节不变；旧收据里的待读状态不能让 C 永远显示未读。 |
| A05 同一命中后来被排除 | 为 C 保存明确排除理由后重新查看。给出该 ID 与当前排除理由，保持检索曾命中的事实；不能把排除记录当作“没有命中”，也不能继续要求对已排除 C 执行普通纳入阅读。 |
| A06 原候选依据后来失效 | 修改或移除其一项来源、人工决定或筛选状态。仍能校验并查看历史候选，但不能把其中旧证据当成当前受支持前提；当前评估过期或明确列出失效缺口。 |
| A07 操作性变化与恢复 | 只提高预算、增加无关进度日志或恢复已经完成的阶段，不产生新候选身份，也不使未变的评估依赖失效；记录实际模型尝试计数。 |
| A08 版本与附件完整性 | 生成第二个不同候选批次后仍能按第一个 ID 查到正确历史。改写该版本任一正式产物时明确报完整性问题，保留文件；不默默跳到另一个版本。 |

C 使用新写的原创模拟资料，不冒充真实论文；可设为“80 个模拟任务，某负载下等待时间 10→10，未观察到改善，不能现实外推”。数值只属于这份输入的模拟条件，不能从它推导真实系统效果。若使用受控响应建立此用例，只记录引用/状态机制通过；未知 C 被固定 Demo 拒绝应如实记录，不扩充标识来伪装通用理解。

评估必须分别输出新颖性线索、研究价值、可行性和证据强度，各自有理由、引用或明确证据不足。独立审查对所给完整上下文逐项复核，保留部分支持、冲突及不足。宿主决定当前资料和检索缺口是否已被实际操作解决；模型不能自行删除这些缺口。

只读状态验收还要比较操作前后的研究行与无关文件，并监测模型/来源调用计数为零。允许数据库正常 WAL/SHM 协调文件；不允许为了查看候选而初始化缺失研究库。历史内容可校验与当前内容有效是两个检查，分别记录结果。
