# 下一阶段接口核对（0.3 设计输入）

2026-09-09。本文件记录依据当前代码核对的设计约束，不表示创新候选功能已经实现；正式实现前另立版本规格与计划。

## 已有可复用能力

- `ModelJob` 已支持 `synthesize`，Codex 和 Exchange 按任意结构化 Schema 返回；无需增加第二个顶层调度框架。
- `Runner.backend.validated()` 在领域产物校验后才提交缓存，所有新模型任务都应走这一层。`ModelJob` 的输入、模型、提示词和 Schema 参与缓存身份。
- `current_cards()` 和 `decisions()` 已验证文档版本、证据位置以及复核对应的卡片哈希；“支持某条文献陈述”不能被新模块升级为“支持创新性”。
- `Runner.search()` 保存查询结果、失败/截断/候选上限并保守去重；新增候选资料仍需明确筛选、阅读，元数据相似只能成为反例线索。
- 0.2 的快照与可复算统计只描述语料；可作为输入证据，不能让语言模型自由改写数值或宣称领域全貌。

## 后续实现应保留的边界

1. 区分作者自述贡献、系统提出的假设、基于当前材料的评估，分别保存其来源与类型。不能把旧 Claim 的 contribution 分类当成已证明创新。
2. 生成候选是实际结构化模型任务，包含问题、最接近工作、差异、支持与反例、可证伪假设、最小验证方案、资源条件和检索截止。无可用证据时明确缺口，不以固定模板冒充模型推理。
3. 定向反例检索和评估分阶段保存。检索失败、未筛选或未读全文的线索不能被归类为“未发现反例”；缺少阅读时应生成明确待办。
4. 评估分别描述新颖性线索、价值、可行性和证据强度；始终是“候选”，没有“全球首次”或合并后的伪精确总分。
5. 独立审查必须看到候选依赖的当前资料和相关上下文，不能只复述生成者的意见。更改原文、筛选、复核、出版状态或检索范围后，旧产物明确失效并保留历史。
6. DemoBackend 当前只接受原创单文档样例，不支持 synthesize。新增演示必须有显式原创夹具、任务类型和真实性标记；不能让 demo 自动处理真实论文或声称人工学术质量已测量。
7. 真正完成此阶段的使用测试应包括：候选生成、定向反例线索、补读后评估、故障/预算恢复、版本失效，以及把“没有检索”与“本次范围内没有发现”区分开。

已读代码依据：`models.py` ModelJob、`workflow.py` MeteredBackend/Runner.search、`analysis.py` read/review、`backends.py` DemoBackend/CodexBackend/ExchangeBackend。0.2 的发布仍按当前计划完成；这些约束用于后续版本，不提前缩小持续目标。
