# 0.3 创新候选：阶段规格

2026-09-09。来自已接受的完整设计中“创新候选与反例检索”阶段；本文件为后续开发规格，功能尚未实现。0.2 的实现与发布不依赖本阶段。

## 目标与实际操作

研究者已有一个完成筛选、阅读和复核的文献项目。系统使用真实 Codex/可替换后端提出有限数量的研究候选，执行定向反例检索，再依据实际可读、已复核材料给出多维评估和最小验证方案。不能以固定模板或仅支持人工填写的卡片替代候选生成能力。

操作顺序：

1. 从当前有效的纳入文献和已支持陈述生成至多 3 张候选卡；可显式选择文献子集，输入超过配置上限时明确拒绝，不暗中截断原文。
2. 运行候选中的定向查询，最多 2 轮，每轮最多 2 条查询，每来源每查询最多 10 条结果。保留查询、来源、时间、返回、失败、截断和项目上限。
3. 返回新线索及待筛选/待阅读/待复核事项，研究者使用现有命令处理。元数据相似不能被写成已确认反例。
4. 根据候选、检索记录和当前已复核材料生成独立评估。未完成必要阅读时保留缺口；不能把未检索、失败、截断或未读线索解释成“没有反例”。
5. 导出可修改的中文候选/评估报告、引用表与证据附表；所有版本保留，输入改变后旧评估显示过期。

拟新增命令为 `innovate`、`challenge`、`assess-innovation`，各自可重试/恢复成功部分；名称在本阶段实现计划固定。现有搜索—阅读—综述命令保持兼容。

## 候选与评估契约

每个候选包含稳定 ID、研究问题、最接近已有工作及陈述 ID、具体差异、支持证据、反例/已解决的可能、可证伪假设、最低验证方案、数据/算力条件、风险、定向查询及生成时检索截止。输出始终叫“候选”，不能提供证明全球首次的状态或证书。

评估分别记录新颖性线索、研究价值、可行性、证据强度及各自理由和引用，不合成无依据的总分。主张类型显式分为作者自述贡献、系统假设、基于本次材料的评估。系统假设不是论文实验结果，不能进入现有原文 Claim 的 result 分类。

模型只可引用本任务已提供的工作、陈述和证据 ID；宿主校验所有引用与文档版本、筛选、撤稿和复核状态，未知 ID 或无效依赖拒绝。独立审查看到所引用的实际文档上下文和候选，不继承生成者会话。审查可能不支持、部分支持或证据不足；无法确认时不能升级为支持。

外部线索保留 `metadata_only` 等访问层级。已复核的相近工作也只证明在本次语料中的相似与差异；结果用“本次检索范围内”描述，不把无命中等同全球不存在。

## 快照、恢复与预算

候选生成和评估分别有不可变输入快照、输出与日志。候选可作为历史研究设想继续查看；增加反例资料后应更新评估，而不是抹掉原候选或强迫生成另一张无关卡片。

不能直接把包含所有日志计数/成功任务数的 `exports.snapshot_token` 当作模型任务输入有效性：生成任务本身会改变这些计数。新增语料依赖指纹需精确固定研究范围、文献版本、文档/证据哈希、当前阅读卡和复核决定、相关检索记录；排除该分析自己的运行日志与计量事件。使用模型前冻结，提交前验证相关输入仍然一致。

每次模型调用必须经过 `MeteredBackend.validated()` 及完整领域验证，再提交成功缓存。提示词/Schema/模型/输入版本参与缓存键。读取、生成、评估、审查与恢复共用项目预算；超时未知消耗保持占用，不隐含免费重试，不自动提高预算。

状态至少区分待检索、来源失败、待筛选/阅读、待模型输入、预算暂停、待评估、待人工判断以及过期。已经完成且输入未变的模型或查询任务复用；未完成任务可继续，最多允许规格内的检索与审查往返。

检索新增记录沿用保守去重、具理由筛选和容量上限。需要为 Runner 的搜索提供更小的显式单次上限时，缓存身份包含有效上限，旧默认行为不改变。任何额外参数先做兼容与限额测试。

当前 `Runner.search` 日志的 summary 被 0.2 严格冻结模型消费。为反例流程返回已保留工作 ID 时，不得随意给 summary 增加字段或改变统计快照序列化；可在搜索事件的独立顶层字段保存 ID，并在新调用返回对象中提供。显式小上限采用独立缓存身份，历史查询仍可用原默认路径。验收必须用 0.2 已保存的语料文件验证跨版本重算，不能只测新生成文件。

## 后端、真实性与扩展

沿用 `ModelJob(kind="synthesize")` 和现有 Codex/Exchange 协议，不增加第二个顶层调度框架或新购 API 密钥前提。生成、评估和独立审查用显式任务类型及版本区分。模型不获得论文外的任意文件、工具或网络权限；定向检索由确定性工具执行。

Demo 的新增行为只适用于包含显式原创标识、合法证据的固定演示输入。对真实论文必须拒绝合成回答。演示可展示支持、反例和未知状态，但不能声称是真实模型能力或学术准确率评测。

0.2 已发布后的统计文件兼容性须保留；若未来改变统计报告渲染，单独版本化渲染/产物协议，不能把旧的完好文件误报为损坏。

## 验收证据

- 候选不是空模板：可在已安装包中从现有原创阅读/复核项目完成结构化生成，并验证真实后端接口能调用该任务。
- 语义边界：作者贡献不会被变成已证明创新；系统假设不能伪造已观察结果；不存在的工作/陈述/证据 ID 被拒绝。
- 反例使用流程：定向查询成功、有命中待阅读、补读后评估；另测零命中、失败、截断、容量不足和未读线索，均保留不同状态。
- 恢复：预算暂停或 Exchange 等待后恢复，不重复已完成且输入有效的调用；源文档、人工复核或范围改变后，旧评估明确失效。
- 真实 Codex 小规模冒烟使用原创文本，不上传用户真实研究私料；真实公开检索探测限量执行并记录可用性。合成测试、真实接口和人工学术评价分别报告。
- 每个任务独立审查，完整回归、安装包使用测试与六环境 CI 通过；沿 Git Flow 发布 0.3.0。人工学术准确率在没有固定真实论文人工标注前继续明确“未执行”。
