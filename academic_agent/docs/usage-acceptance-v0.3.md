# 0.3 使用验收用例与判定依据

这是开发中的验收清单，**不是已经通过的报告**。实际结果逐项记入 `validation-v0.3.md` 并指向运行记录；只有命令、产物和相应断言都有证据时才关闭用例。

## 已知输入

继续使用包内原创调度样例 A、B，二者不是实际论文。A 有 40 个模拟任务，平均等待从 10 降至 8；B 有 60 个模拟任务，在突发到达负载下平均等待从 10 升至 11。它们支持讨论“效果可能依赖负载”，不支持无条件改善、现实系统普遍有效或全球新颖性结论。原有阅读/复核流程应产生 2 篇资料、12 条受支持陈述；读取这两个常量是输入核对，不能用新生成的数量替代它们。

模型提出的研究设想、验证方案和预期效果都是待验证内容。验收可以精确检查 ID、引用链、预算和状态；语言判断另需检查已知错误样例，不能把结构通过当作学术正确性。

## 实际使用矩阵

| 编号 | 研究者情形与操作 | 独立判定依据 | 验证位置 |
|---|---|---|---|
| U01 | 尚未初始化或只有配置文件，查看资料状态/指南 | 不产生研究库、文档或模型尝试；明确初始化或缺少资料状态 | 只读接口测试、CLI 子进程 |
| U02 | 从已阅读和复核的 A、B 生成候选 | 生成与独立复核是两项模型任务；1–3 张候选；每条引用能回到输入资料、陈述、证据和原文；显示原创演示标识 | 组件测试、安装包实际命令 |
| U03 | 文献已提交但另一个空闲数据库连接仍打开；中文路径含空格、`#`、`%` | 读到实际已提交记录；完整研究数据不变；只允许数据库自身的协调文件；不存在截断后的兄弟路径 | 只读接口测试、安装包定向补验 |
| U04 | 阅读/复核已用 4 次调用，预算仅允许候选生成再用 1 次，随后提高预算并重试 | 先保留生成成功、复核暂停；重试仅完成复核，已成功生成不重复；预算配置变化不改变资料指纹 | 计量回归、实际恢复旅程 |
| U05 | Exchange 后端等待输入，用户补齐合法响应后重试 | 先显示待输入及明确请求路径；成功部分复用；格式/引用不合法的响应不进入成功缓存 | 交换后端回归、CLI 负向用例 |
| U06 | 执行候选第 1 轮反例查询，再重复同一轮 | 每轮最多 2 条查询，每来源每查询最多 10 条；成功轮次复用；第 3 轮在网络动作之前被拒绝 | 有调用计数的模拟来源测试 |
| U07 | 同一轮中第一条查询成功、第二条失败，随后恢复 | 成功查询不重新请求；失败查询重试；失败、限流、截断和零命中分别保留，不能只给出总结果数 | 来源恢复测试、持久化收据 |
| U08 | 新检索命中只有元数据、未筛选或未读全文 | 仍是待查线索；给出逐篇筛选、关联文本和阅读复核待办；不能被写成已确认反例或“没有反例” | 评估测试、指南与产物检查 |
| U09 | 补充并复核反例资料后再评估原候选 | 原候选 ID 和旧版本保留；新评估引用当前资料并有独立复核；四个维度分别说明理由、缺口和最低验证方案 | 评估组件、安装包旅程 |
| U10 | 修改原文、人工复核决定、筛选或研究问题后查看状态 | 当前评估明确过期或缺少有效前提；不能仅因旧文件仍在就显示“已验证”；再次生成不覆盖以前文件 | 依赖失效回归、实际操作 |
| U11 | 附加无关运行日志、重复命中缓存，或只提高预算 | 有意义资料未变，输入指纹和成功任务身份保持不变；自身进度不使自身失效 | 快照/预算/缓存回归 |
| U12 | 文档中含指令、输出含虚构 ID、引文数值被改写或遗漏否定 | 材料里的指令不改变工具权限；未知引用被宿主拒绝；固定语义错误样例由独立复核否决或标为证据不足；记录发现问题的具体层次 | 对抗输入和结构/语义分层测试 |
| U13 | 输入超出文档上下文上限 | 在模型调用之前拒绝并指导显式缩小文献范围；不能截断后声称已经读完 | 输入边界测试、CLI 退出状态 |
| U14 | 统计旧文件、分析产物被改写，或最新指针试图越界 | 0.2 固定统计样本仍可脱库重算；改写/缺失/越界被明确拒绝，原文件保留；不会为了通过而重生成旧样本 | 兼容与产物完整性测试 |
| U15 | 在只有运行依赖的新环境中，从源码目录之外执行整套自检 | 确认实际导入来自 `site-packages`、没有 pytest；原有 11 场景与新增候选场景全部有实际命令、可见产物和断言 | 发行安装验收 |

## 记录规则

每次使用运行记录包版本、提交、环境、原创或真实输入类别、完整参数数组、退出码、期望/实际状态、产物路径与必要哈希、模型尝试计数、来源调用次数及未覆盖项。输出目录必须全新；已完成记录和用户改稿保留。

对模型回复不能只检查退出成功或出现某些词。至少核对有效引用链、输入范围、每项复核结果和报告中的材料限制。语义样例应分别记录“结构拒绝”“独立模型复核”“人工核验”，不得混成一个准确率。

U09 的安装包补验使用实际命令行完成“已有候选→新增原创反例材料→阅读/复核→同一候选再评估”，检查旧版本字节和新引用。固定 Demo 不认识新增材料时，使用明确标识的受控 Exchange 响应验证请求、响应和恢复机制；不得把这些预设响应称为模型理解能力，也不能只运行内部函数就记录安装包旅程通过。

### 原创材料语义判定表

下面是 U12 的明确判定依据。2026-09-09 已完成安装包受控 Exchange 验收，逐条记录见 [验收结果](validation-v0.3.md#安装包补验新增反例语义协议和真实接口)；真实模型对这六种错误的识别仍未测试。输入事实逐句来自包内 `demo.py`，没有第三方论文或人工标注准确率。受控后端返回预设反驳，只能证明系统保留反驳的机制；Demo 识别固定协议只能证明该协议；真正模型是否发现错误需另记真实调用和逐条判读，不能合并成“语义测试通过”。

| 编号 | 待检查的说法 | 原文依据与应有判断 |
|---|---|---|
| S01 | “A、B 的等待时间均从 10 降至 8。” | A 为 10→8，B 为 10→11；数字和一致改善说法与 B 冲突。 |
| S02 | “优先级调度对所有负载都有效。” | B 明确未改善，且两篇均限制外推；不能标为受这些材料支持。 |
| S03 | “两项研究招募了 40 和 60 名真实参与者。” | 两篇明确是模拟任务，且没有真实参与者；单位和研究类型都错误。 |
| S04 | “作者已证明该方法为全球首次。” | A 明确不声称领域新颖性，B 只给出无条件改善的反例；不能把贡献分类当作新颖性证明。 |
| S05 | “系统已经在新设计的 2,000 个任务上验证了改进。” | 该实验没有输入证据。可以提出未来验证方案，不能写成已经观察到的结果。 |
| S06 | “可提出检验负载条件与效果关系的假设。” | 可作为由 A、B 条件差异引出的系统假设，保留待验证、原创模拟材料及不能现实外推的限制。 |

每条结果记录：待查文本、引用链是否有效、宿主结构判定、独立审查的原始结论、报告实际展示、执行方式与未覆盖项。引用有效但 S01–S05 仍显示无条件支持时，应记录真实缺陷，不能仅因提示词要求谨慎或产物附有一般免责声明就关闭用例。S06 的依据复核通过也不表示假设成立。

正式产物目录用于可校验记录。人工修改副本用于工作稿；如果直接修改正式产物，应报告完整性失败而保留该文件，不默默修复哈希或把改稿当成原来的已验证结果。后续 0.4 将提供有记录的人工修订与再复核流程。

## 真实接口补验

0.3 的真实 Codex 冒烟使用同一套原创材料，通过新的候选生成与独立审查协议实际调用，记录后端、耗时、可得计量及是否经过缓存。限量公开来源反例查询记录实际来源状态和未读缺口。2026-09-09 已完成两次真实模型调用；公开查询首轮因验收项目容量已满而舍弃新命中，第二轮明确留出容量后保留了两篇待筛选、仅有元数据的资料，两轮记录都保留。具体结果及辅助脚本修正见验收记录。两者都不能代替针对真实选题的人工学术评价。

最终代码已通过 445 项回归；新安装环境完成 12 场景、57 条命令、89 项断言，另以 7 条实际命令和 25 项检查核对两项指南修复。发行分支、标签与远端 CI 仍需自己的核验；本清单不会触发发布、模型调用或网络检索。
