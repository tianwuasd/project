# 冻结语料描述统计

趋势模块只计算当前文献库的组成。它不推断领域总体增长，不预测、不聚类、不做显著性检验，也不把测试通过率当学术质量评测。未执行人工评测。

## 输入与日期口径

`freeze_corpus(store, annotations=None, date_basis="record_year", as_of_year=None)` 冻结全部候选 Work 字段、记录修订、来源与关系、出版检查、活动文档 ID/内容哈希/产物哈希/阅读层级、项目检索式和限制、检索摘要、来源状态/错误/截断/命中总量/检索时间以及人工批注。项目配置只导出研究范围与限额，代理地址不写入语料。

没有新生成的运行时间参与输入哈希；相同研究状态、批注和截止年得到相同输入和结果。默认截止年为冻结时的 UTC 年；显式 `as_of_year` 用于重现某个统计截止年，该年仍按未结束年处理。冻结不重新检索、不更新出版状态、不改变数据库。来源的现有时间与修订被原样保留，不代表信息在冻结时重新核验。

日期口径有三种：

| 参数 | 使用年份 | 边界 |
|---|---|---|
| `record_year` | Work 元数据年份 | 默认；出版、首次上线、版本年份语义未统一；人工批注不覆盖它 |
| `first_publication_year` | 带来源说明的人工批注 `year` | 使用者应按首次公开出版的统一定义批注；缺失不回退元数据 |
| `formal_publication_year` | 带来源说明的人工批注 `year` | 使用者应按正式出版的统一定义批注；缺失不回退元数据 |

一个批注文件服务于一次选定日期口径；如两种口径不同，请分别维护文件和版本。程序验证来源说明存在，但不能自动核实该说明是否支持该口径。

合法年份必须是整数 1000..9999，布尔、字符串与浮点数不作为合法年份。元数据中的非法年份保留原值并单列；人工年份与截止年的非法输入直接拒绝。未来年份单列，不为任意元数据年份扩展无限区间。

## 人工方法标签

批注是严格 JSON，未知字段、未知文献 ID、空版本/批注者、空标签、无理由标签、无来源年份均被拒绝。例如：

```json
{
  "version": "1",
  "annotator": "研究者",
  "label_definitions": {
    "图模型": "方法以显式图结构表示研究对象",
    "优化": "以明确目标函数求解决策变量"
  },
  "works": {
    "WORK_ID": {
      "year": 2023,
      "year_source": "论文首页 Published 日期",
      "labels": ["图模型", "优化"],
      "rationale": "方法章节给出图结构与优化目标"
    }
  }
}
```

替换 `WORK_ID` 为本库真实 ID。标签去除首尾空格并去重，大小写与同义词不会自动合并。`label_definitions` 可省略；省略时固定词表来自整个批注文件，报告明确“未另附定义”，含义仅由逐文献理由说明。提供定义后，使用的全部标签必须在定义表内；已定义但未出现的标签也报告零次。词表在整个快照内固定，不从摘要或模型自由文本推断标签。

空批注文件 `{"version":"1","annotator":"研究者","works":{}}` 和不提供批注均可计算，报告未标注覆盖。人工批注所有 ID 必须在本库，允许为待筛选或排除记录预先批注，但这些记录不计入标签次数。

## 计数与分母

`compute_trends(snapshot)` 是纯函数；无需数据库、网络或模型即可完全重算。

- 候选总量、筛选纳入/排除/待定和撤稿数覆盖全部候选。筛选分类互斥；撤稿与筛选分类重叠。
- 合格纳入 `eligible`：`screening=include` 且没有任何已标记撤稿的出版检查。每个 Store 去重书目 ID 只计一次。
- 年度分母：合格纳入中，选定年份合法且不晚于截止年的记录总量。年度占比为该年次数除以此分母。观察到的最早与最晚合法年份之间补零；区间外不虚构覆盖。截止年如有记录单列未结束，不用于完整年度比较。
- 标签分母：全部合格纳入，包含缺失/非法/未来年份。每篇同标签只计一次，多标签之和可超过 100%。逐年标签占比的分母为该年全部合格记录，年度间空白年分母为零。
- 零分母对应 JSON `null`、CSV 空单元格与 Markdown“未定义”，不表示 0%。未标注不等于没有使用某种方法。
- 文档层级、疑似关系数、arXiv 标识覆盖均使用合格纳入集合；没有活动文档按 `metadata_only`。arXiv 标识覆盖仅表示存在非空 ID，不是来源召回、来源覆盖或质量评价。
- 去重书目不等于独立研究；预印本与正式版不自动合并，关系记录不算独立重复验证。
- 小样本诊断：合格纳入总量 `<50`，或任一实际比较年份（含观察区间内零值年份、排除截止年）记录数 `<10`。任何样本量都保留仅描述语料的边界。

结果保留每个分类的具体 ID（`work_ids`）、计数（`counts`）、`annual`、`labels`（含逐年数据）、`document_levels`、`arxiv_share`、参数、诊断与计算公式。

检索日志展示全部冻结摘要与来源响应状态，不隐藏失败、截断、候选上限丢弃、来源总量及检索时间缺失。没有日志的语料标记检索覆盖未知；混有本地导入记录时，其覆盖仍未知。成功的有限检索同样不证明全面覆盖。

## 产物与核验

`build_trends(store, annotations=None, date_basis="record_year")` 每次写新目录：

```text
analyses/trends/<unique-version>/
  corpus.json
  computation.json
  annual.csv
  labels.csv
  report.md
  manifest.json
analyses/trends/latest.json
```

旧目录和人工改稿从不覆盖。写入前后检查 Store 快照；发表时在 `BEGIN IMMEDIATE` 中再次检查研究修订、日志数、成功任务数及配置哈希。发生冲突抛出 `ValueError`，旧 `latest.json` 不变；未发表暂存目录保留，便于审计。配置文件采用既有快照哈希规则，数据库事务不能阻止外部程序在最后一次检查后改写配置；下一次状态检查应重新核对快照。

输入 SHA-256 是完整 `CorpusSnapshot` JSON 的 UTF-8 规范形式：`sort_keys=True, separators=(',', ':'), ensure_ascii=False, allow_nan=False`。算法版本固定为 `corpus-trends-1`。输出字节确定，CSV 使用既有公式注入防护，Markdown 使用既有转义。

`manifest.json` 严格列举五个固定文件及各自字节 SHA-256，绑定算法、输入哈希和研究快照。`manifest_hash` 是去除此字段后清单规范 JSON 的 SHA-256，避免循环自哈希；这不是数字签名。`latest.json` 包含：

| 字段 | 含义 |
|---|---|
| `schema_version` | 1 |
| `version` | 新版本目录名 |
| `snapshot` | `[research_revision, log_count, succeeded_job_count, config_hash]`，可与既有 `snapshot_token(store)` 比较 |
| `input_hash` | 规范语料输入哈希 |
| `manifest_hash` | 新版本清单摘要 |

`verify_trends(Path(directory))` 完全离线：验证清单契约、自摘要、固定文件字节哈希、输入绑定，再重算 `ComputationRecord` 并重新生成全部五个文件逐字节比较。清单缺条目/多条目、路径穿越、产物符号链接、缺失/损坏文件、不支持版本、不等价重算均抛出 `ValueError`。更新一个文件的清单哈希仍不能绕过重算。

成功返回 `{"valid": true, "algorithm_version": "corpus-trends-1", "input_hash": "...", "snapshot": [...], "files_verified": 6}`。核验不读取 `latest.json`，也不需要原数据库或文献文件。它验证冻结产物内部一致性，不能证明快照中元数据/人工来源真实、当前数据库未变或外部文档仍存在，也不能识别同时重写全部输入、输出和清单的攻击者。需要外部真实性时应另存受信任摘要或签名。
