## 完成目标的范围

在现有本地研究内核上，完成从多源文献发现、证据阅读到描述性趋势、创新候选评估和可追溯写作的可用闭环。每个阶段交付可安装版本、使用说明、自动化与使用测试记录，沿 Git Flow 发布到 `tianwuasd/testing_tools/academic_agent`。

“完成”指以下版本验收全部通过；不代表系统替代研究者、证明全球首创、自动产生实验结果或达到未经人工测量的准确率。具体题目的领域验收待用户给题目后进行，不阻塞通用能力研发。

## 每个阶段的质量门槛

1. 设计说明和有明确接口的开发计划先入项目，记录默认选择。
2. 关键失败路径有针对性回归；既有测试保持通过。
3. 使用已安装的包模拟研究者操作，检查可见产物和退出状态；不能只调用内部函数。
4. 对正常输入、缺失信息、来源故障、恢复、修改后重新生成、中文路径进行实际操作验证。
5. 独立审查后处理重要缺陷；保存审查和实测证据，区分模拟、真实接口和人工学术评测。
6. feature → develop → release → main → develop；以 `academic-agent-v<版本>` 标记发布。验证远端提交与 CI，成果仍是仓库中的整体文件夹。

## 使用测试的层次

- 离线使用测试：原创合成文本和书目夹具，结果可手工精确核对，每次 CI 运行。
- 真实接口冒烟：限量公开检索/已授权 Codex 调用；记录时间、覆盖、限流和未知计量，失败不伪装为零结果。
- 学术质量评测：未来固定真实论文开发集/保留集，人工标注并测量证据支持、数值和引用错误；未执行前不报告准确率。

首阶段沿用个人本地、中文文档、Markdown 产物和 CLI 的既有选择。用户以后提供题目、研究方法或交互偏好时，更新相应阶段的验收，而非丢弃通用测试。
