2026-09-13 发行前冻结：六项实现、离线安装使用、I1–I4/M1 复审关闭及四阶段真实接口观察已完成，详见[验收记录](validation-v0.4.md)。两篇合成材料的真实整稿复核保留 13 supported/1 insufficient，正文数字、条件和证据定位已检查；此结果不代表人工学术质量评测。历史完整测试 1 failed/619 passed、后续相关 17 项修正及写作 70 项覆盖分别保留，不合并计数。最终包核验、Git Flow 与正式提交六环境 CI 的状态以发行收据为准；其完成前不宣称总目标结束。[实施计划](superpowers/plans/2026-09-09-v04-writing.md)与[设计补充](superpowers/specs/2026-09-09-v04-writing-design.md)保持本阶段执行依据。

## 要交付的闭环

研究者从现有已复核资料选择研究问题和写作范围，生成可修改的大纲及实际段落草稿，看到每段的主张、证据和独立审查结果。修改某段后提交有来源记录的新修订，再复核该修订；原文、复核决定、选题范围或领域规则变化时，受影响内容不能继续显示当前有效。

默认文稿为文献综述、相关工作及拟开展研究的论证。它必须有真正的跨文献综合段落，不能只把阅读卡列表重新排版。没有用户实验/实证产物时，不生成已经实施的实验、观察到的结果或可投稿的完成论文承诺。已有创新候选只能作为待验证研究设想。

交付仍为本地应用：Markdown、BibTeX、结构化正文与引用/证据审计，不把完整网站、Word 排版、实验执行或云协作列入本阶段。

## 正文与依赖

每份正文有稳定文稿身份和独立版本，每个段落有主张列表、引用、来源类型、作者/模型来源、创建时间和父版本。引用键仍来自已入库文献，不由模型自由编造。至少区分原文陈述、跨文献归纳、冻结统计结果和系统提出的假设，不能把作者自述贡献升级为已经证明的新颖性。

所有实质性句子都应在结构化主张中有对应记录，不能只对一段的一句话建引用就宣称整段通过。段落可以包含非实证的连接语，但其用途和范围应明确。未知、互相矛盾、只有摘要或仍需 OCR 的资料保持相应限制。

实现时应让正文由有序的文本单元构成，每个单元显式声明主张或连接语类型；正文由宿主拼接，不能另藏一份未经覆盖检查的自由段落。宿主能验证每段文字都进入了待审集合，但不能仅凭“连接语”标签判断其中没有事实断言。独立审查必须同时看到并检查连接语，测试包含把虚假数字藏在连接语中的样例。这样把可精确核验的文字覆盖与仍需语义判断的事实性质分开，不宣称结构检查已经解决语言理解。

原文依赖连接到当前资料快照中的 Work、Document、Claim、Evidence 和有效复核决定。跨文献归纳保留多个来源各自的条件与差异；不能把两个样例的观察直接泛化到真实系统。统计句子连接到明确选择的、已经校验的 0.2 冻结语料和 ComputationRecord，不能伪装成某篇论文的原话，也不能让模型重新计算数值。

统计引用保留选定快照、口径、分母和时间，不自动替换成“最新”结果；报告明确它描述的是该冻结语料。来源变化需要重新检查当前稿，自身写作任务增加的计量或进度日志不能单独使已选统计证据失效。

## 生成与独立审查

大纲和正文生成使用现有 Codex/可替换 Backend 的实际结构化任务，所有调用经已有预算预留、领域验证和缓存层。领域验证检查主张与引用身份、类型、版本和完整覆盖；无效结果不进入成功缓存。全量可用上下文超过上限时停止并要求显式缩小范围，不静默删掉反例或局限段落。

独立审查是另一个模型任务，看到完整的限定上下文、正文和主张依赖，不继承写作者会话。逐项记录支持、部分支持、冲突、证据不足及理由。报告展示缺口和未通过项；模型复核不标成已由人类验证，不把两个模型一致视作学术正确性保证。

语义与结构分开验收：引用存在并不等于支持句子。固定用例必须包含改错数字、遗漏否定、隐藏负载条件、无依据的普遍化，以及把假设写成已经观察到的结果；记录问题由宿主校验、独立模型还是人工核验发现。

## 人工修订

提供可供研究者修改的稿件副本和明确的导入修订操作。导入时记录父版本、作者、修改理由、输入文件哈希及变化段落，创建新版本而不覆盖旧稿。修改后的文字不能继承旧段落的“已支持”标签；变化内容需重新建立主张依赖并进行独立复核。

只改变排版也要可追踪，不能仅凭文本相似就把数值/引用改动判断为无实质变化。初版可以保守地把发生文字变化的整段列为待复核；其代价是多检查一些段落，避免默默保留过期标签。未变且依赖不变的部分允许复用已完成成果。

人工输入的正文、段落编号或引用标签本身不授予“支持”状态。导入先形成待审的新修订，记录原始修改内容；需要重新划分主张时，生成的划分也须覆盖提交的全部文本，不能让模型在复核前悄悄润色或删掉改错的句子。对不认识、重复或越界的段落标识给出具体错误，不猜测应该替换哪一段。

正式产物的直接手工改写仍按哈希完整性问题处理，保留原件并给出修订导入路径；不能为了接受改稿而重写旧版校验清单。正文、审查和引用表都保留版本和相互关联。

## 领域包必须实际改变处理结果

实现一个受限的数据型领域包入口。领域包声明名称、版本、兼容契约、术语、检索/筛选提示、需要提取的附加字段、比较表列、评价依据和写作结构。包内容进入明确的任务输入，不能覆盖通用证据、预算、来源权限或发表真实性规则；不执行包内任意脚本。

验收不止检查“能读取配置”：安装独立领域包后，必须从固定样例提取新增字段，生成对应比较表，并让写作结构或评价项实际变化，同时保留通用引用追踪。缺失字段明确“文中未报告”，每个有值字段连接到该篇资料的有效证据并经独立检查。新包不要求修改核心存储或工作流代码。

以现有原创调度仿真为例，可以比较负载条件、样本量、指标和对照方法；A 的模拟任务数应为 40，B 为 60。A 未交代的具体到达分布不能补造；B 没有独立交代的对照细节不能直接从 A 搬过来。提取新增字段与输出比较表才算完成领域特化，换一个报告标题不算。

至少再加载一个放在包源码之外、字段名不同的测试领域包，证明字段与列由契约驱动。对未知领域，Demo 必须明确拒绝或使用显式原创测试协议；不能伪装成通用模型理解。可用 Exchange 的原创协议响应和一次有界真实后端测试分别核对扩展机制与真实调用。

## 恢复、状态与版本

草稿生成和审查共用项目预算；预算暂停、等待输入及失败分别保存。恢复复用已成功且输入未变的阶段，不自动提高预算。资料、人工复核、问题、大纲、领域包或选定统计产物变化时，相应依赖指纹变化；文稿仍作为历史保留。

指南需指向具体动作：补资料、复核主张、生成草稿、导入修订、重审变化段落或重算失效依赖。状态检查读取当前资料和经过校验的历史版本，不创建研究库、执行模型调用或主动搜索。

## 使用验收与最终完成

1. 安装包从多源/导入项目经过阅读、复核、趋势、创新候选到实际段落写作，最终产物可沿引用回查证据；每一步的来源和未完成状态都可见。
2. 用原创 A、B 生成一段包含条件差异和反例的综合说明；A 的 10→8 与 B 的 10→11 不被写成一致改善，40/60 不被当作真实参与者样本。
3. 人工把数字或结论改错后导入新修订，新内容进入待审/冲突状态；旧稿和未变内容保留，不重复已完成有效调用。
4. 修改来源、筛选、复核或领域字段定义后，受影响内容过期；只变更预算或新增无关运行日志不使正文无故失效。
5. 独立领域包提取额外字段并改变比较表/写作结构，核心代码在安装新包前后不变，未知字段或证据被拒绝。
6. 原有 0.1–0.3 命令与固定统计产物兼容；单元/失败回归、完整套件、独立审查、运行依赖安装包旅程及六环境 CI 均完成。
7. 完成相应 Git Flow 发行、获得所需发布确认并核对远端分支/标签后，才将总目标标为完成。具体研究题目的人工学术评测仍是后续用户给题目后的工作，不虚报为已经完成。
