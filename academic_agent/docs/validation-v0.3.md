6. 任务 3 增加一个现有模块的修改边界，从 `innovation_analysis.py` 提取共享的候选/审查校验，并提供只读历史候选入口供评估使用。已实现的任务 2 尚无历史定位接口，直接各写一套会重复引用和宿主 ID 校验，或产生服务循环依赖。代价是多审查一次局部重构；旧生成测试和新历史读取测试必须共同覆盖它。新检索事件的实际保留 ID/有效上限投影也在任务 3 核验，旧日志中未记录的值保持未知。
7. 检索轮次的身份使用候选内容/输入和查询范围，不使用保存目录、manifest 哈希或捕获时间；原候选 manifest 另行固定为来源记录。相同缓存候选重新保存会产生新文件版本，把该版本混入轮次身份会破坏恢复或重置轮次。代价是相同内容重新保存不能暗中开启同名新轮次；明确请求未使用的第 2 轮仍按第 5 项执行新查询。
8. 每轮保存当前查询收据及全部已核验的历史尝试，命中 ID 取历史尝试的并集。否则部分失败时已经保存的 C，可能因重试只返回 D 而从评估范围消失。当前重试失败依据当前收据判断，早先失败保留为历史；代价是多保存尝试记录和命中状态，需要清楚区分历史与当前，而不能重复计数为不同论文。
9. 第 1 轮来源持续失败时，允许用调整后的来源配置开始第 2 轮，再恢复原配置续跑第 1 轮；不增加“前轮必须全部成功”的门槛。为防止相同查询跨轮误认，每次实际检索前持久化独立请求 ID，实际搜索日志和收据绑定该 ID 及查询范围；原缓存不能补贴新 ID。代价是搜索接口和日志增加一个可选字段及恢复测试，旧默认缓存身份和摘要保持兼容。此项细化第 5 项的起点恢复约束。
10. 提供共享的只读候选前提有效性入口供评估使用，与反例检索复用同一政策；单独改变检索来源配置不使原资料依据过期，但问题、项目查询、标题及资料/证据/复核依赖继续核对。这样既允许第 9 项的来源调整，也避免评估另写一套不同的前提判断。代价是多一个公共接口与明确的来源配置例外；当前评估仍将实际检索范围作为输入，不能沿用旧范围的评估。
11. U09 的“新增反例后更新原候选”安装包补验采用实际 CLI 和明确受控的 Exchange 响应，保留固定 Demo 对未知材料的拒绝。这样能验证完整操作与版本变化，而不借扩充演示标识伪装模型理解。代价是多一段离线请求/响应操作和显式样例维护；其结果只证明协议与状态机制，真实模型能力仍由单独冒烟记录。
12. 评估沿用当前完整纳入范围，不为本阶段增加新的文献选择参数。超限仍在派发前明确拒绝，并提示按实际研究范围处理不相关材料或人工配置适配后端的上限；不能自动排除材料或暗示删掉反例以取得结论。代价是大项目不能仅为一次评估临时选子集，无法合理缩小时保留失败。评估及独立逐文本单元审查的版本、七个产物名称同时固定，方便命令行与后续写作消费。
13. 针对审查 T4-R1，将任务 4 的“存储路径/UUID 变化不影响身份”明确为分析输出目录及分析版本 UUID；原文 `source_path` 等来源追溯字段继续遵循已审查的共享依赖政策。绑定阶段规格要求固定文档版本与证据，并未承诺原文迁移透明；原决策要避免的是同一候选或评估另存版本导致重复计算。代价是直接改变原文追溯路径即使字节相同，也可能需要重新核对及计算。本阶段不另做原文迁移归一化，也不只在评估一处删字段而让其他依赖规则分歧。

第 4 项有本地输入规模依据：只读检查上一阶段保存的一次 Crossref 查询（18 条元数据，无新增网络请求），完整检索数据为 73,106 字符，覆盖摘要为 165 字符，Work 元数据总计 20,756 字符；相比默认 100,000 字符模型上限，直接重复传入来源原响应会挤占正文空间。记录位于 `.runs/search-context-size-evidence.json`。任务 2 增加对应的显式投影和选文完整性回归，不改变任务 1 的完整审计快照。
