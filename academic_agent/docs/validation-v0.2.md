规格判断：本轮修复应沿用现有摘要阅读流程、保持数据库检查只读，并准确说明描述性统计能力。若摘要规则理解有误，会改变用户看到的下一步建议；回归将直接对照现有 `Runner.prepare` 的文档选择规则，保留需 OCR 的附件提示。

`ca15d4f` 修复以上三个触发条件，23 项操作/CLI 覆盖测试通过（39.14 秒）。一次限定复审确认 FR-1、FR-2 原始路径问题和 FR-3 已解决，同时用原创数据发现修复新引入的 FR-4：`immutable=1` 会忽略已提交但仍在 WAL 中的记录。一个普通空闲连接保持打开、没有未提交事务也没有并发写入时，正常只读查询看到 1 条文献，而指南显示 0 条。该问题必须纠正，不能以先前 CI 通过代替验证。

规格裁定：指南不得修改研究内容，但允许 SQLite 自身的 WAL/SHM 协调文件；不接受新增“数据库必须静止或已完成 checkpoint”的前提。保留正确编码的路径和正常只读连接，允许的代价是可能留下数据库辅助文件，仍要求研究数据和无关路径不变。这与 [SQLite URI 文档](https://www.sqlite.org/uri.html) 对 `immutable` 会跳过锁定和变化检测的说明一致。

流程裁定：在一次整版修复及限定复审后，对 FR-4 再执行一次有明确范围的必要纠正，以安装包的独立 WAL 操作验证和最终 CI 收口，不重启整版审查。若这一步多余，代价是有界的返工时间；直接保留则会发布已复现的错误状态提示。

`5a56dc3` 去掉 `immutable`，保留编码后的 `mode=ro` 并以显式读取事务取得一致数据库快照。WAL 回归先失败、后通过；9 项指南覆盖测试通过（2.03 秒），Ruff 通过。控制者检查了这两个文件的实际差异，再重新构建 wheel/sdist 并安装到纯运行环境。
